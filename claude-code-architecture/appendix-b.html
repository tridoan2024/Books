Layer Architecture

The system follows a four-layer architecture where each layer may only depend on layers below it:

Layer Components Responsibility
UI Terminal UI, Input Processing, Markdown Renderer User interaction, display, input capture
Application Agent Loop, Skill System, Hook Engine, Scheduler Workflow orchestration, lifecycle management
Domain Tool Registry, Permission System, Context Engine, Subagent Manager Core agent logic, security, tool execution
Infrastructure API Client, MCP Client, Session Storage, Configuration, Global State External communication, persistence, config

The Dependency Rule

Each layer depends only on layers below it:

graph TB
    A["UI Layer<br/>(React/Ink components)"] --> B["Application Layer<br/>(Agent loop, hooks, skills)"]
    B --> C["Domain Layer<br/>(Tools, permissions, context)"]
    C --> D["Infrastructure Layer<br/>(API, MCP, storage, config)"]

The UI layer never calls the API client directly — it goes through the agent loop. The permission system never renders UI — it returns a decision that the UI layer displays. This strict layering prevents circular dependencies and keeps each component testable in isolation.

Circular Dependency Prevention

Several design patterns prevent circular dependencies in the architecture:

1. The Event Pattern (Hooks)

Instead of the Hook Engine calling back into the Agent Loop, hooks communicate through exit codes and stderr:

Agent Loop → Hook Engine → Shell Script → Exit Code → Agent Loop

The hook returns data, not control flow. This breaks what would otherwise be a circular dependency.

2. The Callback Pattern (Permissions)

The AI auto-mode classifier needs to call the API client, but the permission system is called FROM the agent loop which also calls the API client. Solution: The classifier uses a separate API call (side-query) that bypasses the normal agent loop entirely. It is a direct API client call with its own context, not a recursive agent turn.

3. The State Pattern (Global State)

Instead of components depending on each other for shared data, both depend on Global State. The State singleton breaks potential circular chains by serving as a shared data hub that any component can read from and write to.

4. The Registry Pattern (Tools)

Tools do not call the Tool Registry — the Registry calls tools. Tools are registered at startup and invoked through a uniform interface. No tool ever imports or calls the registry, maintaining a strict one-way dependency.
