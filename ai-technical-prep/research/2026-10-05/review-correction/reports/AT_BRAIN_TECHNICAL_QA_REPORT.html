1. Executive summary

AT-Brain is an advisory-only "judgment sidecar" for the capture-at SPY PAPER trading bot. It does not trade. On each decision it answers a fixed set of typed questions about the evidence capture-at already parses from its source of truth (the v9 live page at 127.0.0.1:8887) and returns typed verdicts — a ranked evidence list, a convergence reading, a setup regime + quality score, hazard flags, and a lesson/citation audit — each with provenance and (optionally) a calibrated probability. capture-at may fold these into its own scoring/sizing/exit logic, but AT-Brain never sends, sizes, or blocks an order (action_authorized is always False), never touches adapters.py / the 8887 order path, and is default-OFF + fail-open so that, disabled, capture-at behaviour is byte-identical.

Two things make it a Jev brain rather than "another LLM wrapper":

  1. Typed decisions, not prose. Every family emits a Jev primitive — Choice, Score, or Noul (a calibrated probability that a proposition is true) — never free text. Output is machine-consumable and auditable.
  2. Calibration is a first-class, opt-in property. The default local engine is deterministic but uncalibrated (calibrated=False, confidence=None). Only the opt-in TypeSafe Jev model (jev-1.13.0, verified live via @jkudish/jev-mcp) returns calibrated probabilities, under an explicit budget.

Validated results (on the owner's own 119-trade backtest): AT-Brain's J3 convergence screen separates winners from losers well enough to turn a take-all book of −4.75 pts into +2.38 pts in-sample, and to cut held-out loss from −2.45 to −0.78 pts (−1.68 avoided). Both real-money losers that motivated the J4 guardrail independently fire shorting_into_floor at p=0.95 in shadow. All of this is advisory. See §4 for the honest limits.

2. Jev / TypeSafe "System One" — an engineering primer

2.1 What "Jev" is

Jev (the model family behind TypeSafe) is a non-autoregressive, typed-decision model. Where a conventional LLM generates a token stream left-to-right and you parse structure back out of the prose, a Jev model is asked a typed question and returns a typed value with a calibrated probability distribution in a single bounded forward pass. The usual metaphor is Kahneman's two systems:

System One (Jev) System Two (generative LLM)
Output one typed value (Choice/Score/Noul) a token stream of prose
Shape fixed, schema-bound, machine-readable open-ended, must be re-parsed
Latency low, bounded (one decision) higher, grows with tokens
Uncertainty calibrated probability per option implicit / not calibrated
Failure mode abstain / low-confidence hallucinate fluent prose
Good at fast, repeatable judgments reasoning, synthesis, writing

The engineering point: when what you need is a decision ("which of these is most decisive?", "how strong is this setup, 0–8?", "is this hazardous?"), a System-One model is cheaper, faster, auditable, and — crucially — tells you how sure it is in a number you can threshold on.

2.2 The three typed primitives

Every Jev question resolves to exactly one of three primitives. AT-Brain uses all three:

  • Choice — pick one option from a closed set, with a probability distribution over the set. (AT-Brain J3 regime: trend-up | trend-down | chop | unclear.)
  • Score — an ordinal grade on a bounded scale. (AT-Brain J3 quality: integer 0..8.)
  • Noul — P(proposition is true), a single calibrated probability in [0,1]. The name is Jev-specific; think "a calibrated yes/no." (AT-Brain J2 convergence masses and every J4 hazard are Nouls.)

A reranking question ("order these N items by relevance") is expressed as repeated scoring; AT-Brain treats J1/J5 rerank as a deterministic dot-product today and can defer the selection to a Jev Choice over item_0..item_{n-1} via the reference path (§3.8).

2.3 Why calibration matters

A calibrated probability means: of all the times the model says 0.7, roughly 70% are true. That is what lets a downstream system threshold safely — "only act when the hazard Noul is < 0.2", "size up only when quality ≥ 4". An uncalibrated score can still rank correctly while being a poor probability; you can sort by it but you cannot trust its magnitude. AT-Brain makes this distinction explicit and structural (next section), rather than pretending every number is a probability.

3. Jev in AT-Brain — how the brain is engineered

3.1 Design stance

AT-Brain is a pure function from typed evidence to typed verdicts. engine.judge(request): performs no network, no file, no clock (beyond elapsed timing), raises ValueError on a malformed request (which the service turns into a fail-open abstain), and stamps every result with action_authorized=False and bounded provenance. The brain can therefore be unit-tested exhaustively and can never, by construction, place a trade.

3.2 Two backends — this is the core engineering decision

                     ┌──────────────────────────────────────┐
  request ──────────▶│  custom backend  (engine.py)         │──▶ deterministic verdicts
  (typed evidence)   │  J1–J5, pure, DETERMINISTIC,         │    calibrated = False
                     │  UNCALIBRATED (confidence = None)     │    confidence  = None
                     └──────────────────────────────────────┘    provider_calls = 0
                     ┌──────────────────────────────────────┐
  request ──(opt-in, │  typesafe reference (reference.py)   │──▶ CALIBRATED probabilities
   budgeted, live)──▶│  → transport.py → @jkudish/jev-mcp   │    calibrated = True
                     │  → Jev model jev-1.13.0              │    confidence  = <float>
                     └──────────────────────────────────────┘    provider_calls = 1 (budgeted)
  • Custom backend (default). A deterministic re-implementation of the judgment logic. It is honest about being uncalibrated: every verdict carries calibrated=False, confidence=None. It is free, offline, and fully reproducible — ideal for shadow mode and CI.
  • TypeSafe reference (opt-in). reference.evaluate(..., live=True, credential=…, send=…) projects a bounded choice-payload and calls the real Jev model. It is default-disabled (live=False → status="disabled", zero network), budgeted (store.reserve(budget_id, cap), cap ≤ 32), cached (5-min TTL), and fail-open (any error → no-verdict stub). Only this path returns calibrated=True probabilities.

This split means you never confuse "a deterministic ranking" with "a calibrated probability," and you only pay (money, latency, external dependency) when you explicitly ask for calibration.

3.3 The typed evidence vocabulary

Callers pass bounded, provenance-bearing Candidate records (evidence.py) that mirror the fields capture-at already parses. The engine reads only the typed metadata, never the free text as an instruction (untrusted-reason-isolated): text is used for lexical relevance and provenance hashing only.

Field Meaning
id, text, source_ref identity + bounded excerpt (≤1600 chars, rejected not truncated) + provenance pointer
kind one of 12 typed kinds: short_color, mid_long, vwap, level, price, mlma, option_packet, ownership, authority, session_band, lesson, citation
direction bullish \| bearish \| neutral \| unknown → lean ∈
observed, fresh, in_scope provenance/quality flags feeding freshness & sufficiency
age_seconds, proximity_ticks recency decay & level-proximity features
hazard, present J4 guardrail: one of 5 hazards + whether the condition holds
cited_value, source_value J5 citation audit pair
source_sha256 SHA-256 of text (auto-filled) — provenance hash

Directional weights (documented constants, not learned in v1): short_color 1.0, mid_long 0.8, vwap 0.7, mlma 0.6, level 0.5, price 0.4. Recency decays by half every 900 s (0.5 ** (age/900)); unknown age → neutral 0.5. Freshness factor = (1.0 if observed else 0.5) × (1.0 if fresh else 0.75) ∈ [0.5, 1.0].

3.4 The J1–J5 judgment catalog

One batched engine.judge pass runs the requested families. Each maps to a Jev primitive:

Family Question Jev primitive Output
J1 Which evidence is most decisive right now? rerank (Score×N) ordered list + surfaced/grouped_low
J2 How much do signals converge? three Nouls P(bull), P(bear), P(chop)
J3 What regime, and how good is the setup? Choice + Score regime ∈ 4; quality ∈ 0..8
J4 Any guardrail hazards? (shadow) one Noul per hazard per-hazard p + BACKSTOP notes
J5 Which lesson applies; do citations match? rerank + audit lesson order + per-citation match

J1 — evidence rerank. A 10-feature vector per candidate (query_coverage, text_precision, phrase, specificity, observed, fresh, in_scope, recency, directional_info, level_proximity) dotted with bounded weights; stable sort; top-k surfaced, the rest grouped-low. Weights are learnable (§3.9) but v1 ships documented defaults.

J2 — convergence. Directional "mass" per side = kind_weight × freshness × recency, split into bull / bear / neutral. Then:

P(bull) = bull / total
P(bear) = bear / total
P(chop) = 1 − |bull − bear| / total

If there is no directional evidence, all three abstain (abstained=True) rather than emit a fake 0.5.

J3 — regime + quality (the convergence screen that drove the validation).

strength      = |bull − bear| / total              # how one-sided the evidence is
q_sufficiency = min(1, n_fresh_observed / 4)        # how corroborated it is
quality       = round(8 × strength × q_sufficiency) # integer 0..8

This is the mechanism behind Evidence A (§4.2): a solo fresh+observed signal has q_sufficiency = 1/4 → quality ≈ 2; add one independent agreeing family → q_sufficiency = 2/4 → quality ≈ 4; two → 3/4 → quality ≈ 6. "Only take setups where ≥1 independent family corroborates" is exactly quality ≥ 4.

J4 — guardrail (shadow, advisory). One Noul per hazard (separate-flags — never a blended severity). A present+observed hazard:

p = clamp(0.6 + 0.25·observed + 0.10·fresh, 0.02, 0.97)   # present
p = clamp(0.1 − 0.05·observed,              0.02, 0.97)   # absent

Advisory severity is the max hazard p, never the mean (max-not-average). A present+observed hazard also emits a deterministic, model-independent BACKSTOP note (deterministic-backstop). Mode is always "shadow".

J5 — lesson relevance + citation audit. Reranks lesson candidates by the same relevance machinery, and for every citation candidate checks that the cited number matches its source (whitespace/case-normalized). A mismatch emits CITATION MISMATCH […] — a DIASENTINEL-style guard against acting on a misquoted number.

3.5 Safety DNA — five grader rules (adopted verbatim from TypeSafe practice)

These are not decoration; they are enforced in code and covered by tests:

  1. separate-flags — one Noul per hazard; hazards never averaged into one number.
  2. max-not-average — advisory severity = worst hazard, so one serious hazard is never diluted.
  3. deterministic-backstop — a present+observed hazard raises a hard note regardless of any model output. Model silence cannot suppress it.
  4. untrusted-reason-isolated — candidate free text is data, never an instruction. No evidence string can steer the engine.
  5. no-noul-confidence — the uncalibrated custom backend never fabricates a confidence; only the calibrated reference path sets one.

3.6 Bounds & provenance

  • Candidate count: default 8, hard ceiling 32. Per-candidate text ≤1600 chars (oversized → rejected, never silently truncated). Request ≤32 768 bytes.
  • Canonical wire form (common.wire): sorted keys, compact, allow_nan=False — stable hashing.
  • Every verdict carries request_sha256 and per-candidate source_sha256; provider_calls, usage, and elapsed_ms are always reported.

3.8 The live TypeSafe seam (reference + transport + MCP)

reference.evaluate builds a bounded choice-payload — question + item_0..item_{n-1} candidates + the fixed evidence-relevance rubric — and hands it to an injected send(payload, credential) transport. transport.py provides that transport by driving the verified jev MCP over stdio:

initialize (protocolVersion 2025-06-18) → notifications/initialized → tools/call jev_decide

It maps reference's candidates to jev_decide arguments (candidates keyed by description), and maps the model's calibrated recommendation.{selected, probabilities, confidence} back into reference's answers.priority envelope. Non-item escape tokens map to abstentions (ask_user/investigate → unknown, none → none). Model identity is pinned (jev-1.13.0); a resolved-model mismatch raises and fail-opens.

Why it is safe to ship now: the whole seam is proven offline (test_transport.py drives the full handshake + reference.evaluate with a fake stdio spawn) — no paid call, no real trade data sent to the third party. Live use stays owner-gated and budgeted.

3.9 Learning under a lookahead firewall

learner.py can propose new J1/J5 rerank weights, but only under strict gates ported from the custom_jev learner:

  • known_at lookahead firewall. Every curated case must carry an ISO-8601 known_at; features must predate the decision timestamp (prevents label leakage).
  • Split isolation. No source/request/group may leak across train/final.
  • Held-out promotion gate. Activation requires ≥8 fresh training cases and ≥8 fresh held-out final cases with real accuracy gain and zero regressions, under an unchanged parent (atomic pointer swap). Otherwise it stays in shadow or is rejected.
  • No generated code is executed; weights clipped to [−16, 16].

v1 ships the documented default weights; the learner is wired and tested but not required.

4.2 Evidence A — the J3 convergence screen separates winners from losers

Setup. capture-at's backtest emits the same entry signal under independent families (published20 [executed], kendall8, efficiency8). AT-Brain treats agreement of the other families within ±120 s as corroboration and runs J2/J3. No P/L, price, or outcome enters the request — only signal co-occurrence known at entry. Rule: endorse iff J3 quality ≥ 4 (≥1 independent corroborator). Harness: scripts/replay_capture_at.py → docs/replay_results.json.

4.5 Honest limitations (do not overclaim)

  • The net-positive +2.38 result is full-window (in-sample-leaning). On the held-out fold the kept bucket is still −0.78 — the screen reduces loss out-of-sample but did not, on that small fold, reach net-positive.
  • The held-out gain is driven by avoiding larger-magnitude losers, not higher win-rate (held-out endorsed win-rate 41.2% ≤ screened 43.5%). Loss-magnitude control is the mechanism there.
  • One instrument, one 10-session window, one executed set (published20/off/dots), n=119. This is suggestive, repeatable evidence — not a powered statistical claim.
  • J1/J5 (rerank, citation audit) are built and unit-tested but not yet separately measured on trading P/L.

Consistent with the owner's honest-null discipline ("Oview has NO measured edge"), the claim is bounded: AT-Brain's convergence screen materially reduces loss and, on the full window, flips the book positive; the J4 guardrail catches the known worst-loss pattern. Wider, live-shadow validation is required before calling it a durable edge.

5. If you integrate it into capture-at — what to expect

5.1 Where it plugs in

The integration surface already exists and is inert: one guarded line in the non-live legacy path (score_signal.py:758) calls at_brain_shadow.observe(event) after the score event and before execute. With AT_BRAIN_SHADOW unset, capture-at is byte-identical. Enabling is a single env flag; AT-Brain reads the event dict already in hand and writes advisories to a JSONL log. It never imports adapters.py and cannot reach the order path.

5.2 Expected help — three channels

  1. Convergence gating (J3) → fewer, better trades. Historically, restricting to corroborated setups (quality ≥ 4) flipped the book from −4.75 → +2.38 pts in-sample and cut held-out loss ~68% (−2.45 → −0.78), while taking ~half the trades. Expectation if consumed as a size/skip input: materially fewer low-conviction entries (the quality-2 bucket held the losses), a higher win rate on what remains, and smaller drawdowns — directionally, not a guaranteed net-positive on every window.
  2. Hazard surfacing (J4) → avoid the worst single losses. The two documented worst losses (including a −$150 / −19.4% circuit-breaker) both fire shorting_into_floor at p=0.95. Expectation if consumed as a soft veto / size-down near King floors: the specific pattern behind the fattest-tail losses gets flagged pre-entry, giving capture-at's own gates a chance to skip or shrink size. Advisory only — the bot still decides.
  3. Evidence rerank + citation audit (J1/J5) → act on the right, correctly-quoted data. Surfaces the decisive evidence and catches cited-number/source mismatches. Expectation: fewer entries driven by stale or misquoted fields. Qualitative today — not yet measured on P/L.

5.3 What it will not do

  • It will not place, size, cancel, or block an order. action_authorized is always False.
  • It will not override capture-at's ownership/authority/protection gates.
  • It will not make capture-at profitable on a window where the underlying signals have no edge — it reweights which signals you act on; it does not manufacture an edge.
  • Enabling it will not change capture-at behaviour until you choose to consume a verdict; in shadow it only logs.

5.4 Recommended rollout (measure before you lean on it)

  1. Shadow (now, zero risk). export AT_BRAIN_SHADOW=1 on the live PAPER bot. Log advisory vs realized outcome to at_brain_shadow.jsonl for a meaningful number of sessions. Order path untouched.
  2. Measure online. Re-run the Evidence-A analysis on the fresh live shadow log (not the backtest). Confirm the J3-quality → P/L separation holds out-of-sample with a confidence interval.
  3. Consume selectively. If the lift holds, let capture-at read J3 quality as a sizing/skip input and J4 as a soft veto near floors — still inside its own gates, still PAPER.
  4. Calibrate borderline cases (optional, budgeted). For setups near the quality threshold, spend a budgeted TypeSafe reference call for a calibrated confidence, with the 5-min cache and cap ≤ 32 budget.
