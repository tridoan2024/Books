Chapter 19: Closed Loops First, Open Loops Later

Level: S (Standard) · ~4,000 words · Levels served: L3, L4, L5

19.1 The Two Modes of Operation

A closed loop follows a human-designed path through a problem. The steps are predetermined. The verification is explicit. The scope is bounded. The model exercises judgment within these constraints, but the constraints themselves are fixed.

An open loop follows a model-discovered path. The model decides what to investigate, what approaches to try, and when to change direction. The scope is emergent. The constraints are minimal.


Closed Loop:                          Open Loop:
┌─────────────────────┐               ┌─────────────────────┐
│ Human designs path  │               │ Human defines goal   │
│ Model walks path    │               │ Model discovers path │
│ Oracle checks steps │               │ Model self-evaluates │
│ Bounded scope       │               │ Emergent scope       │
│ Predictable cost    │               │ Variable cost        │
└─────────────────────┘               └─────────────────────┘

Both have their place. But if you're building your first loops — or if you need reliability — start closed. Open loops are powerful but treacherous.

19.2 Closed Loops: Bounded Reliability

A closed loop constrains the model at every decision point:


closed_loop_example:
  trigger: "PR opened"
  steps:
    1: "Read the diff"
    2: "Check each file against security rules (enumerated)"
    3: "For each finding, verify it's real (call tool X)"
    4: "Format findings using template Y"
    5: "Post review comment"
  oracle: "Findings match expected format, no false positives vs. test set"
  budget: "3 iterations max"

The model can't decide to do something else. It can't pivot to a different approach. It can't expand scope. It follows the script, applying judgment only within each step.

Advantages of closed loops:

  • Predictable cost: You know how many steps, how many tokens per step, what the maximum cost will be.
  • Debuggable: When something goes wrong, you know exactly which step failed and why. The path is traceable.
  • Reliable: The same loop produces similar results across runs. The variance is low.
  • Auditable: Every decision is constrained by the design. You can explain why the system did what it did.
  • Fast to build: You already know the right path. You're just encoding it.

Disadvantages of closed loops:

  • Brittle: If the problem doesn't fit the designed path, the loop fails rather than adapting.
  • Limited: Can't discover novel approaches or handle unexpected situations.
  • Requires expertise: You must know the right path in advance to design it.

19.3 Open Loops: Exploratory Power

An open loop gives the model freedom to discover the path:


open_loop_example:
  trigger: "Bug reported"
  goal: "Identify root cause and produce a fix that passes all tests"
  constraints:
    - "Stay within src/ directory"
    - "Don't modify test files"
    - "Budget: 10 iterations, 500K tokens"
  approach: "Agent decides investigation strategy"

The model might read logs, search code, form hypotheses, test them, backtrack, try different approaches — whatever it takes to reach the goal.

Advantages of open loops:

  • Adaptive: Handles novel problems that don't fit a predetermined path.
  • Discovers: Can find solutions the designer wouldn't have thought of.
  • Resilient: When one approach fails, it can try another without human redesign.

Disadvantages of open loops:

  • Expensive: Exploration burns tokens. Wrong paths are tried before right ones.
  • Unpredictable: Cost and time vary widely between runs. Hard to budget.
  • Hard to debug: When the loop produces a wrong result, tracing why through an emergent path is difficult.
  • Drift-prone: Without constraints, the model may wander away from the goal.

19.4 The Reliability-Cost Tradeoff


                     │
    Reliability      │    Closed loops
                     │    ●●●●●
                     │         ●
                     │          ●
                     │           ●
                     │            ●  Open loops
                     │             ●●●●●
                     │
                     └───────────────────────
                              Cost

Closed loops: high reliability, predictable cost, limited capability.

Open loops: variable reliability, unpredictable cost, broad capability.

The tradeoff isn't fixed — you can push open loops toward higher reliability by investing in better oracles, tighter budgets, and stronger guardrails. But at baseline, a closed loop will outperform an open loop on reliability for any well-understood task.

19.5 The Graduation Criteria

Start closed. Graduate to open only when:

Criterion 1: Your oracle is strong

An open loop without a strong oracle is a random walk. The model explores freely but can't verify when it's found the right answer. You need an oracle that reliably distinguishes good output from bad output regardless of the path taken to produce it.

Minimum oracle quality for open loops: >90% detection rate for incorrect output, with <5% false positive rate.

Criterion 2: Your stop conditions are robust

Open loops are more likely to oscillate, thrash, or drift than closed loops. Your stop controller must detect all three conditions reliably. If you're still debugging your oscillation detector, keep the loop closed.

Criterion 3: The task genuinely requires exploration

If you know the right path, encode it as a closed loop. Open loops pay exploration tax on every run — tokens spent discovering a path you already know. Only use open loops for tasks where the path is genuinely unknown or varies between runs.

Criterion 4: You can afford the variance

Open loops have higher cost variance. One run might take 50K tokens; another run of the same task might take 300K. If your budget can't absorb this variance, stay closed.

Criterion 5: You have monitoring

Open loops require monitoring to detect drift, runaway cost, and quality degradation. Without observability into what the open loop is doing, you can't tell when it's misbehaving until the results arrive (or the bill does).

19.6 The Hybrid: Closed Shell, Open Core

The most practical architecture for production: a closed outer loop with open inner steps.


Closed outer loop (fixed structure):
  Step 1: Load context and skills              [closed]
  Step 2: Discover relevant information        [OPEN — agent decides what to search]
  Step 3: Plan approach                        [OPEN — agent decides strategy]
  Step 4: Execute plan                         [OPEN — agent adapts to errors]
  Step 5: Verify against goal                  [closed — oracle is deterministic]
  Step 6: If failed, iterate                   [closed — fixed retry logic]
  Step 7: Report result                        [closed — fixed format]

The outer structure is deterministic: always load context, always verify, always report. The inner steps are open: the model decides what to search, how to plan, and how to execute. This gives you the reliability of a closed loop (fixed checkpoints, guaranteed verification) with the adaptability of an open loop (flexible investigation and execution).

19.7 Widening a Closed Loop

When a closed loop hits its limits — when you keep encountering tasks it can't handle — you widen it incrementally:

Step 1: Identify the constraint

Which fixed step is limiting? Is it the investigation strategy? The approach? The retry logic?

Step 2: Add one degree of freedom

Don't open everything at once. Make one step adaptive while keeping the rest closed. Example: "The investigation step can choose which files to read" (previously it always read the same 3 files).

Step 3: Verify reliability held

After widening, does the loop still produce reliable results? If reliability dropped significantly, the new freedom needs tighter guardrails or a better oracle.

Step 4: Repeat if needed

Widen one step at a time. Each widening is a controlled experiment. If it improves outcomes without degrading reliability, keep it. If it hurts reliability, either strengthen the oracle or revert.

19.8 Cost Profiles in Practice

Real-world comparison for a PR security review task:

Metric Closed Loop Hybrid Open Loop
Avg tokens/run 80K 150K 350K
Cost/run $0.24 $0.45 $1.05
Avg iterations 1.2 2.1 4.7
Success rate 92% 94% 89%
Finds novel issues Rarely Sometimes Often
Time to result 30s 90s 4min

The closed loop is cheapest and most reliable for known patterns. The open loop finds issues the closed loop misses — but at 4x the cost and lower reliability. The hybrid captures most of the open loop's benefits at moderate cost.

19.9 Anti-Patterns

Opening too early: Adding open-ended exploration to a loop before the oracle and stop conditions are reliable. The result: expensive runs that produce unverified output.

Never opening: Keeping a closed loop that consistently fails on edge cases, rather than adding adaptability where the fixed path is insufficient.

Opening everything at once: Going from fully-closed to fully-open in one step. If reliability drops, you can't tell which new freedom caused it. Open one degree of freedom at a time.

Closing after failure: A loop encounters one expensive open-loop run, and the team restricts it to closed-only. The fix is better budgets and stop conditions, not less capability.

19.10 The Decision Rule


Is the path from input to output known and stable?
├── Yes → Closed loop (encode the path)
├── Mostly, with occasional variation → Hybrid (closed shell, open investigation)
└── No, varies significantly per task → Open loop (with strong oracle + budget)

Start closed. Measure where it fails. Open specifically at those failure points. Monitor the impact. Repeat. This is the safest path to capable, reliable loops that handle real-world variation without burning money on unnecessary exploration.
