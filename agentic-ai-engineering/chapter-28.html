Chapter 28: Cost Engineering

Level: S (Standard) · ~4,000 words · Levels served: L3, L4, L5

28.1 The Five Levers

Cost engineering for loops pulls five levers, each addressing a different source of waste:

  1. Caching — Don't re-compute what hasn't changed
  2. Batching — Amortize overhead across multiple items
  3. Cascading — Use the cheapest model that handles each step
  4. Compression — Keep contexts small without losing signal
  5. Killing — Stop loops that aren't converging

Each lever is independent. Pulling all five simultaneously can reduce loop cost by 60-80% without quality degradation.

28.2 Prompt Caching

When the same prefix appears in consecutive model calls (common in loops where the system prompt and skills are identical each iteration), prompt caching avoids re-processing those tokens.


# Without caching: full system prompt re-processed every call
# 10 iterations × 10K system prompt = 100K tokens processed 10x = 1M token equivalents

# With caching: system prompt cached after first call
# 10K processed once + 10K × 9 cache hits = 10K + 90K (at 90% discount)
# Effective cost: 10K + 9K = 19K token equivalents (vs 100K)

How caching works with Anthropic:

The first call with a given prefix processes all tokens at full cost. Subsequent calls within the cache TTL (5 minutes) hit the cache — paying only 10% of the input token cost for cached portions.

Maximizing cache hits:

  1. Stable prefixes: Put stable content (system prompt, skills, tools) at the start of the message. Variable content (current step, tool results) at the end.
  2. Consistent ordering: Send messages in the same order across iterations. Reordering invalidates the cache.
  3. Iteration timing: Keep iterations under 5 minutes apart to stay within the cache TTL. If a step takes longer, the next iteration pays full price again.

Cache-aware loop design:


class CacheAwareLoop:
    def __init__(self):
        self.stable_prefix = self.build_system_prompt()  # Cached across iterations
    
    async def iterate(self, current_state: str) -> str:
        messages = [
            {"role": "system", "content": self.stable_prefix},  # Cached ✓
            {"role": "user", "content": current_state},         # Variable
        ]
        # Only current_state is processed at full cost
        return await model.generate(messages)

28.3 Batch Processing

Many loops process items independently — reviewing each file in a PR, checking each finding, evaluating each candidate. Batching groups items into single model calls:


# Without batching: one call per file (5 files = 5 calls)
for file in pr_files:
    review = await model.review(file)  # 5 separate inference calls

# With batching: one call for all files
review = await model.review_batch(pr_files)  # 1 inference call

# Cost difference:
# Unbatched: 5 × (system_prompt + file + generation) = 5 × 15K = 75K tokens
# Batched: 1 × (system_prompt + 5_files + generation) = 1 × 55K = 55K tokens
# Savings: 27% (system prompt overhead amortized)

When batching helps:

  • Multiple independent items to process
  • Each item is small relative to the context window
  • Processing doesn't depend on item order

When batching hurts:

  • Items are large (batch exceeds context window)
  • Quality degrades with more items (attention dilution)
  • Items require different approaches (can't be processed uniformly)

28.4 Model Cascades

Use the cheapest model that handles each task type. Escalate to more expensive models only when cheaper ones fail:


class ModelCascade:
    def __init__(self):
        self.tiers = [
            ("haiku", 0.25),      # Try cheapest first
            ("sonnet", 3.00),     # Escalate if haiku fails
            ("opus", 15.00),      # Last resort
        ]
    
    async def generate(self, prompt: str, validator: Callable) -> str:
        for model, cost in self.tiers:
            result = await call_model(model, prompt)
            if validator(result):
                return result
            # This tier failed — escalate
        raise AllTiersFailedError()

Cost cascade rules:

Task Type Start With Escalate If
Formatting, extraction Haiku Output doesn't match schema
Code implementation Sonnet Tests fail after 2 attempts
Architecture, synthesis Opus (Don't cascade — start here)
Code review Sonnet Findings seem insufficient
Classification Haiku Low confidence in output

The lead-cheap-specialists-expensive pattern:

For fleets, a powerful pattern: use an expensive model (Opus) for the lead (which does planning and synthesis) and cheap models (Sonnet or Haiku) for specialists (which do focused, well-scoped work).

The lead needs broad reasoning to decompose and synthesize. Specialists need narrow execution within clear constraints — a cheaper model handles that well.

28.5 Context Compression

Every token in context costs money. Compression reduces context size without losing essential information:

Summarization:

Replace verbose content with concise summaries.


# Before: 5,000 token tool result
full_result = tool.read_file("src/auth.py")  # Returns entire file

# After: 800 token summary
summary = summarize_for_task(full_result, current_goal)
# "auth.py contains: UserAuth class (line 15-89) with methods validate_token,
#  refresh_token, revoke_session. validate_token checks JWT signature and expiry.
#  The bug is likely in validate_token:42 where expiry is compared using `<` not `<=`."

Selective loading:

Only load portions of files relevant to the current step.


# Instead of reading entire file
content = read_file("src/auth.py")  # 3,000 tokens

# Read only relevant section
content = read_file("src/auth.py", lines=(40, 70))  # 500 tokens

History pruning:

Remove old iterations from context, keeping only the current state.


def prune_history(messages: list, keep_last_n: int = 2) -> list:
    system = [m for m in messages if m["role"] == "system"]
    recent = messages[-keep_last_n * 2:]  # Last N user/assistant pairs
    return system + recent

28.6 Extended Thinking Budgets

Claude's extended thinking feature generates reasoning tokens before producing output. These tokens cost money but improve quality. Budget them per step:


thinking_config = {
    "simple_edit": {"max_thinking_tokens": 1024},
    "bug_diagnosis": {"max_thinking_tokens": 8192},
    "architecture": {"max_thinking_tokens": 16384},
    "formatting": {"max_thinking_tokens": 0},  # No thinking needed
}

For simple tasks, extended thinking is waste — the model knows what to do without extensive reasoning. For complex tasks, it's essential — skimping on thinking tokens produces worse output that requires more iterations (which costs more than the thinking would have).

28.7 Killing Non-Converging Loops

The most underused cost lever: stopping early when the loop won't converge.


class ConvergenceMonitor:
    def __init__(self, patience: int = 3):
        self.scores: list[float] = []
        self.patience = patience
    
    def should_kill(self) -> bool:
        if len(self.scores) < self.patience:
            return False
        
        recent = self.scores[-self.patience:]
        
        # No improvement in last N iterations
        if max(recent) - min(recent) < 0.05:
            return True
        
        # Scores are declining
        if all(recent[i] >= recent[i+1] for i in range(len(recent)-1)):
            return True
        
        return False

A loop killed at iteration 3 (when it's clearly not converging) saves 60% of budget compared to a loop that runs all 7 iterations. The early termination produces the same result (escalation to human) but at lower cost.

28.8 Cost Monitoring and Alerts

Track cost in real-time and alert when anomalies appear:


class CostMonitor:
    def __init__(self, daily_budget: float = 50.0):
        self.daily_budget = daily_budget
        self.spent_today = 0.0
    
    def record(self, tokens: int, model: str):
        cost = self.calculate_cost(tokens, model)
        self.spent_today += cost
        
        if self.spent_today > self.daily_budget * 0.8:
            alert("Cost warning: 80% of daily budget consumed")
        if self.spent_today > self.daily_budget:
            alert("Cost exceeded: killing non-critical loops")
            self.kill_non_critical_loops()

28.9 The Latency-Cost Tradeoff

Cheaper approaches are often slower (batching waits for items, cascading retries, caching requires warm-up). The tradeoff:

Technique Cost Reduction Latency Impact
Prompt caching 30-50% None (faster, actually)
Batching 20-30% Higher (waits for batch)
Model cascade 40-60% Higher (retries on failure)
Context compression 20-40% Slight (summarization step)
Early termination 30-60% Lower (stops sooner)

For latency-sensitive loops (real-time responses, interactive use), favor caching and compression over cascading and batching. For batch workloads (nightly scans, bulk processing), use all techniques aggressively.

28.10 Putting It All Together

A fully cost-engineered loop:


class CostEngineeredLoop:
    def __init__(self):
        self.cache = PromptCache(ttl=300)
        self.cascade = ModelCascade(["haiku", "sonnet", "opus"])
        self.monitor = CostMonitor(daily_budget=50.0)
        self.convergence = ConvergenceMonitor(patience=3)
    
    async def run(self, goal: str, budget: Budget) -> Result:
        # Stable prefix cached across iterations
        prefix = self.cache.get_or_build(self.system_prompt + self.skills)
        
        for iteration in range(budget.max_iterations):
            # Select cheapest sufficient model
            model = self.cascade.select(step_type=self.current_step_type())
            
            # Compressed context
            context = self.compress(self.state, keep_last_n=2)
            
            # Generate with thinking budget
            output = await model.generate(
                prefix + context,
                thinking_budget=self.thinking_for_step(),
            )
            
            # Track cost
            self.monitor.record(output.tokens, model.name)
            
            # Check convergence
            score = await self.verify(output)
            self.convergence.record(score)
            
            if score >= self.threshold:
                return Result(success=True, output=output)
            
            if self.convergence.should_kill():
                return Result(success=False, reason="not_converging")
        
        return Result(success=False, reason="budget_exhausted")
