Chapter 33: SRE for Agent Fleets

Level: S (Standard) · ~4,000 words · Levels served: L3, L4, L5

33.1 Loops Are Services

An agent loop in production is a service. It has uptime requirements, failure modes, deployment risks, and operational runbooks. But it differs from traditional services in ways that matter:

Traditional service Agent loop
Deterministic behavior Non-deterministic (same input, different paths)
Fixed resource usage Variable (cost depends on iterations, context size)
Fails fast or succeeds May degrade gradually without clear failure signal
Code changes are the deployment risk Prompt changes, model version changes, tool changes — all are deployment risks
Tests prove correctness Tests prove behavior over a distribution

SRE for agent fleets requires adapting reliability engineering to this non-deterministic, multi-variable environment.

33.2 Deployment Patterns

Prompts and Skills as Code

Every component of a loop — system prompt, skill definitions, tool schemas, oracle criteria — lives in version control. Deployment of a loop change follows the same pipeline as code:


# Directory structure for a versioned loop
# loops/
# ├── pr-reviewer/
# │   ├── v2.3.1/
# │   │   ├── system_prompt.md
# │   │   ├── skills/
# │   │   │   ├── security_review.md
# │   │   │   └── logic_review.md
# │   │   ├── tools.json
# │   │   ├── oracle_criteria.yaml
# │   │   └── config.yaml
# │   ├── v2.3.2/  (next version)
# │   └── CHANGELOG.md


@dataclass
class LoopVersion:
    """A specific version of a loop configuration."""
    
    name: str
    version: str
    system_prompt: str
    skills: dict[str, str]
    tools: list[dict]
    oracle_criteria: dict
    config: dict
    
    @classmethod
    def load(cls, loop_name: str, version: str) -> "LoopVersion":
        base = Path(f"loops/{loop_name}/{version}")
        return cls(
            name=loop_name,
            version=version,
            system_prompt=(base / "system_prompt.md").read_text(),
            skills={
                p.stem: p.read_text()
                for p in (base / "skills").glob("*.md")
            },
            tools=json.loads((base / "tools.json").read_text()),
            oracle_criteria=yaml.safe_load(
                (base / "oracle_criteria.yaml").read_text()
            ),
            config=yaml.safe_load((base / "config.yaml").read_text()),
        )

33.3 Canary Loops

A canary loop runs the new version on a subset of traffic while the stable version handles the rest. Compare metrics between them to detect regressions before they affect all users.


import random


class CanaryRouter:
    """Routes loop invocations between stable and canary versions."""

    def __init__(
        self,
        stable_version: LoopVersion,
        canary_version: LoopVersion,
        canary_percentage: float = 0.10,
    ):
        self.stable = stable_version
        self.canary = canary_version
        self.canary_pct = canary_percentage
        self.metrics = CanaryMetrics()

    async def route(self, task: str) -> tuple[str, str]:
        """Returns (result, version_used)."""
        if random.random() < self.canary_pct:
            version = self.canary
            label = "canary"
        else:
            version = self.stable
            label = "stable"
        
        loop = self._build_loop(version)
        result = await loop.run(task)
        
        # Record metrics per version
        self.metrics.record(
            version=label,
            passed=loop.trace.final_status == "succeeded",
            cost=loop.trace.total_cost_usd,
            iterations=len(loop.trace.iterations),
            duration_s=loop.trace.duration_seconds,
        )
        
        return result, label

    def should_promote(self) -> bool:
        """Check if canary is ready for full promotion."""
        if self.metrics.canary_sample_size < 50:
            return False  # Insufficient data
        
        return (
            self.metrics.canary_pass_rate >= self.metrics.stable_pass_rate * 0.95
            and self.metrics.canary_avg_cost <= self.metrics.stable_avg_cost * 1.20
            and self.metrics.canary_avg_iterations <= self.metrics.stable_avg_iterations * 1.15
        )

    def should_rollback(self) -> bool:
        """Check if canary should be abandoned."""
        if self.metrics.canary_sample_size < 20:
            return False
        
        return (
            self.metrics.canary_pass_rate < self.metrics.stable_pass_rate * 0.80
            or self.metrics.canary_avg_cost > self.metrics.stable_avg_cost * 2.0
        )

Canary Metrics Comparison


@dataclass
class CanaryMetrics:
    stable_runs: list[RunMetric] = field(default_factory=list)
    canary_runs: list[RunMetric] = field(default_factory=list)

    @property
    def canary_sample_size(self) -> int:
        return len(self.canary_runs)

    @property
    def canary_pass_rate(self) -> float:
        if not self.canary_runs:
            return 0.0
        return sum(1 for r in self.canary_runs if r.passed) / len(self.canary_runs)

    @property
    def stable_pass_rate(self) -> float:
        if not self.stable_runs:
            return 0.0
        return sum(1 for r in self.stable_runs if r.passed) / len(self.stable_runs)

    def comparison_report(self) -> str:
        return (
            f"Canary vs Stable:\n"
            f"  Pass rate: {self.canary_pass_rate:.1%} vs {self.stable_pass_rate:.1%}\n"
            f"  Avg cost: ${self.canary_avg_cost:.3f} vs ${self.stable_avg_cost:.3f}\n"
            f"  Avg iters: {self.canary_avg_iterations:.1f} vs {self.stable_avg_iterations:.1f}\n"
            f"  Sample size: {self.canary_sample_size} canary, {len(self.stable_runs)} stable"
        )

33.4 Rollback

When a canary fails or a newly promoted version degrades quality, rollback must be immediate. Unlike code rollbacks, loop rollbacks involve multiple components:


class LoopRollback:
    """Rolls back a loop to a previous known-good version."""

    def __init__(self, version_store: VersionStore, router: CanaryRouter):
        self.versions = version_store
        self.router = router

    async def rollback(self, loop_name: str, reason: str) -> str:
        current = await self.versions.get_active(loop_name)
        previous = await self.versions.get_previous_stable(loop_name)
        
        if not previous:
            raise RollbackError(f"No previous stable version for {loop_name}")
        
        # Swap immediately
        await self.versions.set_active(loop_name, previous.version)
        
        # Kill any in-flight canary runs
        await self.router.drain_canary()
        
        # Record rollback event
        await self.versions.record_event(
            loop_name=loop_name,
            event="rollback",
            from_version=current.version,
            to_version=previous.version,
            reason=reason,
        )
        
        logger.warning(
            "Loop rolled back",
            loop=loop_name,
            from_version=current.version,
            to_version=previous.version,
            reason=reason,
        )
        
        return previous.version

What Triggers Automatic Rollback

Signal Threshold Action
Pass rate drops > 20% below baseline over 30 min Immediate rollback
Cost spikes > 2x baseline per-run cost Rollback after 5 confirmations
Kill rate spikes > 25% of runs killed by guards Immediate rollback
Latency increases > 3x P95 baseline Rollback after 10 min sustained
Oracle score drops > 1 stdev below mean Rollback after 50 samples confirm

33.5 Incident Response for Autonomous Systems

When a loop goes rogue — producing bad output, burning money, or taking unauthorized actions — the response playbook differs from traditional incidents.

The Loop Incident Playbook


INCIDENT_PLAYBOOK = """
## Loop Incident Response

### Severity Classification
- SEV1: Loop took unauthorized action (data modification, external comms)
- SEV2: Loop producing incorrect output at scale
- SEV3: Loop performance degraded (cost spike, slow convergence)
- SEV4: Loop intermittently failing (occasional bad runs)

### Immediate Actions (all severities)
1. PAUSE the loop (do not kill — preserve state for investigation)
2. Check: Is the loop still running? How many iterations since anomaly?
3. Pull the trace for the problematic run(s)

### SEV1 Additional Actions
4. KILL the loop immediately
5. Assess blast radius: What actions did it take? What data did it access?
6. Revoke any credentials the loop had access to
7. Notify affected systems/teams
8. Preserve full trace and all artifacts for forensics

### Investigation
- Replay the problematic trace (Chapter 29) to reproduce the failure
- Check: Was this injection? Model degradation? Tool failure? Harness bug?
- Check: Did this affect other loops sharing the same model/tools?

### Resolution
- If injection: identify the source, add to filter rules, re-scan recent runs
- If model degradation: pin to previous model version, report to provider
- If tool failure: fix tool, replay affected traces
- If harness bug: fix, test, deploy via normal pipeline
"""

The Automated First Responder


class LoopIncidentResponder:
    """Automated first response to loop anomalies."""

    async def respond(self, alert: Alert) -> IncidentResponse:
        # Step 1: Classify severity
        severity = self._classify(alert)
        
        # Step 2: Immediate action based on severity
        if severity <= 1:
            await self.kill_loop(alert.loop_id)
            await self.revoke_credentials(alert.loop_id)
        elif severity <= 2:
            await self.pause_loop(alert.loop_id)
        
        # Step 3: Gather context
        trace = await self.get_trace(alert.trace_id)
        recent_traces = await self.get_recent_traces(alert.loop_id, count=10)
        
        # Step 4: Preliminary diagnosis
        diagnosis = self._diagnose(trace, recent_traces, alert)
        
        # Step 5: Notify
        incident = IncidentResponse(
            severity=severity,
            loop_id=alert.loop_id,
            diagnosis=diagnosis,
            action_taken="killed" if severity <= 1 else "paused",
            trace_id=alert.trace_id,
        )
        
        await self.notify_oncall(incident)
        return incident

    def _classify(self, alert: Alert) -> int:
        if alert.type == "unauthorized_action":
            return 1
        if alert.type == "output_quality" and alert.affected_count > 10:
            return 2
        if alert.type in ("cost_spike", "performance_degradation"):
            return 3
        return 4

    def _diagnose(
        self, trace: LoopTrace, recent: list[LoopTrace], alert: Alert
    ) -> str:
        # Check for injection markers
        if any("injection" in tc.result_summary.lower() for tc in trace.all_tool_calls):
            return "Possible prompt injection detected in tool results"
        
        # Check for model behavior change
        if self._model_version_changed(recent):
            return "Model version changed recently — possible regression"
        
        # Check for tool failures
        tool_errors = [tc for tc in trace.all_tool_calls if tc.error]
        if tool_errors:
            return f"Tool failures: {[tc.tool_name for tc in tool_errors]}"
        
        return "Root cause unknown — manual investigation required"

33.6 Failure Taxonomy

Not all loop failures are the same. Categorizing failures enables targeted fixes:


from enum import Enum


class FailureCategory(Enum):
    # Model failures — the model produced wrong output
    MODEL_HALLUCINATION = "model_hallucination"      # Model invented facts
    MODEL_REFUSAL = "model_refusal"                  # Model refused valid action
    MODEL_LOOP = "model_loop"                        # Model repeated same action
    MODEL_REGRESSION = "model_regression"            # New model version worse
    
    # Harness failures — the loop infrastructure broke
    HARNESS_TIMEOUT = "harness_timeout"              # Exceeded time limit
    HARNESS_BUDGET = "harness_budget"                # Exceeded cost limit
    HARNESS_STATE = "harness_state"                  # State corruption
    HARNESS_CONFIG = "harness_config"                # Misconfiguration
    
    # Oracle failures — the quality check was wrong
    ORACLE_FALSE_POSITIVE = "oracle_false_positive"  # Rejected good output
    ORACLE_FALSE_NEGATIVE = "oracle_false_negative"  # Accepted bad output
    ORACLE_CRASH = "oracle_crash"                    # Oracle itself failed
    
    # Integration failures — external systems broke
    INTEGRATION_API = "integration_api"              # External API error
    INTEGRATION_TIMEOUT = "integration_timeout"      # External service slow
    INTEGRATION_AUTH = "integration_auth"            # Credential expired
    INTEGRATION_SCHEMA = "integration_schema"        # Response format changed
    
    # Security failures — adversarial content
    SECURITY_INJECTION = "security_injection"        # Prompt injection succeeded
    SECURITY_EXFIL = "security_exfil"               # Data exfiltration detected
    SECURITY_ESCALATION = "security_escalation"      # Privilege escalation


class FailureClassifier:
    """Classifies loop failures for targeted remediation."""

    def classify(self, trace: LoopTrace) -> FailureCategory:
        # Check for repeated tool sequences (model loop)
        if self._detect_repetition(trace):
            return FailureCategory.MODEL_LOOP
        
        # Check for tool errors (integration failure)
        tool_errors = [tc for tc in trace.all_tool_calls if tc.error]
        if tool_errors:
            if any("401" in tc.error or "403" in tc.error for tc in tool_errors):
                return FailureCategory.INTEGRATION_AUTH
            if any("timeout" in tc.error.lower() for tc in tool_errors):
                return FailureCategory.INTEGRATION_TIMEOUT
            return FailureCategory.INTEGRATION_API
        
        # Check for budget exhaustion
        if trace.final_status == "killed" and trace.total_cost_usd >= trace.budget_limit:
            return FailureCategory.HARNESS_BUDGET
        
        # Check for security blocks
        if trace.security_blocks:
            return FailureCategory.SECURITY_INJECTION
        
        # Default: model produced wrong output
        return FailureCategory.MODEL_HALLUCINATION

Remediation by Category

Category Fix approach Automation
Model hallucination Add failing case to test suite, improve prompt Semi-automated
Model loop Add stuck detection (Chapter 29), reduce temperature Automated
Model regression Pin model version, report to provider Manual
Harness timeout Increase limit or optimize loop (Chapter 28) Automated
Harness budget Increase limit or add cascading (Chapter 28) Semi-automated
Oracle false positive Review oracle criteria, add exception Manual
Integration API Retry with backoff, add circuit breaker Automated
Integration auth Rotate credentials, update vault Automated
Security injection Add pattern to filters, re-scan recent runs Semi-automated

Automated Postmortem Data Collection


class PostmortemCollector:
    """Automatically gathers postmortem data from traces and metrics."""

    async def collect(self, incident: Incident) -> dict:
        traces = await self.trace_store.get_range(
            loop_name=incident.loop_id,
            start=incident.detected_at - timedelta(hours=1),
            end=incident.resolved_at or datetime.now(timezone.utc),
        )
        
        # Build timeline from traces
        timeline = []
        for trace in traces:
            timeline.append({
                "time": trace.started_at.isoformat(),
                "event": f"Run {trace.trace_id[:8]}: {trace.final_status}",
                "cost": trace.total_cost_usd,
                "iterations": len(trace.iterations),
            })
        
        # Identify the first failure
        first_failure = next(
            (t for t in traces if t.final_status == "failed"), None
        )
        
        # Classify
        category = self.classifier.classify(first_failure) if first_failure else None
        
        return {
            "timeline": timeline,
            "category": category.value if category else "unknown",
            "affected_count": sum(1 for t in traces if t.final_status == "failed"),
            "cost_impact": sum(t.total_cost_usd for t in traces),
            "trace_ids": [t.trace_id for t in traces if t.final_status == "failed"],
            "first_failure_trace": first_failure.trace_id if first_failure else None,
        }

33.8 Fleet-Wide Health

When you operate multiple loop types (code review, testing, deployment, documentation), you need fleet-level visibility:


@dataclass
class FleetStatus:
    """Aggregate health across all loop types."""
    
    loops: dict[str, LoopHealth]
    
    @property
    def fleet_pass_rate(self) -> float:
        total = sum(l.total_runs for l in self.loops.values())
        passed = sum(l.succeeded for l in self.loops.values())
        return passed / max(total, 1)
    
    @property
    def fleet_daily_cost(self) -> float:
        return sum(l.daily_cost for l in self.loops.values())
    
    @property
    def unhealthy_loops(self) -> list[str]:
        return [
            name for name, health in self.loops.items()
            if health.pass_rate < 0.80 or health.kill_rate > 0.15
        ]
    
    def summary(self) -> str:
        lines = [
            f"Fleet: {len(self.loops)} loops, "
            f"{self.fleet_pass_rate:.1%} pass rate, "
            f"${self.fleet_daily_cost:.0f}/day",
        ]
        
        if self.unhealthy_loops:
            lines.append(f"Unhealthy: {', '.join(self.unhealthy_loops)}")
        
        for name, health in sorted(
            self.loops.items(), key=lambda x: x[1].pass_rate
        ):
            status = "OK" if health.pass_rate >= 0.80 else "DEGRADED"
            lines.append(
                f"  [{status}] {name}: "
                f"{health.pass_rate:.0%} pass, "
                f"${health.daily_cost:.1f}/day, "
                f"v{health.active_version}"
            )
        
        return "\n".join(lines)

33.9 Capacity Planning

Unlike traditional services where you provision fixed infrastructure, agent fleet capacity planning involves model API quotas, cost budgets, and concurrency limits:


@dataclass
class CapacityPlan:
    """Plan for fleet resource needs."""
    
    # Throughput
    expected_runs_per_day: int
    peak_concurrent_runs: int
    
    # Model API
    tokens_per_day: int
    required_rpm: int  # Requests per minute at peak
    
    # Cost
    daily_budget_usd: float
    monthly_budget_usd: float
    cost_per_run_p50: float
    cost_per_run_p95: float
    
    # Infrastructure
    container_instances: int
    storage_gb_per_day: float  # For traces and replay data

    @classmethod
    def estimate(cls, historical_metrics: FleetStatus, growth_factor: float = 1.2):
        """Estimate capacity needs from historical data with growth buffer."""
        return cls(
            expected_runs_per_day=int(historical_metrics.daily_runs * growth_factor),
            peak_concurrent_runs=int(historical_metrics.peak_concurrent * growth_factor),
            tokens_per_day=int(historical_metrics.daily_tokens * growth_factor),
            required_rpm=int(historical_metrics.peak_rpm * growth_factor),
            daily_budget_usd=historical_metrics.fleet_daily_cost * growth_factor,
            monthly_budget_usd=historical_metrics.fleet_daily_cost * growth_factor * 30,
            cost_per_run_p50=historical_metrics.cost_p50,
            cost_per_run_p95=historical_metrics.cost_p95,
            container_instances=int(historical_metrics.peak_concurrent * 1.5),
            storage_gb_per_day=historical_metrics.daily_trace_storage_gb * growth_factor,
        )
