Appendix A: Loop Specification Template

Use this template when designing any new loop. Fill in every field — a missing field is a bug waiting to happen.


# Loop Specification: [Name]
# Version: 1.0
# Author: [Name]
# Date: [YYYY-MM-DD]

meta:
  name: "[descriptive-name]"
  purpose: "[One sentence: what this loop produces]"
  autonomy_level: "L[2-5]"
  domain: "[code | research | operations | content | security]"

loop_contract:
  goal:
    description: "[What constitutes done, in machine-checkable terms]"
    type: "[binary | threshold | convergent | comparative | composite]"
    criteria:
      - "[Criterion 1 — must be machine-evaluable]"
      - "[Criterion 2]"
    
  oracle:
    primary: "[Cheapest check that discriminates good from bad]"
    secondary: "[Additional checks for dimensions primary misses]"
    judge: "[Model judge criteria, if needed]"
    
  budget:
    max_iterations: N
    max_tokens: N
    max_time_seconds: N
    max_cost_usd: N.NN
    
  stop_conditions:
    success: "[Oracle passes]"
    no_progress: "[Last N iterations produced <X% improvement]"
    oscillation: "[Same state repeated within last N iterations]"
    budget: "[Any budget limit exceeded]"
    
  escalation_path:
    on_budget_exhaustion: "[Notify | Create ticket | Email]"
    on_no_progress: "[Change approach | Escalate to human]"
    on_safety_concern: "[Immediate halt + notify]"
    report_includes: "[Diagnosis, what was tried, best result, recommendations]"

substrate:
  model:
    primary: "[Model for main generation]"
    judge: "[Model for verification, if model-based]"
    lead: "[Model for orchestration, if fleet]"
  
  tools:
    - "[tool_name]: [when used]"
    
  skills:
    - "[skill_file]: [what it provides]"
    
  memory:
    types_used: "[episodic | semantic | procedural]"
    storage: "[file | database | hybrid]"

trigger:
  type: "[schedule | event | threshold | webhook | chained | manual]"
  specification: "[cron expression | event name | threshold condition]"
  idempotency: "[How duplicate triggers are handled]"
  cooldown: "[Minimum time between runs]"

fleet: # (omit if single-agent)
  lead:
    model: "[model]"
    role: "[Decompose, coordinate, synthesize]"
  specialists:
    - name: "[specialist_name]"
      model: "[model]"
      scope: "[What files/domain this specialist handles]"
      tools: "[Available tools]"
  topology: "[hierarchy | pipeline | blackboard]"
  coordination: "[push | pull]"

verification:
  maker_checker_split: true/false
  checker_context_isolation: true/false
  adversarial_checking: true/false
  
security:
  permission_scope: "[What the loop CAN do]"
  forbidden_actions: "[What the loop MUST NOT do]"
  approval_gates: "[Actions requiring human approval]"
  
economics:
  estimated_cost_per_run: "$N.NN"
  estimated_runs_per_day: N
  estimated_monthly_cost: "$N,NNN"
  value_produced_per_run: "[Time saved, quality improvement, etc.]"
  roi_positive: true/false

Appendix B: Oracle Catalog by Task Type

Quick reference for choosing oracles by task domain:

Task Type L1: Deterministic L2: Property L3: Rubric L4: Model Judge
Bug fix Tests pass Invariants hold — —
Feature Tests pass + coverage Contract tests Feature completeness rubric UX quality
Refactor Tests pass + no behavior change Performance properties Code quality rubric —
Documentation Links resolve, format valid Coverage (all methods documented) Clarity rubric Accuracy judge
Security review No known-bad patterns OWASP properties Severity assessment rubric Finding validity
Code review Linter passes — Review quality rubric Issue accuracy
Research Sources exist Claims have citations Depth/breadth rubric Accuracy judge
Content writing Format/length valid Factual claims verifiable Quality rubric Tone/voice judge
Data transform Schema valid, counts match Referential integrity — —
API design Schema valid, examples work Idempotency properties Design quality rubric —
Migration Old tests pass on new schema Data integrity — —
Performance Benchmarks meet threshold No regression — —

Decision rule: Start at L1 (leftmost applicable column). Add higher levels only when L1 doesn't cover a critical quality dimension.

Appendix C: SKILL.md Templates and Anti-Patterns

Minimal Viable Skill (~2K tokens)


# [Project Name]

## Stack
- Language: [e.g., Python 3.12]
- Framework: [e.g., FastAPI]
- Database: [e.g., PostgreSQL 15]
- Tests: [e.g., pytest + pytest-asyncio]

## Build & Verify
\```bash
pytest tests/ -x --tb=short    # Must pass before any commit
pyright src/                    # Zero errors required
ruff check src/ --fix           # Zero warnings
\```

## Rules
- [Rule 1: Hard constraint the agent must never violate]
- [Rule 2]
- [Rule 3]

Full Skill (~8-12K tokens)

Add to the minimal skill:

  • Architecture section with component descriptions
  • File organization guide
  • Common tasks with step-by-step guides
  • Anti-patterns section (learned from past mistakes)
  • Domain-specific knowledge

Anti-Patterns

Anti-Pattern Problem Fix
Kitchen sink Everything in one 30K-token skill Split into composable sub-skills
Stale rules Rules reference removed code/patterns Review monthly, version with code
No verification commands Agent can't test its own work Always include build/test commands
Vague rules "Write good code" Operationalize: specific, measurable
Duplicating docs Copy of README in skill Reference, don't duplicate
Missing anti-patterns Same mistakes repeated Add after every failure

Appendix E: Failure Taxonomy Quick Reference

Model Errors

Failure Symptom Response
Hallucination References non-existent file/function Ground with tool calls before acting
Logic error Incorrect reasoning chain Decompose into smaller steps
Instruction violation Ignores constraints in prompt Move constraint to tool-level enforcement
Context overflow Loses early information Prune aggressively, use skills
Sycophancy Agrees with incorrect premise Independent checker agent

Harness Errors

Failure Symptom Response
Missing tool Agent can't perform needed action Add tool to available set
Bad error message Agent retries blindly Improve tool error messages
Context rot Quality degrades with iterations Prune old tool results
Stale skill Agent uses outdated information Update skill file
Missing stop condition Loop runs forever Add convergence/budget checks

Oracle Errors

Failure Symptom Response
False positive (too strict) Good output rejected Relax threshold or fix criteria
False negative (too lenient) Bad output accepted Add checks, tighten rubric
Reward hacking Output games the metric Add quality constraints
Missing dimension Quality issue not caught Add oracle for uncovered dimension
Stale baseline Comparison against outdated reference Update baseline regularly

Integration Errors

Failure Symptom Response
Tool timeout Slow external service Add timeout + retry logic
Auth failure Expired credentials Credential refresh in harness
Rate limiting Too many API calls Add backoff + rate limiter
Schema change External API changed format Version pin + schema validation
Network failure Connectivity lost Retry with exponential backoff

Appendix F: Primitive Selection Decision Tree


START: "I need the loop to do X"
│
├── Is X deterministic (same input → same output)?
│   ├── YES → Use CODE (not model)
│   └── NO → Continue
│
├── Does X require reasoning about ambiguous input?
│   ├── YES → Does it need independence from current context?
│   │   ├── YES → Use SUBAGENT
│   │   └── NO → Use PROMPT (in current context)
│   └── NO → Continue
│
├── Does X require external system interaction?
│   ├── YES → Is this integration shared across loops?
│   │   ├── YES → Use MCP SERVER
│   │   └── NO → Use TOOL (direct)
│   └── NO → Continue
│
├── Does X require stable project knowledge?
│   ├── YES → Does it change between runs?
│   │   ├── YES → Load dynamically (tool/search)
│   │   └── NO → Use SKILL (pre-loaded)
│   └── NO → Continue
│
└── None of the above → Re-examine X. It may be decomposable
    into sub-operations that fit the tree above.

Appendix G: Glossary

Agent: A system that observes, reasons, and acts autonomously within defined constraints.

Autonomy Ladder: The six levels (L0-L5) of agent independence, from autocomplete to self-designing fleets.

Blast Radius: The maximum damage a failed loop can cause before being caught and stopped.

Closed Loop: A loop following a human-designed path with predetermined steps and bounded scope.

Compaction: Lossy compression of conversation context to free space for new information.

Context Rot: Progressive contamination of the context window with stale, irrelevant information.

Convergence: The loop progressing toward its goal across iterations, measured by oracle scores.

Escalation Path: The mechanism by which a stuck loop transitions from autonomous to human-guided operation.

Fleet: Multiple coordinated loops (lead + specialists) working toward a shared goal.

Harness: The scaffold around a model — tools, verification, context management, orchestration — that determines system behavior.

Loop Contract: The five-element specification (goal, oracle, budget, stop condition, escalation path) that defines a complete loop.

Loop Engineering: The discipline of designing automated feedback cycles that produce verified outcomes from AI models.

Maker-Checker: Architecture where the agent producing output and the agent verifying output operate in isolated contexts.

MCP (Model Context Protocol): The standard interface for connecting AI systems to external tools and services.

Memory: Persistent knowledge that survives between loop runs — episodic, semantic, and procedural.

Open Loop: A loop where the model discovers its own path through the problem, with minimal predetermined structure.

Oracle: The mechanism that evaluates loop output against the goal, determining pass/fail.

Oscillation: A loop repeatedly making and undoing the same changes without progress.

Prompt Caching: Reusing previously-processed input token prefixes to avoid redundant computation.

Reward Hacking: The model optimizing for the metric (oracle) rather than the underlying intent.

Skill: A reusable document encoding project knowledge, loaded into agent context on demand.

Stop Condition: The precise criteria under which a loop terminates — success, budget, no-progress, or oscillation.

Subagent: A separate model execution with its own context, tools, and scope — used for isolation or specialization.

Token Economics: The discipline of understanding and reducing the cost of loop operation.

Tool Search: A meta-tool that discovers and loads tool schemas on demand, avoiding upfront context cost.

Worktree: An isolated copy of a git repository where an agent can work without affecting the main workspace.
