Chapter 29: Observability, Tracing, and Replay

Level: S (Standard) · ~4,000 words · Levels served: L3, L4, L5

29.1 Why Traditional APM Fails for Loops

Traditional Application Performance Monitoring tracks request/response latencies, error rates, and throughput. It assumes a synchronous model: request comes in, work happens, response goes out. Agent loops break every assumption:

  1. No fixed duration. A loop might take 30 seconds or 30 minutes. P99 latency is meaningless.
  2. No single request. A loop makes dozens of model calls and tool invocations per run. The "request" is the entire loop execution.
  3. Non-deterministic paths. Two runs on the same input may take different tool sequences. You can't alert on "unexpected path" because every path is unexpected.
  4. Cost is the primary metric. In traditional APM, cost is infrastructure. In loops, cost is per-token — and a single runaway iteration can burn $50 before you notice.

What you need instead is loop-level telemetry: traces structured around iterations, decisions, and outcomes rather than HTTP spans.

29.2 What to Trace

Every loop run emits a trace. The trace contains:

The Trace Schema


from __future__ import annotations
from dataclasses import dataclass, field
from datetime import datetime
from typing import Any


@dataclass
class ToolCall:
    tool_name: str
    arguments: dict[str, Any]
    result_summary: str  # Truncated — never store full tool output in traces
    duration_ms: int
    tokens_in: int
    tokens_out: int
    error: str | None = None


@dataclass
class Iteration:
    index: int
    started_at: datetime
    ended_at: datetime
    model: str
    prompt_tokens: int
    completion_tokens: int
    cache_hit_tokens: int
    tool_calls: list[ToolCall] = field(default_factory=list)
    decision: str = ""  # What the model decided to do (1-line summary)
    outcome: str = ""   # What actually happened (success/failure/escalation)


@dataclass
class LoopTrace:
    trace_id: str
    loop_name: str
    input_hash: str       # Deterministic hash of the input for dedup
    started_at: datetime
    ended_at: datetime | None = None
    iterations: list[Iteration] = field(default_factory=list)
    final_status: str = "running"  # running | succeeded | failed | killed
    total_cost_usd: float = 0.0
    metadata: dict[str, Any] = field(default_factory=dict)

What belongs in a trace vs. what doesn't

Trace it Don't trace it
Every model call (model, tokens, latency) Full prompt text (too large, PII risk)
Every tool call (name, args summary, duration) Full tool output (store in separate artifact store)
Each iteration boundary Intermediate chain-of-thought (model reasoning is ephemeral)
Decision points ("chose to retry" vs "chose to escalate") Raw API responses from external services
Cost per iteration and cumulative User data flowing through the loop
Cache hits and misses Secrets or credentials (never)

The Instrumented Loop


import time
import hashlib
import uuid
from datetime import datetime, timezone


class InstrumentedLoop:
    def __init__(self, loop_name: str, tracer: "Tracer"):
        self.loop_name = loop_name
        self.tracer = tracer

    async def run(self, task: str) -> str:
        trace = self.tracer.start_trace(
            loop_name=self.loop_name,
            input_hash=hashlib.sha256(task.encode()).hexdigest()[:16],
        )

        try:
            for i in range(self.max_iterations):
                iter_start = time.perf_counter()
                iteration = trace.start_iteration(index=i, model=self.model)

                # Model call
                response = await self.call_model(task, iteration)

                # Tool execution
                for tool_call in response.tool_calls:
                    tc_start = time.perf_counter()
                    result = await self.execute_tool(tool_call)
                    iteration.record_tool_call(
                        tool_name=tool_call.name,
                        arguments=self._summarize_args(tool_call.arguments),
                        result_summary=result[:200],
                        duration_ms=int((time.perf_counter() - tc_start) * 1000),
                    )

                # Record decision
                iteration.decision = response.decision_summary
                iteration.close(outcome="continue" if not response.done else "complete")

                if response.done:
                    trace.close(status="succeeded")
                    return response.final_output

            trace.close(status="failed", reason="max_iterations_exceeded")
            raise LoopExhaustedError(trace.trace_id)

        except Exception as e:
            trace.close(status="failed", reason=str(e))
            raise

29.3 Structured Spans for Agent Systems

In a multi-agent system, traces nest. The lead agent's trace contains child spans for each specialist it dispatches:


LoopTrace: pr-review-loop (trace_id: abc123)
├── Iteration 0: Lead analyzes PR
│   ├── ToolCall: fetch_diff (450ms)
│   └── Decision: "Dispatch 3 specialists"
├── Iteration 1: Await specialists
│   ├── ChildSpan: security-reviewer (trace_id: def456)
│   │   ├── Iteration 0: Read files
│   │   └── Iteration 1: Report findings
│   ├── ChildSpan: logic-reviewer (trace_id: ghi789)
│   │   └── Iteration 0: Analyze logic
│   └── ChildSpan: style-reviewer (trace_id: jkl012)
│       └── Iteration 0: Check style
└── Iteration 2: Lead synthesizes
    └── Decision: "Merge specialist findings, post review"

Propagating trace context


class TraceContext:
    """Propagates trace identity across agent boundaries."""

    def __init__(self, trace_id: str, parent_span_id: str | None = None):
        self.trace_id = trace_id
        self.span_id = uuid.uuid4().hex[:16]
        self.parent_span_id = parent_span_id

    def child(self) -> "TraceContext":
        """Create a child context for a sub-agent."""
        return TraceContext(
            trace_id=self.trace_id,
            parent_span_id=self.span_id,
        )

    def to_headers(self) -> dict[str, str]:
        """Serialize for cross-process propagation."""
        return {
            "x-trace-id": self.trace_id,
            "x-span-id": self.span_id,
            "x-parent-span-id": self.parent_span_id or "",
        }

When the lead dispatches a specialist, it passes ctx.child() — the specialist's trace links back to the parent, enabling full reconstruction of the execution tree.

29.4 Deterministic Replay

Replay is the most valuable debugging tool for loops. When something goes wrong at 3 AM, you don't want to re-run the loop against live systems — you want to replay it from its trace.

What replay requires

  1. Recorded model responses. Every model call's output must be stored (or reproducible via a seed).
  2. Recorded tool results. Every tool call's response captured at trace time.
  3. Iteration state snapshots. The working memory at each iteration boundary.

The Replay Engine


from pathlib import Path
import json


class ReplayEngine:
    """Replays a loop execution from a stored trace."""

    def __init__(self, trace_path: Path):
        self.trace = json.loads(trace_path.read_text())
        self.model_responses: list[dict] = self.trace["model_responses"]
        self.tool_responses: list[dict] = self.trace["tool_responses"]
        self._model_idx = 0
        self._tool_idx = 0

    def mock_model_call(self, messages: list[dict]) -> dict:
        """Return the recorded model response for this call."""
        response = self.model_responses[self._model_idx]
        self._model_idx += 1
        return response

    def mock_tool_call(self, tool_name: str, args: dict) -> str:
        """Return the recorded tool response."""
        recorded = self.tool_responses[self._tool_idx]
        assert recorded["tool_name"] == tool_name, (
            f"Replay divergence: expected {recorded['tool_name']}, got {tool_name}"
        )
        self._tool_idx += 1
        return recorded["result"]

    def run(self, loop_class: type) -> str:
        """Execute the loop with mocked I/O."""
        loop = loop_class()
        loop.call_model = self.mock_model_call
        loop.execute_tool = self.mock_tool_call
        return loop.run(self.trace["input"])

Recording for replay

The cost of recording is storage, not latency. Store replay data in a tiered system:

Tier Retention What's stored
Hot (last 24h) Full replay data: model responses, tool results, state snapshots S3/GCS, ~10MB per trace
Warm (7 days) Trace metadata + model responses only Compressed, ~1MB per trace
Cold (90 days) Trace metadata only (cost, duration, status) ~10KB per trace

Replay divergence detection

When you replay a trace and swap the model (e.g., testing a new model version), divergence detection tells you where behavior changed:


class DivergenceDetector:
    def compare_runs(
        self, original: LoopTrace, replayed: LoopTrace
    ) -> list[Divergence]:
        divergences = []
        for i, (orig_iter, replay_iter) in enumerate(
            zip(original.iterations, replayed.iterations)
        ):
            if orig_iter.decision != replay_iter.decision:
                divergences.append(Divergence(
                    iteration=i,
                    field="decision",
                    original=orig_iter.decision,
                    replayed=replay_iter.decision,
                ))
            # Tool call sequence divergence
            orig_tools = [tc.tool_name for tc in orig_iter.tool_calls]
            replay_tools = [tc.tool_name for tc in replay_iter.tool_calls]
            if orig_tools != replay_tools:
                divergences.append(Divergence(
                    iteration=i,
                    field="tool_sequence",
                    original=orig_tools,
                    replayed=replay_tools,
                ))
        return divergences

29.5 The Operational Dashboard

A fleet of loops needs a single pane of glass. Not the model provider's usage dashboard — that shows tokens consumed. You need the loop health dashboard.

Core Metrics

Metric What it tells you Alert threshold
Pass rate % of loops that reach "succeeded" status < 80% over 1h
Cost per success Total spend / successful completions > 2x rolling 7d average
Avg iterations Mean iterations before convergence > 2x baseline for that loop type
Kill rate % of loops terminated by budget/time guards > 15%
Replay divergence rate % of replays that show different decisions with same model > 5% (indicates non-determinism)
Tool error rate % of tool calls that return errors > 10%
Cache hit ratio Cached tokens / total input tokens < 50% (you're overpaying)

The Dashboard Implementation


from dataclasses import dataclass
from datetime import timedelta


@dataclass
class FleetHealth:
    window: timedelta
    total_runs: int
    succeeded: int
    failed: int
    killed: int
    total_cost_usd: float
    avg_iterations: float
    p95_duration_seconds: float
    cache_hit_ratio: float
    tool_error_rate: float

    @property
    def pass_rate(self) -> float:
        return self.succeeded / max(self.total_runs, 1)

    @property
    def cost_per_success(self) -> float:
        return self.total_cost_usd / max(self.succeeded, 1)

    @property
    def kill_rate(self) -> float:
        return self.killed / max(self.total_runs, 1)

    def check_alerts(self) -> list[str]:
        alerts = []
        if self.pass_rate < 0.80:
            alerts.append(f"Pass rate critical: {self.pass_rate:.1%}")
        if self.kill_rate > 0.15:
            alerts.append(f"Kill rate elevated: {self.kill_rate:.1%}")
        if self.tool_error_rate > 0.10:
            alerts.append(f"Tool errors spiking: {self.tool_error_rate:.1%}")
        if self.cache_hit_ratio < 0.50:
            alerts.append(f"Cache utilization low: {self.cache_hit_ratio:.1%}")
        return alerts

Drift Detection

The most insidious failure mode is quality drift — the loop still "succeeds" but its output quality degrades over time. Detect this by tracking oracle scores (as discussed in Chapter 8) across time:


class DriftDetector:
    def __init__(self, baseline_window_days: int = 7):
        self.baseline_window_days = baseline_window_days

    def detect(self, recent_scores: list[float], baseline_scores: list[float]) -> bool:
        """Returns True if recent quality has drifted below baseline."""
        import statistics

        if len(recent_scores) < 10 or len(baseline_scores) < 30:
            return False  # Insufficient data

        recent_mean = statistics.mean(recent_scores)
        baseline_mean = statistics.mean(baseline_scores)
        baseline_stdev = statistics.stdev(baseline_scores)

        # Alert if recent mean is >2 standard deviations below baseline
        return recent_mean < (baseline_mean - 2 * baseline_stdev)

Traces must integrate with existing observability infrastructure. Two practical formats:

OpenTelemetry Spans

Map loop iterations to OTEL spans for compatibility with Jaeger, Honeycomb, Datadog:


from opentelemetry import trace

tracer = trace.get_tracer("agent-loop")


async def instrumented_iteration(loop_ctx: TraceContext, iteration: int):
    with tracer.start_as_current_span(
        f"loop.iteration.{iteration}",
        attributes={
            "loop.name": loop_ctx.loop_name,
            "loop.iteration": iteration,
            "loop.trace_id": loop_ctx.trace_id,
        },
    ) as span:
        response = await call_model(...)
        span.set_attribute("model.tokens_in", response.usage.input_tokens)
        span.set_attribute("model.tokens_out", response.usage.output_tokens)
        span.set_attribute("model.cost_usd", response.cost)

        for tool_call in response.tool_calls:
            with tracer.start_as_current_span(
                f"tool.{tool_call.name}",
                attributes={"tool.name": tool_call.name},
            ) as tool_span:
                result = await execute_tool(tool_call)
                tool_span.set_attribute("tool.duration_ms", result.duration_ms)
                if result.error:
                    tool_span.set_status(trace.StatusCode.ERROR, result.error)

29.7 Practical Patterns

Pattern 1: The "Why Did It Cost $12?" Investigation


async def investigate_expensive_run(trace_id: str) -> str:
    trace = await trace_store.get(trace_id)
    
    # Find the expensive iterations
    by_cost = sorted(trace.iterations, key=lambda i: i.total_cost, reverse=True)
    top_3 = by_cost[:3]
    
    report = []
    for iteration in top_3:
        report.append(
            f"Iteration {iteration.index}: ${iteration.total_cost:.2f} "
            f"({iteration.prompt_tokens} in, {iteration.completion_tokens} out) "
            f"— {iteration.decision}"
        )
        # Check for tool calls that returned large results (context bloat)
        large_tools = [tc for tc in iteration.tool_calls if tc.tokens_in > 5000]
        for tc in large_tools:
            report.append(f"  ^ {tc.tool_name} returned ~{tc.tokens_in} tokens")
    
    return "\n".join(report)

Pattern 2: The "Is This Loop Stuck?" Detector


class StuckDetector:
    """Detects loops that are iterating without making progress."""

    def check(self, trace: LoopTrace) -> bool:
        if len(trace.iterations) < 3:
            return False

        # Check if last 3 iterations used the same tools in the same order
        recent = trace.iterations[-3:]
        tool_sequences = [
            tuple(tc.tool_name for tc in it.tool_calls)
            for it in recent
        ]
        if len(set(tool_sequences)) == 1:
            return True  # Same tool sequence 3x in a row — stuck

        # Check if decisions are repeating
        decisions = [it.decision for it in recent]
        if len(set(decisions)) == 1:
            return True  # Same decision 3x — stuck

        return False

Pattern 3: Trace-Based Regression Testing

Before deploying a prompt change, replay the last 100 traces with the new prompt and compare outcomes:


async def regression_test(
    new_prompt: str,
    trace_ids: list[str],
    threshold: float = 0.95,
) -> bool:
    """Returns True if the new prompt maintains quality on historical inputs."""
    results = []
    for trace_id in trace_ids:
        original = await trace_store.get(trace_id)
        replayed = await replay_with_prompt(original, new_prompt)
        
        # Compare: did the new prompt produce equivalent or better outcomes?
        score = await evaluate_equivalence(original.output, replayed.output)
        results.append(score)
    
    pass_rate = sum(1 for s in results if s >= 0.8) / len(results)
    return pass_rate >= threshold

29.8 Cost of Observability

Tracing is not free. For a fleet processing 10,000 runs/day:

Component Daily cost estimate
Trace storage (hot tier) ~$5 (assuming 10MB/trace compressed to 2MB)
OTEL collector infrastructure ~$20 (managed service)
Dashboard queries ~$10 (query engine costs)
Replay storage (full fidelity) ~$50 (model responses are large)
Total ~$85/day

Against a fleet that spends $2,000/day on model calls, $85 for full observability is 4.25% overhead. The first time you catch a runaway loop within minutes instead of hours, you save more than a month of observability costs.

The rule: if you can't afford to trace it, you can't afford to run it autonomously.
