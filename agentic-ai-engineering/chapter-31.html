Chapter 31: Sandboxing, Permissions, and Blast Radius

Level: S (Standard) · ~4,000 words · Levels served: L3, L4, L5

31.1 The Already-Compromised Agent

Chapter 30 covered how attacks happen. This chapter assumes the worst already happened: the model has been successfully prompt-injected. It believes the attacker's instructions are legitimate. What can it do?

The answer depends entirely on what capabilities you gave it. A compromised agent with full shell access, network egress, and credential access is indistinguishable from a remote code execution vulnerability. A compromised agent with read-only access to a scoped file set and no egress can do... nothing meaningful to an attacker.

The principle: design for the already-compromised case. Every capability you add to a loop is a capability an attacker gains when injection succeeds.

31.2 Capability Scoping

The Tool Permission Matrix

Every agent in your system should have an explicit capability specification — what tools it can access, with what arguments, under what conditions:


from __future__ import annotations
from dataclasses import dataclass
from typing import Any


@dataclass
class ToolPermission:
    tool_name: str
    allowed: bool = True
    argument_constraints: dict[str, Any] = None  # Restrict argument values
    rate_limit: int | None = None  # Max calls per loop run
    requires_confirmation: bool = False  # Human-in-the-loop gate


@dataclass
class AgentCapabilities:
    """Explicit capability specification for an agent."""
    
    agent_name: str
    tools: list[ToolPermission]
    max_iterations: int = 20
    max_cost_usd: float = 5.0
    network_egress: bool = False
    file_write_paths: list[str] | None = None  # None = no write access
    file_read_paths: list[str] | None = None   # None = read everything

    def can_use_tool(self, tool_name: str) -> ToolPermission | None:
        for perm in self.tools:
            if perm.tool_name == tool_name and perm.allowed:
                return perm
        return None


# Example: A code review agent
CODE_REVIEWER = AgentCapabilities(
    agent_name="code-reviewer",
    tools=[
        ToolPermission("read_file", allowed=True),
        ToolPermission("list_directory", allowed=True),
        ToolPermission("search_code", allowed=True),
        ToolPermission("write_file", allowed=False),      # Cannot modify code
        ToolPermission("run_command", allowed=False),      # Cannot execute
        ToolPermission("http_request", allowed=False),     # No network
        ToolPermission("post_comment", allowed=True, rate_limit=10),
    ],
    max_iterations=15,
    max_cost_usd=3.0,
    network_egress=False,
    file_write_paths=None,  # No write access
    file_read_paths=["./src/", "./tests/", "./config/"],
)

Enforcement Layer

Capabilities must be enforced in the harness, not requested of the model. The model can try to call any tool — it's the harness that blocks:


class CapabilityEnforcer:
    """Mechanical enforcement of agent capabilities."""

    def __init__(self, capabilities: AgentCapabilities):
        self.caps = capabilities
        self._call_counts: dict[str, int] = {}

    def check(self, tool_name: str, arguments: dict) -> tuple[bool, str]:
        """Returns (allowed, reason)."""
        
        perm = self.caps.can_use_tool(tool_name)
        if perm is None:
            return False, f"Tool '{tool_name}' not in agent capability set"

        # Rate limit check
        if perm.rate_limit is not None:
            count = self._call_counts.get(tool_name, 0)
            if count >= perm.rate_limit:
                return False, f"Tool '{tool_name}' rate limit exceeded ({perm.rate_limit})"

        # Argument constraint check
        if perm.argument_constraints:
            for key, constraint in perm.argument_constraints.items():
                actual = arguments.get(key)
                if not self._matches_constraint(actual, constraint):
                    return False, f"Argument '{key}' violates constraint: {constraint}"

        # Path restriction check
        if tool_name in ("read_file", "list_directory") and self.caps.file_read_paths:
            path = arguments.get("path", "")
            if not any(path.startswith(allowed) for allowed in self.caps.file_read_paths):
                return False, f"Path '{path}' outside allowed read paths"

        if tool_name == "write_file" and self.caps.file_write_paths is not None:
            path = arguments.get("path", "")
            if not any(path.startswith(allowed) for allowed in self.caps.file_write_paths):
                return False, f"Path '{path}' outside allowed write paths"

        # Track for rate limiting
        self._call_counts[tool_name] = self._call_counts.get(tool_name, 0) + 1
        return True, "ok"

31.3 Egress Control

The most critical capability to restrict is network egress. If a compromised agent cannot send data out, exfiltration fails regardless of what data it can access.

Levels of Egress Control

Level What it means Implementation
No egress Agent cannot make any outbound network requests Remove all HTTP/network tools; run in network-isolated container
Allowlisted egress Agent can only reach specific domains DNS-level or proxy-level filtering
Logged egress Agent can reach anywhere but all requests are logged and auditable Transparent proxy with full request logging
Unrestricted Agent can reach any destination Only acceptable for fully trusted, non-data-processing agents

Implementation: Network Namespace Isolation


import subprocess
from contextlib import contextmanager


@contextmanager
def network_isolated_execution():
    """Execute tool calls in a network-isolated Linux namespace."""
    # Create isolated network namespace
    ns_name = f"agent-{uuid.uuid4().hex[:8]}"
    subprocess.run(
        ["ip", "netns", "add", ns_name],
        check=True,
    )
    try:
        yield ns_name
    finally:
        subprocess.run(["ip", "netns", "delete", ns_name])


class NetworkIsolatedSandbox:
    """Execute tools with no network access."""

    async def execute(self, tool_name: str, args: dict) -> str:
        with network_isolated_execution() as ns:
            # Run tool inside the namespace — it has no network interfaces
            result = await self._run_in_namespace(ns, tool_name, args)
            return result

Implementation: Allowlisted Proxy

For agents that need some network access (e.g., fetching documentation):


class EgressProxy:
    """HTTP proxy that only allows requests to allowlisted domains."""

    def __init__(self, allowed_domains: set[str]):
        self.allowed = allowed_domains

    async def handle_request(self, request: Request) -> Response:
        domain = urlparse(request.url).hostname
        
        if domain not in self.allowed:
            logger.warning(
                "Blocked egress attempt",
                domain=domain,
                url=request.url,
                agent=request.headers.get("x-agent-id"),
            )
            return Response(status=403, body=f"Egress to {domain} blocked by policy")
        
        return await self._forward(request)


# Agent configuration
DOCS_AGENT_EGRESS = EgressProxy(allowed_domains={
    "docs.python.org",
    "developer.mozilla.org",
    "api.github.com",
})

31.4 Credential Handling

Rule: Secrets never enter model context. If the model can see a credential, an injection can exfiltrate it. Instead, tools authenticate on behalf of the agent without exposing credentials to the model.

The Credential Proxy Pattern


class CredentialProxy:
    """Tools authenticate via proxy — credentials never reach model context."""

    def __init__(self, vault: SecretVault):
        self.vault = vault

    async def github_api(self, endpoint: str, method: str = "GET") -> dict:
        """Agent calls this tool. The token is injected at execution time,
        never visible in the tool's arguments or the model's context."""
        
        token = self.vault.get("GITHUB_TOKEN")  # Retrieved at execution time
        
        async with httpx.AsyncClient() as client:
            response = await client.request(
                method=method,
                url=f"https://api.github.com{endpoint}",
                headers={"Authorization": f"Bearer {token}"},  # Injected here
            )
            return response.json()

What the model sees in its tool schema:


{
  "name": "github_api",
  "description": "Make a GitHub API request",
  "parameters": {
    "endpoint": {"type": "string", "description": "/repos/owner/repo/pulls"},
    "method": {"type": "string", "enum": ["GET", "POST", "PATCH"]}
  }
}

The model never sees the token. It cannot exfiltrate what it cannot access.

Anti-Patterns to Avoid


# WRONG: Secret in environment, accessible via tool
result = await agent.run_command("echo $GITHUB_TOKEN")  # Model can ask for this

# WRONG: Secret in system prompt
system_prompt = f"Use API key {api_key} when making requests..."  # Visible to model

# WRONG: Secret in tool result
# If a tool returns a response that contains auth headers/tokens, strip them
result = await http_tool.get(url)
# result might contain: {"headers": {"Authorization": "Bearer sk-..."}}
# Filter before returning to model context

# RIGHT: Secret injected at execution layer, invisible to model

31.5 The Container Pattern

Containers provide the strongest blast radius limitation. Each agent loop runs in an isolated container with:

  • Scoped filesystem (only the files it needs, mounted read-only where possible)
  • Network policy (no egress, or allowlisted only)
  • Resource limits (CPU, memory, time)
  • No access to host credentials or other containers

Container Specification per Agent Type


@dataclass
class AgentContainer:
    image: str
    filesystem_mounts: list[Mount]
    network_policy: str  # "none" | "allowlist" | "full"
    allowed_domains: list[str] = None
    cpu_limit: str = "2"
    memory_limit: str = "4Gi"
    timeout_seconds: int = 300
    read_only_root: bool = True
    capabilities_drop: list[str] = None  # Linux capabilities to drop


# Code review agent: read-only, no network, limited scope
CODE_REVIEW_CONTAINER = AgentContainer(
    image="agent-runtime:latest",
    filesystem_mounts=[
        Mount(source="/workspace/repo", target="/repo", read_only=True),
        Mount(source="/tmp/agent-work", target="/work", read_only=False),
    ],
    network_policy="none",
    cpu_limit="2",
    memory_limit="4Gi",
    timeout_seconds=120,
    read_only_root=True,
    capabilities_drop=["NET_RAW", "SYS_ADMIN", "SETUID", "SETGID"],
)

# Documentation agent: needs to fetch docs, can write output
DOCS_CONTAINER = AgentContainer(
    image="agent-runtime:latest",
    filesystem_mounts=[
        Mount(source="/workspace/repo", target="/repo", read_only=True),
        Mount(source="/workspace/output", target="/output", read_only=False),
    ],
    network_policy="allowlist",
    allowed_domains=["docs.python.org", "developer.mozilla.org"],
    cpu_limit="1",
    memory_limit="2Gi",
    timeout_seconds=180,
    read_only_root=True,
    capabilities_drop=["ALL"],
)

31.6 Permission Hierarchies

Not all actions are equal. A four-tier permission model:


┌─────────────────────────────────────────────────┐
│  TIER 0: AUTONOMOUS                             │
│  Read files, search code, analyze, classify     │
│  → Agent executes freely                        │
├─────────────────────────────────────────────────┤
│  TIER 1: LOGGED                                 │
│  Write files, post comments, create branches    │
│  → Agent executes, full audit trail             │
├─────────────────────────────────────────────────┤
│  TIER 2: GATED                                  │
│  Run tests, deploy to staging, modify config    │
│  → Agent proposes, automated gate approves/deny │
├─────────────────────────────────────────────────┤
│  TIER 3: HUMAN-APPROVED                         │
│  Deploy to production, delete data, send email  │
│  → Agent proposes, human must approve           │
└─────────────────────────────────────────────────┘

Implementation


from enum import IntEnum


class PermissionTier(IntEnum):
    AUTONOMOUS = 0
    LOGGED = 1
    GATED = 2
    HUMAN_APPROVED = 3


TOOL_TIERS: dict[str, PermissionTier] = {
    "read_file": PermissionTier.AUTONOMOUS,
    "search_code": PermissionTier.AUTONOMOUS,
    "list_directory": PermissionTier.AUTONOMOUS,
    "write_file": PermissionTier.LOGGED,
    "create_branch": PermissionTier.LOGGED,
    "post_comment": PermissionTier.LOGGED,
    "run_tests": PermissionTier.GATED,
    "deploy_staging": PermissionTier.GATED,
    "deploy_production": PermissionTier.HUMAN_APPROVED,
    "delete_resource": PermissionTier.HUMAN_APPROVED,
    "send_email": PermissionTier.HUMAN_APPROVED,
}


class TieredPermissionSystem:
    def __init__(self, approval_gate: ApprovalGate):
        self.gate = approval_gate
        self.audit_log = AuditLog()

    async def authorize(self, tool_name: str, args: dict, agent_id: str) -> bool:
        tier = TOOL_TIERS.get(tool_name, PermissionTier.HUMAN_APPROVED)

        if tier == PermissionTier.AUTONOMOUS:
            return True

        if tier == PermissionTier.LOGGED:
            self.audit_log.record(agent_id, tool_name, args)
            return True

        if tier == PermissionTier.GATED:
            self.audit_log.record(agent_id, tool_name, args)
            return await self.gate.automated_check(tool_name, args)

        if tier == PermissionTier.HUMAN_APPROVED:
            self.audit_log.record(agent_id, tool_name, args, pending=True)
            approved = await self.gate.request_human_approval(
                agent_id=agent_id,
                tool_name=tool_name,
                args=args,
                timeout_seconds=300,
            )
            self.audit_log.update(agent_id, tool_name, approved=approved)
            return approved

        return False

31.7 Blast Radius Assessment

Before deploying a loop, answer this question: "If this loop goes completely rogue, what is the maximum damage it can cause?"

Blast Radius Scorecard


@dataclass
class BlastRadiusAssessment:
    """Quantifies the worst-case damage from a compromised agent."""

    agent_name: str
    
    # Data access
    can_read_secrets: bool = False
    can_read_customer_data: bool = False
    can_read_source_code: bool = False
    
    # Mutation capability
    can_modify_code: bool = False
    can_modify_infra: bool = False
    can_delete_data: bool = False
    
    # Communication
    can_send_external_comms: bool = False
    can_post_to_production: bool = False
    
    # Scope
    affected_systems: list[str] = None
    max_cost_if_rogue: float = 0.0  # Budget guard cap

    @property
    def risk_score(self) -> int:
        """0-10 composite risk score."""
        score = 0
        if self.can_read_secrets:
            score += 3
        if self.can_read_customer_data:
            score += 2
        if self.can_modify_code:
            score += 2
        if self.can_delete_data:
            score += 3
        if self.can_send_external_comms:
            score += 2
        if self.can_modify_infra:
            score += 3
        if self.can_post_to_production:
            score += 3
        return min(score, 10)

    @property
    def acceptable(self) -> bool:
        """Risk score <= 3 is acceptable for autonomous operation."""
        return self.risk_score <= 3

31.8 Principle of Least Privilege, Applied

Every agent should start with zero capabilities and gain only what it demonstrably needs:


class MinimalCapabilityBuilder:
    """Build agent capabilities from requirements, defaulting to deny-all."""

    def __init__(self, agent_name: str):
        self.agent_name = agent_name
        self._tools: list[ToolPermission] = []
        self._read_paths: list[str] = []
        self._write_paths: list[str] = []
        self._egress: bool = False
        self._egress_domains: list[str] = []

    def needs_to_read(self, *paths: str) -> "MinimalCapabilityBuilder":
        self._read_paths.extend(paths)
        self._tools.append(ToolPermission("read_file", allowed=True))
        return self

    def needs_to_write(self, *paths: str) -> "MinimalCapabilityBuilder":
        self._write_paths.extend(paths)
        self._tools.append(ToolPermission("write_file", allowed=True))
        return self

    def needs_network(self, *domains: str) -> "MinimalCapabilityBuilder":
        self._egress = True
        self._egress_domains.extend(domains)
        return self

    def build(self) -> AgentCapabilities:
        return AgentCapabilities(
            agent_name=self.agent_name,
            tools=self._tools,
            network_egress=self._egress,
            file_read_paths=self._read_paths or None,
            file_write_paths=self._write_paths if self._write_paths else None,
        )


# Usage:
reviewer_caps = (
    MinimalCapabilityBuilder("security-reviewer")
    .needs_to_read("./src/", "./config/", "./tests/")
    .build()
)
# Result: can read 3 directories, nothing else. No write, no network, no commands.

31.9 Runtime Capability Revocation

Capabilities aren't static for the lifetime of a loop run. If anomalous behavior is detected mid-run, revoke capabilities dynamically:


class DynamicCapabilityManager:
    """Revoke capabilities at runtime when anomalies are detected."""

    def __init__(self, base_capabilities: AgentCapabilities):
        self.capabilities = base_capabilities
        self.revoked: set[str] = set()

    def revoke(self, tool_name: str, reason: str) -> None:
        self.revoked.add(tool_name)
        logger.warning(
            "Capability revoked",
            agent=self.capabilities.agent_name,
            tool=tool_name,
            reason=reason,
        )

    def is_allowed(self, tool_name: str) -> bool:
        if tool_name in self.revoked:
            return False
        return self.capabilities.can_use_tool(tool_name) is not None

    def on_anomaly(self, anomaly_type: str) -> None:
        """Automatically revoke capabilities based on detected anomaly."""
        revocation_map = {
            "repeated_blocked_calls": ["run_command", "http_request"],
            "high_entropy_arguments": ["write_file", "run_command"],
            "unexpected_tool_sequence": ["write_file", "post_comment"],
        }
        for tool in revocation_map.get(anomaly_type, []):
            self.revoke(tool, f"Auto-revoked due to: {anomaly_type}")

31.10 Putting It Together

A production-ready agent deployment combines all layers:

  1. Static capability specification — What the agent is allowed to do (design time).
  2. Container isolation — Physical boundary limiting filesystem, network, and compute (deploy time).
  3. Harness enforcement — Mechanical checking of every tool call against the capability spec (run time).
  4. Dynamic revocation — Capability removal when anomalies are detected (run time).
  5. Blast radius assessment — Ongoing evaluation that the worst case remains acceptable (review time).

The goal is not zero risk — that would mean zero capability. The goal is that a compromised agent's worst-case behavior stays within acceptable bounds. If the worst an attacker can achieve through injection is reading 3 directories of source code with no way to send it anywhere, that's a manageable risk. If the worst case is deploying malicious code to production, your permission model needs work.
