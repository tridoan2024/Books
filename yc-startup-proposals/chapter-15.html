Chapter 15: VaultAgent — Secrets Management for AI Agents

The Drop-In Solution for the AI Credential Crisis

Chapter 14 documented the problem: every AI coding agent stores credentials insecurely, and the cumulative exposure across enterprises is staggering. This chapter introduces VaultAgent — a secrets management platform purpose-built for AI coding assistants.

VaultAgent is not another general-purpose secrets manager. It is not a fork of HashiCorp Vault repackaged for a new market. It is a purpose-built system designed around the unique requirements of AI agent credential flows: the conversation history problem, the cross-tool proliferation problem, the silent fallback problem, and the compliance visibility gap.

This chapter covers the product vision, core capabilities, integration model, and the zero-knowledge architecture that makes VaultAgent trustworthy even to the most security-conscious enterprises.

Capability 1: Encrypted Vault

The encrypted vault replaces every AI agent's insecure credential storage with a single, encrypted, OS-integrated credential store.

What it does: - Intercepts credential write operations from AI agents (OAuth tokens, API keys, session tokens) - Encrypts credentials using XSalsa20-Poly1305 (libsodium) before writing to disk - Integrates with OS keychain for key management (macOS Keychain, Linux libsecret/GNOME Keyring, Windows DPAPI/Credential Manager) - Provides a unified credential access API that all AI agents use instead of their own storage

What it replaces: - ~/.claude/.credentials.json (plaintext JSON) - ~/.cursor/auth.json (plaintext JSON) - ~/.copilot/hosts.json (plaintext JSON) - Every other AI agent's ad-hoc credential file

Key design decision: VaultAgent does not require agents to be modified. The Agent SDK hooks into each agent's credential storage path via filesystem-level interception (on macOS: Endpoint Security framework; on Linux: eBPF/fanotify; on Windows: minifilter driver). When an agent writes to its credential file, VaultAgent transparently encrypts the content. When the agent reads, VaultAgent transparently decrypts. From the agent's perspective, nothing changes. From a security perspective, everything changes.

Encryption at rest:

Agent writes: {"accessToken": "sk-ant-....", "refreshToken": "rt-..."}
  → VaultAgent intercepts write
    → Generate per-file nonce (24 bytes, random)
    → Encrypt payload: XSalsa20-Poly1305(payload, key, nonce)
    → Key derived from: OS keychain master key + machine-specific salt
    → Write encrypted blob + nonce to original file path
    → Agent sees success (transparent)

Agent reads: (encrypted blob on disk)
  → VaultAgent intercepts read
    → Retrieve key from OS keychain
    → Decrypt: XSalsa20-Poly1305_open(blob, key, nonce)
    → Return plaintext to agent
    → Agent sees normal JSON (transparent)

Capability 2: Secret Scanner

The secret scanner monitors AI agent conversation histories, tool outputs, and telemetry for secrets that should not be stored in plaintext.

What it scans: - Conversation history files (JSONL, SQLite, custom formats) - Paste cache directories - Agent configuration files - Debug log files - Telemetry metadata

What it detects:

Secret Type Detection Method Examples
AWS access keys Regex: AKIA[0-9A-Z]{16} AKIAIOSFODNN7EXAMPLE
GitHub tokens Regex: gh[pso]_[a-zA-Z0-9]{36,} ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
API keys (generic) High-entropy string detection + context sk-proj-xxxxxxxxxxxxxxxxxxxxxxxxxx
Database connection strings URI pattern matching postgres://user:pass@host:5432/db
Private keys PEM header/footer detection -----BEGIN RSA PRIVATE KEY-----
JWT tokens Three-part base64 pattern eyJhbGciOiJIUzI1NiIs...
OAuth tokens Prefix matching + entropy ya29.a0AfH6SMBxxxxxxxxx
Passwords in context NLP-based contextual detection "password is hunter2"
SSH keys Key format detection ssh-rsa AAAA...
Certificate files PEM/DER pattern detection -----BEGIN CERTIFICATE-----

Actions on detection:

The scanner operates in three modes, configurable per environment:

  1. Detect mode (default for evaluation): Identifies secrets and generates alerts without modifying files. Reports to the admin dashboard with severity, location, and remediation guidance.

  2. Redact mode (recommended for production): Automatically redacts detected secrets in conversation history and logs, replacing them with references: [REDACTED: AWS_ACCESS_KEY detected, ref: VA-2027-001]. The original secret is moved to the encrypted vault with a cross-reference.

  3. Block mode (available for high-security environments): Prevents secrets from being written to unencrypted storage in the first place. When an agent attempts to write a file containing a detected secret, VaultAgent intercepts the write and stores the secret in the vault, replacing it with a reference in the file.

Scanner performance: The scanner operates as a background daemon, processing file changes via filesystem event notifications (FSEvents on macOS, inotify on Linux, ReadDirectoryChangesW on Windows). Typical latency: <100ms from file write to detection. CPU overhead: <2% on a modern development machine.

Capability 3: Lifecycle Manager

The lifecycle manager solves the "immortal token" problem identified in our audit research. It manages the complete lifecycle of credentials used by AI agents: creation, rotation, expiry enforcement, and revocation.

Token rotation: - Monitors credential expiry timestamps across all managed agents - Proactively refreshes tokens before expiry (configurable buffer, default: 10% of token lifetime) - For tokens without refresh mechanisms (environment variable tokens), enforces a maximum lifetime (configurable, default: 24 hours) and alerts when tokens should be rotated - Maintains rotation history for audit trail

Expiry enforcement: - Overrides the "immortal token" pattern where agents set expiresAt: null - Applies organization-defined maximum token lifetimes - Alerts when tokens exceed maximum age - Supports graceful degradation: warn → restrict → revoke pipeline

Revocation propagation: - When a credential is revoked (server-side or admin-initiated), VaultAgent removes it from all agent credential stores simultaneously - Revocation is immediate and atomic — no agent continues using a revoked credential - Revocation events are logged with full context (who revoked, why, which agents affected)

Environment variable token management: - Monitors *_TOKEN, *_KEY, *_SECRET, *_PASSWORD environment variables - Replaces long-lived env var tokens with short-lived tokens from VaultAgent - Provides a CLI tool: vaultagent inject that sets environment variables from the encrypted vault with automatic expiry - Integrates with CI/CD systems (GitHub Actions, GitLab CI, Jenkins) for pipeline token management

Capability 5: Zero-Knowledge Architecture

The most critical design decision in VaultAgent is what it does NOT know.

VaultAgent never sees plaintext credentials on our servers. All encryption and decryption happens locally on the developer's machine. The encryption key is derived from the OS keychain and never leaves the device. Our cloud backend stores only:

  • Encrypted credential metadata (what type, when created, when last accessed)
  • Policy configurations
  • Audit log entries (with credential IDs, not credential values)
  • License and usage telemetry

Why zero-knowledge matters:

  1. Trust model. If VaultAgent could read your credentials, you would need to trust us not to be compromised. With zero-knowledge, a breach of our servers exposes no credential data.

  2. Compliance simplification. VaultAgent's cloud backend is not in scope for PCI, HIPAA, or other credential-focused compliance frameworks because it never processes credentials.

  3. Enterprise procurement. Security teams evaluating VaultAgent can verify the zero-knowledge claim through code audit (we publish the encryption module as open source) and network traffic analysis (no plaintext credentials leave the machine).

Transparent mode requires zero changes to the AI agent. VaultAgent watches the known credential file paths and intercepts reads/writes at the filesystem level. This is the primary integration path for existing agents.

SDK mode provides deeper integration for agents that want to use VaultAgent's API directly:

import { VaultAgent } from '@vaultagent/sdk';

const vault = new VaultAgent({
  appName: 'my-custom-agent',
  encryptionLevel: 'hardware', // Use OS keychain
});

// Store a credential
await vault.store({
  key: 'anthropic-oauth',
  value: accessToken,
  type: 'oauth_token',
  expiresAt: new Date(Date.now() + 3600_000),
  metadata: { provider: 'anthropic', scope: 'write' },
});

// Retrieve a credential
const token = await vault.retrieve('anthropic-oauth');

// Credential is automatically rotated before expiry
// Credential access is automatically logged
// Credential is automatically encrypted at rest

Technical Differentiators: What Makes VaultAgent Hard to Replicate

Five technical capabilities that create defensibility beyond market timing:

1. Cross-Agent Behavioral Fingerprinting. VaultAgent builds a behavioral model of how each AI agent accesses credentials. This fingerprint enables anomaly detection: if a process claiming to be Claude Code accesses credentials using a pattern that does not match Claude Code's known behavior, VaultAgent blocks the access. Building this fingerprint library requires observing millions of credential access events across thousands of deployments — a dataset that grows with our customer base.

2. Secret Pattern Database. Our scanner maintains a curated database of 400+ secret patterns with context-specific tuning. This database is continuously updated as new AI tools emerge and new secret formats appear. The database is the product of ongoing security research, not a one-time engineering effort. Competitors can replicate the initial patterns, but staying current requires the same research investment.

3. Platform-Specific Encryption Integrations. Deep integration with macOS Keychain, Linux libsecret, Windows DPAPI, and hardware security modules (TPM, Secure Enclave) across all major platforms. Each integration is a multi-week engineering effort with platform-specific edge cases. The combined matrix (3 platforms x 2+ security backends per platform) represents 6+ months of platform engineering that any competitor must replicate.

4. Agent Adapter Library. Transparent filesystem interception for 6+ AI agents, each with its own credential file format, storage location, and access pattern. Each adapter requires reverse-engineering the agent's credential storage behavior. As new agents launch, we add adapters within days — competitors starting from zero face a growing backlog.

5. Compliance Template Library. Pre-built compliance report templates mapped to SOC 2, PCI DSS, HIPAA, GDPR, and NIST 800-53. Each template was developed with input from compliance auditors to ensure it meets the specific evidence requirements of each framework. Creating audit-ready templates requires compliance expertise, not just engineering.
