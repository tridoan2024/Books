8.3 The Application Questions

What does your company do? (max 200 words)

AgentShield is runtime security for AI coding agents. We use eBPF (Linux) and macOS Endpoint Security to monitor and control what AI agents do on developer machines -- which files they read, which commands they execute, which network connections they make.

Every major AI coding agent (Claude Code, Cursor, GitHub Copilot) executes shell commands with the developer's full permissions. There is no sandboxing, no monitoring, and no access control. A single prompt injection can make an agent read SSH keys, modify source code, or exfiltrate data. We found 50 vulnerabilities in the largest AI coding agent's source code -- including agents spawning agents with no isolation, MCP servers executing without verification, and credentials stored in plaintext.

AgentShield installs in 30 seconds (brew install / VS Code extension), requires zero changes to the AI agent, and enforces security policies at the kernel level. The agent cannot bypass it because the agent does not know it exists.

We are building the CrowdStrike for AI agents: endpoint security that understands not just processes, but agent identities, tool invocations, and subagent hierarchies.

Free for individuals. $15/seat/month for teams. $25/seat/month for enterprises.

Commentary: 196 words. Hits five things in order: (1) what it is, (2) why it matters, (3) evidence of the problem (50 vulns found), (4) how it works technically, (5) pricing. The CrowdStrike analogy gives YC partners an immediate mental model. The pricing at the end signals business maturity.

Why did you pick this idea to work on? (max 200 words)

We spent 4 months doing the deepest security audit ever performed on a production AI coding agent -- 500K+ lines of source code, every tool, every permission path, every MCP integration. We found 50 vulnerabilities: 2 critical, 8 high, 23 medium. The critical findings: no cryptographic signature verification for plugins (CVSS 9.1), and subagent execution without process isolation (CVSS 7.8).

These are not theoretical bugs. They are production vulnerabilities in tools used by millions of developers every day. And every other AI agent has the same issues because they all share the same architecture: an LLM that can execute arbitrary system commands through tools.

We did not pick this idea from a market analysis. We picked it because we are the people who found the problems, we understand why they exist at the source code level, and we know exactly how to fix them. The fix is AgentShield.

The vulnerability research is our unfair advantage. No one else has audited AI agent internals at this depth. The findings directly inform product requirements -- every AgentShield feature maps to a specific vulnerability we discovered.

Commentary: This answer establishes founder-market fit through action, not claims. "We spent 4 months auditing" is more compelling than "We are passionate about security." The specific numbers (50 vulnerabilities, CVSS scores) signal technical depth. The last paragraph explicitly names the unfair advantage.

  2. Design partner enthusiasm. All 3 design partners signed LOIs within 2 weeks of the first call. The fastest enterprise sales cycle any of us have seen. The urgency is real.

  3. The compliance trigger. Two design partners have the same story: their AI adoption initiative was blocked by the security team because they could not demonstrate monitoring and access control for AI agent tool execution. AgentShield unblocks AI adoption. We are not selling security for its own sake -- we are selling the ability to deploy AI agents at scale.

What do you know that others do not?

We know the exact attack surface of AI coding agents because we have read their source code. Specifically:

  1. Subagents inherit parent permissions with no attenuation (Claude Code, finding #3, CWE-269)
  2. MCP servers execute tools without cryptographic verification (finding #1-2, CWE-494, CVSS 9.1)
  3. Credential storage falls back to plaintext on non-macOS systems (finding #7-10, CWE-312)
  4. Permission systems rely on regex matching that can be bypassed with shell quoting tricks (finding #19-20)
  5. The agent identity problem -- no existing tool can attribute a syscall to a specific agent → tool → session chain

This knowledge is not academic. It is the product specification.

If you had to pick one thing that makes you different from everyone else, what would it be?

We are the only team that has both (a) discovered the vulnerabilities in production AI agents and (b) built the technology (eBPF + agent identity) to fix them. Security researchers who can ship product are rare. Product teams that understand kernel-level security are rare. The intersection is us.

What would you do if funding ran out?

The eBPF sensor and policy engine are already built. We would open-source the entire product (not just the community tier), build community, and self-fund through consulting -- security audits of AI agent deployments for enterprises at $50K-$100K per engagement. The consulting builds pipeline for the product. This is the Hashicorp model: consulting funds open-source, open-source drives enterprise.

What is your burn rate?

$45K/month pre-YC (2 founders, cloud infrastructure, conference travel). Post-YC with seed funding: $100K/month (7 people, expanded infrastructure). 30-month runway on a $3M seed.

If the application advances to interview (10% of applicants), the interview is 10 minutes with 2-3 YC partners. The format:

Minutes 0-1: "What do you do?" (30-second version of the description) Minutes 1-3: Demo (our 90-second script, extended to answer questions) Minutes 3-7: Hard questions (market size, competition, technical feasibility, team) Minutes 7-10: "What do you need?" and closing

Expected Hard Questions and Answers

Q: "What if Anthropic / OpenAI just builds this into their agents?"

A: "They should. And some of them will. But self-policing does not work -- an agent cannot enforce security on itself because prompt injection bypasses its own guardrails. AgentShield works at the kernel level, below the agent. The agent cannot turn it off because the agent does not know it exists. Also, enterprises need a single security layer across all AI agents, not per-vendor solutions. We are the cross-agent security layer."

Q: "This seems like a feature, not a company."

A: "CrowdStrike is a $70B company built on a 'feature' that every OS vendor could have built: endpoint detection and response. The OS vendors did not build it well enough, fast enough. The AI agent vendors will not build runtime security well enough, fast enough. This is a company because the problem is multi-vendor, the solution requires deep kernel expertise, and the market is $4.8B."

Q: "How do you get enterprises to install a kernel-level tool?"

A: "The same way CrowdStrike does: start with developer-led adoption (no admin required for monitoring-only mode), then upgrade to enforcement when the security team mandates it. Our macOS System Extension does not require disabling SIP. Our Linux eBPF probes require CAP_BPF but not root. The trust comes from the open-source code -- security teams can audit every line of our sensor."

Q: "What is your biggest risk?"

A: "Execution speed. The market window is 12-18 months before incumbents enter. We need to be at $5M+ ARR with 50+ enterprise logos before CrowdStrike or Wiz builds an 'AI agent security' checkbox feature. That is why we are applying to YC -- the batch accelerates our go-to-market by 6 months compared to doing it alone."
