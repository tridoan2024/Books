Chapter 30: Context and Memory Management

"A context window forgets everything the moment a session ends. A memory system forgets nothing the moment it is designed well."

The previous treatment of context — Chapter 20's token budgets, autocompaction, and prompt cache — addressed the question of what the model can see within a single session. This chapter addresses what it can remember across sessions. These are fundamentally different problems.

Within a session, the harness manages a linear message history. Across sessions, there is no built-in persistence — the API has no memory, the harness has no implicit state, and the model has no recall of prior work. Every session begins from the same blank slate unless the harness explicitly reconstructs it. For short-lived tasks, this is fine. For a production agent that monitors security vulnerabilities across hundreds of repositories, or a coding assistant that learns the quirks of a particular codebase over months, blank-slate restarts are a correctness failure.

This chapter builds a memory system from first principles. The design is grounded in the copilot-mem MCP server — a production deployment with 1,035 memories, 2,627 knowledge links, a 35MB SQLite store, and a relevance scoring algorithm tuned over hundreds of real sessions. The lab at the end implements the core mechanics: store, search, score, link, and decay.

30.1 Context Window Strategy: What to Load, What to Defer, When to Compress

Before examining persistent memory, the context window itself requires a loading strategy. The naive approach — inject everything at the start of every session — fails at scale because context space is finite, expensive, and nonuniform in value. Senior harness engineers think about context loading the way a database administrator thinks about query plans: what data do I need, when do I need it, and how do I avoid pulling the full table when a targeted read will do?

The Loading Decision Tree

Every piece of information that might go into a context window has a cost (tokens consumed) and a benefit (probability of contributing to correct output). The loading decision is always a cost-benefit calculation:

Information candidate
         │
         ▼
    ┌─────────────────────────────────────┐
    │ Is it needed for the current task?  │
    └─────────────────────────────────────┘
         │                   │
       YES                   NO
         │                   │
         ▼                   ▼
    ┌──────────────┐    ┌─────────────────────────────┐
    │ How stable   │    │ Can it be loaded on demand? │
    │ is it?       │    └─────────────────────────────┘
    └──────────────┘         │                   │
         │                   YES                 NO
    STABLE     DYNAMIC        │                   │
         │         │          ▼                   ▼
         ▼         ▼     [Defer — tool call   [Skip — out
    [Load in   [Load just   when relevant]     of scope]
    system     before use]
    prompt —
    cache it]

Stable context belongs in the system prompt. Tool descriptions, project conventions, the base behavioral instructions — these do not change between turns, so they belong at the beginning of the request where the prompt cache can serve them repeatedly. Each additional turn in a session that hits the cache instead of re-processing the system prompt saves the full input token cost of that content.

Dynamic context belongs close to the point of use. File contents should be read when referenced, not pre-loaded at session start. MCP tool schemas that may change should be loaded when the tool is first needed. User preferences from a memory store should be fetched based on the current task's domain, not dumped wholesale into the system prompt.

Deferrable context should be left out until requested. A code review agent does not need the full git history unless asked to trace a bug's origin. A writing assistant does not need prior document drafts unless asked to continue from a checkpoint. Deferred loading is not laziness — it is the correct architectural choice when the probability of needing a piece of information is low or conditional.

What to Compress versus What to Preserve

When approaching the context limit, the harness must distinguish compressible content from critical state. A rough taxonomy:

Content typeCompress?Preserve mechanism
Tool call results from early in sessionYes — summarizeKey findings in state file
File contents already incorporated into outputYesThe output itself
Intermediate reasoning about completed subtasksYesDecision journal entry
Active task requirementsNoInject into compaction summary
Confirmed findings that affect remaining workNoPreCompact hook output
User preferences learned during sessionNoSave to memory store
API keys, secrets, auth tokensNeverExternal secret store only

The principle: compress what is historical, preserve what is load-bearing. A summary of what happened is usually as useful as the transcript for future reasoning. But the current task state — where we are, what we have confirmed, what comes next — must survive compression intact, not as a lossy summary.

30.2 Compression Implementation: Summarize Prior Turns, Preserve Critical State

Manual compression is occasionally necessary when the harness's automatic compression would destroy context that the automatic algorithm does not know to preserve. The PreCompact hook (Chapter 20) is the injection mechanism; this section covers what to inject.

The Preservation Budget

The compaction summary has its own token budget — it cannot be unbounded. In practice, a well-structured state snapshot should stay under 600 tokens (roughly 2,400 characters). That budget must cover:

  • Current task identity: one sentence on what the agent is doing
  • Phase and progress: numeric counters, current position in a workflow
  • Critical confirmed state: findings, decisions, or facts that would be expensive to re-derive
  • Resumption instructions: exactly what to do when the session continues

The copilot-mem implementation writes a structured compaction payload:

from dataclasses import dataclass, field
from datetime import datetime, timezone
import json
from pathlib import Path


@dataclass
class CompactionState:
    task: str
    phase: str
    progress: dict[str, int]
    confirmed: list[dict]
    next_action: str
    timestamp: str = field(
        default_factory=lambda: datetime.now(timezone.utc).isoformat()
    )

    def to_compaction_text(self, max_chars: int = 2400) -> str:
        payload = {
            "task": self.task,
            "phase": self.phase,
            "progress": self.progress,
            "confirmed": self.confirmed,
            "next_action": self.next_action,
            "timestamp": self.timestamp,
        }
        text = json.dumps(payload, indent=2)
        if len(text) > max_chars:
            # Truncate confirmed list first — it is the largest variable
            payload["confirmed"] = payload["confirmed"][:3]
            payload["confirmed"].append({"note": "truncated — see state file"})
            text = json.dumps(payload, indent=2)
        return (
            "CRITICAL SESSION STATE — preserve verbatim through compaction:\n"
            + text
            + "\nOn resume: read full state from disk before continuing."
        )


def write_state_for_precompact(
    state: CompactionState,
    state_dir: Path,
) -> Path:
    state_dir.mkdir(parents=True, exist_ok=True)
    path = state_dir / f"state-{int(datetime.now().timestamp())}.json"
    path.write_text(json.dumps(state.__dict__, indent=2))
    return path

The agent calls write_state_for_precompact at each task boundary — after completing a scan phase, after making a significant decision, after confirming a finding. The PreCompact hook reads the most recent state file and calls to_compaction_text() to produce its stdout. The resulting text is woven into the autocompaction summary by the harness.

Summarization Quality

The harness's built-in summarization is model-generated and generally good at preserving narrative continuity. Where it fails is in preserving exact values — specific line numbers, exact function names, precise error messages. These details compress to paraphrases, and a paraphrase of a line number is useless.

The rule: any value that must be exact after compression must be written to persistent storage before compression, not left in the conversation. Conversation summaries preserve intent; they do not reliably preserve data.

30.3 Prompt Cache Optimization: Stable Prefixes, Dynamic Suffixes, 5-Minute TTL Awareness

Chapter 20 established the cache mechanics. This section addresses the engineering discipline of building a context assembly pipeline that maximizes cache utilization across a multi-session memory-augmented agent.

The Prefix-Suffix Split

The Anthropic API caches based on a content hash of the prefix of the request. Everything that is identical across requests hits the cache; the first byte that differs is the cache boundary. The harness's assembly pipeline must be designed so that stable content accumulates at the front and dynamic content appears only at the end:

Request structure (cache-optimized)
┌────────────────────────────────────────────────────────┐
│ SYSTEM PROMPT                                          │
│  ├── Base instructions (static — never changes)        │  ← cache tier 1
│  ├── Tool descriptions (static per session)            │  ← cache tier 1
│  └── Project CLAUDE.md (static per project)            │  ← cache tier 1
├────────────────────────────────────────────────────────┤
│ CONVERSATION HISTORY                                   │
│  ├── Turns 1..N-5 (stable — served from cache)         │  ← cache tier 2
│  └── Turns N-4..N (recent — may miss cache)            │  ← computed fresh
├────────────────────────────────────────────────────────┤
│ INJECTED CONTEXT (THIS TURN)                           │
│  ├── Memory search results (dynamic — retrieved now)   │  ← not cached
│  └── Current task specifics                            │  ← not cached
└────────────────────────────────────────────────────────┘

The critical implication: memory injection belongs at the end, not the beginning. A common mistake in memory-augmented agents is to prepend retrieved memories into the system prompt. This destroys cache coherence: different queries return different memories, and every unique memory set produces a unique system prompt prefix, guaranteeing a cache miss on every turn.

The correct pattern is to inject retrieved memories as the last user message in the conversation, or as a structured section appended after the conversation history:

def assemble_request(
    base_system_prompt: str,
    conversation_history: list[dict],
    retrieved_memories: list[str],
    current_user_message: str,
) -> dict:
    """
    Assemble a cache-optimized request.
    The base_system_prompt is stable and will hit the prompt cache.
    Retrieved memories are injected late, after the stable prefix.
    """
    messages = list(conversation_history)

    if retrieved_memories:
        memory_block = "\n\n".join(retrieved_memories)
        # Inject as a system-role message after history — does not break cache prefix
        messages.append({
            "role": "user",
            "content": (
                f"[MEMORY CONTEXT — relevant to current task]\n{memory_block}"
                f"\n\n[CURRENT REQUEST]\n{current_user_message}"
            ),
        })
    else:
        messages.append({"role": "user", "content": current_user_message})

    return {
        "system": base_system_prompt,
        "messages": messages,
    }

TTL Management

The 5-minute ephemeral cache TTL has a practical consequence: if an agent is processing a long operation and a turn takes longer than 5 minutes, the next turn will re-process the system prompt from scratch. For agents that run long-running subagents between turns, this is a real cost.

Two mitigations: keep the system prompt compact (smaller prompt = cheaper re-processing when the cache misses), and for workflows that will have long gaps between turns, deliberately send a no-op turn shortly before the 5-minute mark to refresh the cache:

async def refresh_cache_if_needed(
    client: anthropic.AsyncAnthropic,
    last_turn_at: float,
    system: str,
    messages: list[dict],
    ttl_seconds: int = 270,  # 4.5 min — 30s margin before 5-min TTL
) -> None:
    """Send a minimal ping turn to keep the prompt cache warm."""
    import time
    if time.time() - last_turn_at < ttl_seconds:
        return  # cache still fresh
    await client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=1,
        system=system,
        messages=messages + [{"role": "user", "content": "ok"}],
    )

This technique costs a negligible output token but prevents the full system prompt from being re-billed as input tokens on the next substantive turn.

30.4 Memory System Design: Episodic, Semantic, and Procedural Memory

A production memory system is not a flat key-value store. The copilot-mem deployment demonstrates why: with 1,035 entries and only a flat store, relevance retrieval degrades to keyword search, which returns noise. A structured taxonomy combined with a multi-factor relevance scorer returns the three memories that actually matter.

The taxonomy has three types, drawn from cognitive science and adapted for agent workloads:

Episodic Memory

Episodic memories are time-indexed records of what happened. They answer "what did I do?" and "what happened during session X?" They are inherently short-lived — an episode from six months ago is rarely relevant today.

Characteristics:

  • Created automatically during agent sessions (as opposed to being explicitly saved)
  • Expire by default — daily work logs age out, significant events promote to semantic
  • Low default importance (1–2 on a 1–5 scale)
  • Anchor: a specific timestamp, task, or session identifier

Examples: "Reviewed PR #9965 on 2026-07-15", "Ran security scan on payments module — found 3 issues", "Completed ch01 draft at 14:32 CDT"

In the copilot-mem deployment, episodic memories account for 26 of 1,035 entries — a small fraction — because most episodes either age out or get promoted to semantic when a pattern becomes clear.

Semantic Memory

Semantic memories are facts, preferences, architectural decisions, and domain knowledge. They answer "what is true about X?" They are durable and often manually saved.

Characteristics:

  • Created intentionally: save_fact, save_preference, save_decision operations
  • Long-lived by default (temporal tier: long)
  • High default importance (3–5 on a 1–5 scale)
  • Anchor: a domain, project, or concept rather than a timestamp

Examples: "Project uses RS256 JWT signing in production, HS256 in test", "User prefers one bundled PR over many small ones for large refactors", "sec-pr never votes approve — only votes -5 for CRITICAL/HIGH"

Semantic memory is the largest type in production deployments. At copilot-mem: 685 of 1,035 entries. Most of the agent's durable knowledge lives here.

Procedural Memory

Procedural memories are workflows, recipes, and repeatable processes. They answer "how do I do X?" They are distinct from semantic knowledge because they encode sequence, not just fact.

Characteristics:

  • Capture multi-step processes: setup procedures, debugging approaches, deployment workflows
  • Reused across sessions when a matching task is detected
  • Saved explicitly: capture_app_knowledge with category: workflow or workflow_recipe
  • High retrieval value when the agent is starting a known task type

Examples: "Workflow for deploying a security patch to production: 1. Cut branch from main, 2. Run full test suite...", "Recipe for debugging a failing cron: check cron syntax, verify environment variables, check log output at..."

In copilot-mem: 324 of 1,035 entries — a rich procedural library covering nearly every recurring task in the workspace.

Why the Taxonomy Matters for Retrieval

The type distinction is not just organizational — it directly shapes retrieval scoring. When an agent starts a new security scan, procedural memories tagged workflow for security scanning get elevated relevance. When a user asks about a preference, semantic memories tagged preference score higher. The type is one of the seven factors in the relevance algorithm, covered in section 30.5.

30.5 Memory Architecture: SQLite Backend, 7-Factor Relevance Scoring, Knowledge Links, Temporal Tiers

Schema

The SQLite backend for a production memory system needs to support both fast keyword search and flexible multi-factor scoring. The core schema:

CREATE TABLE memories (
    id          TEXT PRIMARY KEY,       -- UUID
    type        TEXT NOT NULL,          -- episodic | semantic | procedural
    category    TEXT NOT NULL,          -- fact | workflow | preference | decision | etc.
    key         TEXT NOT NULL,          -- human-readable identifier
    value       TEXT NOT NULL,          -- the memory content
    importance  INTEGER NOT NULL        -- 1 (low) to 5 (critical)
                CHECK (importance BETWEEN 1 AND 5),
    temporal_tier TEXT NOT NULL         -- short | medium | long
                DEFAULT 'long',
    project     TEXT,                   -- project context, if any
    tags        TEXT,                   -- JSON array of strings
    access_count INTEGER NOT NULL DEFAULT 0,
    last_accessed TEXT,                 -- ISO-8601
    created_at  TEXT NOT NULL,          -- ISO-8601
    expires_at  TEXT,                   -- ISO-8601, NULL = never expires
    archived    INTEGER NOT NULL DEFAULT 0  -- soft delete
);

CREATE TABLE knowledge_links (
    id           TEXT PRIMARY KEY,
    from_id      TEXT NOT NULL REFERENCES memories(id),
    to_id        TEXT NOT NULL REFERENCES memories(id),
    link_type    TEXT NOT NULL,  -- related_to | evolved_from | caused_by | part_of | contradicts
    created_at   TEXT NOT NULL
);

CREATE TABLE daily_summaries (
    date        TEXT PRIMARY KEY,  -- YYYY-MM-DD
    summary     TEXT NOT NULL,
    memory_ids  TEXT NOT NULL      -- JSON array of contributing memory IDs
);

-- Full-text search index on key + value
CREATE VIRTUAL TABLE memories_fts USING fts5(
    key, value,
    content='memories',
    content_rowid='rowid'
);

The memories_fts virtual table enables SQLite's built-in full-text search, which handles prefix matching, phrase queries, and relevance ranking without a separate search engine. For a 35MB store with ~1,000 memories, FTS5 is sufficient and eliminates an external dependency.

The 7-Factor Relevance Scorer

When search_memory executes a query, raw FTS results are re-ranked by a composite score that combines seven factors. Each factor is normalized to [0, 1] and multiplied by a weight:

from __future__ import annotations

import math
from dataclasses import dataclass
from datetime import datetime, timezone
from typing import Optional


@dataclass
class Memory:
    id: str
    type: str           # episodic | semantic | procedural
    category: str
    key: str
    value: str
    importance: int     # 1–5
    temporal_tier: str  # short | medium | long
    project: Optional[str]
    access_count: int
    last_accessed: Optional[str]
    created_at: str
    fts_rank: float     # raw FTS5 rank score (negative — closer to 0 = better match)


# Factor weights — must sum to 1.0
WEIGHTS = {
    "query_match":     0.35,  # FTS relevance — highest weight, the query is the oracle
    "importance":      0.20,  # importance 1–5, normalized
    "recency":         0.15,  # how recently was this memory accessed or created
    "frequency":       0.10,  # how often is this memory accessed
    "project_match":   0.10,  # does the memory's project match the current context
    "type_affinity":   0.05,  # does the memory type match the query intent
    "temporal_tier":   0.05,  # long > medium > short for general queries
}

TIER_SCORES = {"long": 1.0, "medium": 0.6, "short": 0.2}
TYPE_AFFINITY_MAP = {
    "workflow":  {"procedural": 1.0, "semantic": 0.4, "episodic": 0.1},
    "fact":      {"semantic":   1.0, "procedural": 0.4, "episodic": 0.2},
    "recent":    {"episodic":   1.0, "semantic": 0.3, "procedural": 0.2},
    "default":   {"semantic":   0.7, "procedural": 0.7, "episodic": 0.3},
}


def score_memory(
    memory: Memory,
    query: str,
    current_project: Optional[str] = None,
    query_intent: str = "default",  # workflow | fact | recent | default
    now: Optional[datetime] = None,
) -> float:
    """
    Compute a composite relevance score in [0, 1] for a candidate memory.
    Higher is more relevant.
    """
    if now is None:
        now = datetime.now(timezone.utc)

    # Factor 1: Query match (FTS rank, negated and normalized)
    # FTS5 returns negative ranks; closer to 0 = better match
    # We normalize to [0, 1] using a sigmoid on the raw rank
    raw_rank = abs(memory.fts_rank) if memory.fts_rank else 10.0
    f_query = 1.0 / (1.0 + raw_rank)

    # Factor 2: Importance (1–5 → 0.0–1.0)
    f_importance = (memory.importance - 1) / 4.0

    # Factor 3: Recency — exponential decay from last access or creation
    reference_time_str = memory.last_accessed or memory.created_at
    try:
        reference_dt = datetime.fromisoformat(reference_time_str)
        if reference_dt.tzinfo is None:
            reference_dt = reference_dt.replace(tzinfo=timezone.utc)
        age_days = (now - reference_dt).total_seconds() / 86400.0
    except (ValueError, TypeError):
        age_days = 365.0
    # Decay half-life: 30 days — a memory accessed 30 days ago scores 0.5
    f_recency = math.exp(-age_days * math.log(2) / 30.0)

    # Factor 4: Frequency — logarithmic to avoid runaway bias toward old memories
    f_frequency = math.log1p(memory.access_count) / math.log1p(100)
    f_frequency = min(f_frequency, 1.0)

    # Factor 5: Project match — binary with partial credit for no-project memories
    if current_project and memory.project:
        f_project = 1.0 if memory.project == current_project else 0.0
    elif memory.project is None:
        f_project = 0.5  # global memory — relevant to any project, not ideal for any
    else:
        f_project = 0.3  # project-specific memory, wrong project

    # Factor 6: Type affinity — does memory type match query intent?
    affinity_table = TYPE_AFFINITY_MAP.get(query_intent, TYPE_AFFINITY_MAP["default"])
    f_type = affinity_table.get(memory.type, 0.3)

    # Factor 7: Temporal tier — long-lived memories preferred for general queries
    f_tier = TIER_SCORES.get(memory.temporal_tier, 0.2)

    score = (
        WEIGHTS["query_match"]   * f_query
        + WEIGHTS["importance"]  * f_importance
        + WEIGHTS["recency"]     * f_recency
        + WEIGHTS["frequency"]   * f_frequency
        + WEIGHTS["project_match"] * f_project
        + WEIGHTS["type_affinity"] * f_type
        + WEIGHTS["temporal_tier"] * f_tier
    )

    return round(score, 4)

The weight distribution reflects a deliberate design choice: query relevance is paramount (35%), but a highly relevant memory that was last accessed two years ago and has low importance will still score lower than a moderately relevant memory that is frequently used and currently important. The recency and frequency factors prevent the index from becoming a graveyard of forgotten entries that crowd out actionable knowledge.

Knowledge Links

Knowledge links make the memory graph navigable beyond keyword search. When two memories are related, a link encodes the type of relationship:

Link typeMeaningExample
related_toGeneral associationJWT security finding ↔ auth module architecture note
evolved_fromOne memory supersedes anothersec-pr v2 rules evolved_from sec-pr v1 rules
caused_byA finding explains a decisionPR #35989 miss caused_by trusting tracker status
part_ofHierarchical membershipsec-pr cron rule part_of sec-pr autonomous workflow
contradictsConflicting informationOld deploy procedure contradicts new blue/green deploy process

The 2,627 knowledge links in the production deployment are the feature that makes the memory system genuinely useful for complex, multi-session work. A search for "sec-pr approval" returns a small set of semantic memories; following their part_of links traverses the full sec-pr workflow graph.

def get_linked_memories(
    conn: "sqlite3.Connection",
    memory_id: str,
    link_types: list[str] | None = None,
    max_hops: int = 2,
) -> list[tuple[str, str, int]]:
    """
    Walk the knowledge graph from a seed memory.
    Returns (memory_id, link_type, hop_distance) tuples.
    Breadth-first, bounded by max_hops.
    """
    visited: set[str] = {memory_id}
    frontier = [(memory_id, "", 0)]
    results: list[tuple[str, str, int]] = []

    while frontier:
        current_id, via_link, depth = frontier.pop(0)
        if depth >= max_hops:
            continue

        placeholders = ""
        params: list = [current_id, current_id]
        if link_types:
            placeholders = f"AND link_type IN ({','.join('?' * len(link_types))})"
            params.extend(link_types)

        rows = conn.execute(
            f"""
            SELECT CASE WHEN from_id = ? THEN to_id ELSE from_id END AS neighbor_id,
                   link_type
              FROM knowledge_links
             WHERE (from_id = ? OR to_id = ?)
               {placeholders}
            """,
            [current_id] + params,
        ).fetchall()

        for neighbor_id, link_type in rows:
            if neighbor_id not in visited:
                visited.add(neighbor_id)
                results.append((neighbor_id, link_type, depth + 1))
                frontier.append((neighbor_id, link_type, depth + 1))

    return results

Temporal Tiers and Decay

Three tiers govern how long a memory is retained before becoming eligible for archival:

TierDefault retentionUse case
short7 daysEpisodic work logs, daily session summaries
medium90 daysActive project decisions, current-sprint knowledge
longIndefinitePreferences, architectural facts, core workflow recipes

Archival is soft-deletion: memories move to an archived=1 state and are excluded from search results. They remain recoverable for 30 days before permanent deletion. This matches the copilot-mem production behavior — the 86 archived memories are a recoverable buffer against accidental over-pruning.

The decay process runs as a scheduled job:

from datetime import datetime, timedelta, timezone
import sqlite3


def run_decay(db_path: str, dry_run: bool = False) -> dict[str, int]:
    """
    Archive memories that have passed their expiration or temporal tier retention.
    Returns counts of archived memories by tier.
    """
    now = datetime.now(timezone.utc)
    tier_cutoffs = {
        "short":  now - timedelta(days=7),
        "medium": now - timedelta(days=90),
        # long tier: only expires if expires_at is explicitly set
    }

    counts: dict[str, int] = {"short": 0, "medium": 0, "explicit": 0}
    conn = sqlite3.connect(db_path)

    try:
        for tier, cutoff in tier_cutoffs.items():
            rows = conn.execute(
                """
                SELECT id, key, temporal_tier FROM memories
                 WHERE archived = 0
                   AND temporal_tier = ?
                   AND created_at < ?
                   AND importance < 4  -- preserve high-importance even if tier suggests decay
                """,
                (tier, cutoff.isoformat()),
            ).fetchall()
            counts[tier] = len(rows)
            if not dry_run:
                conn.execute(
                    "UPDATE memories SET archived = 1 WHERE id IN ({})".format(
                        ",".join("?" * len(rows))
                    ),
                    [r[0] for r in rows],
                )

        # Explicit expiration
        expired = conn.execute(
            """
            SELECT id FROM memories
             WHERE archived = 0
               AND expires_at IS NOT NULL
               AND expires_at < ?
            """,
            (now.isoformat(),),
        ).fetchall()
        counts["explicit"] = len(expired)
        if not dry_run and expired:
            conn.execute(
                "UPDATE memories SET archived = 1 WHERE id IN ({})".format(
                    ",".join("?" * len(expired))
                ),
                [r[0] for r in expired],
            )

        if not dry_run:
            conn.commit()
    finally:
        conn.close()

    return counts

The importance < 4 guard is load-bearing. A memory at importance 5 (critical) should not decay out of the store just because it is a short-tier episodic entry. An example: a critical architectural finding from yesterday's session should persist even if it was recorded as episodic with tier: short. The importance override prevents the decay clock from erasing facts that still matter.

30.6 Session Persistence: JSONL Transcripts, Checkpoint Files, State Recovery on Resume

How Claude Code Persists Sessions

Every session in Claude Code is recorded as a JSONL file in ~/.claude/sessions/. Each line is a complete JSON object representing one event in the session: a user message, an assistant turn, a tool call, a tool result. The format is append-only — lines are never edited after being written.

~/.claude/sessions/
├── <session-uuid>.jsonl           # full transcript, one event per line
└── ...

~/.claude/projects/<project-hash>/
├── state/                         # agent-written state files
│   ├── state-1722117131.json
│   └── state-1722120600.json
└── ...

~/.claude/plans/                   # plan files from Plan tool
│   └── <plan-uuid>.md

~/.claude/tasks/<task-uuid>        # task files from TodoWrite

A JSONL session line looks like:

{
  "type": "tool_result",
  "timestamp": "2026-07-28T14:32:11.421Z",
  "tool_name": "Read",
  "tool_use_id": "toolu_01XYZ",
  "content": [{"type": "text", "text": "...file contents..."}],
  "session_id": "sess_01ABC"
}

The session UUID links all events in a session. The harness uses it for --resume and --continue flags that reload the conversation history from the JSONL transcript rather than requiring the user to reconstruct it manually.

Building a Recovery Reader

When an agent fails mid-task — a crash, a timeout, a context compaction that went wrong — the most reliable recovery mechanism reads the JSONL transcript to reconstruct what state was in place before the failure:

from __future__ import annotations

import json
from pathlib import Path
from typing import Iterator


def iter_session_events(session_path: Path) -> Iterator[dict]:
    """Yield parsed events from a JSONL session transcript."""
    with session_path.open() as f:
        for line in f:
            line = line.strip()
            if line:
                yield json.loads(line)


def extract_tool_results(
    session_path: Path,
    tool_name: str,
) -> list[dict]:
    """
    Extract all results for a specific tool from a session transcript.
    Useful for recovering what files were read, what commands ran, etc.
    """
    results = []
    for event in iter_session_events(session_path):
        if event.get("type") == "tool_result" and event.get("tool_name") == tool_name:
            results.append(event)
    return results


def find_latest_state_file(project_hash: str) -> Path | None:
    """
    Return the most recently written state file for a project.
    The project hash is derived from the working directory path.
    """
    state_dir = Path.home() / ".claude" / "projects" / project_hash / "state"
    if not state_dir.exists():
        return None
    candidates = sorted(state_dir.glob("*.json"), key=lambda p: p.stat().st_mtime)
    return candidates[-1] if candidates else None


def recover_session_state(
    session_uuid: str,
    project_hash: str,
) -> dict:
    """
    Attempt to recover session state from both JSONL transcript and state files.
    Returns a dict describing what was found and the recommended resume point.
    """
    sessions_dir = Path.home() / ".claude" / "sessions"
    transcript_path = sessions_dir / f"{session_uuid}.jsonl"

    recovery: dict = {
        "session_uuid": session_uuid,
        "transcript_found": transcript_path.exists(),
        "state_file": None,
        "last_tool_calls": [],
        "last_assistant_message": None,
    }

    if transcript_path.exists():
        events = list(iter_session_events(transcript_path))
        # Most recent tool calls (last 5)
        tool_calls = [e for e in events if e.get("type") == "tool_use"]
        recovery["last_tool_calls"] = tool_calls[-5:]
        # Most recent assistant text
        assistant = [e for e in events if e.get("role") == "assistant"]
        if assistant:
            last = assistant[-1]
            content = last.get("content", [])
            texts = [b["text"] for b in content if b.get("type") == "text"]
            recovery["last_assistant_message"] = " ".join(texts)[:500]

    state_path = find_latest_state_file(project_hash)
    if state_path:
        try:
            recovery["state_file"] = json.loads(state_path.read_text())
        except json.JSONDecodeError:
            recovery["state_file"] = {"error": "parse failed", "path": str(state_path)}

    return recovery

The Resume Contract

When claude --resume <session-uuid> is used, the harness reloads the JSONL transcript into the conversation history and presents the model with the reconstituted context. The model sees the full prior turn history as if the session had never ended — subject to the context window limit. If the transcript is too large, the harness compresses it before reloading, which is why state files matter: the compression may lose the transcript detail, but the state file remains intact as a recovery anchor.

For long-running agents, the recommended pattern is:

  1. Write state files at task boundaries (not just on crash)
  2. Use meaningful file names with timestamps so the most recent is recoverable
  3. Design state files to be self-describing — include enough context that the file alone is sufficient to reconstruct the task without the transcript

from __future__ import annotations

import math
import sqlite3
import uuid
from dataclasses import dataclass, field
from datetime import datetime, timezone
from pathlib import Path
from typing import Optional


DB_PATH = Path.home() / ".claude" / "memory-agent" / "memories.db"
SCHEMA_PATH = Path(__file__).parent / "schema.sql"


def get_conn() -> sqlite3.Connection:
    DB_PATH.parent.mkdir(parents=True, exist_ok=True)
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    # Apply schema if tables don't exist
    if not conn.execute(
        "SELECT name FROM sqlite_master WHERE type='table' AND name='memories'"
    ).fetchone():
        conn.executescript(SCHEMA_PATH.read_text())
        conn.commit()
    return conn


@dataclass
class MemoryRecord:
    id: str
    type: str
    category: str
    key: str
    value: str
    importance: int
    temporal_tier: str
    project: Optional[str]
    access_count: int
    last_accessed: Optional[str]
    created_at: str
    fts_rank: float = 0.0


WEIGHTS = {
    "query_match": 0.35,
    "importance":  0.20,
    "recency":     0.15,
    "frequency":   0.10,
    "project_match": 0.10,
    "type_affinity": 0.05,
    "temporal_tier": 0.05,
}

TIER_SCORES = {"long": 1.0, "medium": 0.6, "short": 0.2}
TYPE_AFFINITY = {
    "workflow": {"procedural": 1.0, "semantic": 0.4, "episodic": 0.1},
    "fact":     {"semantic":   1.0, "procedural": 0.4, "episodic": 0.2},
    "default":  {"semantic":   0.7, "procedural": 0.7, "episodic": 0.3},
}


def _score(
    m: MemoryRecord,
    current_project: Optional[str],
    query_intent: str,
    now: datetime,
) -> float:
    f_query = 1.0 / (1.0 + abs(m.fts_rank))
    f_importance = (m.importance - 1) / 4.0

    ref = m.last_accessed or m.created_at
    try:
        ref_dt = datetime.fromisoformat(ref)
        if ref_dt.tzinfo is None:
            ref_dt = ref_dt.replace(tzinfo=timezone.utc)
        age_days = (now - ref_dt).total_seconds() / 86400.0
    except (ValueError, TypeError):
        age_days = 365.0
    f_recency = math.exp(-age_days * math.log(2) / 30.0)

    f_frequency = min(math.log1p(m.access_count) / math.log1p(100), 1.0)

    if current_project and m.project:
        f_project = 1.0 if m.project == current_project else 0.0
    elif m.project is None:
        f_project = 0.5
    else:
        f_project = 0.3

    affinity = TYPE_AFFINITY.get(query_intent, TYPE_AFFINITY["default"])
    f_type = affinity.get(m.type, 0.3)
    f_tier = TIER_SCORES.get(m.temporal_tier, 0.2)

    return round(
        WEIGHTS["query_match"]   * f_query
        + WEIGHTS["importance"]  * f_importance
        + WEIGHTS["recency"]     * f_recency
        + WEIGHTS["frequency"]   * f_frequency
        + WEIGHTS["project_match"] * f_project
        + WEIGHTS["type_affinity"] * f_type
        + WEIGHTS["temporal_tier"] * f_tier,
        4,
    )


def search(
    query: str,
    project: Optional[str] = None,
    query_intent: str = "default",
    limit: int = 10,
) -> list[dict]:
    conn = get_conn()
    now = datetime.now(timezone.utc)

    # FTS5 search — returns rowid and rank
    rows = conn.execute(
        """
        SELECT m.id, m.type, m.category, m.key, m.value,
               m.importance, m.temporal_tier, m.project,
               m.access_count, m.last_accessed, m.created_at,
               f.rank AS fts_rank
          FROM memories_fts f
          JOIN memories m ON m.rowid = f.rowid
         WHERE memories_fts MATCH ?
           AND m.archived = 0
         ORDER BY f.rank
         LIMIT 50
        """,
        (query,),
    ).fetchall()

    records = [
        MemoryRecord(
            id=r["id"], type=r["type"], category=r["category"],
            key=r["key"], value=r["value"], importance=r["importance"],
            temporal_tier=r["temporal_tier"], project=r["project"],
            access_count=r["access_count"], last_accessed=r["last_accessed"],
            created_at=r["created_at"], fts_rank=r["fts_rank"] or 0.0,
        )
        for r in rows
    ]

    scored = sorted(
        [(m, _score(m, project, query_intent, now)) for m in records],
        key=lambda x: x[1],
        reverse=True,
    )[:limit]

    # Update access_count and last_accessed for returned memories
    ids = [m.id for m, _ in scored]
    if ids:
        conn.execute(
            f"""
            UPDATE memories
               SET access_count = access_count + 1,
                   last_accessed = ?
             WHERE id IN ({','.join('?' * len(ids))})
            """,
            [now.isoformat()] + ids,
        )
        conn.commit()

    return [
        {"id": m.id, "key": m.key, "value": m.value, "score": score,
         "type": m.type, "category": m.category, "importance": m.importance}
        for m, score in scored
    ]


def save(
    key: str,
    value: str,
    memory_type: str = "semantic",
    category: str = "fact",
    importance: int = 3,
    temporal_tier: str = "long",
    project: Optional[str] = None,
    tags: Optional[list[str]] = None,
    expires_at: Optional[str] = None,
) -> str:
    conn = get_conn()
    now = datetime.now(timezone.utc).isoformat()
    memory_id = str(uuid.uuid4())

    conn.execute(
        """
        INSERT INTO memories
            (id, type, category, key, value, importance, temporal_tier,
             project, tags, access_count, created_at, expires_at, archived)
        VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, 0, ?, ?, 0)
        """,
        (
            memory_id, memory_type, category, key, value, importance,
            temporal_tier, project,
            __import__("json").dumps(tags or []),
            now, expires_at,
        ),
    )
    # Keep FTS index in sync
    conn.execute(
        "INSERT INTO memories_fts (rowid, key, value) "
        "SELECT rowid, key, value FROM memories WHERE id = ?",
        (memory_id,),
    )
    conn.commit()
    return memory_id


def link(from_id: str, to_id: str, link_type: str) -> str:
    conn = get_conn()
    link_id = str(uuid.uuid4())
    conn.execute(
        "INSERT INTO knowledge_links (id, from_id, to_id, link_type, created_at) "
        "VALUES (?, ?, ?, ?, ?)",
        (link_id, from_id, to_id, link_type, datetime.now(timezone.utc).isoformat()),
    )
    conn.commit()
    return link_id


def decay(dry_run: bool = False) -> dict[str, int]:
    from datetime import timedelta
    conn = get_conn()
    now = datetime.now(timezone.utc)
    counts: dict[str, int] = {}

    for tier, days in [("short", 7), ("medium", 90)]:
        cutoff = (now - timedelta(days=days)).isoformat()
        rows = conn.execute(
            "SELECT id FROM memories WHERE archived=0 AND temporal_tier=? "
            "AND created_at<? AND importance<4",
            (tier, cutoff),
        ).fetchall()
        counts[tier] = len(rows)
        if not dry_run and rows:
            conn.execute(
                f"UPDATE memories SET archived=1 WHERE id IN "
                f"({','.join('?' * len(rows))})",
                [r["id"] for r in rows],
            )

    # Explicit expires_at
    expired = conn.execute(
        "SELECT id FROM memories WHERE archived=0 AND expires_at IS NOT NULL "
        "AND expires_at<?",
        (now.isoformat(),),
    ).fetchall()
    counts["explicit"] = len(expired)
    if not dry_run and expired:
        conn.execute(
            f"UPDATE memories SET archived=1 WHERE id IN "
            f"({','.join('?' * len(expired))})",
            [r["id"] for r in expired],
        )

    if not dry_run:
        conn.commit()
    conn.close()
    return counts


def stats() -> dict:
    conn = get_conn()
    total = conn.execute("SELECT COUNT(*) FROM memories WHERE archived=0").fetchone()[0]
    by_type = {
        r["type"]: r["cnt"]
        for r in conn.execute(
            "SELECT type, COUNT(*) AS cnt FROM memories WHERE archived=0 GROUP BY type"
        ).fetchall()
    }
    by_tier = {
        r["temporal_tier"]: r["cnt"]
        for r in conn.execute(
            "SELECT temporal_tier, COUNT(*) AS cnt FROM memories "
            "WHERE archived=0 GROUP BY temporal_tier"
        ).fetchall()
    }
    links = conn.execute("SELECT COUNT(*) FROM knowledge_links").fetchone()[0]
    archived = conn.execute("SELECT COUNT(*) FROM memories WHERE archived=1").fetchone()[0]
    conn.close()
    return {
        "total": total,
        "by_type": by_type,
        "by_tier": by_tier,
        "knowledge_links": links,
        "archived": archived,
    }

server.py

#!/usr/bin/env python3
"""
Memory MCP server — stdio transport.
Exposes: search_memory, save_memory, link_memories, decay_memories, get_session_stats
"""
from __future__ import annotations

import json
import sys
from typing import Any

import store


def handle(request: dict) -> dict:
    method = request.get("method", "")
    req_id = request.get("id")
    params = request.get("params", {})

    if method == "initialize":
        return {
            "jsonrpc": "2.0", "id": req_id,
            "result": {
                "protocolVersion": "2024-11-05",
                "serverInfo": {"name": "memory-agent", "version": "1.0.0"},
                "capabilities": {"tools": {}},
            },
        }

    if method == "tools/list":
        return {
            "jsonrpc": "2.0", "id": req_id,
            "result": {"tools": [
                {
                    "name": "search_memory",
                    "description": "Search memories by keyword. Returns top matches ranked by 7-factor relevance score.",
                    "inputSchema": {
                        "type": "object",
                        "properties": {
                            "query": {"type": "string", "description": "Search query"},
                            "project": {"type": "string", "description": "Filter by project context"},
                            "intent": {"type": "string", "enum": ["workflow", "fact", "default"], "description": "Query intent for type affinity scoring"},
                            "limit": {"type": "integer", "default": 10},
                        },
                        "required": ["query"],
                    },
                },
                {
                    "name": "save_memory",
                    "description": "Save a new memory to the store.",
                    "inputSchema": {
                        "type": "object",
                        "properties": {
                            "key": {"type": "string"},
                            "value": {"type": "string"},
                            "type": {"type": "string", "enum": ["episodic", "semantic", "procedural"], "default": "semantic"},
                            "category": {"type": "string", "default": "fact"},
                            "importance": {"type": "integer", "minimum": 1, "maximum": 5, "default": 3},
                            "temporal_tier": {"type": "string", "enum": ["short", "medium", "long"], "default": "long"},
                            "project": {"type": "string"},
                        },
                        "required": ["key", "value"],
                    },
                },
                {
                    "name": "link_memories",
                    "description": "Create a knowledge link between two memories.",
                    "inputSchema": {
                        "type": "object",
                        "properties": {
                            "from_id": {"type": "string"},
                            "to_id": {"type": "string"},
                            "link_type": {"type": "string", "enum": ["related_to", "evolved_from", "caused_by", "part_of", "contradicts"]},
                        },
                        "required": ["from_id", "to_id", "link_type"],
                    },
                },
                {
                    "name": "decay_memories",
                    "description": "Archive memories past their temporal tier retention. Use dry_run=true to preview.",
                    "inputSchema": {
                        "type": "object",
                        "properties": {
                            "dry_run": {"type": "boolean", "default": True},
                        },
                    },
                },
                {
                    "name": "get_session_stats",
                    "description": "Return counts of memories by type, tier, and link counts.",
                    "inputSchema": {"type": "object", "properties": {}},
                },
            ]},
        }

    if method == "tools/call":
        tool = params.get("name")
        args: dict[str, Any] = params.get("arguments", {})

        try:
            if tool == "search_memory":
                results = store.search(
                    query=args["query"],
                    project=args.get("project"),
                    query_intent=args.get("intent", "default"),
                    limit=args.get("limit", 10),
                )
                text = json.dumps(results, indent=2)

            elif tool == "save_memory":
                mem_id = store.save(
                    key=args["key"],
                    value=args["value"],
                    memory_type=args.get("type", "semantic"),
                    category=args.get("category", "fact"),
                    importance=args.get("importance", 3),
                    temporal_tier=args.get("temporal_tier", "long"),
                    project=args.get("project"),
                )
                text = json.dumps({"id": mem_id, "status": "saved"})

            elif tool == "link_memories":
                link_id = store.link(args["from_id"], args["to_id"], args["link_type"])
                text = json.dumps({"id": link_id, "status": "linked"})

            elif tool == "decay_memories":
                counts = store.decay(dry_run=args.get("dry_run", True))
                text = json.dumps({"archived": counts, "dry_run": args.get("dry_run", True)})

            elif tool == "get_session_stats":
                text = json.dumps(store.stats(), indent=2)

            else:
                raise ValueError(f"Unknown tool: {tool}")

            return {
                "jsonrpc": "2.0", "id": req_id,
                "result": {"content": [{"type": "text", "text": text}]},
            }

        except Exception as exc:
            return {
                "jsonrpc": "2.0", "id": req_id,
                "result": {"content": [{"type": "text", "text": f"Error: {exc}"}], "isError": True},
            }

    return {"jsonrpc": "2.0", "id": req_id, "result": {}}


def main() -> None:
    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue
        try:
            request = json.loads(line)
        except json.JSONDecodeError:
            continue
        response = handle(request)
        sys.stdout.write(json.dumps(response) + "\n")
        sys.stdout.flush()


if __name__ == "__main__":
    main()
