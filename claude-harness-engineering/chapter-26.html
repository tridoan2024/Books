Chapter 26: Implementing the Tool Layer

"The tool layer is where your harness earns its reputation. Get the schema wrong and the model thrashes. Return too much data and you burn the context budget. Get it right and the model moves with precision."

26.1 Tool Interface: Name, Description, InputSchema, Execute

Every tool in a harness is a contract with four parts. Not three, not five — four. If you are coming from Claude Code's sdk-tools.d.ts, you recognize this shape immediately:

from __future__ import annotations

from abc import ABC, abstractmethod
from typing import Any

from pydantic import BaseModel


class ToolResult(BaseModel):
    """Base type for all tool results."""
    pass


class Tool(ABC):
    """
    The four-part contract every tool must satisfy.
    """

    @property
    @abstractmethod
    def name(self) -> str:
        """
        Unique identifier used in tool_use blocks.
        The model calls tools by this name — treat it as an API surface.
        Rename it and you break existing transcripts.
        """
        ...

    @property
    @abstractmethod
    def description(self) -> str:
        """
        Shown to the model in the system prompt.
        Every character costs tokens every turn.
        Write for the model, not for documentation.
        """
        ...

    @property
    @abstractmethod
    def input_schema(self) -> dict[str, Any]:
        """
        JSON Schema for the tool's input.
        The harness validates the model's tool_use input against this before
        calling execute(). Validation errors go back to the model as
        InputValidationError — the model uses the error to self-correct.
        """
        ...

    @abstractmethod
    async def execute(self, input: dict[str, Any]) -> ToolResult:
        """
        Execute the tool with pre-validated input.
        MUST NOT throw. Return error in the result instead.
        """
        ...

That is the complete interface. But the four parts are not equally important, and the way you implement each one determines whether your harness is usable or frustrating.

The Description Trap

The description is the part most engineers get wrong on the first pass. They write it like documentation — complete, thorough, with examples. Then they benchmark their harness and notice system prompt costs are crushing the per-turn budget.

Here is the rule: descriptions are context budget, not documentation. Every token in a tool description is paid on every API call for the lifetime of the session. A 400-token description for a tool used once per session costs 40,000 tokens over 100 turns. A 50-token description costs 5,000.

The practical target:

Tool usage patternTarget description length
Used on most turns (Read, Bash)≤100 tokens
Used occasionally (Edit, Write)≤80 tokens
Used rarely, should be deferred≤30 tokens (stub for registry)
Deferred tool (loaded on demand)Full description loaded on demand

Write descriptions that answer one question: "What does this tool do, when should I use it, and what are the gotchas?" That is three things, and you should need 50–150 words to cover them.

Bad description (what not to do):

Read files from the local filesystem. Supports text files (.txt, .md, .ts, .py, .go, 
.rs, .json, .yaml and more), image files (.jpg, .jpeg, .png, .gif, .webp), PDF files 
(.pdf, up to 10 pages inline, larger PDFs split into parts), and Jupyter notebooks 
(.ipynb). For text files, you can paginate with offset (zero-based line number) and 
limit (number of lines). For PDFs, use the pages parameter with a range like "1-5". 
Returns a discriminated union on the type field. If you read the same file twice 
without modification, returns file_unchanged to save tokens...
[continues for 300 more tokens]

Good description:

Read a file from disk. Handles text, images (returned as base64), PDFs (use pages 
"1-5" for large files), and .ipynb notebooks. Repeat reads of unchanged files return 
file_unchanged — no token cost. Always use absolute paths.

Forty-three words. The model knows what the tool does, knows about the optimization hint, and knows the one constraint (absolute paths). That is enough.

The Name Contract

Tool names are permanent. Once a model learns to call ReadFile to read files, renaming it to FileRead breaks every cached transcript, every few-shot example in your system prompt, and every integration test that checks tool calls by name.

Choose names that match the Claude Code convention: PascalCase, verb-object for action tools (ReadFile, EditFile), noun for query tools (TaskList, CronList). If you are building a harness that will call Claude Code's own API in the future, avoid names that shadow Claude Code's tool names — Bash, Read, Edit, Write, Agent, Glob, Grep, WebFetch, WebSearch, and the full list in Appendix A.

The Input Schema Contract

The input schema drives three things:

  1. Model behavior — the schema tells the model what parameters to provide and what constraints they have. A schema with maximum: 30000 on a timeout field tells the model not to request a 5-minute timeout.
  1. Harness validation — the harness validates the model's tool_use.input against the schema before calling execute(). Invalid input never reaches the executor.
  1. Error message quality — when validation fails, the error message comes from the schema validator. A schema with description fields on each property produces validation errors that name the field and explain what was expected. A schema without descriptions produces generic errors like "value is not of type 'string'".

Always include "additionalProperties": false and an explicit "required" array. These two settings do more for model reliability than any amount of prompt engineering.

26.2 Schema Validation: Errors That Guide the Model

Schema validation is not a reject-or-pass gate. It is a feedback mechanism. When the model sends malformed input, the harness returns a structured error, and the model uses that error to fix its next attempt. This is the self-correction loop. Your job is to make the error messages good enough that one round of feedback is sufficient.

The Validator

Use jsonschema for validation. It is the reference implementation, well-maintained, and produces verbose error messages when configured correctly:

from __future__ import annotations

import json
from typing import Any

import jsonschema
from jsonschema import Draft7Validator, ValidationError


class SchemaValidator:
    """
    Validate tool inputs and produce model-readable error messages.
    """

    def __init__(self, schema: dict[str, Any]) -> None:
        self._validator = Draft7Validator(schema)

    def validate(self, input: dict[str, Any]) -> list[str]:
        """
        Validate input against schema.
        Returns a list of human-readable error strings.
        Empty list means valid.
        """
        errors = sorted(
            self._validator.iter_errors(input),
            key=lambda e: list(e.path),
        )
        return [self._format_error(e) for e in errors]

    def _format_error(self, error: ValidationError) -> str:
        """
        Format a validation error for model consumption.
        The model reads this and adjusts its next call.
        Be specific: name the field, state the constraint, give the received value.
        """
        field_path = " -> ".join(str(p) for p in error.path) if error.path else "input"

        if error.validator == "required":
            missing = error.validator_value
            return f"Missing required field(s): {missing}. Field path: {field_path}"

        if error.validator == "type":
            expected = error.validator_value
            received = type(error.instance).__name__
            return (
                f"Field '{field_path}': expected {expected}, got {received} "
                f"(value: {json.dumps(error.instance)[:100]})"
            )

        if error.validator == "maximum":
            limit = error.validator_value
            received = error.instance
            return (
                f"Field '{field_path}': value {received} exceeds maximum {limit}"
            )

        if error.validator == "minimum":
            limit = error.validator_value
            received = error.instance
            return (
                f"Field '{field_path}': value {received} is below minimum {limit}"
            )

        if error.validator == "enum":
            allowed = error.validator_value
            received = error.instance
            return (
                f"Field '{field_path}': '{received}' is not one of the allowed values: "
                f"{allowed}"
            )

        if error.validator == "additionalProperties":
            extra = set(error.instance.keys()) - set(
                error.schema.get("properties", {}).keys()
            )
            return (
                f"Unknown field(s): {sorted(extra)}. "
                f"Allowed fields: {sorted(error.schema.get('properties', {}).keys())}"
            )

        # Fallback: include the full error message — it is usually readable
        return f"Field '{field_path}': {error.message}"

Wrapping the Validation in the Dispatch Layer

The harness control loop validates every tool_use block before dispatching:

from __future__ import annotations

from dataclasses import dataclass
from typing import Any


@dataclass
class ToolUseBlock:
    id: str
    name: str
    input: dict[str, Any]


@dataclass
class ToolResultBlock:
    tool_use_id: str
    content: str
    is_error: bool = False


class ToolDispatcher:
    """
    Route tool_use blocks to executors, validate input, return tool_result.
    """

    def __init__(self, registry: "ToolRegistry") -> None:
        self._registry = registry

    async def dispatch(self, block: ToolUseBlock) -> ToolResultBlock:
        # Step 1: Is this tool registered?
        tool = self._registry.get(block.name)
        if tool is None:
            # Check if it is a deferred tool with a known stub
            if self._registry.is_deferred(block.name):
                return ToolResultBlock(
                    tool_use_id=block.id,
                    content=(
                        f"InputValidationError: Tool '{block.name}' schema is not loaded. "
                        f"Call ToolSearch to load it before use."
                    ),
                    is_error=True,
                )
            return ToolResultBlock(
                tool_use_id=block.id,
                content=f"Unknown tool: '{block.name}'",
                is_error=True,
            )

        # Step 2: Validate input against schema
        validator = SchemaValidator(tool.input_schema)
        errors = validator.validate(block.input)
        if errors:
            error_list = "\n".join(f"  - {e}" for e in errors)
            return ToolResultBlock(
                tool_use_id=block.id,
                content=f"InputValidationError for '{block.name}':\n{error_list}",
                is_error=True,
            )

        # Step 3: Execute — never throws, returns ToolResult
        result = await tool.execute(block.input)
        return ToolResultBlock(
            tool_use_id=block.id,
            content=result.render(),
        )

The dispatch layer enforces two contracts: tools are never called with invalid input, and tools never throw (if an executor raises an exception, it is caught here and returned as an error result). The model deals with structured results, not stack traces.

Why Not Pydantic for Schema Generation?

Pydantic's .model_json_schema() is tempting for input validation — define a BaseModel, call .model_validate(), done. The problem is that Pydantic's error messages are not designed for LLM consumption. They are designed for developers. A Pydantic ValidationError surfaces as:

1 validation error for BashInput
timeout
  Input should be less than or equal to 600000 [type=less_than_equal, input_value=999999, input_type=int]

This is readable, but it mixes Python type names and validator identifiers into the error text. The model can parse it, but you have given up control over the message format.

The cleaner approach: use Pydantic for your own code's data structures, but generate the JSON Schema from Pydantic models and validate against that schema with jsonschema. You get Pydantic's ergonomics for defining schemas and jsonschema's validation with your own error formatting:

from pydantic import BaseModel, Field


class BashInput(BaseModel):
    command: str = Field(description="Shell command to execute")
    timeout: int | None = Field(
        default=None,
        ge=1,
        le=600_000,
        description="Timeout in milliseconds. Max 600000 (10 minutes).",
    )
    description: str | None = Field(
        default=None,
        description="Human-readable label shown in permission UI and audit logs",
    )
    run_in_background: bool = Field(
        default=False,
        description="Return immediately with task ID; poll TaskOutput for result",
    )


# Generate the JSON Schema from the Pydantic model
BASH_SCHEMA = BashInput.model_json_schema()
# Then validate tool_use inputs against BASH_SCHEMA with SchemaValidator above

26.3 Tool Result Types: Minimal Is Correct

A tool result is not a comprehensive report. It is the answer to exactly the question the model asked. The discipline is: return what the model needs to continue, nothing more.

Claude Code's result taxonomy covers four cases:

from __future__ import annotations

from typing import Literal

from pydantic import BaseModel


class TextResult(BaseModel):
    type: Literal["text"] = "text"
    text: str

    def render(self) -> str:
        return self.text


class ImageResult(BaseModel):
    type: Literal["image"] = "image"
    base64: str
    media_type: Literal["image/jpeg", "image/png", "image/gif", "image/webp"]

    def render(self) -> str:
        # The harness encodes this as a multimodal content block, not text.
        # This render() is for text-mode fallback only.
        return f"[image/{self.media_type}, {len(self.base64)} base64 chars]"


class StructuredResult(BaseModel):
    type: Literal["structured"] = "structured"
    data: dict

    def render(self) -> str:
        import json
        return json.dumps(self.data, indent=2)


class ErrorResult(BaseModel):
    type: Literal["error"] = "error"
    error: str
    # Optional: structured hint for self-correction
    hint: str | None = None

    def render(self) -> str:
        if self.hint:
            return f"{self.error}\nHint: {self.hint}"
        return self.error


ToolResult = TextResult | ImageResult | StructuredResult | ErrorResult

Token Budget in Results

The Read tool's file_unchanged response is the canonical example of token-budget awareness in results. When a file has not changed, the harness returns 10 tokens instead of 10,000. The model understands this result and skips the content without re-processing it.

Every tool you implement should have an equivalent. Ask: "What is the minimal response that lets the model proceed?" A Bash tool that returns the full stdout of a 10,000-line log file is technically correct. It is also burning the context window. Consider:

async def execute(self, input: dict[str, Any]) -> ToolResult:
    result = await run_command(input["command"], timeout=input.get("timeout"))

    stdout = result.stdout
    stderr = result.stderr

    # If stdout is large, truncate and annotate
    MAX_STDOUT_CHARS = 20_000
    truncated = False
    if len(stdout) > MAX_STDOUT_CHARS:
        stdout = stdout[:MAX_STDOUT_CHARS]
        truncated = True

    output = stdout
    if stderr:
        output += f"\n[stderr]: {stderr[:2000]}"
    if truncated:
        output += f"\n[stdout truncated at {MAX_STDOUT_CHARS} chars — use grep or head to filter]"

    return TextResult(text=output)

The truncation annotation is load-bearing. Without it, the model might believe it saw the full output and make decisions based on incomplete data. The hint tells it exactly what to do next.

Structured Results and the Model's Token Budget

For tools that return structured data — task lists, file metadata, search results — use StructuredResult with a minimal schema. Do not return every field from your database row. Return the fields the model will actually use:

# Too much — the model pays to read every field, uses two of them
return StructuredResult(data={
    "id": task.id,
    "subject": task.subject,
    "description": task.description,  # often 500+ tokens
    "created_at": task.created_at.isoformat(),
    "updated_at": task.updated_at.isoformat(),
    "owner": task.owner,
    "metadata": task.metadata,        # arbitrary blob
    "status": task.status,
    "blockedBy": task.blocked_by,
})

# Right — return what drives the next decision
return StructuredResult(data={
    "id": task.id,
    "subject": task.subject,
    "status": task.status,
    "blockedBy": task.blocked_by,
})

The description is not in the summary view for the same reason TaskList in Claude Code returns a summary: the model uses the list to decide which task to work on, not to process each task's description. If it needs the description, it calls TaskGet(id=...).

26.4 Async Execution: Background Tools

Some tools take longer than the model should wait. Compiling a large codebase, running a full test suite, fetching and processing a large dataset — these can take minutes. The pattern for handling them is the same one Claude Code uses for background Bash: return immediately with a task ID, let the model poll or subscribe for completion.

from __future__ import annotations

import asyncio
import time
from dataclasses import dataclass, field
from enum import Enum
from typing import Any
from uuid import uuid4


class TaskStatus(str, Enum):
    PENDING = "pending"
    RUNNING = "running"
    COMPLETED = "completed"
    FAILED = "failed"
    CANCELLED = "cancelled"


@dataclass
class BackgroundTask:
    id: str
    status: TaskStatus = TaskStatus.PENDING
    result: str | None = None
    error: str | None = None
    started_at: float = field(default_factory=time.time)
    completed_at: float | None = None
    _cancel_event: asyncio.Event = field(default_factory=asyncio.Event)

    def cancel(self) -> None:
        self._cancel_event.set()

    def is_cancelled(self) -> bool:
        return self._cancel_event.is_set()


class BackgroundTaskStore:
    """
    In-memory store for background task state.
    In production, back this with a persistent store
    (SQLite, Redis) for session-resume support.
    """

    def __init__(self) -> None:
        self._tasks: dict[str, BackgroundTask] = {}

    def create(self) -> BackgroundTask:
        task = BackgroundTask(id=str(uuid4())[:8])
        self._tasks[task.id] = task
        return task

    def get(self, task_id: str) -> BackgroundTask | None:
        return self._tasks.get(task_id)

    def cancel(self, task_id: str) -> bool:
        task = self._tasks.get(task_id)
        if task and task.status in (TaskStatus.PENDING, TaskStatus.RUNNING):
            task.cancel()
            task.status = TaskStatus.CANCELLED
            return True
        return False

A background tool implementation follows this pattern:

class BackgroundBashTool(Tool):
    name = "Bash"
    description = (
        "Execute a shell command. Set run_in_background=true for long-running commands — "
        "returns task_id immediately. Use TaskOutput(task_id) to get result, "
        "TaskStop(task_id) to cancel."
    )

    def __init__(self, task_store: BackgroundTaskStore) -> None:
        self._store = task_store

    @property
    def input_schema(self) -> dict[str, Any]:
        return {
            "type": "object",
            "properties": {
                "command": {"type": "string", "description": "Shell command"},
                "timeout": {
                    "type": "integer",
                    "minimum": 1,
                    "maximum": 600_000,
                    "description": "Timeout ms. Default 30000.",
                },
                "description": {
                    "type": "string",
                    "description": "Human-readable label for audit logs",
                },
                "run_in_background": {
                    "type": "boolean",
                    "default": False,
                    "description": "Return task_id immediately without waiting",
                },
            },
            "required": ["command"],
            "additionalProperties": False,
        }

    async def execute(self, input: dict[str, Any]) -> ToolResult:
        command = input["command"]
        timeout_ms = input.get("timeout", 30_000)
        run_in_background = input.get("run_in_background", False)

        if run_in_background:
            task = self._store.create()
            task.status = TaskStatus.RUNNING
            # Fire and forget — execution continues without blocking
            asyncio.create_task(
                self._run_and_store(task, command, timeout_ms)
            )
            return StructuredResult(data={
                "backgroundTaskId": task.id,
                "status": "running",
                "message": (
                    f"Command launched in background. "
                    f"Call TaskOutput(task_id='{task.id}') to get result."
                ),
            })

        # Foreground execution
        return await self._run_foreground(command, timeout_ms)

    async def _run_and_store(
        self, task: BackgroundTask, command: str, timeout_ms: int
    ) -> None:
        try:
            result = await asyncio.wait_for(
                asyncio.create_subprocess_shell(
                    command,
                    stdout=asyncio.subprocess.PIPE,
                    stderr=asyncio.subprocess.STDOUT,
                ),
                timeout=timeout_ms / 1000,
            )
            stdout, _ = await result.communicate()
            task.result = stdout.decode("utf-8", errors="replace")
            task.status = TaskStatus.COMPLETED
        except asyncio.TimeoutError:
            task.error = f"Command timed out after {timeout_ms}ms"
            task.status = TaskStatus.FAILED
        except Exception as exc:
            task.error = str(exc)
            task.status = TaskStatus.FAILED
        finally:
            task.completed_at = time.time()

    async def _run_foreground(
        self, command: str, timeout_ms: int
    ) -> ToolResult:
        try:
            proc = await asyncio.create_subprocess_shell(
                command,
                stdout=asyncio.subprocess.PIPE,
                stderr=asyncio.subprocess.PIPE,
            )
            stdout, stderr = await asyncio.wait_for(
                proc.communicate(),
                timeout=timeout_ms / 1000,
            )
            text = stdout.decode("utf-8", errors="replace")
            err = stderr.decode("utf-8", errors="replace")
            combined = text + (f"\n[stderr]: {err}" if err else "")
            return TextResult(text=combined[:20_000])
        except asyncio.TimeoutError:
            return ErrorResult(
                error=f"Command timed out after {timeout_ms}ms",
                hint="Increase timeout or use run_in_background=true",
            )
        except Exception as exc:
            return ErrorResult(error=str(exc))

The TaskOutput and TaskStop tools are thin wrappers over the same BackgroundTaskStore:

class TaskOutputTool(Tool):
    name = "TaskOutput"
    description = "Get output from a background task. Returns status and result when complete."

    def __init__(self, task_store: BackgroundTaskStore) -> None:
        self._store = task_store

    @property
    def input_schema(self) -> dict[str, Any]:
        return {
            "type": "object",
            "properties": {
                "task_id": {"type": "string", "description": "ID from backgroundTaskId"},
            },
            "required": ["task_id"],
            "additionalProperties": False,
        }

    async def execute(self, input: dict[str, Any]) -> ToolResult:
        task = self._store.get(input["task_id"])
        if task is None:
            return ErrorResult(
                error=f"No task found with id '{input['task_id']}'",
                hint="Task IDs are session-scoped and expire on session end",
            )
        return StructuredResult(data={
            "id": task.id,
            "status": task.status.value,
            "result": task.result,
            "error": task.error,
            "durationMs": (
                int((task.completed_at - task.started_at) * 1000)
                if task.completed_at else None
            ),
        })

26.5 Tool Composition: Tools That Call Tools

The most powerful harness architectures let tools compose. Claude Code does this in two places: the REPL tool registers new tools at runtime, and the Workflow tool spawns Agent tool calls. Both patterns are worth understanding before you implement them.

Why Not Just Call Tools Directly?

A tool that calls execute() on another tool directly creates a hidden dependency: both tools must be in the same process, the inner tool's execution does not go through the permission layer, and errors from the inner tool are caught by the outer tool rather than being returned to the model. You lose the safety net.

The correct pattern is indirect composition: the outer tool puts a request on the task queue or calls the harness control loop, which dispatches through the full stack including permission checks.

For simple compositions, a shared service is enough:

class ReadFileTool(Tool):
    """A tool that provides filesystem reads."""

    def __init__(self, file_service: "FileService") -> None:
        self._fs = file_service

    async def execute(self, input: dict[str, Any]) -> ToolResult:
        content = await self._fs.read(input["file_path"])
        return TextResult(text=content)


class GrepTool(Tool):
    """
    A tool that searches files. Internally uses FileService,
    not the ReadFileTool — composition at the service level,
    not at the tool level.
    """

    def __init__(self, file_service: "FileService") -> None:
        self._fs = file_service

    async def execute(self, input: dict[str, Any]) -> ToolResult:
        results = await self._fs.grep(
            pattern=input["pattern"],
            path=input.get("path", "."),
        )
        return TextResult(text="\n".join(results))

Both tools share FileService, but neither calls the other's execute(). The harness control loop decides which tool to call.

The REPL Pattern: Runtime Tool Registration

The REPL tool in Claude Code lets the model write JavaScript that registers new tools into the live tool registry. Your harness can implement the equivalent in Python:

class REPLTool(Tool):
    """
    In-process Python execution with access to the tool registry.
    The model can define new tools at runtime.
    """
    name = "REPL"
    description = (
        "Execute Python in a persistent in-process environment. "
        "Call register_tool(name, description, schema, fn) to add new tools this session."
    )

    def __init__(self, registry: "ToolRegistry") -> None:
        self._registry = registry
        self._globals: dict[str, Any] = {
            "register_tool": self._register_tool,
        }

    def _register_tool(
        self,
        name: str,
        description: str,
        schema: dict,
        fn: Any,  # async callable
    ) -> str:
        """Called from REPL-executed code to register a new tool."""

        class DynamicTool(Tool):
            # Capture by closure
            _name = name
            _desc = description
            _schema = schema
            _fn = staticmethod(fn)

            @property
            def name(self) -> str:
                return self._name

            @property
            def description(self) -> str:
                return self._desc

            @property
            def input_schema(self) -> dict:
                return self._schema

            async def execute(self, input: dict) -> ToolResult:
                try:
                    result = await self._fn(input)
                    return TextResult(text=str(result))
                except Exception as exc:
                    return ErrorResult(error=str(exc))

        self._registry.register(DynamicTool())
        return f"Tool '{name}' registered successfully"

    @property
    def input_schema(self) -> dict[str, Any]:
        return {
            "type": "object",
            "properties": {
                "code": {"type": "string", "description": "Python code to execute"},
            },
            "required": ["code"],
            "additionalProperties": False,
        }

    async def execute(self, input: dict[str, Any]) -> ToolResult:
        import io
        from contextlib import redirect_stdout

        buf = io.StringIO()
        try:
            with redirect_stdout(buf):
                exec(input["code"], self._globals)  # noqa: S102
            output = buf.getvalue()
            return TextResult(text=output or "(no output)")
        except Exception as exc:
            return ErrorResult(error=f"{type(exc).__name__}: {exc}")

The key insight: register_tool is injected into the REPL globals. The model writes register_tool("WeatherFetch", ...) in REPL code, and the tool becomes available in the same session without a harness restart. This is how you build extensible harnesses without redeployment.

26.6 Deferred Loading: ToolSearch Pattern

In a harness with 30+ tools, loading all tool descriptions into the system prompt at startup is expensive. A system prompt carrying 30 tool descriptions at 100 tokens each adds 3,000 tokens to every API call. Over a 100-turn session, that is 300,000 tokens of pure overhead.

The fix is deferred loading: tools are registered in a lightweight registry at startup, but their full schemas are not added to the system prompt until the model explicitly requests them.

The Registry

from __future__ import annotations

from dataclasses import dataclass, field
from typing import Any


@dataclass
class DeferredToolStub:
    """
    Minimal information about a deferred tool.
    Only this stub is shown in the system prompt at startup.
    Full schema is loaded on demand via ToolSearch.
    """
    name: str
    stub_description: str           # ≤30 words — enough to know when to search
    categories: list[str]           # index terms for ToolSearch matching
    full_tool: "Tool | None" = None # loaded on first ToolSearch hit


class ToolRegistry:
    def __init__(self) -> None:
        self._active: dict[str, "Tool"] = {}        # loaded, schema in system prompt
        self._deferred: dict[str, DeferredToolStub] = {}  # stubs only

    def register(self, tool: "Tool") -> None:
        """Register a tool as always-active (schema in system prompt)."""
        self._active[tool.name] = tool

    def register_deferred(
        self,
        tool: "Tool",
        stub_description: str,
        categories: list[str],
    ) -> None:
        """Register a tool as deferred — stub only until ToolSearch loads it."""
        self._deferred[tool.name] = DeferredToolStub(
            name=tool.name,
            stub_description=stub_description,
            categories=categories,
            full_tool=tool,
        )

    def get(self, name: str) -> "Tool | None":
        return self._active.get(name)

    def is_deferred(self, name: str) -> bool:
        return name in self._deferred

    def load_deferred(self, name: str) -> "Tool | None":
        """
        Move a deferred tool to active.
        Called by ToolSearch when the model requests a tool's schema.
        """
        stub = self._deferred.get(name)
        if stub and stub.full_tool:
            self._active[stub.name] = stub.full_tool
            del self._deferred[stub.name]
            return stub.full_tool
        return None

    def search(self, query: str) -> list[DeferredToolStub]:
        """
        Find deferred tools matching a natural language query.
        Simple implementation: check if any category or name substring matches.
        Production: use embeddings for semantic search.
        """
        query_lower = query.lower()
        matches = []
        for stub in self._deferred.values():
            score = 0
            for cat in stub.categories:
                if cat.lower() in query_lower or query_lower in cat.lower():
                    score += 2
            if query_lower in stub.name.lower():
                score += 3
            if query_lower in stub.stub_description.lower():
                score += 1
            if score > 0:
                matches.append((score, stub))
        matches.sort(key=lambda x: -x[0])
        return [stub for _, stub in matches[:5]]

The ToolSearch Tool

class ToolSearchTool(Tool):
    name = "ToolSearch"
    description = (
        "Load deferred tool schemas by query. Call this when you know a capability "
        "exists but its schema is not loaded. Returns full schemas for matched tools."
    )

    def __init__(self, registry: ToolRegistry) -> None:
        self._registry = registry

    @property
    def input_schema(self) -> dict[str, Any]:
        return {
            "type": "object",
            "properties": {
                "query": {
                    "type": "string",
                    "description": "Natural language description of the capability you need",
                },
            },
            "required": ["query"],
            "additionalProperties": False,
        }

    async def execute(self, input: dict[str, Any]) -> ToolResult:
        query = input["query"]
        matches = self._registry.search(query)

        if not matches:
            available = [
                f"{s.name}: {s.stub_description}"
                for s in self._registry._deferred.values()
            ]
            return TextResult(
                text=(
                    f"No tools found matching '{query}'.\n"
                    f"Available deferred tools:\n"
                    + "\n".join(f"  - {t}" for t in available)
                )
            )

        # Load the matched tools into the active registry
        loaded = []
        for stub in matches:
            tool = self._registry.load_deferred(stub.name)
            if tool:
                loaded.append({
                    "name": tool.name,
                    "description": tool.description,
                    "schema": tool.input_schema,
                })

        import json
        return TextResult(
            text=(
                f"Loaded {len(loaded)} tool(s). "
                f"You can now call them directly.\n\n"
                + json.dumps(loaded, indent=2)
            )
        )

System Prompt Integration

At startup, the system prompt includes only the active tools plus a deferred tool inventory:

def build_system_prompt(registry: ToolRegistry) -> str:
    sections = []

    # Active tools — full schema included
    sections.append("## Available Tools\n")
    for tool in registry._active.values():
        sections.append(f"### {tool.name}\n{tool.description}\n")

    # Deferred tool stubs — names and brief descriptions only
    if registry._deferred:
        sections.append(
            "\n## Additional Tools (deferred — call ToolSearch to load)\n"
            "These tools are available but their schemas are not loaded. "
            "Calling them directly will fail with InputValidationError. "
            "Use ToolSearch(query=...) to load their schemas.\n\n"
        )
        for stub in registry._deferred.values():
            sections.append(f"- **{stub.name}**: {stub.stub_description}\n")

    return "\n".join(sections)

The savings compound. A session that never uses scheduling tools — CronCreate, CronDelete, CronList, ScheduleWakeup — never pays for their descriptions. For tools with 200-word descriptions, deferring four scheduling tools saves ~800 tokens per turn, or 80,000 tokens over a 100-turn session.

26.7 Lab: Read, Edit, Write, Bash as a Reusable Tool Library

This lab assembles the four core filesystem and shell tools as a production-ready Python library. The goal is a set of tools you can drop into any harness with minimal adaptation.

"""
core_tools.py — Reusable Read, Edit, Write, Bash tool library.
Implements Claude Code's filesystem and shell tool semantics in Python.
"""
from __future__ import annotations

import asyncio
import difflib
import hashlib
import time
from pathlib import Path
from typing import Any

from pydantic import BaseModel, Field


# ─── Result types ────────────────────────────────────────────────────────────

class TextResult(BaseModel):
    type: str = "text"
    text: str

    def render(self) -> str:
        return self.text


class ErrorResult(BaseModel):
    type: str = "error"
    error: str
    hint: str | None = None

    def render(self) -> str:
        return f"Error: {self.error}" + (f"\nHint: {self.hint}" if self.hint else "")


ToolResult = TextResult | ErrorResult


# ─── Read ─────────────────────────────────────────────────────────────────────

class ReadTool:
    """
    Read files from the local filesystem.
    Handles text and binary files. Returns file_unchanged on repeat reads.
    Supports line-range pagination via offset/limit.
    """

    name = "Read"
    description = (
        "Read a file. Returns content with line numbers (cat -n format). "
        "Use offset/limit for large files. Repeat reads of unchanged files "
        "return file_unchanged — no token cost. Absolute paths only."
    )

    def __init__(self) -> None:
        # Track file state for deduplication: path → content hash
        self._seen: dict[str, str] = {}

    @property
    def input_schema(self) -> dict[str, Any]:
        return {
            "type": "object",
            "properties": {
                "file_path": {
                    "type": "string",
                    "description": "Absolute path to the file",
                },
                "offset": {
                    "type": "integer",
                    "minimum": 0,
                    "description": "Zero-based line number to start reading from",
                },
                "limit": {
                    "type": "integer",
                    "minimum": 1,
                    "maximum": 2000,
                    "description": "Number of lines to read. Max 2000.",
                },
            },
            "required": ["file_path"],
            "additionalProperties": False,
        }

    async def execute(self, input: dict[str, Any]) -> ToolResult:
        file_path = Path(input["file_path"])
        offset = input.get("offset", 0)
        limit = input.get("limit")

        if not file_path.is_absolute():
            return ErrorResult(
                error=f"Path must be absolute: {file_path}",
                hint="Use an absolute path starting with /",
            )

        if not file_path.exists():
            return ErrorResult(
                error=f"File not found: {file_path}",
                hint="Check the path with Bash(command='ls -la <directory>')",
            )

        if not file_path.is_file():
            return ErrorResult(
                error=f"Path is not a file: {file_path}",
                hint="Use Bash(command='ls <directory>') to list directory contents",
            )

        try:
            raw = file_path.read_bytes()
        except PermissionError:
            return ErrorResult(error=f"Permission denied: {file_path}")

        # Deduplication check
        content_hash = hashlib.sha256(raw).hexdigest()[:16]
        cache_key = str(file_path)
        if self._seen.get(cache_key) == content_hash:
            return TextResult(text=f"[file_unchanged: {file_path}]")
        self._seen[cache_key] = content_hash

        # Decode — handle binary gracefully
        try:
            text = raw.decode("utf-8")
        except UnicodeDecodeError:
            return ErrorResult(
                error=f"File is binary or non-UTF-8: {file_path}",
                hint="Binary files cannot be read as text",
            )

        lines = text.splitlines(keepends=True)
        total_lines = len(lines)

        # Apply pagination
        start = offset
        end = start + limit if limit else len(lines)
        page = lines[start:end]

        # Format with line numbers (cat -n style, 1-based)
        formatted = "".join(
            f"{start + i + 1}\t{line}" for i, line in enumerate(page)
        )

        footer = ""
        if end < total_lines:
            footer = (
                f"\n[Showing lines {start + 1}-{start + len(page)} of {total_lines}. "
                f"Use offset={end} to continue.]"
            )

        return TextResult(text=formatted + footer)

    def mark_changed(self, file_path: str) -> None:
        """
        Called by Edit/Write after modifying a file.
        Forces Read to re-read the file on next call.
        """
        self._seen.pop(file_path, None)


# ─── Edit ─────────────────────────────────────────────────────────────────────

class EditTool:
    """
    Make exact string replacements in files.
    old_string must match exactly once (unless replace_all=True).
    Verifies uniqueness before applying — prevents accidental multi-site edits.
    """

    name = "Edit"
    description = (
        "Replace exact text in a file. old_string must appear exactly once "
        "(use replace_all=true for global replace). Fails with uniqueness error "
        "if old_string matches multiple locations — add surrounding context to disambiguate."
    )

    def __init__(self, read_tool: ReadTool) -> None:
        # Share state with Read for dedup invalidation
        self._read = read_tool

    @property
    def input_schema(self) -> dict[str, Any]:
        return {
            "type": "object",
            "properties": {
                "file_path": {
                    "type": "string",
                    "description": "Absolute path to the file",
                },
                "old_string": {
                    "type": "string",
                    "description": "Exact text to replace. Must be unique in file.",
                },
                "new_string": {
                    "type": "string",
                    "description": "Replacement text",
                },
                "replace_all": {
                    "type": "boolean",
                    "default": False,
                    "description": "Replace all occurrences (default: false)",
                },
            },
            "required": ["file_path", "old_string", "new_string"],
            "additionalProperties": False,
        }

    async def execute(self, input: dict[str, Any]) -> ToolResult:
        file_path = Path(input["file_path"])
        old_string = input["old_string"]
        new_string = input["new_string"]
        replace_all = input.get("replace_all", False)

        if not file_path.is_absolute():
            return ErrorResult(error=f"Path must be absolute: {file_path}")

        if not file_path.exists():
            return ErrorResult(
                error=f"File not found: {file_path}",
                hint="Use Write to create a new file",
            )

        try:
            content = file_path.read_text(encoding="utf-8")
        except (PermissionError, UnicodeDecodeError) as exc:
            return ErrorResult(error=str(exc))

        # Uniqueness check — BEFORE applying the change
        count = content.count(old_string)

        if count == 0:
            # Help the model understand what is actually in the file
            lines = content.splitlines()
            similar = difflib.get_close_matches(
                old_string[:60], [l.strip() for l in lines], n=3, cutoff=0.6
            )
            hint = (
                f"old_string not found in {file_path}. "
                + (
                    f"Similar lines found: {similar}"
                    if similar
                    else "Re-read the file to verify current content."
                )
            )
            return ErrorResult(error="old_string not found", hint=hint)

        if count > 1 and not replace_all:
            return ErrorResult(
                error=(
                    f"old_string matches {count} locations in {file_path}. "
                    "Add more surrounding context to make it unique, "
                    "or set replace_all=true to replace all occurrences."
                )
            )

        # Apply the replacement
        if replace_all:
            new_content = content.replace(old_string, new_string)
        else:
            new_content = content.replace(old_string, new_string, 1)

        file_path.write_text(new_content, encoding="utf-8")

        # Invalidate dedup cache — file has changed
        self._read.mark_changed(str(file_path))

        # Build a brief diff summary for the model
        old_lines = old_string.splitlines()
        new_lines = new_string.splitlines()
        diff = list(difflib.unified_diff(
            old_lines, new_lines, lineterm="", n=0
        ))
        diff_summary = "\n".join(diff[:20]) if diff else "(no visible diff — whitespace change?)"

        return TextResult(
            text=(
                f"Edited {file_path}\n"
                f"Replaced {count if replace_all else 1} occurrence(s)\n"
                f"Diff:\n{diff_summary}"
            )
        )


# ─── Write ────────────────────────────────────────────────────────────────────

class WriteTool:
    """
    Create or overwrite a file.
    Reports whether file was created or updated.
    For targeted edits to existing files, use Edit instead.
    """

    name = "Write"
    description = (
        "Create or overwrite a file. Creates parent directories as needed. "
        "Use Edit for targeted changes to existing files — Write replaces the entire content."
    )

    def __init__(self, read_tool: ReadTool) -> None:
        self._read = read_tool

    @property
    def input_schema(self) -> dict[str, Any]:
        return {
            "type": "object",
            "properties": {
                "file_path": {
                    "type": "string",
                    "description": "Absolute path to write",
                },
                "content": {
                    "type": "string",
                    "description": "Full file content to write",
                },
            },
            "required": ["file_path", "content"],
            "additionalProperties": False,
        }

    async def execute(self, input: dict[str, Any]) -> ToolResult:
        file_path = Path(input["file_path"])
        content = input["content"]

        if not file_path.is_absolute():
            return ErrorResult(error=f"Path must be absolute: {file_path}")

        action = "updated" if file_path.exists() else "created"

        try:
            file_path.parent.mkdir(parents=True, exist_ok=True)
            file_path.write_text(content, encoding="utf-8")
        except PermissionError as exc:
            return ErrorResult(error=f"Permission denied: {exc}")
        except OSError as exc:
            return ErrorResult(error=f"Write failed: {exc}")

        # Invalidate dedup cache
        self._read.mark_changed(str(file_path))

        line_count = content.count("\n") + 1
        return TextResult(
            text=f"File {action}: {file_path} ({line_count} lines)"
        )


# ─── Bash ─────────────────────────────────────────────────────────────────────

class BashTool:
    """
    Execute shell commands with CWD persistence.
    CWD changes (cd) persist across calls within the session.
    Shell state (env vars set in a call) does NOT persist.
    """

    name = "Bash"
    description = (
        "Execute a shell command. CWD persists across calls (cd works). "
        "Shell state (env vars) resets each call. "
        "Use run_in_background=true for long commands."
    )

    def __init__(self, initial_cwd: str | None = None) -> None:
        self._cwd = Path(initial_cwd or Path.cwd())
        self._task_store = BackgroundTaskStore()

    @property
    def input_schema(self) -> dict[str, Any]:
        return {
            "type": "object",
            "properties": {
                "command": {
                    "type": "string",
                    "description": "Shell command to execute",
                },
                "timeout": {
                    "type": "integer",
                    "minimum": 1,
                    "maximum": 600_000,
                    "description": "Timeout in milliseconds. Default 30000.",
                },
                "description": {
                    "type": "string",
                    "description": "Human-readable label for audit logs",
                },
                "run_in_background": {
                    "type": "boolean",
                    "default": False,
                },
            },
            "required": ["command"],
            "additionalProperties": False,
        }

    async def execute(self, input: dict[str, Any]) -> ToolResult:
        command = input["command"]
        timeout_ms = input.get("timeout", 30_000)
        run_in_background = input.get("run_in_background", False)

        # CWD persistence: wrap command to emit final CWD on last line
        # This lets us track CWD changes across calls
        wrapped = f"cd {self._cwd!s} && ({command}); echo \"__CWD__:$(pwd)\""

        if run_in_background:
            task = self._task_store.create()
            task.status = TaskStatus.RUNNING
            asyncio.create_task(
                self._run_background(task, wrapped, timeout_ms)
            )
            return TextResult(
                text=(
                    f"Background task started: {task.id}\n"
                    f"Call TaskOutput(task_id='{task.id}') to get result."
                )
            )

        return await self._run_foreground(wrapped, timeout_ms)

    async def _run_foreground(
        self, wrapped_command: str, timeout_ms: int
    ) -> ToolResult:
        start = time.monotonic()
        try:
            proc = await asyncio.create_subprocess_shell(
                wrapped_command,
                stdout=asyncio.subprocess.PIPE,
                stderr=asyncio.subprocess.PIPE,
            )
            stdout, stderr = await asyncio.wait_for(
                proc.communicate(),
                timeout=timeout_ms / 1000,
            )
        except asyncio.TimeoutError:
            return ErrorResult(
                error=f"Command timed out after {timeout_ms}ms",
                hint="Use run_in_background=true for long commands",
            )

        elapsed_ms = int((time.monotonic() - start) * 1000)
        out = stdout.decode("utf-8", errors="replace")
        err = stderr.decode("utf-8", errors="replace")

        # Extract and update CWD from sentinel line
        lines = out.splitlines()
        if lines and lines[-1].startswith("__CWD__:"):
            new_cwd = lines[-1][len("__CWD__:"):]
            self._cwd = Path(new_cwd)
            out = "\n".join(lines[:-1])

        MAX_OUTPUT = 20_000
        truncated = len(out) > MAX_OUTPUT
        if truncated:
            out = out[:MAX_OUTPUT]

        result = out
        if err:
            result += f"\n[stderr]:\n{err[:2000]}"
        if truncated:
            result += f"\n[stdout truncated at {MAX_OUTPUT} chars, {elapsed_ms}ms]"

        return TextResult(text=result)

    async def _run_background(
        self, task: "BackgroundTask", command: str, timeout_ms: int
    ) -> None:
        try:
            proc = await asyncio.create_subprocess_shell(
                command,
                stdout=asyncio.subprocess.PIPE,
                stderr=asyncio.subprocess.STDOUT,
            )
            stdout, _ = await asyncio.wait_for(
                proc.communicate(), timeout=timeout_ms / 1000
            )
            task.result = stdout.decode("utf-8", errors="replace")[:50_000]
            task.status = TaskStatus.COMPLETED
        except asyncio.TimeoutError:
            task.error = f"Timed out after {timeout_ms}ms"
            task.status = TaskStatus.FAILED
        except Exception as exc:
            task.error = str(exc)
            task.status = TaskStatus.FAILED
        finally:
            task.completed_at = time.time()

Wiring It Together

def build_core_tool_library() -> tuple[list[Tool], ToolRegistry]:
    """
    Assemble the core tool library with proper dependency injection.
    Returns tools list (for system prompt) and registry (for dispatch).
    """
    registry = ToolRegistry()

    # Read is the foundation — other tools share its dedup state
    read = ReadTool()
    edit = EditTool(read_tool=read)
    write = WriteTool(read_tool=read)
    bash = BashTool()
    tool_search = ToolSearchTool(registry=registry)

    for tool in [read, edit, write, bash, tool_search]:
        registry.register(tool)

    return [read, edit, write, bash, tool_search], registry

A deferred tool call before schema loading produces the exact InputValidationError message the model expects. If all three pass, the tool layer is behaving correctly.

Summary

The tool layer is built on four principles that pull in opposite directions and must be balanced deliberately.

Descriptions are budget, not docs. Every word in a tool description costs tokens on every turn. Write for the minimum that lets the model use the tool correctly, then stop. Core tools earn their always-loaded status; everything else defers.

Validation errors are instructions. When the model sends malformed input, the error it receives is the instruction for its next attempt. Write validation errors that name the field, state the constraint, and suggest the fix. "value exceeds maximum 600000" is better than "validation failed".

Results are minimal. Return what the model needs to continue, not everything you have. The file_unchanged response exists because returning 10 tokens is better than returning 10,000 when the content has not changed. Apply this discipline to every tool result you design.

Composition is indirect. Tools that call other tools should do so through shared services, not through each other's execute() methods. The permission layer, error handling, and dispatch logic only apply to tool calls that go through the harness control loop. Bypassing the loop bypasses the safety net.

The lab in this chapter gives you Read, Edit, Write, and Bash as a portable Python library.
