Chapter 27: Permission System Implementation

"A permission system built on vibes is a permission system that fails the moment someone creative reads the source."

27.1 Permission Rule DSL: Design a Composable Allow/Deny Language

The permission rule is the atomic unit of policy in a harness. Everything else — the cascade resolver, the auto-mode classifier, the sandbox, the audit log — exists to enforce what the rules say. Getting the rule language right is therefore the highest-leverage design decision in the entire permission system.

Claude Code's production rule syntax is: ToolName(glob_pattern). The tool name selects which tool the rule applies to. The optional glob pattern narrows the rule to specific inputs within that tool's domain. Rules appear in two lists: permissions.allow and permissions.deny.

Rule     ::= ToolSpec [ "(" GlobPattern ")" ]
ToolSpec ::= ToolName | McpToolSpec
ToolName ::= "Bash" | "Read" | "Edit" | "Write" | "WebFetch" | "WebSearch" | ...
McpSpec  ::= "mcp__" ServerName "__" ToolName
           | "mcp__" ServerName "__" "*"
GlobPattern ::= <standard glob: * matches within segment, ** crosses segments>

Examples worth studying:

RuleWhat it covers
Bash(*)All Bash commands
Bash(git *)Any Bash command starting with git
Bash(git commit *)git commit with any flags
Edit(/src/**)Any file edit under /src/ (recursive)
Read(./.env)Exact .env read in project root
Read(./**/*.pem)Any .pem anywhere in project tree
mcp__memory__*All tools from the memory MCP server
mcp__memory__searchOnly the search tool from memory

The glob semantics matter precisely because your rules are only as good as their matching logic. * matches any sequence of characters that does not contain /. ** matches across path separators. So Read(./*.env) matches ./.env but not ./.config/.env. Read(./**/.env) matches both. If you intend to protect credentials recursively, you must use **.

Building the Rule Parser

A production rule parser needs to handle four concerns: tokenization of the rule string, validation of the tool name, extraction and compilation of the glob pattern, and normalization of edge cases (rules with no pattern, MCP wildcard rules, tildes in paths).

from __future__ import annotations

import fnmatch
import os
import re
from dataclasses import dataclass, field
from enum import Enum
from pathlib import Path
from typing import Optional


class RuleList(Enum):
    ALLOW = "allow"
    DENY = "deny"


# MCP tool names follow the pattern mcp__server__tool
_MCP_PATTERN = re.compile(r"^mcp__(?P<server>[^_][^_]*)__(?P<tool>.+)$")

# Built-in tool names accepted by the harness
BUILTIN_TOOLS = frozenset({
    "Bash", "Read", "Edit", "Write", "Glob", "Grep",
    "WebFetch", "WebSearch", "Agent", "AskUserQuestion",
    "TodoRead", "TodoWrite", "Task",
})


@dataclass(frozen=True)
class PermissionRule:
    """A single parsed permission rule."""
    raw: str
    tool_spec: str          # Normalized tool name or mcp__ form
    glob: Optional[str]     # Compiled glob pattern (None = match all inputs)
    list_type: RuleList     # Which list this rule came from

    def matches(self, tool_name: str, tool_input: str) -> bool:
        """Return True if this rule applies to the given tool call."""
        if not self._tool_matches(tool_name):
            return False
        if self.glob is None:
            return True
        return fnmatch.fnmatch(self._normalize_input(tool_input), self.glob)

    def _tool_matches(self, tool_name: str) -> bool:
        if self.tool_spec == tool_name:
            return True
        # MCP wildcard: mcp__server__* matches any tool from that server
        if self.tool_spec.endswith("__*"):
            prefix = self.tool_spec[:-1]  # strip trailing *
            return tool_name.startswith(prefix)
        return False

    @staticmethod
    def _normalize_input(tool_input: str) -> str:
        """Expand ~ and resolve the path for filesystem rules."""
        if tool_input.startswith("~/") or tool_input == "~":
            return str(Path(tool_input).expanduser())
        return tool_input


def parse_rule(raw: str, list_type: RuleList) -> PermissionRule:
    """
    Parse a rule string into a PermissionRule.

    Raises ValueError for malformed rules.
    """
    raw = raw.strip()
    if not raw:
        raise ValueError("Empty rule string")

    # Split on first '(' to separate tool spec from pattern
    if "(" in raw:
        if not raw.endswith(")"):
            raise ValueError(f"Malformed rule (unclosed paren): {raw!r}")
        tool_spec, rest = raw.split("(", 1)
        glob_pattern = rest[:-1]  # strip trailing )
        if not glob_pattern:
            raise ValueError(f"Empty glob pattern in rule: {raw!r}")
    else:
        tool_spec = raw
        glob_pattern = None

    tool_spec = tool_spec.strip()
    _validate_tool_spec(tool_spec)

    return PermissionRule(
        raw=raw,
        tool_spec=tool_spec,
        glob=glob_pattern,
        list_type=list_type,
    )


def _validate_tool_spec(tool_spec: str) -> None:
    if tool_spec in BUILTIN_TOOLS:
        return
    if _MCP_PATTERN.match(tool_spec):
        return
    # MCP wildcard form: mcp__server__*
    if re.match(r"^mcp__[^_][^_]*__\*$", tool_spec):
        return
    raise ValueError(
        f"Unknown tool spec {tool_spec!r}. "
        f"Expected a built-in tool name or mcp__server__tool form."
    )

The key design decisions here: the glob pattern is kept as a raw string and matched with fnmatch rather than pre-compiled to a regex. This keeps the rule representation serializable and debuggable. The _normalize_input method handles tilde expansion so that Read(~/.aws/credentials) matches regardless of the home directory. The MCP wildcard case — mcp__server__* — is a first-class concept because server-level blocking is the common enterprise pattern.

Rule Composability

Rules are composable because the matching functions are pure predicates. You can combine them with standard set operations: a rule set is the union of all rules in a list, and matching is a linear scan. For large enterprise deployments with hundreds of rules, a two-level index — first by tool name, then by glob prefix — reduces the scan to a manageable cost. The implementation above is correct-first; the indexing optimization belongs in a later performance pass.

27.2 Auto-Mode Classifier: Rule-Based and Heuristic Decisions

The auto-mode classifier sits between the rule evaluator and the user prompt system. Its job: when neither the allow list nor the deny list has a definitive match, produce a decision without human input. It must err toward ask when uncertain — a false allow is a security incident; a false ask is an inconvenience.

The classifier considers six inputs, evaluated in order:

  1. Deny list match — immediate deny, no further evaluation.
  2. Allow list match — immediate allow, no further evaluation.
  3. Read-only predicate — is this a read-only operation against a non-sensitive path?
  4. Known-safe pattern — does the command match a library of pre-vetted patterns?
  5. Network access predicate — does the command involve outbound network calls?
  6. Recent denial history — has a similar call been denied in this session?
from __future__ import annotations

import re
import time
from dataclasses import dataclass, field
from enum import Enum
from typing import Optional

from .rules import PermissionRule, RuleList, parse_rule


class Decision(Enum):
    ALLOW = "allow"
    DENY = "deny"
    ASK = "ask"


@dataclass
class ClassifierResult:
    decision: Decision
    decided_by: str          # "deny_rule" | "allow_rule" | "heuristic" | "default"
    matched_rule: Optional[str] = None
    reason: str = ""


# Commands that are structurally read-only: they cannot modify filesystem state.
_READ_ONLY_COMMANDS = re.compile(
    r"^(cat|head|tail|grep|rg|awk|sed -n|find|ls|pwd|echo|printf|"
    r"git (log|diff|status|show|branch|remote -v)|"
    r"npm (list|outdated)|pip (list|show|freeze)|"
    r"curl -I|curl --head|"
    r"wc|sort|uniq|cut|tr|jq)\b"
)

# Commands that access the network. These get an ASK even if not in deny list.
_NETWORK_COMMANDS = re.compile(
    r"\b(curl|wget|fetch|nc|ncat|socat|ssh|scp|rsync|"
    r"git (push|pull|fetch|clone)|"
    r"npm (install|publish|ci)|pip (install|download))\b"
)

# Dangerous patterns that should always ASK regardless of allow rules.
_ALWAYS_ASK_PATTERNS = re.compile(
    r"(rm\s+-rf|mkfs|dd\s+if|chmod\s+777|sudo|su\s+-|"
    r">\s*/dev/(sd|nvme|hd)|"
    r"fork\s*bomb|\(\s*\)\s*\{.*\};"
    r")"
)

# Recently denied call fingerprints tracked per session.
_RECENT_DENIALS: list[str] = []
_MAX_DENIAL_HISTORY = 50


def classify(
    tool_name: str,
    tool_input: str,
    allow_rules: list[PermissionRule],
    deny_rules: list[PermissionRule],
) -> ClassifierResult:
    """
    Produce an allow/deny/ask decision for a tool call.

    Evaluation order:
      1. Deny rules (highest priority)
      2. Allow rules
      3. Always-ask patterns
      4. Read-only heuristic
      5. Network access heuristic
      6. Recent denial history
      7. Default: ASK
    """
    # 1. Check deny rules first — no appeal.
    for rule in deny_rules:
        if rule.matches(tool_name, tool_input):
            _record_denial(tool_name, tool_input)
            return ClassifierResult(
                decision=Decision.DENY,
                decided_by="deny_rule",
                matched_rule=rule.raw,
                reason=f"Matched deny rule: {rule.raw}",
            )

    # 2. Check allow rules.
    for rule in allow_rules:
        if rule.matches(tool_name, tool_input):
            return ClassifierResult(
                decision=Decision.ALLOW,
                decided_by="allow_rule",
                matched_rule=rule.raw,
                reason=f"Matched allow rule: {rule.raw}",
            )

    # 3. Always-ask destructive patterns — even if an allow rule would match,
    #    we escalate. (Allow rules were already checked; this handles heuristic-only
    #    cases where no allow rule exists.)
    if tool_name == "Bash" and _ALWAYS_ASK_PATTERNS.search(tool_input):
        return ClassifierResult(
            decision=Decision.ASK,
            decided_by="heuristic",
            reason="Matched always-ask destructive pattern",
        )

    # 4. Read-only heuristic: auto-allow non-sensitive reads.
    if tool_name in ("Read", "Glob", "Grep"):
        # Sensitive paths are already blocked by deny rules above.
        # Remaining Read calls on non-sensitive paths are safe to allow.
        return ClassifierResult(
            decision=Decision.ALLOW,
            decided_by="heuristic",
            reason="Read-only tool, no deny rule matched",
        )

    if tool_name == "Bash" and _READ_ONLY_COMMANDS.match(tool_input.strip()):
        return ClassifierResult(
            decision=Decision.ALLOW,
            decided_by="heuristic",
            reason="Command matches read-only pattern",
        )

    # 5. Network access: escalate to ASK.
    if tool_name == "Bash" and _NETWORK_COMMANDS.search(tool_input):
        return ClassifierResult(
            decision=Decision.ASK,
            decided_by="heuristic",
            reason="Command involves network access",
        )

    # 6. Recent denial history: if we denied something similar recently,
    #    ask rather than silently repeating the deny. Gives the user a chance
    #    to adjust policy.
    fingerprint = f"{tool_name}:{tool_input[:80]}"
    if any(fingerprint.startswith(denied[:40]) for denied in _RECENT_DENIALS):
        return ClassifierResult(
            decision=Decision.ASK,
            decided_by="heuristic",
            reason="Similar call recently denied — escalating for review",
        )

    # 7. Default: ask. Unknown operations are never silently allowed.
    return ClassifierResult(
        decision=Decision.ASK,
        decided_by="default",
        reason="No rule or heuristic matched — defaulting to ask",
    )


def _record_denial(tool_name: str, tool_input: str) -> None:
    fingerprint = f"{tool_name}:{tool_input[:80]}"
    _RECENT_DENIALS.append(fingerprint)
    if len(_RECENT_DENIALS) > _MAX_DENIAL_HISTORY:
        _RECENT_DENIALS.pop(0)

The critical design invariant: deny rules are checked before allow rules. This is not a convention — it is a security requirement. If allow rules ran first, a broad Bash(*) allow rule would shadow a deny rule protecting ~/.ssh/*. The deny list is the security boundary; the allow list is the ergonomics layer.

The _ALWAYS_ASK_PATTERNS regex is a last-resort safety net for commands so destructive (rm -rf, mkfs, fork bombs) that the classifier escalates regardless of what allow rules say. This is not the same as a deny rule — the user can still approve the action after the ask prompt — but it prevents silent auto-execution of irreversible operations.

27.3 Sandbox: Network Isolation, Filesystem Boundaries, Command Allowlists

Rules and heuristics operate at the decision layer — they determine whether a tool call should run. The sandbox operates at the execution layer — it constrains what a tool call can do even after it has been allowed. This distinction is load-bearing: a misconfigured allow rule can be partially compensated by sandbox restrictions; the reverse is not true.

Architecture Overview

flowchart TD
    TC["Tool Call\nBash(command)"] --> CL["Classifier\nallow/deny/ask"]

    CL -->|allow| SB{"Sandbox\nEnabled?"}

    SB -->|no| EXEC["Execute Directly\n(full system access)"]

    CHECKS --> NC["Network Check\nDomain in allowedDomains?"]
    CHECKS --> CC["Command Check\nIn blocklist?"]

    NC -->|pass| CC
    CC -->|pass| SANDBOXED["Execute in Sandbox\n(restricted environment)"]
    FC -->|fail| SANDBOXBLOCKED["Blocked — EPERM"]

Filesystem Boundary Enforcement

from __future__ import annotations

import os
import shlex
from pathlib import Path


class FilesystemSandbox:
    """
    Enforce that a command only touches paths within allowed roots.

    The check is static (based on path arguments parsed from the command string)
    because dynamic enforcement requires kernel-level interception (seccomp/eBPF).
    Static checks are a defense-in-depth layer, not a complete isolation guarantee.
    """

    def __init__(self, allowed_roots: list[str], project_root: str) -> None:
        self.allowed_roots = [
            Path(r).expanduser().resolve() for r in allowed_roots
        ]
        self.project_root = Path(project_root).resolve()

    def check(self, command: str) -> tuple[bool, str]:
        """
        Return (allowed, reason).

        Scans the tokenized command for path-like arguments and verifies each
        is within an allowed root.
        """
        try:
            tokens = shlex.split(command)
        except ValueError:
            # Unparseable command (heredocs, complex quoting) — let sandbox
            # kernel enforcement handle it rather than false-blocking.
            return True, "unparseable — deferred to kernel enforcement"

        for token in tokens:
            if not token.startswith(("/", "~", "../", "..")):
                continue
            candidate = Path(token).expanduser().resolve()
            if not self._within_any_root(candidate):
                return False, f"Path {candidate} is outside allowed roots"

        return True, "all paths within allowed roots"

    def _within_any_root(self, path: Path) -> bool:
        for root in self.allowed_roots:
            try:
                path.relative_to(root)
                return True
            except ValueError:
                continue
        return False

The limitation stated in the docstring is real and important: static path scanning only catches literal path arguments. A command like cd /tmp && cat /etc/passwd will have /tmp parsed correctly but the cat /etc/passwd is part of the shell evaluation, not visible to the tokenizer. Full filesystem isolation requires kernel-level interception — Linux namespaces with a mount namespace that remounts the filesystem tree, or a seccomp policy that intercepts open() / openat() syscalls and checks the path. The Python sandbox here provides defense-in-depth for the common case; the kernel layer closes the gaps.

Network Domain Allowlist

from __future__ import annotations

import re
import socket
from dataclasses import dataclass


@dataclass
class NetworkSandbox:
    """
    Intercept outbound network connections and check against an allowed domain list.

    In practice, this is implemented at the network namespace level (Linux) or
    via a transparent proxy (macOS). This class provides the domain-matching
    logic that both implementations share.
    """
    allowed_domains: list[str]  # May include wildcard prefixes like *.example.com

    def is_allowed(self, host: str) -> bool:
        host = host.lower().rstrip(".")
        for pattern in self.allowed_domains:
            if self._domain_matches(host, pattern.lower()):
                return True
        return False

    @staticmethod
    def _domain_matches(host: str, pattern: str) -> bool:
        if pattern.startswith("*."):
            suffix = pattern[2:]
            return host == suffix or host.endswith("." + suffix)
        return host == pattern

Command Blocklist

The command blocklist is a named list of command prefixes that are blocked outright at the sandbox layer, regardless of what allow rules say. This is the last line before execution — it catches dangerous commands that slipped past both the deny rules and the heuristic classifier.

from __future__ import annotations

import shlex

# Commands that are categorically blocked in the sandbox.
# These represent irreversible system modifications or privilege escalation vectors.
COMMAND_BLOCKLIST: frozenset[str] = frozenset({
    "sudo",
    "su",
    "doas",
    "pkexec",
    "chmod",        # blocked unless specifically needed; use allow rules to re-enable
    "chown",
    "mkfs",
    "dd",
    "fdisk",
    "parted",
    "iptables",
    "ip6tables",
    "nftables",
    "insmod",
    "rmmod",
    "modprobe",
    "systemctl",
    "service",
    "reboot",
    "shutdown",
    "halt",
    "poweroff",
})


def check_command_blocklist(command: str) -> tuple[bool, str]:
    """
    Return (allowed, reason).

    Parses the first token of the command (the executable name) and checks
    it against the blocklist.
    """
    try:
        tokens = shlex.split(command)
    except ValueError:
        return True, "unparseable command — deferred to kernel enforcement"

    if not tokens:
        return True, "empty command"

    exe = tokens[0].split("/")[-1]  # Strip path prefix: /usr/bin/sudo → sudo
    if exe in COMMAND_BLOCKLIST:
        return False, f"Command {exe!r} is in the sandbox blocklist"

    return True, "command not in blocklist"

The three sandbox layers work in concert. The filesystem check catches path traversal. The network check catches exfiltration. The command blocklist catches privilege escalation. None of them alone is sufficient; together they make a determined adversary's job substantially harder.

27.4 Audit Logging: What Was Executed, Parameters, Timing, Outcome

An audit log that doesn't record enough context to reconstruct what happened is compliance theater. Every entry must answer six questions: what ran, what input was given, when, who decided to allow it, how long it took, and whether it succeeded.

from __future__ import annotations

import json
import time
import uuid
from dataclasses import asdict, dataclass, field
from datetime import datetime, timezone
from enum import Enum
from pathlib import Path
from typing import Any, Optional


class AuditOutcome(Enum):
    SUCCESS = "success"
    ERROR = "error"
    BLOCKED = "blocked"
    PENDING = "pending"


@dataclass
class AuditEntry:
    """One record per tool call attempt."""
    # Identity
    entry_id: str = field(default_factory=lambda: str(uuid.uuid4()))
    session_id: str = ""

    # What ran
    tool_name: str = ""
    tool_input: dict[str, Any] = field(default_factory=dict)

    # Decision
    decision: str = ""              # allow | deny | ask
    decided_by: str = ""            # deny_rule | allow_rule | heuristic | user | default
    matched_rule: Optional[str] = None

    # Timing
    timestamp: str = field(
        default_factory=lambda: datetime.now(timezone.utc).isoformat()
    )
    duration_ms: Optional[int] = None

    # Outcome
    outcome: str = AuditOutcome.PENDING.value
    error: Optional[str] = None

    # Sandbox
    sandbox_enabled: bool = False
    sandbox_checks: dict[str, bool] = field(default_factory=dict)


class AuditLogger:
    """
    Append-only JSONL audit log for tool call decisions and outcomes.

    One line per AuditEntry. The JSONL format is chosen because:
    - Each line is independently parseable (partial writes don't corrupt history)
    - Trivially queryable with jq, grep, or any log aggregation system
    - Append-only writes avoid read-modify-write race conditions
    """

    def __init__(self, log_path: str, session_id: str) -> None:
        self.log_path = Path(log_path)
        self.session_id = session_id
        self._pending: dict[str, tuple[AuditEntry, float]] = {}  # entry_id → (entry, start_time)

        # Ensure log directory exists
        self.log_path.parent.mkdir(parents=True, exist_ok=True)

    def record_decision(
        self,
        tool_name: str,
        tool_input: dict[str, Any],
        decision: str,
        decided_by: str,
        matched_rule: Optional[str] = None,
        sandbox_enabled: bool = False,
        sandbox_checks: Optional[dict[str, bool]] = None,
    ) -> str:
        """
        Log the permission decision for a tool call.

        Returns the entry_id, which the caller must pass to record_outcome()
        when the call completes.
        """
        entry = AuditEntry(
            session_id=self.session_id,
            tool_name=tool_name,
            tool_input=self._sanitize_input(tool_name, tool_input),
            decision=decision,
            decided_by=decided_by,
            matched_rule=matched_rule,
            sandbox_enabled=sandbox_enabled,
            sandbox_checks=sandbox_checks or {},
        )

        if decision == "deny":
            entry.outcome = AuditOutcome.BLOCKED.value
            self._write(entry)
        else:
            # Store pending — we'll complete this entry when the call finishes
            self._pending[entry.entry_id] = (entry, time.monotonic())

        return entry.entry_id

    def record_outcome(
        self,
        entry_id: str,
        outcome: AuditOutcome,
        error: Optional[str] = None,
    ) -> None:
        """Complete a pending audit entry with the execution outcome."""
        if entry_id not in self._pending:
            return  # Entry was blocked (deny); already written

        entry, start_time = self._pending.pop(entry_id)
        entry.duration_ms = int((time.monotonic() - start_time) * 1000)
        entry.outcome = outcome.value
        entry.error = error
        self._write(entry)

    def _write(self, entry: AuditEntry) -> None:
        line = json.dumps(asdict(entry), default=str)
        with self.log_path.open("a", encoding="utf-8") as fh:
            fh.write(line + "\n")

    @staticmethod
    def _sanitize_input(tool_name: str, tool_input: dict[str, Any]) -> dict[str, Any]:
        """
        Strip or redact sensitive content from tool inputs before logging.

        The audit log must not become a secondary credential store.
        Long file contents are truncated; environment variable values
        with secret-like names are redacted.
        """
        sanitized = dict(tool_input)

        # Truncate long string values (file contents from Write/Edit tools)
        for key, value in sanitized.items():
            if isinstance(value, str) and len(value) > 512:
                sanitized[key] = value[:512] + f"...[{len(value) - 512} chars truncated]"

        # Redact env var values that look like secrets
        if tool_name == "Bash" and "command" in sanitized:
            sanitized["command"] = _redact_env_secrets(sanitized["command"])

        return sanitized


_SECRET_PREFIXES = ("TOKEN", "SECRET", "PASSWORD", "KEY", "CREDENTIAL", "AUTH")


def _redact_env_secrets(command: str) -> str:
    """Replace secret-looking env var assignments with redacted placeholders."""
    import re
    def redact_match(m: re.Match) -> str:
        name = m.group(1)
        if any(name.upper().startswith(p) for p in _SECRET_PREFIXES):
            return f"{name}=[REDACTED]"
        return m.group(0)

    return re.sub(r"\b([A-Z_][A-Z0-9_]*)=\S+", redact_match, command)

The _sanitize_input method deserves emphasis. A naive audit log that records the full content of every Write call will accumulate credentials, private keys, and configuration secrets. The log becomes a high-value target for attackers who compromise the logging system. Truncating long values and redacting secret-pattern env vars keeps the log useful for forensics while avoiding the credential accumulation problem.

The duration_ms field answers a question that naive audit systems miss: how long did the operation take? A Bash command that normally completes in 50ms but takes 45 seconds on a specific input has flagged a potential data exfiltration event. Anomaly detection over duration distributions is a cheap and effective behavioral analysis layer.

27.5 The Permission Cascade: Precedence Resolution Across Multiple Config Layers

Real deployments have multiple sources of permission configuration: enterprise managed settings, user settings (~/.claude/settings.json), project settings (.claude/settings.json), and local overrides (settings.local.json). These sources can conflict. The cascade resolver determines which rule wins.

The resolution order, from highest to lowest priority:

  1. Deny rules from all layers — collected first, evaluated before any allow rules. A deny rule in any layer blocks the call.
  2. Allow rules from managed settings — if allowManagedPermissionRulesOnly is set, this is the only allow source.
  3. Allow rules from project settings — if not locked out by managed settings.
  4. Allow rules from user settings — if not locked out by managed settings.
  5. Allow rules from local settings — lowest priority, intended for per-developer tuning.
  6. Mode-specific default — auto triggers the classifier; default asks the user; bypassPermissions allows.
flowchart TD
    TC["Tool Call"] --> DR["Collect deny rules\nfrom ALL layers"]
    DR --> DM{"Any deny rule\nmatches?"}
    DM -->|yes| DENIED["DENY\n(reason: matched deny rule)"]
    DM -->|no| MANAGED_ONLY{"allowManaged\nPermissionRulesOnly?"}
    MANAGED_ONLY -->|yes| MALLOW["Check managed\nallow rules only"]
    MANAGED_ONLY -->|no| ALLALLOW["Check allow rules\nManaged → Project → User → Local"]
    MALLOW --> AMATCH{"Match?"}
    ALLALLOW --> PMATCH{"Match?"}
    AMATCH -->|yes| ALLOWED["ALLOW\n(reason: matched allow rule)"]
    AMATCH -->|no| MODEDEFAULT["Mode default:\nauto/default/bypass"]
    PMATCH -->|yes| ALLOWED
    PMATCH -->|no| MODEDEFAULT
    MODEDEFAULT -->|auto| CLASSIFIER["Auto-mode classifier"]
    MODEDEFAULT -->|default| USER["ASK user"]
    MODEDEFAULT -->|bypassPermissions| ALLOWED
    CLASSIFIER --> RESULT["allow / deny / ask"]
from __future__ import annotations

from dataclasses import dataclass
from enum import Enum
from typing import Optional

from .classifier import ClassifierResult, Decision, classify
from .rules import PermissionRule, RuleList, parse_rule


class PermissionMode(Enum):
    PLAN = "plan"
    DEFAULT = "default"
    ACCEPT_EDITS = "acceptEdits"
    AUTO = "auto"
    DONT_ASK = "dontAsk"
    BYPASS = "bypassPermissions"


@dataclass
class PolicyLayer:
    """One configuration source contributing rules to the cascade."""
    source: str          # "managed" | "project" | "user" | "local"
    allow_rules: list[PermissionRule]
    deny_rules: list[PermissionRule]


@dataclass
class CascadeResult:
    decision: Decision
    decided_by: str
    source_layer: str
    matched_rule: Optional[str] = None
    reason: str = ""


class PermissionCascade:
    """
    Resolve a permission decision across multiple configuration layers.

    Layers are added in priority order: managed first, local last.
    Deny rules from all layers are collected before any allow rule is checked.
    """

    def __init__(
        self,
        mode: PermissionMode = PermissionMode.DEFAULT,
        managed_permission_rules_only: bool = False,
    ) -> None:
        self.mode = mode
        self.managed_permission_rules_only = managed_permission_rules_only
        self._layers: list[PolicyLayer] = []

    def add_layer(self, layer: PolicyLayer) -> None:
        self._layers.append(layer)

    def resolve(self, tool_name: str, tool_input: str) -> CascadeResult:
        # bypassPermissions skips everything
        if self.mode == PermissionMode.BYPASS:
            return CascadeResult(
                decision=Decision.ALLOW,
                decided_by="mode",
                source_layer="bypass",
                reason="bypassPermissions mode — all checks skipped",
            )

        # Collect ALL deny rules from ALL layers first
        all_deny = [
            rule
            for layer in self._layers
            for rule in layer.deny_rules
        ]

        for rule in all_deny:
            if rule.matches(tool_name, tool_input):
                return CascadeResult(
                    decision=Decision.DENY,
                    decided_by="deny_rule",
                    source_layer=self._rule_source(rule),
                    matched_rule=rule.raw,
                    reason=f"Matched deny rule from {self._rule_source(rule)}: {rule.raw}",
                )

        # Collect allow rules — managed only, or all layers
        if self.managed_permission_rules_only:
            allow_sources = [l for l in self._layers if l.source == "managed"]
        else:
            allow_sources = self._layers

        all_allow = [rule for layer in allow_sources for rule in layer.allow_rules]

        for rule in all_allow:
            if rule.matches(tool_name, tool_input):
                return CascadeResult(
                    decision=Decision.ALLOW,
                    decided_by="allow_rule",
                    source_layer=self._rule_source(rule),
                    matched_rule=rule.raw,
                    reason=f"Matched allow rule from {self._rule_source(rule)}: {rule.raw}",
                )

        # No rule matched — fall through to mode default
        return self._mode_default(tool_name, tool_input, all_allow, all_deny)

    def _mode_default(
        self,
        tool_name: str,
        tool_input: str,
        allow_rules: list[PermissionRule],
        deny_rules: list[PermissionRule],
    ) -> CascadeResult:
        if self.mode == PermissionMode.AUTO:
            result: ClassifierResult = classify(tool_name, tool_input, allow_rules, deny_rules)
            return CascadeResult(
                decision=result.decision,
                decided_by=result.decided_by,
                source_layer="classifier",
                matched_rule=result.matched_rule,
                reason=result.reason,
            )

        if self.mode in (PermissionMode.DONT_ASK, PermissionMode.ACCEPT_EDITS):
            return CascadeResult(
                decision=Decision.ALLOW,
                decided_by="mode",
                source_layer="mode_default",
                reason=f"{self.mode.value} mode — auto-allowed",
            )

        # DEFAULT and PLAN both escalate to user for unmatched calls
        return CascadeResult(
            decision=Decision.ASK,
            decided_by="mode",
            source_layer="mode_default",
            reason=f"{self.mode.value} mode — no matching rule, asking user",
        )

    def _rule_source(self, rule: PermissionRule) -> str:
        for layer in self._layers:
            if rule in layer.allow_rules or rule in layer.deny_rules:
                return layer.source
        return "unknown"

The architectural fact worth repeating: deny rules cross all layers. A deny rule in user settings is just as binding as a deny rule in managed settings. This is intentional — it lets security-conscious developers add personal deny rules (protecting their SSH keys, their personal .env files) without requiring enterprise policy changes. The managed settings lockdown via allowManagedPermissionRulesOnly applies only to allow rules, not deny rules, because there is no security justification for blocking users from adding additional restrictions.

The target: a harness policy for a team that needs full developer productivity (git, test runners, linters) while protecting credentials, enforcing network boundaries, and maintaining a complete audit trail for SOC 2 compliance.

def build_dev_cascade() -> PermissionCascade:

    # --- Managed layer (enterprise policy — overrides everything) ---

            "Write(**)",

        ]
    ]

    cascade.add_layer(PolicyLayer(
        source="managed",

        deny_rules=managed_deny,
    ))

    # --- Project layer (per-repo policy) ---
    # Note: with managed_permission_rules_only=True, these allow rules are
    # ignored. Shown here for documentation; use managed layer in production.
    project_allow = [
        parse_rule(r, RuleList.ALLOW) for r in [
            "Bash(npm install)",
            "Bash(npm ci)",
            "Bash(pip install *)",

        ]
    ]

    cascade.add_layer(PolicyLayer(
        source="project",
        allow_rules=project_allow,
        deny_rules=[],
    ))

    return cascade

Step 3: Wire the Audit Logger

# executor.py — wrap tool execution with audit logging
from __future__ import annotations

import subprocess
from typing import Any

from permission_system.audit import AuditLogger, AuditOutcome
from permission_system.cascade import PermissionCascade
from permission_system.classifier import Decision
from permission_system.sandbox import (
    FilesystemSandbox,
    NetworkSandbox,
    check_command_blocklist,
)


class SecureBashExecutor:
    """
    Execute Bash tool calls with full permission checking and audit logging.
    """

    def __init__(
        self,
        cascade: PermissionCascade,
        audit: AuditLogger,
        project_root: str,
        allowed_domains: list[str],
    ) -> None:
        self.cascade = cascade
        self.audit = audit
        self.fs_sandbox = FilesystemSandbox(
            allowed_roots=[project_root],
            project_root=project_root,
        )
        self.net_sandbox = NetworkSandbox(allowed_domains=allowed_domains)

    def execute(self, command: str, timeout: int = 30) -> dict[str, Any]:
        """
        Run a Bash command through the full permission stack.

        Returns a dict with keys: allowed, output, error, entry_id.
        """
        # 1. Cascade resolution
        result = self.cascade.resolve("Bash", command)

        # 2. Sandbox checks (even for allowed commands)
        sandbox_checks = self._run_sandbox_checks(command)
        sandbox_passed = all(sandbox_checks.values())

        # Determine final decision
        if result.decision == Decision.DENY or not sandbox_passed:
            final_decision = "deny"
            decided_by = result.decided_by if result.decision == Decision.DENY else "sandbox"
        elif result.decision == Decision.ASK:
            final_decision = "ask"
            decided_by = result.decided_by
        else:
            final_decision = "allow"
            decided_by = result.decided_by

        # 3. Record the decision
        entry_id = self.audit.record_decision(
            tool_name="Bash",
            tool_input={"command": command},
            decision=final_decision,
            decided_by=decided_by,
            matched_rule=result.matched_rule,
            sandbox_enabled=True,
            sandbox_checks=sandbox_checks,
        )

        if final_decision != "allow":
            return {
                "allowed": False,
                "output": None,
                "error": result.reason,
                "entry_id": entry_id,
            }

        # 4. Execute
        try:
            proc = subprocess.run(
                command,
                shell=True,
                capture_output=True,
                text=True,
                timeout=timeout,
            )
            outcome = AuditOutcome.SUCCESS if proc.returncode == 0 else AuditOutcome.ERROR
            error = proc.stderr if proc.returncode != 0 else None
            self.audit.record_outcome(entry_id, outcome, error=error)
            return {
                "allowed": True,
                "output": proc.stdout,
                "error": error,
                "entry_id": entry_id,
            }
        except subprocess.TimeoutExpired as exc:
            self.audit.record_outcome(entry_id, AuditOutcome.ERROR, error=f"Timeout after {timeout}s")
            return {"allowed": True, "output": None, "error": str(exc), "entry_id": entry_id}
        except OSError as exc:
            self.audit.record_outcome(entry_id, AuditOutcome.ERROR, error=str(exc))
            return {"allowed": True, "output": None, "error": str(exc), "entry_id": entry_id}

    def _run_sandbox_checks(self, command: str) -> dict[str, bool]:
        fs_ok, _ = self.fs_sandbox.check(command)
        bl_ok, _ = check_command_blocklist(command)
        return {
            "filesystem_boundary": fs_ok,
            "command_blocklist": bl_ok,
            # Network check would require parsing command for curl/wget targets
            # and calling self.net_sandbox.is_allowed(host)
            "network_domain": True,  # placeholder — requires DNS resolution
        }

Step 4: Query the Audit Trail

After a session runs, the audit log is a JSONL file. Query it with jq for the most common compliance questions:

# All denied calls in the last session
jq 'select(.decision == "deny")' /var/log/claude-harness/audit.jsonl

# Commands that took longer than 5 seconds (potential exfiltration signal)
jq 'select(.tool_name == "Bash" and .duration_ms > 5000)' audit.jsonl

# Distribution of decisions by tool
jq -r '.tool_name + ":" + .decision' audit.jsonl | sort | uniq -c | sort -rn

# All calls decided by the auto-mode classifier
jq 'select(.decided_by | test("heuristic|default"))' audit.jsonl

# Calls that matched the credential deny rules
jq 'select(.matched_rule != null and (.matched_rule | test("credentials|secret|pem|ssh")))' audit.jsonl

# Session summary: total calls, allowed vs denied, total execution time
jq -s '{
  total: length,
  allowed: [.[] | select(.decision == "allow")] | length,
  denied: [.[] | select(.decision == "deny")] | length,
  asked: [.[] | select(.decision == "ask")] | length,
  total_ms: [.[] | .duration_ms // 0] | add
}' audit.jsonl

Summary

The permission system is not a single function — it is a stack of five independent components that must be designed separately and integrated carefully.

The architectural facts that carry forward:

  • The rule DSL is the policy language. Its glob semantics determine what gets protected. Test your deny rules against the actual input forms your tools produce — ~ expansion, relative paths, and path separators are the most common sources of coverage gaps.
  • The classifier's fallback is ask, never allow. Silently allowing unknown operations is how permission systems fail. Every uncertain case escalates to the human; the human's decision can be recorded as a rule so it only has to happen once.
  • Sandbox and rules are complementary, not redundant. Rules operate at the decision layer (should this run?). The sandbox operates at the execution layer (what can it do if it runs?). Both are necessary; neither is sufficient alone.
  • The audit log has a security requirement of its own. Truncate long values. Redact secret-pattern environment variables. A log that accumulates credentials is a target, not a safety net.
  • Deny rules cross all layers; allow rules respect the allowManagedPermissionRulesOnly lock. This asymmetry is intentional. Adding restrictions is always safe; relaxing restrictions requires authorization.
  • The cascade resolver must be tested against its policy document. Every requirement in the policy table from Step 1 of the lab must have a corresponding test. Policy drift without test coverage is the mechanism by which "enterprise-grade" permission systems quietly become rubber stamps.

Chapter 28 applies this permission system to multi-agent deployments, where the challenge is not single-agent policy but policy federation: an orchestrator agent spawning subagents with scoped, delegated permissions that cannot escalate above the orchestrator's own authority.
