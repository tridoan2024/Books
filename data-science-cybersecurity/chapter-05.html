Chapter 5: Python, SQL, and Reproducible Analytical Workflows

Repository Walkthrough: Rebuild the Impossible-Travel Investigation

At 09:10 an investigator asks which identities authenticated from two countries within thirty minutes and whether the second event used a new device. By lunch, a notebook has produced twelve names. By Friday, nobody can reproduce the list. The query was edited in place, the notebook depended on an unrecorded package version, a nested JSON field silently changed type, and a cloud token remains in cell output.

This chapter rebuilds that investigation as a repository. The aim is not infrastructure for its own sake. A result becomes evidence only when another person can reconstruct its input, transformations, assumptions, and checks.

impossible-travel/
├── pyproject.toml
├── data/auth.ndjson
├── sql/{schema.sql,investigate.sql}
├── src/impossible_travel/{ingest.py,pipeline.py}
├── tests/test_pipeline.py
└── notebooks/01_discovery.ipynb

The notebook is deliberately last: it can discover a transformation but is not the authoritative implementation.

Commit Zero: Runtime and Data Contract

A manifest should separate runtime from development dependencies and bound supported Python versions. A lock file then records resolved transitive versions and hashes.

[build-system]
requires = ["setuptools==75.8.0"]
build-backend = "setuptools.build_meta"

[project]
name = "impossible-travel"
version = "0.1.0"
requires-python = ">=3.11,<3.15"
dependencies = []

[project.optional-dependencies]
dev = ["pytest==8.3.5", "ruff==0.9.7"]

This exercise needs no third-party runtime package. A production run manifest should still capture the interpreter, operating-system image digest, source revision, parameters, and immutable data-snapshot identifier.

The input is newline-delimited JSON. Nested objects and arrays are ordinary in identity telemetry. The last record intentionally violates the boolean contract.

{"event_id":"a2","ts":"2026-08-01T10:18:00Z","identity":{"id":"u1","groups":["engineering"]},"source":{"country":"DE","ip":"203.0.113.9"},"device":{"id":"d9","managed":false},"result":{"success":true}}
{"event_id":"a3","ts":"2026-08-01T10:40:00Z","identity":{"id":"u2","groups":["finance"]},"source":{"country":"US","ip":"198.51.100.8"},"device":{"id":"d2","managed":true},"result":{"success":"true"}}

Ingestion Boundary: Reject Ambiguity

Nested JSON is difficult because absent or malformed values acquire accidental meanings. This loader refuses missing paths, duplicate identifiers, non-boolean outcomes, and timestamps without offsets. It flattens the fields needed by the query while retaining canonical raw JSON for audit.

from __future__ import annotations
import hashlib, json
from datetime import datetime
from pathlib import Path
from typing import Any, Iterable

def require(record: dict[str, Any], *path: str) -> Any:
    value: Any = record
    for key in path:
        if not isinstance(value, dict) or key not in value:
            raise ValueError(f"missing JSON path: {'.'.join(path)}")
        value = value[key]
    return value

def parse_line(line: str) -> tuple[object, ...]:
    record = json.loads(line)
    success = require(record, "result", "success")
    if type(success) is not bool:
        raise ValueError("result.success must be a JSON boolean")
    stamp = datetime.fromisoformat(require(record, "ts").replace("Z", "+00:00"))
    if stamp.utcoffset() is None:
        raise ValueError("ts must include an offset")
    raw = json.dumps(record, sort_keys=True, separators=(",", ":"))
    return (require(record, "event_id"), stamp.isoformat(),
            require(record, "identity", "id"), require(record, "source", "country"),
            require(record, "device", "id"), int(require(record, "device", "managed")),
            int(success), raw)

def load_lines(lines: Iterable[str]) -> list[tuple[object, ...]]:
    rows = [parse_line(line) for line in lines if line.strip()]
    ids = [row[0] for row in rows]
    if len(ids) != len(set(ids)):
        raise ValueError("duplicate event_id")
    return rows

def snapshot_id(path: Path) -> str:
    return hashlib.sha256(path.read_bytes()).hexdigest()[:12]

The exact outcome for a3 is:

ValueError: result.success must be a JSON boolean

Converting the string to True would conceal a producer regression. Explicit failure is cheaper than a plausible wrong answer.

SQL That Exposes Its Plan

SQLite stores the normalized subset. Raw JSON remains available for forensic review, but every query need not repeat deep extraction.

CREATE TABLE auth_event (
 event_id TEXT PRIMARY KEY, ts TEXT NOT NULL, identity_id TEXT NOT NULL,
 country TEXT NOT NULL, device_id TEXT NOT NULL,
 managed INTEGER NOT NULL CHECK(managed IN (0,1)),
 success INTEGER NOT NULL CHECK(success IN (0,1)), raw_json TEXT NOT NULL
);
CREATE INDEX auth_identity_ts ON auth_event(identity_id, ts);

LAG compares each success with the immediately preceding success for that identity. The correlated subquery determines whether the current device appeared earlier.

WITH ordered AS (
 SELECT event_id, identity_id, ts, country, device_id,
   LAG(ts) OVER (PARTITION BY identity_id ORDER BY ts,event_id) previous_ts,
   LAG(country) OVER (PARTITION BY identity_id ORDER BY ts,event_id) previous_country
 FROM auth_event WHERE success=1
), candidates AS (
 SELECT *, ROUND((julianday(ts)-julianday(previous_ts))*1440,1) minutes_apart,
   NOT EXISTS (SELECT 1 FROM auth_event p
     WHERE p.identity_id=ordered.identity_id AND p.device_id=ordered.device_id
       AND p.ts<ordered.ts) new_device
 FROM ordered
)
SELECT identity_id,previous_country,country,minutes_apart,device_id,new_device
FROM candidates
WHERE previous_country<>country AND minutes_apart BETWEEN 0 AND 30
ORDER BY identity_id,ts;

After correcting a3 to the JSON boolean true, exact output is:

identity_id  previous_country  country  minutes_apart  device_id  new_device
u1           US                DE       18.0           d9         1

This is a candidate, not proof of compromise. VPN egress and carrier routing can change apparent country without travel.

Inspect properties, not decorative SQL

Run EXPLAIN QUERY PLAN. SQLite wording varies by release, so assert a useful property instead of snapshotting every character:

import sqlite3

connection = sqlite3.connect(":memory:")
connection.executescript("""
CREATE TABLE auth_event(
  event_id TEXT PRIMARY KEY, identity_id TEXT NOT NULL,
  ts TEXT NOT NULL, country TEXT NOT NULL, device_id TEXT NOT NULL,
  success INTEGER NOT NULL
);
CREATE INDEX auth_identity_ts ON auth_event(identity_id, ts);
""")
investigation_sql = """
SELECT identity_id, ts, country
FROM auth_event INDEXED BY auth_identity_ts
WHERE identity_id = 'u1' AND ts >= '2026-08-01T00:00:00+00:00'
ORDER BY identity_id, ts
"""
plan = connection.execute("EXPLAIN QUERY PLAN " + investigation_sql).fetchall()
assert "auth_identity_ts" in "\n".join(row[-1] for row in plan)

In a warehouse, first bound the base scan by event-date partitions and project only needed columns. Then inspect partitions pruned, bytes read, cardinality estimates, join distribution, spill, and sort stages. A thirty-day query that scans five years because its date predicate appears too late is an analytical defect, not merely a slow database.

Independent Python Implementation

Parity is more convincing when Python does not call the SQL implementation.

from datetime import datetime

def find_country_jumps(rows: list[tuple[object, ...]]) -> list[dict[str, object]]:
    seen: dict[str, set[str]] = {}; prior: dict[str, tuple[datetime,str]] = {}
    findings: list[dict[str, object]] = []
    for row in sorted(rows, key=lambda r: (str(r[2]),str(r[1]),str(r[0]))):
        _, ts_text, identity, country, device, _, success, _ = row
        if not success: continue
        ts = datetime.fromisoformat(str(ts_text)); key = str(identity)
        known = seen.setdefault(key, set())
        if key in prior:
            previous_ts, previous_country = prior[key]
            minutes = (ts-previous_ts).total_seconds()/60
            if previous_country != country and 0 <= minutes <= 30:
                findings.append({"identity_id":identity,"previous_country":previous_country,
                    "country":country,"minutes_apart":round(minutes,1),
                    "device_id":device,"new_device":str(device) not in known})
        known.add(str(device)); prior[key]=(ts,str(country))
    return findings

The tie-breaker event_id matters. If SQL orders tied timestamps differently from Python, the engines can disagree nondeterministically.

Tests That Protect Meaning

Tests should cover parsing, temporal logic, duplicate handling, SQL/Python parity, plan properties, and idempotent reruns. unittest keeps the fixture runnable in this repository.

import unittest

GOOD = [
'{"event_id":"a1","ts":"2026-08-01T10:00:00Z","identity":{"id":"u1"},"source":{"country":"US"},"device":{"id":"d1","managed":true},"result":{"success":true}}',
'{"event_id":"a2","ts":"2026-08-01T10:18:00Z","identity":{"id":"u1"},"source":{"country":"DE"},"device":{"id":"d9","managed":false},"result":{"success":true}}']

class PipelineTest(unittest.TestCase):
    def test_jump(self):
        result=find_country_jumps(load_lines(GOOD))
        self.assertEqual(result[0]["minutes_apart"],18.0)
        self.assertIs(result[0]["new_device"],True)
    def test_string_boolean(self):
        bad=GOOD[0].replace('"success":true','"success":"true"')
        with self.assertRaisesRegex(ValueError,"JSON boolean"): parse_line(bad)
    def test_duplicate(self):
        with self.assertRaisesRegex(ValueError,"duplicate"): load_lines([GOOD[0],GOOD[0]])

if __name__ == "__main__": unittest.main()

Expected output:

...

Ran 3 tests

OK

Do not convert every empirical expectation into a brittle assertion. “Exactly twelve findings” fails when legitimate late events arrive. Monitor input count, null rate, identity cardinality, and finding rate within documented tolerances; reserve hard failure for broken schemas and impossible values. Monitoring detects change. Tests define invalidity.

Secrets Are Inputs, Not Notebook Content

Use a workload identity or secret manager. Local code should fail without printing the secret:

import os
def warehouse_token() -> str:
    token=os.environ.get("SECURITY_WAREHOUSE_TOKEN")
    if not token: raise RuntimeError("SECURITY_WAREHOUSE_TOKEN is not configured")
    return token

Avoid credentials in committed .env files, command arguments visible in process listings, query URLs, exception traces, and notebook output. Prefer short-lived credentials, least-privilege read roles, separate development and production identities, and audited access. Fixtures should replace personal identifiers and IP addresses unless their retention is necessary and approved.

Notebook Exit Criteria

A notebook is useful while the analyst asks which transformation explains the observation. It becomes hazardous when hidden state is treated as a scheduled pipeline. Promote work when the answer is recurring, shared, used for enforcement, or expensive enough that silent drift matters.

Promotion means moving logic into typed functions; replacing mutable downloads with snapshot IDs; parameterizing the observation interval instead of using implicit “now”; storing reviewed SQL with deterministic ordering; recording revision, runtime, parameters, counts, and snapshot hash; adding schema, parity, idempotence, and plan checks; scheduling with a service identity, timeout, bounded retries, and alerts; and publishing atomically from staging only after validation.

{"run_id":"2026-08-02T06:00Z","source_revision":"8c31f2a","input_snapshot":"70dc8a7c8225","window_start":"2026-07-03T00:00:00Z","window_end":"2026-08-02T00:00:00Z","input_rows":8420911,"findings":37,"status":"published"}

Retry only likely transient failures. A schema violation will not heal on attempt three. Backfills accept explicit intervals and must produce the same state twice. Alert on stale successful output as well as exceptions: a green job that published zero bytes is unhealthy.

Reproducibility Under Real Failure

The happy path is the least interesting test of a pipeline. Consider a scheduler that reads a date partition, writes findings, and crashes after the write but before it records success. If the retry appends, every finding is duplicated. Give the output a natural idempotency key—perhaps (identity_id, current_event_id, rule_version)—and write with an upsert or transactional replace. When the transformation itself changes, increment the rule version rather than silently overwriting historical meaning.

Late data creates a different problem. Suppose event a2 arrives today but belongs to yesterday. Reprocessing only today's partition misses its relationship to a1; appending it to yesterday changes yesterday's result. A bounded correction policy should identify which input partitions can still change, rebuild the affected output interval, and publish a new revision. The run manifest should distinguish observed_at, event_time, and published_at so an auditor can reconstruct both operational knowledge and corrected history.

Data snapshots require more than a file name. A useful snapshot descriptor includes object URI or table version, content hash where feasible, extraction query revision, inclusive and exclusive time boundaries, row count, schema fingerprint, and source retention policy. If regulations prohibit retaining raw security data, retain a governed reference and enough aggregate evidence to verify the analysis without copying restricted content into the repository.

Test categories have different owners

A unit test belongs close to a function and runs on every change. A contract test confirms that the producer and consumer agree about field names, types, enums, and timestamp semantics. A data-quality test checks a particular snapshot for broken invariants. A statistical test watches distributional movement without asserting that movement is necessarily wrong. An integration test exercises database transactions, permissions, and serialization. A replay test processes a historical interval end to end and compares a versioned result.

Combining these into one “pipeline passed” flag makes diagnosis slower. A new country code may violate an outdated enum but be valid data; a large fall in volume may be a collector outage; a changed finding count may be the intended result of a rule revision. Each failure should name its violated assumption, observed value, expected boundary, snapshot, and remediation owner.

Tests also need adversarial cases. Use a timestamp exactly at the thirty-minute boundary, two events with identical timestamps, reversed arrival order, a failed login between two successes, a device seen only after the candidate event, Unicode identity values, missing country, and an input line large enough to stress memory. The expected behavior must be stated before implementation. Boundary fixtures prevent a future refactor from changing BETWEEN 0 AND 30 into a subtly different policy.

Cost-Aware Baselines Without Semantic Drift

Precomputation is safe only when the aggregate retains sufficient information. A daily table with login_count, device_count, and last_country cannot reproduce an impossible-travel sequence: ordering inside the day has been destroyed. Conversely, daily count, sum, minimum, and maximum can support many rolling summaries exactly. Decide physical grain from the hardest required query, not from storage fashion.

Query optimization should proceed as an experiment. Record the reference query's plan and answer on a fixed snapshot. Change one factor—predicate placement, index, clustering key, materialized daily aggregate, or join strategy. Measure wall-clock time, compute or bytes scanned, peak memory or spill, and answer parity. A query that is twice as fast but loses late-arriving records is not optimized; it computes a different function.

Parameterization deserves equal care. Bind values through the database driver rather than formatting identity strings into SQL. Maintain an allowlist when a parameter selects a column or ordering direction, because bind parameters generally represent values, not SQL identifiers. Log a redacted parameter manifest: time bounds and rule version are useful; access tokens and full lists of sensitive identities are not.

Finally, distinguish reproducible from repeatable. A run is repeatable when the same operator can execute it again. It is reproducible when an independent operator can obtain the same result from the recorded materials. It is robust when reasonable changes—machine, batch size, event arrival order—do not change meaning. A mature analytical repository aims for all three and documents the cases, such as nondeterministic approximate algorithms, where exact equality is neither possible nor required.

A final peer-review checklist should be answerable from the repository alone: What question and interval were evaluated? Which snapshot supplied the records? Which fields can be absent? Which ordering resolves timestamp ties? Which query plan was accepted? Which outputs are exact versus approximate? Which principal can read the source and publish the result? How does an operator rerun one interval without touching others? If any answer exists only in the original analyst's memory, the workflow is not ready to become shared evidence.

Interview Practicum

The Baseline Query Melts the Warehouse

Panel prompt

“A query computes each identity's thirty-day authentication baseline across billions of events. It takes four hours and spills. Analysts need twenty minutes.” The panel then reveals that events arrive forty-eight hours late and no new database will be approved.

Worked Answer

Strong answer as constraints arrive

Ask for the plan, physical layout, daily volume, identity cardinality, skew, freshness requirement, and exact statistics. Counts, quantiles, sequences, and distinct devices do not have identical aggregation properties.

Require predicates that prune partitions, project only baseline columns, and verify pruning. Check whether service identities cause skew. Align clustering or sort order with identity and event time if supported. For mergeable features, materialize daily identity aggregates and combine thirty bounded partitions. Means merge from sum and count; variance from count, mean, and second moment. Exact distinct counts and quantiles do not merge like sums, so either retain sufficient detail or document sketch error.

Rebuild the last two or three daily partitions for the late-data correction horizon, then recompute affected rolling outputs. If raw sequence features are necessary, use aggregates to identify candidates and read raw events only for them. Compare old and new outputs per identity on a frozen replay; investigate mismatches by lateness, null pattern, and high-volume identity. The launch gate includes parity or declared approximation tolerance, bytes scanned, spill, and wall time.

Optimization shortcuts that fail

“Use Spark” ignores the platform constraint and may preserve the scan. “Add an index” is incomplete for a columnar warehouse. “Cache it” omits invalidation. “Sample one percent” can erase rare identities and corrupt individual baselines.

Follow-Up Questions and Answers

Warehouse follow-ups

Exact distinct devices are mandatory—what then? Maintain bounded identity-device membership at a daily grain and compute distinctness over thirty partitions, accepting its cost. Never call a probabilistic sketch exact.

What belongs in the on-call page? Run ID, failed stage, interval, snapshot, last successful publication, count deltas, and sanitized-log link—never credentials or raw sensitive events.

Thirty-second answer: “I would prove partition pruning, replace repeated raw scans with recomputable daily aggregates, rebuild the late-data horizon, and demonstrate semantic parity on an immutable replay before changing production.”

Key Takeaways

  • Reproducibility joins identified code, runtime, parameters, and immutable input.
  • Validate nested JSON before coercion; plausible conversions hide telemetry regressions.
  • SQL performance starts with bounded scans and inspected plans.
  • Independent SQL and Python implementations enable semantic parity tests.
  • Tests distinguish impossible data from unusual data; pipelines must survive retries and backfills.
  • A recurring or consequential notebook should graduate into a package and monitored pipeline.
