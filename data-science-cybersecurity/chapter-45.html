Chapter 45: Case Study: Measuring Security for a Coding Agent

A production coding agent is a principal with a changing view of a repository, access to tools, inherited credentials, and the ability to turn untrusted text into durable effects. A conventional model score therefore answers the wrong question. The deployment question is whether a particular agent, under a particular authority envelope, reduces engineering time without creating unacceptable paths from attacker-controlled context to protected assets.

This capstone joins the threat modeling, telemetry, evaluation, causal measurement, production engineering, and decision-writing methods developed earlier. The hypothetical agent, Forge, may read a granted repository, edit a disposable worktree, run approved build commands, and propose a pull request. It may not read arbitrary host files, retrieve production secrets, change branch protections, merge code, or deploy. Those are architecture properties, not prompt instructions.

Authority-centered threat model

The model uses four objects: principal, provenance, capability, and effect. A principal is the human, agent, or delegated subagent responsible for an operation. Provenance records which observations influenced it. A capability is an unforgeable, expiring grant scoped to a resource and action. An effect is the durable state change that follows.

Forge crosses five trust boundaries: the user's objective may be abusive; repository content is untrusted; model output is nondeterministic; tools translate proposals into filesystem, network, or CI effects; and external tool output can inject a second instruction stream. Protected assets include source integrity, developer credentials, proprietary code, CI identity, release artifacts, audit evidence, and availability.

The important abuse cases extend beyond the phrase prompt injection: credential discovery, cross-repository transfer, dependency substitution, test tampering, persistence in generated configuration, review evasion, resource exhaustion, and confused-deputy use of a developer's ambient authority.

Classification depends on arguments. git diff is S0; a push is S2; editing .github/workflows/release.yml is S3 although it is “just a file write.” Unknown tools and unparsed shell strings fail closed. This taxonomy is the join key across policy, telemetry, evaluation, and reporting.

Architecture: make effects pass through a broker

Forge never invokes a raw shell from model-generated text. It proposes a typed action such as RunBuild(target="//service:test", timeout_s=300) or CreateDraftPR(repo_id, base_sha, patch_digest). The broker checks resource scope, sensitivity, approval, expiry, and policy version. The sandbox mounts only the granted repository, supplies short-lived task credentials, filters egress, enforces compute budgets, and is destroyed afterward. A subagent receives a subset of its parent's grants; delegation only reduces authority.

The key invariant is

\[ executed(a) \Rightarrow grant(p,r,v,t) \land allow(a,v) \land args(a)=args_{checked}(a). \]

Checking one command and executing another is a time-of-check/time-of-use flaw. The broker therefore signs a canonical action digest, and an adapter accepts only that exact digest. Content-origin labels, secret scanning, immutable images, and review views provide defense in depth, but the broker remains authoritative when the model ignores every instruction.

Trace schema and privacy boundary

The trace must reconstruct effects without retaining proprietary prompts forever:

agent_trace(trace_id, parent_trace_id, task_id, tenant_hash,
 principal_type, model_release, orchestrator_release, policy_version,
 sandbox_digest, started_at, ended_at, terminal_state, tokens, wall_ms)

observation(trace_id, seq, observed_at, origin, resource_hash,
 content_digest, trust_label, redaction_profile, encrypted_payload_ref NULL)

action_decision(trace_id, seq, proposed_at, action_type,
 canonical_args_digest, sensitivity_class, capability_hash,
 decision, reason_code, approval_hash NULL, policy_latency_ms)

effect_receipt(trace_id, seq, executed_at, adapter, exit_class,
 bytes_read, bytes_written, egress_class, pre_digest, post_digest, artifact_ref)

Raw code and prompts have short tenant-controlled retention. Digests, origins, decisions, and effect summaries remain longer. Payload access is separately audited. Telemetry loss is a security event: no S2/S3 effect executes if the ledger cannot issue a durable receipt.

Evaluation and control coverage

An evaluation item is a versioned environment, objective, adversarial placement, permitted result, prohibited effects, and executable scoring program. The suite includes direct abuse, injections in READMEs and issues, poisoned tool output, malicious dependency names, encoded instructions, multi-turn escalation, and parent/subagent collusion. Adaptive evaluators see refusal reasons and attempt a second route.

For threat stratum \(k\), estimate compromise probability with uncertainty:

\[ \hat p_k=(x_k+1)/(n_k+2), \qquad P(compromise)=\sum_k w_kp_k. \]

Weights reflect production exposure: frequency of untrusted issues, network use, repository sensitivity, and action class. Report worst-stratum performance too, so a rare S4 bypass is not hidden by easy cases.

Control coverage is over attack paths, not an inventory. A path might be untrusted observation -> model adoption -> privileged proposal -> broker grant -> external effect. A control covers it only when a test demonstrates interruption of a required edge. Weighted residual exposure is

\[ R=\sum_j \lambda_j I_j(1-c_j)d_j, \]

where \(\lambda_j\) is path frequency, \(I_j\) impact, \(c_j\) demonstrated interruption probability, and \(d_j\) a detectability factor bounded above zero. Logging is not prevention.

The benign suite uses real maintenance tasks stratified by language, repository size, and developer experience. Outcomes include independently tested completion, false refusal, unnecessary approval, regression, p95 duration, cost, and override. For task \(i\):

\[ U_i=V_iC_i-C_{review}A_i-C_{delay}T_i-C_{badpatch}B_i. \]

Security and utility remain separate until a decision maker states exchange rates. A composite score must never allow time saved to cancel a catastrophic bypass.

Safe runnable Python lab

This standard-library lab does not execute commands. It applies capability policy to typed proposals.

from dataclasses import dataclass
from hashlib import sha256
import json

RANK = {"S0": 0, "S1": 1, "S2": 2, "S3": 3, "S4": 4}

@dataclass(frozen=True)
class Grant:
    principal: str
    repo: str
    actions: frozenset[str]
    max_class: str

@dataclass(frozen=True)
class Proposal:
    principal: str
    repo: str
    action: str
    sensitivity: str
    args: dict
    untrusted: bool = False

def digest(p):
    body = json.dumps(p.__dict__, sort_keys=True, separators=(",", ":"))
    return sha256(body.encode()).hexdigest()[:10]

def decide(g, p):
    if p.sensitivity == "S4": return "DENY", "prohibited_effect"
    if (p.principal, p.repo) != (g.principal, g.repo): return "DENY", "scope_mismatch"
    if p.action not in g.actions or RANK[p.sensitivity] > RANK[g.max_class]:
        return "DENY", "capability_missing"
    if p.untrusted and RANK[p.sensitivity] >= 2:
        return "REVIEW", "untrusted_to_external_effect"
    return "ALLOW", "bounded_capability"

g = Grant("agent-7", "payments", frozenset({"read", "edit", "draft_pr"}), "S2")
tests = [
 Proposal("agent-7", "payments", "edit", "S1", {"path":"src/tax.py"}),
 Proposal("agent-7", "payments", "draft_pr", "S2", {"base":"a18f"}, True),
 Proposal("agent-7", "payments", "deploy", "S4", {"env":"prod"}),
 Proposal("agent-7", "payroll", "read", "S0", {"path":"salary.csv"}),
]
for p in tests:
    decision, reason = decide(g, p)
    print(p.action, decision, reason)

Expected output:

edit ALLOW bounded_capability
draft_pr REVIEW untrusted_to_external_effect
deploy DENY prohibited_effect
read DENY scope_mismatch

Mutation test: change one approved argument after computing its digest and assert that the adapter rejects it. Production receipts must be authenticated and expiring; this demonstration digest is only a replay identifier.

Staged rollout and telemetry

Rollout moves through offline replay, employee red-team, shadow mode, S0 read-only, S1 sandboxed edits, then a small S2 draft-PR cohort. S3 remains approval-gated and S4 absent. Promotion requires no prohibited effect, an upper confidence bound below the class risk budget, trace completeness above 99.9%, stable accepted-task completion, and acceptable approval latency.

Online monitors separate model drift from enforcement failure: proposal mix by sensitivity and origin; deny/review reasons; canary-secret and out-of-scope access; approval acceptance and reversal; effect receipts without decisions (target zero); task success and abandonment; sandbox failures; and trace ordering or completeness anomalies.

Release eval design and statistical stopping

Each candidate is compared with the current release on a paired repository suite. Pairing matters because difficulty varies more across repositories than across repeated samples within one repository. For nondeterministic inference, run multiple seeded attempts and preserve sampling parameters. Report pass@1, which reflects ordinary use, and attack success across repeated attempts, because an attacker can retry. A safeguard that holds once but fails on the fifth paraphrase is not characterized by its first-attempt rate.

Rare catastrophic failures require different stopping logic from utility regressions. Zero S4 successes in a small suite does not establish zero risk; report an upper confidence bound. Any S4 adapter execution fails the release regardless of aggregate performance. S2 bypasses use a predeclared risk budget and sequential test with alpha spending, preventing repeated inspection until results look favorable. Benign completion and approval latency use equivalence margins agreed before testing.

Eval maintenance is a software supply chain. Items have owners, provenance, expected behavior, last review, and retirement reasons. Public attacks enter quarantine first so teams cannot tune directly against the test. A private holdout and rotating expert red-team set estimate generalization. Dashboards distinguish known-family regression retention from novel-family performance.

Human approval is a measured control

The review surface shows the requested effect, resource scope, security-relevant diff, influential content origins, and test evidence. It never asks a reviewer to approve opaque reasoning text. Approvals expire, bind to one action digest, and cannot authorize a changed retry.

Measure acceptance by action class, later reversal, time spent, and risky-effect escape. High acceptance combined with subsecond review suggests habituation. When volume exceeds capacity, restrict agent authority instead of silently turning approval into notification. Seeded exercises estimate whether reviewers notice secret additions, workflow mutations, and disguised egress. “Human in the loop” thus becomes a subsystem with measured workload and reliability limits.

Failure drills

Poisoned issue proposes egress. Freeze the release, revoke network grants, preserve the repo snapshot and trace, inspect whether the broker denied it, add transformations to replay, and search sibling traces by origin digest. A broker denial is a contained model-control near miss; an effect is an incident.

Ledger outage. S2/S3 fail closed. S0/S1 may continue only in isolated sandboxes with a bounded local queue. Reconciliation proves every queued decision has one terminal receipt.

Productivity cliff after a policy update. Compare matched tasks by reason-code transition, action class, and repository. Roll back the policy independently of the model. Workflow pain does not justify removing the authority boundary.

Final rollout memo

Decision: approve S0/S1 across internal repositories and S2 draft pull requests for a 5% cohort. Do not authorize autonomous merge, workflow-policy modification, secret access, or deployment.

Evidence: typed, digest-bound capabilities; prohibited actions absent from the tool surface; attack-path tests across repository, issue, dependency, and tool-output injections; complete effect receipts; and positive time savings after review cost. Residual uncertainty is highest for novel multi-step attacks and tenant-specific build tools.

Conditions: security owns taxonomy and stops; platform owns adapter invariants and ledger SLOs; model engineering owns replay performance; product owns refusal and approval friction. Expansion requires two stable releases, successful ledger and poisoned-repository drills, and independent red-team review. Any unmatched effect, canary-secret access, cross-repository read, or S4 adapter acceptance triggers rollback.

The memo does not claim “the agent is safe.” It names release, authority, population, evidence, uncertainty, owners, and the next reversible decision.

The decision registry also preserves rejected alternatives: unrestricted developer credentials, prompt-only policy, and immediate universal launch. Recording why they were rejected prevents later teams from rediscovering the same unsafe shortcuts after personnel or product strategy changes. The next review compares actual exposure, utility, and incidents with the memo's assumptions.

Interview Practicum

You lead security measurement for a coding agent used by 4,000 engineers. A red team hid an instruction in a test fixture; the agent attempted to upload a private config to a paste service, but the network proxy blocked it. Product says no breach occurred and wants universal draft-PR launch next week. Security wants shutdown. Raw prompts expired under a seven-day privacy policy, but action metadata remains. Present a decision in 20 minutes and ask for only five facts.

Worked Answer

I would ask: which broker decision preceded egress; whether the destination was denied by the agent-specific allowlist or an unrelated corporate proxy; what alternative egress tools existed; how many traces observed the fixture digest; and what new authority draft-PR mode adds.

This is not proof of safety. It is a demonstrated model-control failure and possibly successful defense in depth. If the broker lacked an egress capability and denied the typed action before the proxy, the architecture held. If it allowed the call and a generic proxy happened to intervene, the agent boundary failed.

I would preserve the fixture, releases, action digests, receipts, and sandbox image; search by observation digest; revoke unnecessary network grants; and add this family to adaptive replay. Deleted raw prompts limit semantic reconstruction but should not prevent reconstructing origin, proposal, decision, and effect. If they do, the schema is inadequate.

I would allow continued S0/S1 only if there was no out-of-scope effect and telemetry is complete. I would hold broad S2 expansion until the team proves draft PRs cannot carry secrets or attacker-controlled links, reruns the family against the candidate, and computes a stratum-specific risk bound. A small canary may proceed with network-deny defaults, scanning, human review, and stops.

The Principal move is to split ownership: platform owns a broker defect, model engineering owns instruction adoption, product owns friction, and security owns risk acceptance. I would document the counterfactual without the proxy and the incremental effect enabled by S2. The answer is a reversible capability-specific rollout, not a vote on whether the model is trustworthy.

Follow-Up Questions and Answers

What if it was one failure in a million tasks? Use exposures to the malicious pattern as the denominator, report the stratum rate and uncertainty, then weight by production prevalence without hiding severity.

How do you estimate false refusals? Sample by reason code and task stratum, replay with independent test oracles, and combine adjudication with abandonment and manual-completion evidence. Random audits correct policy-selected labels.

Store prompts longer? Not automatically. Test encrypted incident sampling against privacy cost. Durable provenance, decisions, and effects are mandatory; full prompt retention is not.

What forces shutdown? An executed prohibited effect, cross-tenant access, an adapter accepting an unmatched action, agent-disabled audit, or loss of containment without reliable reconstruction.

Key Takeaways

  • Govern a coding agent by executable authority, not its system prompt.
  • Typed capabilities and sandboxed adapters turn model failures into containable proposals.
  • Connect untrusted observations to decisions and effects while minimizing content retention.
  • Evaluate adaptive attack paths, production exposure, uncertainty, and benign utility separately.
  • Rollout memos must name action classes, population, stops, evidence gaps, and owners.
