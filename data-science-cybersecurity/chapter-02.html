Chapter 2: Data Types, Structures, and When to Use Them

A security lake receives four objects: an authentication event, an analyst paragraph, a NetFlow record, and an identity-entitlement edge. They all concern the same investigation, but forcing them into one wide table destroys meaning. This chapter treats representation as type design. We will build a catalog, inspect a mixed fixture, and show which operations are valid for each field.

A Type System for Security Evidence

A data type is a set of possible values plus valid operations. Storage syntax is secondary. An IPv4 address stored as an integer is not a quantity; adding two addresses is meaningless. A severity encoded 1–5 is ordered, but the distance from 1 to 2 need not equal the distance from 4 to 5. A timestamp is not a duration. These distinctions prevent silent analytical errors.

Numeric families

Counts are nonnegative integers: failed logins, packets, findings. Their variance often grows with the mean, and exposure differs, so rates may be more comparable. Continuous measurements include latency and bytes after aggregation. Ratio-scale values have a meaningful zero; ratios are meaningful. Interval-scale values have meaningful differences but an arbitrary zero, as with Celsius. Money is ratio-like within a currency and valuation time, but exchange and inflation complicate comparisons.

A rate needs numerator, denominator, and interval. failures_per_attempt differs from failures_per_minute. Store the components when possible; a precomputed rate hides low-denominator instability.

Categorical families

Nominal categories such as operating system have equality but no order. Ordinal categories such as low/medium/high have order but unknown spacing. Binary flags need explicit positive semantics. Multilabel observations may carry several ATT&CK techniques. High-cardinality categories—user IDs, device IDs, process hashes—are identifiers, not automatically model-ready categories.

Encoding nominal values as integers invents order. One-hot encoding can explode dimensions. Hashing trades collisions for bounded size. Learned embeddings can capture similarity but require enough data and careful unknown handling. The choice follows the task, not the source database type.

Time is several types

A UTC timestamp identifies an instant. A local calendar value depends on a timezone and daylight-saving rules. A duration measures elapsed time. A sequence preserves order. A time series associates measurements with regular or irregular times. An event stream adds arrival behavior: late, duplicated, and out-of-order messages.

Store RFC 3339 timestamps with offsets at boundaries and normalize instants to UTC internally. Preserve source timezone where local business behavior matters. Never infer elapsed time by subtracting naive local timestamps across a daylight-saving transition.

Text, code, and documents

Analyst notes are not merely long categories. They contain tokens, sentences, entities, assertions, negation, uncertainty, and sensitive data. Source code has syntax trees and control flow. Prompts have roles and message boundaries. Security reports have sections, citations, indicators, and provenance.

Representations include raw immutable text, normalized text for search, token or n-gram features, embeddings for retrieval, and structured extractions. Retain offsets from extracted facts back to source spans. An embedding is a lossy index, not evidence; investigators must recover the original passage.

Network and spatial values

IP addresses support prefix membership, version, and equality—not arithmetic distance as ordinary integers. Ports are bounded identifiers with conventions, not continuous quantities. Latitude and longitude require spherical distance and privacy controls. “Country” may describe IP geolocation, billing, residence, or legal entity; name the semantics and provider version.

NetFlow is a directional summary with source/destination addresses and ports, protocol, byte and packet counts, and interval. Reversing direction changes interpretation. NAT and proxies mean an address is not an identity.

Graphs

An identity graph contains typed nodes and edges: user member_of group, service principal has_role subscription, device managed_by tenant. Edges often have validity intervals and provenance. A static adjacency table loses the difference between current and historical permission.

Graph questions include reachability, shortest attack path, neighborhood aggregation, centrality, and community structure. Exporting degrees into a tabular model is useful but cannot answer arbitrary path queries. Graph storage is justified by traversal workload, not visual appeal.

Binary, packet, image, audio, and multimodal evidence

Executable bytes support hashes, sections, imports, entropy, and disassembly. Packet captures preserve payload and timing but raise storage and privacy costs. Screenshots may contain phishing cues and text. Audio may contain voice, timing, and codec artifacts. A multimodal record must preserve modality-specific preprocessing and synchronization; concatenating unrelated vectors does not create coherent evidence.

Shape: How Observations Relate

Cross-sectional data take one measurement per unit. Longitudinal data repeat units. Panel data organize multiple units across times. Cohort data align units by an origin such as enrollment. Survival data record time to outcome plus censoring. A user with no observed takeover by study end is right-censored, not proven permanently safe.

Structured data have explicit fields; semi-structured events have envelopes plus variable nested payloads; unstructured artifacts lack a uniform field model. “Unstructured” does not mean structure-free: documents and binaries have rich internal grammars.

Static snapshots answer state questions. Streams answer timely change questions but require watermarks, idempotency, and late-data policy. A snapshot of permissions cannot reconstruct which access existed at incident time unless validity history is retained.

Schema Catalog: One Investigation, Four Stores

Authentication event envelope

auth_event
  event_id: uuid                  identity, not a feature magnitude
  occurred_at: timestamp[UTC]     source-reported instant
  observed_at: timestamp[UTC]     collector availability
  principal_id: opaque_id         join key with tenant scope
  outcome: enum{success,failure,challenge}
  source_ip: ip_address
  factors: set<enum>
  latency_ms: duration
  raw: json                       immutable source payload

The envelope is append-only. Corrections become new records or versioned normalization outputs. observed_at makes point-in-time reconstruction possible.

Analyst document

case_note
  note_id: uuid
  case_id: opaque_id
  author_role: enum
  created_at: timestamp[UTC]
  body: sensitive_text
  assertions: list<{span, predicate, object, confidence}>
  embedding_model: nullable model_version
  embedding: nullable vector<float>

Access control applies to source text and derived vectors. Assertions preserve span provenance and distinguish “user denied travel” from “user traveled.”

Flow fact

network_flow
  sensor_id: opaque_id
  start_at/end_at: timestamp[UTC]
  src/dst_ip: ip_address
  src/dst_port: uint16
  protocol: enum
  packets/bytes: count
  sampling_rate: probability

Sampled counts require weighting. Zero packets is not the same as missing telemetry.

Temporal identity edge

identity_edge
  subject_id/object_id: scoped_id
  relation: enum
  valid_from: timestamp[UTC]
  valid_to: nullable timestamp[UTC]
  asserted_at: timestamp[UTC]
  source: system_version

valid_to IS NULL means currently open, not unknown forever. An as-of query requires valid_from <= t and (valid_to > t or null), plus asserted_at <= t if replay must respect availability.

Lab: Inspect and Type a Mixed Fixture

The lab uses only the standard library. It rejects seductive coercions and emits a compact dictionary.

from datetime import datetime
from ipaddress import ip_address
import json

records = [
    {"field": "attempts", "value": 12, "logical": "count"},
    {"field": "severity", "value": "high", "logical": "ordinal"},
    {"field": "principal_id", "value": "00731", "logical": "opaque_id"},
    {"field": "occurred_at", "value": "2026-08-20T13:45:00Z", "logical": "instant"},
    {"field": "source_ip", "value": "2001:db8::8", "logical": "ip_address"},
    {"field": "analyst_note", "value": "User denies this sign-in.", "logical": "sensitive_text"},
    {"field": "techniques", "value": ["T1078", "T1110"], "logical": "set[nominal]"},
]

def validate(row):
    value, kind = row["value"], row["logical"]
    if kind == "count":
        assert isinstance(value, int) and value >= 0
    elif kind == "ordinal":
        assert value in {"low", "medium", "high", "critical"}
    elif kind == "opaque_id":
        assert isinstance(value, str)
    elif kind == "instant":
        datetime.fromisoformat(value.replace("Z", "+00:00"))
    elif kind == "ip_address":
        value = f"IPv{ip_address(value).version}"
    elif kind == "set[nominal]":
        assert len(value) == len(set(value))
        value = sorted(value)
    elif kind == "sensitive_text":
        value = f"{len(value.split())} tokens (redacted)"
    return {"field": row["field"], "logical_type": kind, "preview": value}

for item in records:
    print(json.dumps(validate(item), sort_keys=True))

Expected output:

{"field": "attempts", "logical_type": "count", "preview": 12}
{"field": "severity", "logical_type": "ordinal", "preview": "high"}
{"field": "principal_id", "logical_type": "opaque_id", "preview": "00731"}
{"field": "occurred_at", "logical_type": "instant", "preview": "2026-08-20T13:45:00Z"}
{"field": "source_ip", "logical_type": "ip_address", "preview": "IPv6"}
{"field": "analyst_note", "logical_type": "sensitive_text", "preview": "4 tokens (redacted)"}
{"field": "techniques", "logical_type": "set[nominal]", "preview": ["T1078", "T1110"]}

The leading zeros in principal_id survive because it is not a number. IPv6 is validated without logging the address. The multilabel set is canonicalized. The note preview avoids reproducing sensitive text.

Mixed-Data Representation Lab

One investigation can be rendered as table, sequence, document retrieval result, and graph neighborhood. Each view answers a different query.

from collections import Counter, defaultdict

auth = [
    ("u1", 1, "failure", "d1"),
    ("u1", 2, "success", "d2"),
    ("u2", 3, "success", "d3"),
]
notes = {"u1": "customer denies login from new device"}
edges = [("u1", "member_of", "admins"), ("admins", "can_access", "billing")]

print("tabular", dict(sorted(Counter(x[2] for x in auth).items())))
print("sequence", [x[2] for x in sorted(auth) if x[0] == "u1"])
query = {"denies", "device"}
hits = [uid for uid, text in notes.items() if query <= set(text.split())]
print("text_hits", hits)

graph = defaultdict(list)
for left, relation, right in edges:
    graph[left].append((relation, right))
frontier = ["u1"]
paths = []
for _ in range(2):
    node = frontier.pop(0)
    for relation, nxt in graph[node]:
        paths.append(f"{node}-{relation}->{nxt}")
        frontier.append(nxt)
print("graph", paths)

Expected output:

tabular {'failure': 1, 'success': 2}
sequence ['failure', 'success']
text_hits ['u1']
graph ['u1-member_of->admins', 'admins-can_access->billing']

The count view loses order; the sequence preserves it. Keyword retrieval finds a note but not its truth. The graph exposes transitive access. No single representation dominates.

Labels, Weak Labels, and Censoring

A confirmed incident label may be precise but selected: only alerted cases receive investigation. A user report is weak evidence with variable delay. A vendor verdict can change. A rule hit is a heuristic label, not ground truth. Keep label source, version, time, and confidence separate from the target.

Unobserved does not mean negative. In survival data, an account observed for seven days without ATO is censored at seven days. In positive-unlabeled learning, unlabeled examples contain negatives and undiscovered positives. In streaming systems, a late label may revise an earlier training snapshot. Schema catalogs should therefore describe outcome maturity and revision behavior.

Catalog Governance and Compatibility

A data dictionary becomes useful when it is executable. Each field entry should include logical type, null semantics, unit, allowed range or vocabulary, sensitivity classification, owner, source, event-time meaning, availability expectation, retention, and known revisions. Examples are valuable, but examples cannot replace constraints.

Schema compatibility has several dimensions. A change can be syntactically additive yet semantically breaking: keeping country as a string while changing it from billing country to IP-geolocation country will pass parsers and corrupt trends. Renaming an enum is obvious; changing the population represented by a boolean is not. Version meaning, not merely serialization.

Producers should publish contract tests. Consumers should test unknown enum values, absent optional fields, duplicates, delayed events, and mixed schema versions. Rejecting every new value creates outages; silently mapping every unknown to “other” can hide attacks and rollout defects. The contract must state whether unknown means unsupported, newly introduced, malformed, or intentionally withheld.

For privacy, classify derived data as carefully as raw data. Hashing an email does not make it anonymous when the hash is stable and linkable. Embeddings may retain sensitive semantic information. Graph neighborhoods can reveal privileged roles. Apply tenant scope, access control, deletion obligations, and retention to derivatives, indexes, caches, and training snapshots.

Choosing Physical Layout from Access Patterns

Logical modeling precedes physical layout. Columnar files suit scans over selected fields and compress repeated values. Row stores suit keyed transactional reads. Inverted indexes suit lexical retrieval. Vector indexes suit approximate semantic neighbors. Graph engines suit variable-depth traversal. Stream logs suit ordered append and replay. These are workload claims that should be benchmarked.

Partitioning by date accelerates bounded time scans but can create tiny files at low volume. Partitioning by high-cardinality user ID is usually disastrous. Clustering or sorting by tenant and time may improve pruning without creating a directory per identity. Storage statistics themselves can leak tenant size, so operational metadata also needs authorization.

Materialized representations need freshness contracts. An online feature may use a five-minute identity-neighborhood cache while an investigator queries the authoritative temporal graph. Both are correct for their declared use, but they are not interchangeable. Record build time, source watermark, and transformation version so disagreement can be explained.

Representation choices should be reversible where uncertainty is high. Preserve an immutable canonical artifact, then derive tables, indexes, vectors, and graph projections. Reversibility does not mean retaining everything forever; retention and deletion must be enforced at the canonical and derived layers. It means avoiding an irreversible lossy transform as the only surviving evidence.

Benchmark with representative queries before adopting another store. Measure ingest throughput, bounded-time scans, key lookup latency, traversal depth, retrieval recall, authorization overhead, backfill duration, and deletion propagation. Include failure experiments: one region unavailable, an index six hours stale, or a schema version arriving early. A fast happy-path benchmark says little about investigative reliability. Document the exit cost, including how canonical data can be exported without losing temporal semantics. Specialized infrastructure is justified when it produces a measured capability the existing platform cannot meet, not when its data model merely resembles a whiteboard drawing. Measure semantics first; optimize their physical execution second.

Interview Practicum

The Architecture Whiteboard

Prompt and constraint cards

“Represent authentication events, analyst notes, NetFlow, and an identity graph for detection and investigation.” Then the panel reveals: notes contain regulated data; flows are sampled 1:100; entitlement edges arrive up to six hours late; investigators need 90-day replay; and the feature service needs results in 100 ms.

Worked Answer

Strong answer

Use an immutable event envelope for authentication with occurrence and observation times. Store typed normalized columns beside raw versioned payloads. Partition by event date and tenant, but avoid putting sensitive identity values in paths. Use a protected document store and inverted/vector indexes for notes; retain source spans and apply the same access policy to embeddings.

Store flows in a columnar fact table with direction, interval, counters, and sampling rate. Weighted aggregate estimates may multiply counts by 100, but uncertainty and collector loss must be distinguished. Store temporal identity edges with validity and assertion intervals. Materialize bounded neighborhoods for the low-latency feature path while keeping a graph-capable historical store for replay.

Use scoped stable IDs and a governed identity-resolution table. Do not join on email text or IP. Every derived object records source versions and as-of time. The 100-ms service reads precomputed typed features; investigation queries can tolerate slower document and graph traversal. Replay blocks facts whose observation time exceeds the historical decision time.

Tradeoffs

A single warehouse simplifies governance and batch joins but may serve graph traversal and text retrieval poorly. Specialized stores improve workloads but multiply consistency and authorization surfaces. Choose the smallest set that meets measured workloads, and publish canonical semantics centrally. Parquet is efficient for scans, not point mutation. A graph database helps variable-depth traversal, not simple one-hop joins. Vector retrieval improves semantic recall but requires evaluation and source recovery.

Weak answers

  • “Put everything in JSON” avoids schema design and weakens constraints.
  • “Use a graph database for all data” confuses connectedness with every workload.
  • “Convert IDs and IPs to integers” invents numeric meaning and breaks formatting.
  • “Embed the notes and delete text” discards evidence and provenance.
  • “Missing edge means no access” ignores late arrival and sensor coverage.

Follow-Up Questions and Answers

Follow-up probes with answers

How do you version a schema without breaking consumers? Use additive evolution by default, stable field identifiers, compatibility tests, explicit semantic versions for changed meaning, and dual-read migration for breaking changes.

How do you represent a deleted entitlement? Close the edge validity interval; do not delete historical state required for replay. Record when the deletion assertion became available.

Can sampled NetFlow identify one connection? No. Sampling supports certain aggregate estimates; it does not reconstruct omitted individual flows. State the sampling mechanism before weighting.

How do you test embeddings containing sensitive notes? Apply document authorization before retrieval, test cross-tenant isolation and memorization risks, minimize retained text, and log access without exposing content.

Communication drills

Thirty seconds: “Keep four canonical forms: typed immutable events, protected documents with span provenance, directional sampled flow facts, and temporal identity edges. Join them through scoped IDs and as-of semantics; materialize only the low-latency features needed online.”

Five minutes: Walk through logical types, canonical stores, transformations, workload indexes, late data, replay, privacy, and why no universal table or database is appropriate.

Key Takeaways

  • Logical type determines valid operations; physical storage does not create semantics.
  • Preserve counts and exposures, instants and durations, validity and availability.
  • IDs, IPs, ports, ranks, and timestamps must not be coerced into false quantities.
  • Text embeddings, graph features, and aggregates are derived views, not substitutes for evidence.
  • Censoring, weak labels, sampling, and late arrival belong in the schema contract.
  • Mixed security investigations need interoperable representations, not one universal shape.
