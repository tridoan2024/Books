Chapter 21: Experiments in High-Stakes Environments

Security teams often ask for an A/B test after the consequential design choice has already been made. A product team wants to enable automatic session revocation, require approval for an agent tool call, or block a suspicious OAuth grant. “Treatment” can therefore mean denying work, exposing a customer to an attack, or changing what the attacker observes. Ordinary experimentation advice—randomize users, watch conversion, ship the winner—does not survive those facts.

A defensible security experiment begins with an intervention envelope: which actions may vary, for whom, for how long, and with what automatic escape route. Randomization is useful only inside that envelope. It removes confounding; it does not make an unethical comparison ethical, make a rare incident common enough to measure, or prevent spillovers between units.

This chapter develops a concrete design for testing a step-up approval control on high-risk administrative actions. It does not withhold the established baseline control. It compares the baseline with an additive candidate, starts with non-enforcing replay and shadow stages, randomizes by tenant rather than event, and treats safety limits as executable policy.

Define the Experimental Object

Suppose an enterprise platform currently requires reauthentication for exporting more than 10,000 records. A proposed control also requires an independent approver when the request is made by an unfamiliar device or an automation agent. The security hypothesis is:

For eligible export attempts, adding independent approval reduces completed unauthorized exports without causing unacceptable delay or abandonment of legitimate exports.

The unit of assignment is the tenant. The unit of observation is an eligible export attempt. Users within one tenant share administrators, policy, attackers, and support channels. Event-level assignment would let a user learn the treatment from one request and alter a later control request; it could also apply inconsistent policy to one incident. Cluster assignment reduces that interference, although it increases variance.

Eligibility is fixed before assignment:

event_type = "bulk_export_requested"
record_count >= 10_000
actor_type IN ("human_admin", "automation_agent")
tenant has approval feature configured
request is not an emergency break-glass operation

Break-glass operations are excluded rather than randomized because delayed recovery can amplify harm. Tenants under active incident response are also removed and analyzed separately. Exclusion changes the target population; the final claim must say “configured tenants outside active incidents,” not “all customers.”

A schema that can reconstruct the decision

CREATE TABLE export_control_observation (
    request_id             TEXT PRIMARY KEY,
    tenant_id              TEXT NOT NULL,
    cluster_arm            TEXT NOT NULL
                           CHECK (cluster_arm IN ('baseline','candidate')),
    assignment_version     TEXT NOT NULL,
    requested_at           TEXT NOT NULL,
    actor_type             TEXT NOT NULL,
    unfamiliar_device      INTEGER NOT NULL CHECK (unfamiliar_device IN (0,1)),
    record_count           INTEGER NOT NULL CHECK (record_count >= 10000),
    decision               TEXT NOT NULL
                           CHECK (decision IN ('allow','challenge','deny')),
    approval_latency_s     REAL,
    completed              INTEGER NOT NULL CHECK (completed IN (0,1)),
    confirmed_unauthorized INTEGER CHECK (confirmed_unauthorized IN (0,1)),
    outcome_mature_at      TEXT,
    policy_version         TEXT NOT NULL,
    sensor_complete        INTEGER NOT NULL CHECK (sensor_complete IN (0,1))
);

confirmed_unauthorized remains null until the investigation window closes. Converting null to zero makes the newest arm look safest. Assignment is stored separately from decision because policy defects, exemptions, or outages create noncompliance. The intention-to-treat estimate uses assignment; an “as treated” comparison inherits the operational selection randomization was meant to remove.

Select a Design the System Can Sustain

The candidate passes through four evidence stages:

  1. Replay: apply the proposed policy to historical events using only fields available at event time. Replay finds workload and compatibility failures but cannot estimate behavioral response.
  2. Shadow: calculate and log the candidate decision without enforcing it. Sample disagreements between candidate and baseline for security and product review.
  3. Canary: enforce the candidate for consenting internal or low-dependency tenants. Stop automatically on safety limits.
  4. Cluster-randomized rollout: assign eligible tenant clusters to baseline or candidate, stratified by size and historical export rate.

A holdback is defensible only while genuine uncertainty remains and both arms meet the accepted minimum standard. Once the candidate is established as materially safer at tolerable cost, a permanent untreated group becomes difficult to justify. Continued learning can compare two safe variants, use randomized encouragement, or exploit scheduled rollout order.

Cluster and switchback designs answer different questions

Cluster randomization is appropriate when treatment persists or spills across actors. If a tenant contains an average of m requests and intracluster correlation is rho, the design effect is D = 1 + (m - 1) * rho. With m = 40 and rho = 0.05, D = 2.95: nearly three times the individually randomized sample is required. More events inside one large tenant do not substitute for independent tenants.

A switchback assigns a whole environment to alternating policies across time blocks. It can work for a SOC queue or global rate limiter when simultaneous arms contaminate one another. It fails when treatment has carryover: an approval learned Monday affects Tuesday, an attacker can wait for a baseline interval, and a revoked token does not become unrevoked at a boundary. Blocks need randomized order and justified washout periods; predictable alternation is an attack schedule.

Estimands, Rare Outcomes, and Power

For tenant j, let Z_j denote candidate assignment and Y_ij(z) indicate whether request i would become an unauthorized completed export under arm z. The primary intention-to-treat estimand is tau = E[Y(1) - Y(0) | eligible and assigned].

reported as a risk difference and risk ratio. A negative risk difference favors the candidate. Analysis clusters uncertainty by tenant and includes the predeclared size strata used in randomization.

For independent proportions with baseline risk p0, candidate risk p1, type-I error alpha, and power 1 - beta, sample size grows with outcome variance and inversely with (p1 - p0)^2. Halving the minimum detectable absolute effect therefore requires roughly four times as much independent information, before cluster inflation.

If unauthorized completion falls from 0.10% to 0.07%, millions of requests may be required before cluster inflation. No dashboard repairs that information limit. Run longer, broaden the population without changing the question, use a validated intermediate outcome, or acknowledge that the study can rule out only large effects.

“Candidate challenged the request” measures mechanism execution, not prevented loss. Better supporting outcomes include confirmed malicious requests stopped before transfer and adversarial test attempts completing the protected action. They supplement rather than replace mature production incidents.

Guardrails as Executable Safety Policy

A control could reduce unauthorized exports by breaking all exports. Pre-register guardrails with denominators and actions:

  • legitimate completion must not decline by more than 2 percentage points;
  • p95 approval latency must remain below 180 seconds;
  • attributable support contacts must remain below 3 per 1,000 challenges;
  • queue age above 10 minutes degrades to reauthentication;
  • any confirmed candidate-policy bypass pauses expansion;
  • sensor completeness below 99.5% invalidates automated comparison.

Some are engineering limits, not hypothesis tests. One severe bypass can stop expansion even when its p-value is uninteresting. Conversely, a five-minute latency spike should not terminate a month-long trial. The runbook specifies persistence, severity, owner, and recovery.

Repeatedly inspecting fixed-horizon p-values inflates false positives. Inspect at predeclared information times with alpha spending, use a sequential probability ratio test for a sharply defined effect, or use confidence sequences valid under optional stopping. “We looked daily but waited for p < .05” is not sequential analysis.

Safe Runnable Lab: Simulate a Cluster Trial

This standard-library fixture creates 80 synthetic tenants, simulates legitimate delay and a security outcome, and calculates tenant-weighted risk. It is seeded and contains no operational data.

from __future__ import annotations

import random
from collections import defaultdict
from statistics import mean, quantiles

rng = random.Random(2101)
rows: list[dict[str, object]] = []

for tenant_number in range(80):
    size = "large" if tenant_number < 20 else "small"
    arm = "candidate" if tenant_number % 2 else "baseline"
    requests = 80 if size == "large" else 20
    tenant_risk = rng.uniform(0.6, 1.4)
    for _ in range(requests):
        malicious = rng.random() < 0.08 * tenant_risk
        block_probability = 0.72 if arm == "candidate" else 0.35
        unauthorized = int(malicious and rng.random() > block_probability)
        legitimate = not malicious
        latency = rng.lognormvariate(3.6 if arm == "candidate" else 2.4, 0.35)
        completed = int((not malicious or not unauthorized) and latency < 180)
        rows.append({
            "tenant": f"t{tenant_number:02d}", "arm": arm,
            "malicious": malicious, "unauthorized": unauthorized,
            "legitimate": legitimate, "completed": completed, "latency": latency,
        })

by_tenant: dict[tuple[str, str], list[dict[str, object]]] = defaultdict(list)
for row in rows:
    by_tenant[(str(row["tenant"]), str(row["arm"]))].append(row)

tenant_rates: dict[str, list[float]] = defaultdict(list)
for (_, arm), events in by_tenant.items():
    tenant_rates[arm].append(mean(float(e["unauthorized"]) for e in events))

risk = {arm: mean(values) for arm, values in tenant_rates.items()}
risk_difference = risk["candidate"] - risk["baseline"]
legitimate = [r for r in rows if r["arm"] == "candidate" and r["legitimate"]]
completion = mean(float(r["completed"]) for r in legitimate)
p95_latency = quantiles([float(r["latency"]) for r in legitimate], n=20)[18]

print(f"tenant-weighted risk difference={risk_difference:.4f}")
print(f"candidate legitimate completion={completion:.3f}")
print(f"candidate p95 latency={p95_latency:.1f}s")

assert risk_difference < 0, "fixture should show lower unauthorized completion"
assert completion > 0.97, "legitimate completion guardrail failed"
assert p95_latency < 180, "latency guardrail failed"

Expected output has a negative risk difference, legitimate completion above 0.97, and p95 latency below 180 seconds. The assertions encode the fixture’s intended claims. Production work needs cluster-robust intervals or randomization inference, both tenant- and event-weighted effects, and sensitivity to dominant tenants.

Production Failure Analysis

Sample-ratio mismatch. Nominal 50/50 assignment becomes 60/40 because failing candidate requests disappear before logging. Audit assignment before outcomes and retain pre-decision exposure records.

Novelty effects. Approval delays are high in week one and then fall. Report effects by time since activation and declare whether the estimand includes ramp-up.

Differential ascertainment. Candidate challenges create investigations, which discover more attempted abuse. The candidate may appear to increase attacks because observation improved. Use arm-independent audit sampling and separate attempts from successful harm.

Cross-cluster interference. A centralized attacker targets both arms, or one approval team services every tenant. Map interference paths before selecting the unit. If isolation is impossible, estimate policy effect at the shared-system level.

Attacker adaptation. Publicly predictable holdbacks invite targeting. Do not expose assignment, do not rely on secrecy, and stop if the experiment becomes a targeting oracle.

Delayed labels. Early reports treat unresolved requests as benign. Freeze the primary analysis only after its outcome window matures and show censoring during operation.

Noncompliance. Approvers bypass the workflow or exemptions expand. Report intention-to-treat as primary, execution as a mechanism measure, and exemption reasons as product defects.

What the Sources Contribute

Pre-launch review record

The approval document should contain enough detail for a reviewer to reject the study before any user is exposed. Record the exact randomization code and seed management, cluster exclusions, stratification variables, anticipated sample-ratio tolerance, outcome maturation date, planned information times, and every person authorized to pause or resume. Include a table mapping each telemetry field to its producer and freshness objective. A field that exists in a warehouse but arrives after the decision cannot justify the online policy.

Run an A/A test through the complete assignment and analysis path. An A/A test will not prove the absence of bias, but it can expose broken hashing, inconsistent eligibility, repeated assignment, cluster leakage, and confidence intervals that are too narrow. Inject synthetic stop events to verify that alerts reach an on-call owner and that degradation actually changes policy. Finally, rehearse analysis on a blinded arm label. If conclusions change after labels are revealed, undisclosed researcher degrees of freedom have entered the process.

The decision memo must distinguish three outcomes: evidence supports expansion; evidence supports stopping; and the experiment is inconclusive at the available information. “No statistically significant harm” is not equivalent to safety, especially when the confidence interval still includes an operationally unacceptable increase.

Archive the assignment manifest and signed protocol with the release artifact. Future analysts must be able to distinguish a planned exclusion from a post-result deletion and a safety pause from ordinary missing traffic. That provenance is part of the experimental result.

Retain it for every arm, phase, pause, restart, and emergency policy revision.

Kohavi, Tang, and Xu supply disciplined assignment, sample-ratio checks, guardrails, and experimentation operations. Security adds an important boundary: an inferior arm can expose harm and assignment can become adversarially observable.

The CONSORT cluster extension forces explicit treatment of clusters, recruitment timing, and intracluster correlation—directly relevant to tenant rollouts. Wald explains why stopping must be part of the test, not an improvised dashboard reaction. Statsmodels implements conventional power calculations, but results remain conditional on baseline rate, effect, independence, and attrition. NIST SP 800-30 contributes the risk frame: experiment approval considers impact and uncertainty, not identifiability alone.

Interview Practicum

Scenario: The Safe Arm Changes Midstream.

Prompt. Product wants an A/B test of a control requiring approval before an AI agent exports customer data.

A strong candidate asks what protects users today, whether the candidate can accidentally authorize, what unit contains spillovers, how enforcement is disabled, how unauthorized exports mature, and whether attackers can observe assignment.

Worked Answer

Start with replay, shadow disagreement review, then tenant-cluster randomization against reauthentication. Stratify on tenant size and historical volume. The primary analysis is intention-to-treat mature unauthorized completion. Guardrails cover legitimate completion, approval latency, support burden, sensor completeness, and severe bypass. Assignment, execution, and outcome remain separate records.

Follow-Up Questions and Answers

Constraint change. Two weeks into shadow mode, red teaming finds that the baseline is bypassable for service accounts. Legal says knowingly retaining it is unacceptable.

Patch every arm immediately. The original comparison ends because treatment versions changed and equipoise disappeared. Preserve it as a superseded phase. After verifying the universal patch, ask a new question: does independent approval add benefit beyond the repaired baseline? Issue a new protocol and assignment version, recalculate power because baseline risk fell, and restart staged rollout. If the remaining outcome is too rare, use bounded adversarial evaluation plus production guardrails rather than claiming equivalence.

Second constraint. The approval service is global, so candidate tenants increase baseline latency.

No-interference is false. Reserve capacity by arm, randomize service shards, or use guarded switchbacks if carryover is short. If none isolates exposure, estimate a system-level policy effect. Do not publish tenant-level A/B standard errors.

Weak answers withhold all protection, optimize challenge rate, ignore clustering, or promise to “monitor p-values.” Staff-level reasoning distinguishes ethical from statistical stops. Principal-level reasoning recognizes that a baseline defect changes the allowable intervention, estimand, and governance record.

Thirty-second answer. Randomize only between controls meeting minimum safety, assign by tenant, and stage replay through canary before enforcement. Measure mature unauthorized completion with executable friction and safety guardrails. If evidence makes an arm unsafe, patch all arms, close the phase, and start a newly versioned experiment.

Key Takeaways

  • Randomization removes confounding in expectation; it does not grant ethical permission or eliminate interference.
  • Assignment must follow spillovers, shared operations, and attacker learning.
  • Rare outcomes impose hard power limits; mechanism metrics do not automatically substitute for harm.
  • Guardrails need denominators, persistence rules, owners, and recovery actions.
  • A newly unsafe baseline ends the old comparison and requires a new protocol.
