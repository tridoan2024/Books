Chapter 35: Instrumenting AI Agents for Security Evidence

A Trace Must Answer a Forensic Question

An agent trace is not a transcript. A transcript helps a developer watch a demo; security evidence must establish who initiated a run, what evidence influenced it, which policy authorized each consequential action, what tool actually executed, and whether the record was altered. Storing every prompt forever is neither necessary nor defensible. It increases breach impact while still failing to prove provenance.

Chapter 34 modeled authority paths. Instrumentation should make those typed edges observable. If a coding agent deploys an artifact, an investigator needs the proposal digest, approver, policy version, credential lease, tool request and response, artifact identity, and ordering relationship. The exact prose of an unrelated brainstorming turn may add privacy risk without forensic value.

Typed Trace Envelope

Use a small stable envelope with typed payloads. Required envelope fields are trace_id, event_id, parent_id, sequence, event_time, ingest_time, actor, event_type, schema_version, policy_version, sensitivity, payload_digest, previous_hash, and event_hash. Payloads vary by event type but are schema-validated.

Event typeRequired payload fieldsSecurity question
run.startedinitiator, tenant, objective digestWho requested what?
evidence.observedsource type, locator, content digest, trust labelWhat influenced reasoning?
model.completedprovider, model, input/output digests, finish reasonWhich model transformation occurred?
tool.proposedtool, canonical arguments digest, consequence classWhat did the agent intend?
policy.decideddecision, reason codes, subject, object, actionWhy was it allowed or denied?
approval.recordedprincipal, proposal digest, expiryWhat exactly was approved?
tool.completedtool version, result digest, status, side effectsWhat actually happened?
memory.changednamespace, old/new digest, provenance, expiryWhat durable state changed?
run.endedoutcome, terminal reason, evidence summary digestHow did the run terminate?

Free-form text is referenced through protected content objects rather than copied into every event. Store a salted digest, classification, encrypted locator, retention class, and redacted preview. High-sensitivity content may be deleted while the event envelope and digest remain, proving that a particular object was used without preserving it indefinitely.

This architecture separates collection, content protection, integrity, and verification. The runtime cannot choose a weaker retention class. The log acknowledges only durable writes. A verifier independent of the producer detects deletion, insertion, reorder, and modification within the chain’s guarantees.

Integrity and Provenance

Canonical serialization is mandatory. Hashing ordinary JSON is unsafe because key order, number rendering, and Unicode forms may differ. Define UTF-8 encoding, normalized strings, sorted keys, no insignificant whitespace, and permitted scalar representations. Better, adopt a documented canonical format such as JSON Canonicalization Scheme.

For canonical event bytes \(b_i\), payload digest \(d_i\), and previous hash \(h_{i-1}\), compute

\[ h_i=H(domain\separator\parallel h{i-1}\parallel b_i\parallel d_i). \]

The domain separator prevents the hash from being reused in another protocol. A hash chain detects changes only if a trusted party knows an anchor. Periodically sign checkpoint tuples (tenant, stream, first_sequence, last_sequence, root_hash, time) using a protected key and publish them to a separately administered store. Otherwise an attacker controlling the log can rewrite the whole chain.

Hash chains do not prove that an event is true or complete. A compromised producer can faithfully hash lies or omit a call. Corroborate high-consequence actions with tool-side logs, cloud audit records, deployment attestations, and credential-broker events. Compare expected state transitions with observed transitions and alert on sequence gaps.

Causality and clocks

Wall clocks drift. Use a monotonic per-stream sequence and parent_id for causal relationships; keep event and ingest times for latency analysis. Concurrent subagents form a directed acyclic graph rather than one global order. Each stream can chain independently, while join events name the terminal hashes of child streams.

Privacy and retention

Data minimization begins before logging. Record normalized tool parameters where needed, but tokenize secrets and omit raw credentials categorically. Separate operational telemetry from restricted content. Access to content requires a case-bound reason, is itself logged, and can be more tightly retained than envelopes.

Retention should follow consequence and purpose: policy decisions and deployment receipts may survive for audit obligations; raw prompts containing customer data may expire in days; cryptographic digests and aggregate metrics may remain longer. Deletion must cover replicas, indexes, caches, and derived embeddings. A digest can itself be personal data when the input space is guessable, so salt or key sensitive digests and control verification access.

Executable Lab: Schema and Hash-Chain Verifier

The lab validates event types and required fields, creates a deterministic chain, verifies it, then demonstrates tamper detection. It uses synthetic payloads and the standard library.

import hashlib, json
from copy import deepcopy

REQUIRED = {
    "run.started": {"initiator", "objective_digest"},
    "policy.decided": {"decision", "proposal_digest", "reason"},
    "tool.completed": {"tool", "status", "result_digest"},
}

def canonical(value):
    return json.dumps(value, sort_keys=True, separators=(",", ":"),
                      ensure_ascii=False).encode()

def seal(events):
    previous = "0" * 64
    sealed = []
    for sequence, raw in enumerate(events, 1):
        event = deepcopy(raw)
        missing = REQUIRED[event["event_type"]] - event["payload"].keys()
        if missing:
            raise ValueError(f"missing fields: {sorted(missing)}")
        event["sequence"] = sequence
        event["previous_hash"] = previous
        body = canonical(event)
        event["event_hash"] = hashlib.sha256(b"agent-trace-v1\0" + body).hexdigest()
        previous = event["event_hash"]
        sealed.append(event)
    return sealed

def verify(chain):
    previous = "0" * 64
    for expected, event in enumerate(chain, 1):
        claimed = event["event_hash"]
        body = {k: v for k, v in event.items() if k != "event_hash"}
        actual = hashlib.sha256(b"agent-trace-v1\0" + canonical(body)).hexdigest()
        if event["sequence"] != expected or event["previous_hash"] != previous:
            return False, f"ordering failure at {expected}"
        if claimed != actual:
            return False, f"hash failure at {expected}"
        previous = claimed
    return True, f"verified {len(chain)} events; anchor={previous[:12]}"

events = [
 {"event_type":"run.started", "payload":{"initiator":"alice",
  "objective_digest":"sha256:111"}},
 {"event_type":"policy.decided", "payload":{"decision":"allow",
  "proposal_digest":"sha256:222", "reason":"staging-only"}},
 {"event_type":"tool.completed", "payload":{"tool":"deploy",
  "status":"ok", "result_digest":"sha256:333"}},
]
chain = seal(events)
print(*verify(chain))
chain[1]["payload"]["decision"] = "deny"
print(*verify(chain))

Expected output:

True verified 3 events; anchor=e26371d4de87
False hash failure at 2

The exact anchor is deterministic for this program. Production code should use a formal schema library, canonicalization standard, per-tenant stream identity, signatures, key rotation, durable checkpoints, and explicit migration tests. Never place secrets into a lab merely to see whether redaction works.

Coverage and Operational Failure Analysis

Happy-path-only traces. Instrumentation often misses policy exceptions, retries, cancellation, timeouts, streaming partials, and sandbox kills. Derive required events from the state machine and test every transition, including denied and failed actions.

Collector loss. If the trace backend is unavailable, decide by consequence class: low-risk reads may buffer locally; consequential writes should fail closed if their authorization receipt cannot be durably recorded. Bound buffers and expose loss counters.

High-cardinality collapse. Aggregating by run can erase the one denied call that explains an incident. Keep event-level evidence in restricted storage while exporting carefully chosen metrics.

Redaction after ingestion. Secrets already reached logs, queues, and error trackers. Redact at the producer boundary, structurally exclude credential fields, and scan canaries across the complete telemetry path.

Broken migrations. Adding a field can change canonical bytes or verifier behavior. Version schemas immutably, preserve old verification logic, and test known fixtures for every version.

Insider reconstruction. Even redacted previews, timing, and tool arguments may reveal sensitive activity. Enforce tenant isolation, purpose-bound access, dual control for bulk export, query auditing, and anomaly detection on investigators.

False assurance from hashes. Integrity is not completeness, authenticity, or correctness. Combine producer chains with independently sourced tool and cloud audit evidence. Record coverage claims explicitly: which tool versions and execution paths emit which events.

Queryability without uncontrolled copying

Forensic evidence is useless when investigators cannot join it, but broad search indexes create new disclosure surfaces. Index stable identifiers, types, times, consequence classes, reason codes, and keyed pseudonyms. Keep sensitive payload search in a restricted enclave with case-bound access. Export tools should default to envelopes and require a separate authorization to include content.

Test common investigation queries against synthetic incidents before launch: list all actions derived from one evidence object, find tool completions without approvals, reconstruct a delegation tree, and verify a chain across key rotation. Measure time to answer and missing joins. A schema that is cryptographically elegant but operationally unqueryable will be bypassed during an incident.

Source Synthesis

Building an Evidence Contract

Start with investigations the organization must perform. For an unauthorized deployment, determine whether the agent proposed the artifact, an eligible human approved it, policy evaluated the same digest, the credential matched the environment, and the service applied that artifact. Convert each question into required events and joins. This avoids collecting attractive but irrelevant model chatter.

Define volume before rollout. Streaming tokens can outnumber consequential actions by orders of magnitude. Keep token diagnostics only in bounded debug samples; retain durable event facts for security. Estimate bytes per run, peak events per second, content-store growth, index cost, and checkpoint frequency. Budgeting is a control because overloaded collectors lose rare failure events.

Classify schema changes as additive, semantic, or breaking. Adding an optional field is additive only when absence has defined meaning. Changing actor from authenticated principal to display name is semantic. Removing an event type is breaking because coverage claims change. Consumers declare supported versions and fail visibly on unknown security semantics.

Sensitive-action taxonomy

Classify observation, local mutation, external communication, privilege change, financial action, destructive action, production change, credential access, and durable memory mutation. Add scope and reversibility. Reading one public file differs from bulk private-repository export; an ephemeral test file differs from deleting production data.

For each class specify required proposal fields, policy evidence, approval, tool receipt, retention, and trace-outage behavior. Share the taxonomy with the tool broker. If tracing calls something local while the broker calls it external, audits will be incoherent.

Completeness reconciliation

Every credential lease should join to allowed calls and closure or expiry. Every consequential completion should join to one proposal and policy decision, plus approval when required. Every deployment should appear in both agent and platform audit streams.

Reconcile continuously. Unmatched completions indicate bypass or collection loss. Unused leases may show aborted work or credential harvesting. Missing terminal events reveal crashes. Accept late events within a bounded window while preserving original sequence and ingest latency.

Cryptographic operations

Keys require identifiers, rotation, revocation, and separation by tenant and environment. Retain public material and algorithms for historical checkpoints after rotation. If a key is compromised, record the affected interval; do not re-sign history. Forward security reduces some retrospective risk but does not cure producer compromise.

Checkpoint frequency trades detection latency, cost, and rewrite exposure. Deployment streams may checkpoint per transaction; observation streams hourly. Anchor to another account, transparency service, or write-once store under a different role. Test archive restoration and verification without the producer database.

Evidentiary limits

An incident package contains chain segments, checkpoints, schemas, canonicalization rules, key history, verifier version, independent logs, access records, and a narrative separating observation from inference. Generate it reproducibly and hash the package.

A signature proves a key signed bytes, not which human controlled it. A matching digest proves byte equality when content exists, not that content was complete or honestly labeled. Put these limits in runbooks so incident pressure does not turn cryptography into folklore.

OpenTelemetry provides trace identity and semantic conventions but is not by itself a forensic integrity system. W3C Trace Context propagates correlation, not trust. RFC 8785 supplies deterministic JSON; NIST log-management guidance addresses operational collection and retention; SLSA and in-toto show how attestations bind subjects, materials, and steps. The practical design borrows correlation from observability and verifiability from supply-chain provenance while applying privacy minimization before collection.

Interview Practicum

Design telemetry for a customer-support agent that reads tickets, queries account systems, drafts refunds, and can issue refunds after approval. Legal permits raw ticket retention for seven days, Finance requires seven-year refund evidence, and Security discovers that model-provider request IDs are unavailable in one region. During the discussion, a suspected insider deletes a trace row.

Specify the schema, trust boundaries, retention split, integrity design, coverage response, and incident evidence package.

Worked Answer

I would define typed envelopes for run start, evidence observation, model completion, tool proposal, policy decision, approval, refund completion, and run end. Raw tickets live in an encrypted content store for seven days; events hold a keyed digest, classification, and case-bound locator. Refund records retain canonical proposal, amount, currency, account pseudonym, approver, policy version, tool receipt, and ledger transaction identifier for the Finance period without retaining unrelated conversation text.

Each tenant and agent stream uses sequence numbers and a hash chain. Hourly signed checkpoints go to a separately administered immutable store. The refund service emits its own receipt and ledger audit event, allowing completeness reconciliation. Missing provider request IDs become an explicit regional coverage flag; model identity, local request digest, timing, and response digest remain, but the team must not claim provider-side correlation there.

For the deletion incident, verification identifies the gap or broken successor link. Preserve the signed checkpoint, adjacent events, collector access logs, refund-service audit, ledger record, key history, and schema/version documentation. Rotate access if compromise is suspected. The report distinguishes proven facts from inference: a broken chain proves inconsistency after the checkpoint, not which person deleted the row or whether the original event was truthful.

Follow-Up Questions and Answers

Can the company keep unsalted prompt hashes forever?

Not safely by default. Guessable messages can be dictionary-attacked and hashes may remain regulated data. Use keyed digests, restricted verification, and purpose-based retention.

What happens when the trace service is down?

Buffer bounded low-consequence events, but fail closed for refunds if durable authorization and completion evidence cannot be recorded. Alert on every loss counter.

How do you measure trace coverage in a nondeterministic agent?

Measure instrumented state transitions and tool boundaries, not textual paths. Run generated scenario suites and reconcile tool-side actions against corresponding proposal, decision, and completion events.

Why not use a blockchain?

A signed, externally anchored append-only log usually provides the required tamper evidence with less complexity. The governance of writers, keys, checkpoints, and independent evidence matters more than the branding of the data structure.

Key Takeaways

  • Security traces are typed evidence, not permanent transcripts.
  • Separate stable envelopes from protected, short-lived content objects.
  • Canonicalize, chain, sign, and externally anchor high-value streams.
  • Integrity does not prove truth or completeness; corroborate at tool boundaries.
  • Design retention by purpose and consequence before collection.
  • Make regional, tool, and failure-path coverage gaps explicit.

Field lesson: a digital thread must expose broken links

The sec-pr implementation indexed 566 evidence artifacts and linked analytical records through deterministic composite identity and hashes. It also quarantined 278 unresolved historical records instead of silently forcing joins. Trace completeness therefore included a reconciliation result: what the system could connect, what it could not connect, and why. See Chapter 47 for the full architecture.
