Chapter 28: Graph Analytics for Attack Paths

An Attack Path Is a Satisfiable Program

A security graph is not valuable because it draws many arrows. It is valuable when it can answer a counterfactual: if an attacker controls this principal under these conditions, which protected assets become reachable, why, and which change breaks the most credible paths?

Ordinary graph reachability is too permissive. An identity may belong to a group only during one interval; a role may require MFA; an exploit may apply only to a vulnerable image version; a network route may permit traffic in one direction; two permissions may need to be exercised in sequence. A reported path is credible only when its edges are simultaneously valid and its prerequisites are satisfiable. Treating all edges as timeless produces attack paths that never existed.

The graph is heterogeneous. Nodes include people, service principals, groups, roles, credentials, workloads, hosts, applications, data stores, vulnerabilities, and controls. Edges include membership, trust, assume-role, owns, can-read, can-write, can-execute, exposed-to, runs-on, vulnerable-to, and blocked-by. Each type has different semantics. A shortest path across untyped edges is usually a shortest explanation of the data model, not attacker effort.

Schema: Facts, Validity, and Preconditions

A compact relational representation is easier to test than an opaque graph import:

CREATE TABLE graph_nodes (
  tenant_id TEXT NOT NULL,
  node_id TEXT NOT NULL,
  node_type TEXT NOT NULL,
  criticality INTEGER NOT NULL DEFAULT 0,
  properties_json TEXT NOT NULL DEFAULT '{}',
  PRIMARY KEY (tenant_id, node_id)
);

CREATE TABLE graph_edges (
  tenant_id TEXT NOT NULL,
  edge_id TEXT NOT NULL,
  src_id TEXT NOT NULL,
  dst_id TEXT NOT NULL,
  edge_type TEXT NOT NULL,
  valid_from TEXT NOT NULL,
  valid_to TEXT,
  confidence REAL NOT NULL CHECK (confidence >= 0 AND confidence <= 1),
  precondition_json TEXT NOT NULL DEFAULT '{}',
  evidence_ref TEXT NOT NULL,
  observed_at TEXT NOT NULL,
  PRIMARY KEY (tenant_id, edge_id)
);

Edges are claims with evidence, not eternal truth. valid_from and valid_to describe the world; observed_at describes when the system learned it. Both are required for historical reconstruction and point-in-time evaluation. A scanner result should connect a workload instance or image digest to a vulnerability with version evidence. A role edge should carry conditions such as external ID, source principal, MFA, session tag, or namespace.

Negative and control facts also matter. A firewall deny, permissions boundary, explicit deny, or non-exportable key can invalidate a candidate path. Absence of an allow edge is not necessarily a deny when collection is incomplete. Record coverage so traversal can return unknown instead of quietly treating missing data as safe or exploitable.

Traversal Semantics

Define an attacker state \(q=(K,C,t)\), where \(K\) is controlled principals/resources, \(C\) is acquired capabilities, and \(t\) is evaluation time. An edge \(e\) is traversable when:

\[ valid_e(t)\land prereq_e(C)\land scope_e(K)\land \neg blocked_e(t). \]

Traversal applies a state transition \(q' = T_e(q)\), perhaps adding a credential, execution capability, or resource control. This captures an important distinction: reading a secret grants a capability that can enable a later assume-role edge; merely being adjacent to the secret node does not.

For static IAM analysis, typed reachability may suffice. For exploit paths, use constrained search over state. Bound path length and prevent repeated states, not merely repeated nodes, because revisiting a node with a new capability can be meaningful. Keep the transition library small and reviewed. Overly expressive preconditions make results impossible to validate.

Centrality, Chokepoints, and Blast Radius

Degree finds hubs, but directory groups and scanners are often benign hubs. Betweenness centrality

\[ C_B(v)=\sum_{s\ne v\ne t}\frac{\sigma_{st}(v)}{\sigma_{st}} \]

counts the fraction of shortest paths passing through \(v\). It can identify chokepoints, but only under the chosen edge weights and path definition. In security, the most important path may not be shortest, and thousands of near-duplicate group paths can dominate.

Blast radius is more actionable: given initial control \(S\), count or value critical assets reachable under valid transitions. Weighting asset value yields

\[ BR(S)=\sum_{a\in Reach(S)}V(a). \]

For remediation edge \(e\), marginal path reduction is \(\Delta_e=BR(S)-BR_{-e}(S)\). This estimates leverage, not guaranteed risk reduction. Removing one group membership may break 300 enumerated paths that all represent the same underlying privilege. Report unique protected assets and independent mechanisms as well as raw path count.

Communities can expose trust zones that do not match intended architecture. Motifs—user to group to role, workload to secret to cloud account—can encode known escalation patterns. Their value comes from typed semantics, not graph-theory novelty.

Ranking Paths Without Fake Probability

Suppose each edge has estimated success \(p_e\), detection probability \(d_e\), time cost \(c_e\), and confidence \(r_e\). A candidate score might be

\[ J(P)=\sum_{e\in P}-\log(p_e)+\lambda\sum c_e+gamma\sum d_e+eta\sum -\log(r_e). \]

Lower is easier or better supported. This additive form implicitly treats factors as separable; shared credentials, controls, and evidence violate independence. Use it for ranking and sensitivity analysis, never as an exact breach probability. Show how rankings change when uncertain weights vary.

A practical priority should include starting-point exposure, target criticality, path feasibility, evidence freshness, existing detections, and remediation leverage. Internet exposure is not a universal starting point: phishing, insider access, vendor compromise, and workload compromise create other starts. Maintain scenario-specific rankings.

Graph embeddings and graph neural networks can rank nodes or missing links, but they introduce identity leakage, temporal leakage, and difficult explanations. A random edge split lets the same identity neighborhood appear in train and test. Evaluate on later graph snapshots and new entities. Begin with typed traversal and transparent path features; add learned representations only for measurable lift on adjudicated tasks.

A Unique Architecture for Temporal Truth

flowchart LR
    S[Source snapshots<br/>IAM, CMDB, scanners, network policy] --> F[Versioned edge facts]
    F --> T[Temporal + prerequisite validator]
    T --> Q[Scenario search<br/>initial control and target]
    Q --> P[Candidate paths]
    P --> E[Evidence expansion<br/>why each hop works]
    E --> R[Edge-removal simulation]
    R --> C[Remediation choice]
    C --> S

The validator is the important component. It rejects edges outside the evaluation time, expands group and trust semantics, checks required capabilities, applies explicit denies, and records unknown coverage. Search and ranking should never bypass it.

Safe Runnable Lab: Temporal Privilege Paths

This standard-library lab finds feasible paths and simulates remediation. The graph is synthetic and contains no real cloud credentials.

from collections import defaultdict, deque

edges = [
 ("internet", "web", "exposed", 1.0),
 ("web", "web-role", "workload_identity", 1.0),
 ("web-role", "build-secret", "read_secret", 1.4),
 ("build-secret", "ci-role", "credential_for", 0.8),
 ("ci-role", "signing-key", "can_sign", 1.0),
 ("contractor", "dev-group", "member_of", 0.2),
 ("dev-group", "ci-role", "assume_role", 1.2),
 ("old-group", "signing-key", "can_sign", 0.1),  # expired
]
valid = {tuple(e[:3]) for e in edges if e[0] != "old-group"}

def paths(source, target, removed=None, cutoff=6):
    removed = removed or set()
    graph = defaultdict(list)
    costs = {}
    for src, dst, kind, cost in edges:
        key = (src, dst, kind)
        if key in valid and key not in removed:
            graph[src].append((dst, kind))
            costs[key] = cost
    queue = deque([(source, [source], [], 0.0)])
    found = []
    while queue:
        node, nodes, hops, cost = queue.popleft()
        if node == target:
            found.append((cost, nodes, hops)); continue
        if len(hops) >= cutoff: continue
        for nxt, kind in graph[node]:
            if nxt not in nodes:
                key = (node, nxt, kind)
                queue.append((nxt, nodes+[nxt], hops+[kind], cost+costs[key]))
    return sorted(found)

internet_paths = paths("internet", "signing-key")
contractor_paths = paths("contractor", "signing-key")
cut = {("dev-group", "ci-role", "assume_role")}
after_cut = paths("contractor", "signing-key", removed=cut)

print(internet_paths[0][1])
print(contractor_paths[0][1])
assert internet_paths[0][1] == ["internet", "web", "web-role",
                                "build-secret", "ci-role", "signing-key"]
assert contractor_paths[0][1] == ["contractor", "dev-group", "ci-role",
                                  "signing-key"]
assert after_cut == []
assert paths("old-group", "signing-key") == []

Expected output is the two asserted node lists. Removing dev-group -> ci-role eliminates the contractor path, while the expired edge never appears. The lab deliberately separates validity from topology. A production extension would represent prerequisites and capabilities explicitly and test that every explanatory hop has accessible source evidence.

Explainable Findings and Remediation Choice

A finding should read like a proof:

  1. The contractor is an active member of dev-group according to directory snapshot X.
  2. The group's trust policy can assume ci-role without MFA under policy version Y.
  3. ci-role can invoke signing with key Z under effective policy simulation.
  4. The key protects production release artifacts and has criticality 5.
  5. Removing membership M breaks this scenario and two other independent paths; removing public web exposure does not affect it.

Include evaluation time, source freshness, unknown checks, and alternative paths. Analysts should be able to replay the query. If an edge depends on a scanner heuristic, label it accordingly. If a control is assumed effective but untested, do not present it as a hard block.

Remediation is a constrained cut problem. The smallest cut may be operationally impossible—removing the CI role stops releases. Candidate actions have engineering cost, availability impact, owner, and time to implement. Optimize a portfolio:

\[ \max_{A}\;\text{critical reachability removed}(A) \quad\text{s.t.}\quad \sum_{a\in A}cost(a)\le B, \]

plus constraints preserving required business paths. Often the best action is to condition a trust edge, shorten credential lifetime, or add approval rather than delete access entirely.

Production Failure Analysis

Timeless edges. Historical grants and remediated vulnerabilities invent paths. Require validity intervals and snapshot reproducibility.

Path explosion. Nested groups and equivalent permissions create combinatorial duplicates. Canonicalize equivalent mechanisms, cap depth, and summarize by target and cut edge.

Missing negative controls. Ignoring explicit deny, network policy, MFA conditions, or key non-exportability overstates feasibility. Model them or return unknown.

Stale ownership and criticality. A graph can rank precisely against obsolete business context. Require owner attestation and freshness indicators.

Tenant boundary failure. One missing predicate can create cross-customer paths. Partition storage and authorize traversal at the service layer.

Scanner confidence laundering. Importing a vulnerability edge can make uncertain version matching look factual. Preserve scanner evidence and confidence.

Remediation metric gaming. Teams close many paths by deleting duplicate edges while critical reachability remains. Measure protected assets and independent scenarios.

Learned leakage. Embeddings memorize high-degree identities and graph snapshots. Use temporal/entity holdouts and compare against typed heuristics.

Testing the Graph as a Security Product

Graph correctness begins below path ranking. Adapter tests should prove that source facts become the right typed edges, validity intervals, and conditions. Semantic tests should cover nested groups, explicit deny precedence, cross-account trust, inherited Kubernetes roles, workload federation, secret versioning, and vulnerability applicability. Use tiny graphs with one intended answer; large realistic fixtures make a wrong path difficult to diagnose.

Metamorphic tests are particularly effective. Adding an unrelated node must not change existing reachability. Expiring an edge must remove every path that depends on it. Adding an explicit deny must not create a path. Renaming a display label must not change node identity. Duplicating equivalent evidence must not double path count. Removing a cut edge must not affect required paths that do not traverse it. These properties catch entire classes of ingestion and traversal defects.

For a sampled production finding, a reviewer should reproduce each hop in the authoritative system or its immutable snapshot. Track edge confirmation rate, invalid-path rate, unknown-control rate, stale-edge rate, time to owner identification, accepted remediation, and verified reachability after change. “Paths closed” is insufficient until the graph is refreshed and the same scenario search confirms that the target is no longer reachable—or explains an alternative.

Freshness has scenario-specific limits. A 24-hour CMDB delay may be acceptable for quarterly architecture review but dangerous for a just-in-time signing path. Give every edge type a freshness SLO and propagate the weakest freshness into the path explanation. If one critical edge is stale, rank may remain useful for investigation, but automation should stop. Snapshot publication should be atomic so a query never mixes half of yesterday's IAM state with half of today's.

Large graphs require engineering discipline rather than semantic shortcuts. Partition by tenant and administrative boundary, maintain reverse indexes from protected targets, precompute safe closures for stable group membership, and run bidirectional search from starts and targets. Cache results by graph snapshot and scenario, invalidating them on affected edge changes. Approximate algorithms may prioritize candidates, but final findings should pass exact semantic validation.

Treat the graph service as highly sensitive. It is an attacker roadmap containing privilege, vulnerability, and critical-asset relationships. Apply least privilege, purpose-bound query APIs, tenant isolation, result limits, audit trails, and controls on bulk export. Explanations shown to broad engineering audiences may need to redact unrelated identities while preserving remediation evidence. Protect source credentials and never let the analytics service acquire the privileges it is modeling merely for convenience.

Interview Practicum

Scenario: The Best Cut Becomes Unavailable.

Prompt. A cloud company has 12 million privilege edges. Find and prioritize paths from internet-facing workloads and contractors to production signing keys, then recommend remediation.

Clarify graph semantics, snapshot history, starting scenarios, target inventory, cloud-policy evaluation, vulnerability evidence, control representation, maximum path depth, and remediation owners.

Worked Answer

Build versioned typed edges with validity and evidence; define attacker-state transitions; enumerate bounded feasible paths; rank by scenario exposure, feasibility, target value, freshness, and uncertainty; then simulate candidate cuts. Validate a sample hop by hop with IAM and service owners.

Follow-Up Questions and Answers

Midstream constraint. The apparent top cut—removing the CI role—would halt releases and is prohibited.

Reframe remediation as constrained optimization. Test narrower changes: remove contractor inheritance, require workload-bound federation, restrict signing conditions to approved pipeline claims, shorten sessions, or add a brokered signing service. Recompute reachability while asserting that the required release path remains. The goal is not minimum graph size; it is reduced unauthorized reachability with preserved business function.

Second constraint. IAM snapshots are daily, while just-in-time grants last 30 minutes.

Daily snapshots cannot prove or exclude those paths. Ingest grant lifecycle events or policy-decision logs with event time. Until then, label JIT traversal unknown and avoid claiming complete coverage. A temporary control can require signing-service logs and alert on non-pipeline callers at the target boundary.

Third constraint. Leadership wants to deploy a GNN because the graph is large.

Ask which supervised task and labels justify it. Scaling traversal is an engineering problem; it does not itself require learning. Partition by tenant/account, precompute reviewed relation closures, and use bidirectional bounded search. Consider a GNN only for a defined ranking task with temporal/entity holdouts, transparent baselines, and path-level explanations. Never allow a learned score to invent authorization semantics.

Weak answers run generic shortest path, multiply edge probabilities as independent, rank by degree, or optimize raw path count. Staff answers model prerequisites, temporal validity, evidence, and operational cuts. Principal answers protect required business paths, expose unknown coverage, choose target-boundary controls when graph data is late, and resist unjustified model complexity.

Key Takeaways

  • A credible attack path is a sequence of satisfiable, simultaneously valid transitions.
  • Typed edges need evidence, confidence, validity, preconditions, and control semantics.
  • Centrality and shortest path are heuristics; prioritize scenario reachability and remediation leverage.
  • Explain findings as replayable proofs and distinguish false, blocked, and unknown paths.
  • Optimize remediation under business constraints, then recompute reachability to verify the cut.
