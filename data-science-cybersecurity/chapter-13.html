Chapter 13: Telemetry — What the System Can Actually Know

At 02:14, an autonomous support agent read a customer ticket, queried an internal account service, generated a refund request, and called a payment tool. The payment was blocked. A dashboard later said the control “caught an unsafe agent action.” That sentence claims more knowledge than the system necessarily possesses. Did the agent intend a refund? Did untrusted ticket text redirect it? Did the model propose the call or did deterministic orchestration construct it? Was the customer record returned by the tool the same record shown to the model? Did policy block execution, or did the payment API merely time out?

Telemetry is the boundary between what happened and what can be defended as known. A log is not a transparent window onto reality. It is a claim emitted by a component, under a particular configuration, at a particular clock time, with blind spots and incentives. Security analysis begins by naming those claims precisely.

The Epistemic Ladder

Treat every investigation as a climb through four levels:

  1. World state: processes executed, credentials were exercised, packets traversed interfaces, people made decisions, and tools changed resources.
  2. Sensor observation: an endpoint hook, identity provider, proxy, application, or agent runtime noticed some projection of that state.
  3. Recorded assertion: the sensor serialized fields, attached its clock and identity, and attempted delivery.
  4. Analytical inference: a rule, query, model, or investigator interpreted one or more assertions.

The levels must not be collapsed. A cloud audit record proves that the provider's control plane recorded an API request; it does not alone prove which human controlled the credential. A DNS log proves what a resolver observed, not every name a process attempted to resolve. An agent trace containing a prompt proves what the tracing layer stored, not necessarily the exact token sequence presented after provider-side transformations.

For a recorded event \(e\), a useful evidence annotation is

\[ K(e)=(s, o, c, d, i), \]

where \(s\) is source identity, \(o\) the observation mechanism, \(c\) the configuration version, \(d\) the delivery path, and \(i\) integrity evidence. An event without these attributes may still be operationally useful, but its evidentiary ceiling is lower.

Seven Surfaces, Seven Different Truths

Endpoint telemetry observes local execution: process start, image hash, parent relationship, command arguments, module load, file mutation, socket creation, user session, and sensor health. Kernel or EDR observations are strong for activity on enrolled hosts, but container boundaries, short-lived workloads, encrypted filesystems, tampering, and unenrolled assets create gaps. A process tree is also an interpretation: parent identifiers can be reused, and operating-system semantics differ.

Identity telemetry records authentication and authorization. Preserve authentication method, credential or session identifier, issuer, subject, client, device claim, challenge result, token scopes, policy decision, and revocation. A successful MFA event says that a factor satisfied a policy; it does not prove benign control of the session. Authorization deserves its own event because “logged in” and “permitted this action” answer different questions.

Network telemetry spans flow records, DNS, DHCP, TLS metadata, proxy transactions, packet capture, and service-mesh observations. Flow records retain endpoints, ports, byte counts, flags, and timing at low cost; they omit content and may be distorted by NAT. Proxies see application requests only for routed traffic. Full packet capture has high investigative value but severe cost, privacy, encryption, and retention limits. No single network feed is “the network.”

Cloud telemetry includes control-plane audit, workload logs, configuration history, identity policy, object access, and managed-service diagnostics. Provider audit is authoritative about the provider's recorded API surface, but data-plane logging is often separately enabled. Organization-level collection, region coverage, account onboarding, and immutable export determine whether an apparently rich feed is complete.

Application telemetry supplies business meaning unavailable elsewhere: tenant, object, operation, authorization reason, workflow stage, request correlation, and outcome. It is also closest to developer change. Free-form logs, inconsistent identifiers, accidental secrets, and success messages emitted before transaction commit are common hazards. Prefer versioned security events at semantic boundaries over parsing prose.

Code and software-supply-chain telemetry records commits, reviews, branch protection, build identities, dependency resolution, provenance attestations, artifact digests, deployments, and runtime version. A repository event links an identity to a change; a signed provenance statement links a builder and inputs to an artifact. Neither alone proves the deployed bytes came from the reviewed source. The chain requires digest continuity.

Model and agent telemetry must represent nondeterministic reasoning and consequential execution without pretending that hidden model cognition is observable. Store inputs, context references, model and policy versions, outputs, tool proposals, approvals, executions, and resulting state as separate records.

A Trace Schema for Consequential Agents

An agent trace should be an event graph, not one enormous JSON transcript. Large blobs impede selective retention, access control, causal reconstruction, and schema evolution. The following envelope separates correlation, semantics, clocks, provenance, and sensitivity:

{
  "event_id": "evt_01J8B8YQ6V",
  "event_type": "agent.tool.execution.completed",
  "schema_version": "1.2.0",
  "observed_at": "2026-08-20T14:03:12.481Z",
  "occurred_at": "2026-08-20T14:03:12.402Z",
  "trace_id": "tr_7f91",
  "span_id": "sp_09",
  "parent_span_id": "sp_08",
  "actor": {"agent_id": "refund-agent", "run_id": "run_441"},
  "subject": {"tenant_token": "tkn_93", "case_id": "case_1882"},
  "action": {"tool": "payments.issue_refund", "operation": "execute"},
  "authorization": {"policy_version": "pay-guard@31", "decision": "allow", "approval_id": "ap_772"},
  "input_ref": {"digest": "sha256:ab...", "vault_uri": "evidence://inputs/991"},
  "output_ref": {"digest": "sha256:de...", "classification": "restricted"},
  "execution": {"attempt": 1, "status": "succeeded", "resource_version_after": "refund/883@2"},
  "runtime": {"orchestrator": "agent-runtime@8f31", "model": "model-release-2026-08"},
  "integrity": {"collector": "trace-gateway-4", "sequence": 91882, "signature": "base64:..."}
}

Prompt content should usually be referenced by digest and controlled storage rather than copied into every event. Record the system instruction, user input, retrieved chunks, memory reads and writes, model response, policy evaluations, tool proposal, approval, tool execution, and observable effect as distinct span types. A proposed tool call is not an executed tool call. A tool's 200 OK is not proof that the intended state changed. Capture a postcondition or resource version when consequences matter.

OpenTelemetry supplies trace and span correlation, but security semantics still require conventions. W3C Trace Context propagates identifiers; it does not establish trust. An attacker can forge an incoming trace header, so gateways should distinguish an untrusted upstream identifier from an internally minted trace identity.

Sensitive values need field-level handling. Prompts can contain credentials, customer data, exploit text, and model-injection payloads. Attach classifications, tokenize identities where attribution is unnecessary, encrypt referenced payloads, and make access purpose-bound. Redaction must preserve analytical meaning: replacing every URL with [REDACTED] destroys the ability to find a repeated malicious domain. Store a keyed token or normalized feature alongside restricted raw evidence.

Authentication, Authorization, and Sensitive Actions

A defensible chain for a sensitive action contains at least five assertions:

credential presented -> authentication evaluated -> session/token issued
        -> authorization evaluated -> resource mutation observed

Each arrow can fail independently. Identity-provider success without application authorization cannot explain why access was granted. Application authorization without token issuance context cannot show whether step-up authentication was required. A tool execution event without resource mutation cannot distinguish a no-op, timeout, rollback, or misleading response.

Define a sensitive-action catalog rather than relying on log severity. Examples include changing MFA factors, granting a role, exporting records, rotating a key, modifying a detector, approving an agent tool, publishing a package, and disabling collection. Each catalog entry names required evidence: actor, effective principal, target, old and new state, authorization policy, approval, request and result identifiers, and independently observable postcondition.

Coverage Is a Set Problem, Not a Volume Metric

Terabytes per day do not answer whether a decision is observable. Let \(U\) be the set of required evidence claims for a threat or control. Sensor \(j\) covers subset \(S_j\), has reliability \(r_j\), latency \(l_j\), cost \(c_j\), and common-mode dependency \(g_j\). Naive coverage is

\[ C=\frac{|\bigcup_j S_j|}{|U|}. \]

Weighted coverage assigns consequence weight \(w_i\) to each claim:

\[ C_w=\frac{\sum_{i\in \cup S_j}w_i}{\sum_{i\in U}w_i}. \]

Neither formula captures independence. Endpoint and local forwarding logs may both disappear when the host is compromised. Two feeds sharing the same upstream collector are not two independent witnesses. Mark common dependencies and require diverse evidence for high-consequence claims.

The practical artifact is a coverage matrix whose rows are evidence requirements and columns are sensors. Cells should be richer than yes/no: D for direct observation, I for inference, H for sensor-health evidence, and blank for no support. Add scope, latency, retention, failure visibility, owner, and validation date outside the matrix. The matrix is versioned because products, policies, and fleets change.

Minimization Without Self-Blinding

Collection minimization asks which evidence is necessary for a defined decision, not which logs are inexpensive. Begin with the sensitive action and work backward. If the decision is whether to suspend a session after impossible token use, exact message bodies and shell history are disproportionate; token lineage, device binding, regions, timing, policy result, and session revocation are germane.

Minimize along several axes:

  • field: omit content when category, digest, or keyed token suffices;
  • population: instrument privileged or exposed workflows more deeply than unrelated users;
  • time: retain high-volume raw evidence briefly and durable derived claims longer;
  • resolution: aggregate health metrics while preserving case evidence under authorization;
  • access: separate operational search, investigation, model training, and audit purposes;
  • location: derive features near the source when central raw collection adds risk without value.

Minimization can create an undocumented blind spot. Record every deliberate omission as a coverage exception with rationale, compensating evidence, approver, and review date. That turns “we do not collect it” from tribal knowledge into an explicit risk decision.

Executable Lab: Audit an Agentic Refund Path

The lab computes weighted direct coverage, reports inferential-only and missing claims, detects common-mode witness failures, and finds a minimum-cost sensor set that directly covers every mandatory claim. Save as coverage_audit.py and run with the book interpreter.

from itertools import combinations

requirements = {
    "untrusted_input": (2, False),
    "model_context": (3, False),
    "tool_proposal": (5, True),
    "policy_decision": (5, True),
    "human_approval": (4, True),
    "tool_execution": (5, True),
    "resource_postcondition": (5, True),
    "collector_health": (3, False),
}

sensors = {
    "agent_trace":   {"cost": 3, "group": "runtime", "D": {"model_context", "tool_proposal"}, "I": {"tool_execution"}},
    "policy_log":    {"cost": 2, "group": "policy",  "D": {"policy_decision", "human_approval"}, "I": set()},
    "tool_gateway":  {"cost": 3, "group": "runtime", "D": {"tool_execution"}, "I": {"policy_decision"}},
    "payment_audit": {"cost": 4, "group": "payment", "D": {"resource_postcondition"}, "I": {"tool_execution"}},
    "input_proxy":   {"cost": 2, "group": "edge",    "D": {"untrusted_input"}, "I": set()},
    "health_ledger": {"cost": 1, "group": "ops",     "D": {"collector_health"}, "I": set()},
}

selected = list(sensors)
direct = set().union(*(sensors[s]["D"] for s in selected))
inferred = set().union(*(sensors[s]["I"] for s in selected)) - direct
missing = set(requirements) - direct - inferred
total_weight = sum(weight for weight, _ in requirements.values())
direct_weight = sum(requirements[r][0] for r in direct)

mandatory = {r for r, (_, required) in requirements.items() if required}
candidates = []
for size in range(1, len(sensors) + 1):
    for names in combinations(sensors, size):
        observed = set().union(*(sensors[n]["D"] for n in names))
        if mandatory <= observed:
            candidates.append((sum(sensors[n]["cost"] for n in names), names))
    if candidates:
        break

best_cost, best = min(candidates)
runtime_claims = set().union(*(sensors[s]["D"] for s in selected if sensors[s]["group"] == "runtime"))

print(f"direct_weighted_coverage={direct_weight}/{total_weight} ({direct_weight/total_weight:.1%})")
print(f"inferential_only={sorted(inferred)}")
print(f"missing={sorted(missing)}")
print(f"minimum_mandatory_set={list(best)} cost={best_cost}")
print(f"runtime_common_mode_claims={sorted(runtime_claims)}")

Exact output:

direct_weighted_coverage=32/32 (100.0%)
inferential_only=[]
missing=[]
minimum_mandatory_set=['agent_trace', 'policy_log', 'tool_gateway', 'payment_audit'] cost=12
runtime_common_mode_claims=['model_context', 'tool_execution', 'tool_proposal']

The 100 percent result is not a declaration of perfect observability. It says only that the enumerated claims have a direct source in the fixture. The last line identifies a correlated dependency: trace and gateway evidence share the runtime group. The resource postcondition from the payment domain provides an independent witness for the consequence. A production audit should also test fleet scope, delivery lag, retention, schema validity, sequence gaps, and controlled canary events.

Operating the Unknowns Register

Coverage gaps belong in an operational register. Each entry states the decision impaired, affected scope, adversary opportunity, present proxy, planned remedy, owner, and expiration. Distinguish known absent evidence from unexpected silence. The former is design debt; the latter may be an incident.

Use canaries to verify end-to-end observation. A synthetic privileged action can traverse authentication, authorization, application, export, normalization, and detection paths. The canary succeeds only if every expected claim arrives within its latency objective and can be joined without manual guessing. Merely checking that a collector process is alive tests machinery, not knowledge.

Detection and response produce their own telemetry: rule version, alert inputs, suppression, routing, analyst access, disposition, containment, restoration, and later outcome. Vulnerability programs need scanner identity, asset scope, finding instance, evidence, deduplication lineage, ownership, exception, remediation, verification, and recurrence. Product telemetry should record whether security controls are enabled, successfully exercised, bypassed, abandoned, or creating friction. These operational records reveal whether an evidence system changes decisions rather than merely accumulating events.

Interview Practicum

You inherit telemetry for a customer-service agent that can credit accounts. The red team demonstrated prompt injection through ticket text, yet the company stores only final model text and application exceptions. The network team refuses payload capture, Legal prohibits indefinite prompt retention, the payment team offers a daily audit export, and launch is in six weeks.

The interviewer asks: Design the minimum telemetry needed to investigate unsafe credits and evaluate the approval control. After ten minutes, two constraints change: payment audit becomes available only after 24 hours, and the agent platform team says trace identifiers can be supplied by clients.

A strong candidate first asks which actions are consequential, maximum credit, authorization boundary, approval modes, tenant isolation, investigation horizon, expected volume, regulator needs, and who can retrieve restricted content. They separate proposal, authorization, execution, and postcondition. They reject client-supplied trace IDs as trusted roots and mint an internal run identity at ingress while preserving the external value as an untrusted correlation attribute.

Worked Answer

Instrument ticket ingestion with content digest, source trust label, tenant token, and restricted payload reference. Record ordered references to system instructions, retrieved material, memory reads, model release, sampling configuration, model response, and parsed tool proposal. The policy service emits rule version, evaluated attributes, decision, and reason. Human approval emits approver role, displayed evidence digest, decision, and latency. The gateway records the exact normalized call and idempotency key. Payment audit supplies independent postcondition evidence one day later.

For immediate containment, treat gateway success as provisional and reconcile it with payment audit. Alert on missing reconciliation after 26 hours. Retain structured trace metadata longer than prompt content; place content in purpose-bound encrypted storage with shorter retention and case holds. Preserve keyed indicators derived from untrusted text so repeated injections can be found without broad content access.

Coverage tests inject a synthetic ticket, approve and deny controlled calls, verify correlation and ordering, then reconcile daily results. The launch gate requires complete observation of all tool proposals, policy decisions, approvals, executions, and eventual postconditions; sequence-gap monitoring; access audit; and a tested kill switch. Report both direct coverage and the 24-hour consequence-confirmation lag.

Weak answers ask for “all logs,” equate model output with executed action, ignore sensor integrity, or promise that distributed tracing proves causality. A costly but still weak answer captures every packet while omitting authorization policy versions and resource postconditions.

Follow-Up Questions and Answers

What if prompts cannot be retained at all? Retain digests, trust labels, token counts, retrieval identifiers, policy-relevant features, and a short-lived quarantined payload only when lawful. Evaluation becomes less capable of semantic replay; document that limitation rather than manufacturing certainty.

How do you distinguish tool retry from duplicate malicious execution? Carry a stable idempotency key across proposal, approval, gateway attempts, and resource audit. Preserve attempt numbers and final resource version.

Would you adopt OCSF or OpenTelemetry? Use OpenTelemetry for propagation and span mechanics, and map security events to a governed semantic model such as OCSF where categories fit. Neither substitutes for agent-specific action and authorization contracts.

How do you prove collection is alive? Exercise a harmless synthetic action end to end and require the expected event graph, latency, signatures, and reconciliation—not just collector heartbeat.

Thirty-second summary? Separate observed claims from inference; capture proposal, policy, approval, execution, and consequence as distinct events; minimize sensitive content; independently verify high-impact state changes; continuously test coverage.

Key Takeaways

  • Telemetry is a chain of claims with an evidentiary ceiling, not reality itself.
  • Endpoint, identity, network, cloud, application, code, model, and agent sources observe different projections.
  • Agent traces need separate, correlated records for context, proposals, decisions, executions, and postconditions.
  • Coverage is defined against required evidence and failure independence, not event volume.
  • Minimization should reduce fields, populations, time, resolution, access, and movement without concealing the resulting gaps.
  • Synthetic end-to-end actions test whether a system can actually know what its diagrams claim.
