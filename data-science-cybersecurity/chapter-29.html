Chapter 29: Threat Intelligence and Exploit Prioritization

Exploitation Is a Forecast, Not a Severity Label

A scanner answers “what weakness is present?” A remediation program must decide which exposed weakness is likely to be used against this organization before it can be fixed. CVSS, EPSS, CISA Known Exploited Vulnerabilities (KEV), exploit reports, asset exposure, and business context describe different parts of that decision. Treating any one as the answer causes predictable mistakes.

CVSS v4.0 characterizes technical severity. EPSS estimates the probability that a published CVE will be exploited in the wild during the next 30 days. KEV says exploitation has occurred and assigns US federal remediation dates. None knows whether the vulnerable code path is reachable in your deployment, a control blocks it, or compromise reaches a material asset. The correct unit is therefore a time-stamped CVE–asset–deployment observation, not a CVE. The same CVE can require emergency work on an internet-facing identity gateway and normal maintenance on an isolated build host.

An Intelligence Contract That Preserves Evidence

Store observations separately from conclusions:

CREATE TABLE exploit_evidence (
  evidence_id TEXT PRIMARY KEY,
  cve_id TEXT NOT NULL,
  observed_at TEXT NOT NULL,
  ingested_at TEXT NOT NULL,
  evidence_type TEXT NOT NULL CHECK (evidence_type IN
    ('kev','epss','advisory','malware','honeypot','public_poc')),
  publisher TEXT NOT NULL,
  source_document TEXT NOT NULL,
  independent_group TEXT NOT NULL,
  supports_exploit INTEGER NOT NULL CHECK (supports_exploit IN (0,1)),
  likelihood_ratio REAL,
  raw_value REAL,
  extraction_method TEXT NOT NULL,
  UNIQUE(cve_id,publisher,source_document,evidence_type)
);

CREATE TABLE deployment_observation (
  observation_id TEXT PRIMARY KEY,
  observed_at TEXT NOT NULL,
  asset_id TEXT NOT NULL,
  cve_id TEXT NOT NULL,
  vulnerable_path INTEGER NOT NULL,
  internet_reachable INTEGER,       -- NULL means unknown
  control_state TEXT NOT NULL,
  asset_loss_usd REAL NOT NULL,
  remediation_hours REAL NOT NULL,
  inventory_source TEXT NOT NULL
);

independent_group prevents three feeds quoting one vendor bulletin from appearing to be three confirmations. observed_at says when an event happened; ingested_at says when the system could know it. Both are essential to honest backtests. STIX 2.1 is useful for exchanging indicators, sightings, relationships, and confidence, but STIX confidence is publisher metadata—not automatically a probability.

ATT&CK technique mappings add behavioral context. A CVE enabling External Remote Services (T1133) may support a campaign hypothesis, but the mapping is a typed, sourced relationship rather than proof that a campaign used that CVE. ATLAS plays an analogous role for attacks on machine-learning systems. Mappings should improve investigation and control selection, not become arbitrary score multipliers.

Bayesian Updating Without Circular Evidence

Let \(H\) mean “this CVE will be exploited against the relevant population during the decision horizon.” Starting with a point-in-time EPSS prior \(p_0\), prior odds are

\[ O(H)=\frac{p_0}{1-p_0}. \]

For conditionally independent evidence groups with calibrated likelihood ratios \(LR_g\):

\[ O(H\mid E)=O(H)\prod_g LR_g, \qquad P(H\mid E)=\frac{O(H\mid E)}{1+O(H\mid E)}. \]

A likelihood ratio is \(P(E\mid H)/P(E\mid\neg H)\), not an analyst’s 1–5 confidence. Estimate it from historical point-in-time observations. KEV inclusion usually deserves a strong positive ratio, but not infinity: “exploited somewhere” is not “will target this tenant.” A public proof of concept may add modest evidence. Four articles copied from the same researcher add one evidence group, not four.

Conditional independence is the fragile assumption. Reporting popularity creates another bias: famous vendors and dramatic CVEs receive more articles. Evaluate calibration by disclosure age, ecosystem size, and vendor prominence, and maintain low-attention challenge cases.

From Forecast to Action

Prioritization should minimize expected loss. For asset \(a\) and action \(d\):

\[ L(d)=p_{exploit}\,p_{reach}(a)\,p_{success}(a,d)\,C_{impact}(a)

  • C_{change}(a,d)+C_{delay}(d).

\]

p_reach represents whether the vulnerable path can be exercised. p_success accounts for remaining controls. C_change includes outage risk and labor. Emergency patching is justified when its expected reduction in compromise loss exceeds change cost. This is why “patch every critical CVSS in 24 hours” is incomplete: it omits exploitation likelihood, reachability, consequence, and patch risk.

Keep the components in the decision record:

{"decision_time":"2026-08-20T14:00:00Z","asset_id":"edge-idp-07",
 "cve_id":"CVE-20XX-9001","epss_asof":0.18,"posterior_exploit":0.798,
 "reachability":0.95,"impact_usd":900000,"change_cost_usd":18000,
 "action":"emergency_patch","evidence_groups":["kev:cisa","poc:r17"],
 "policy_version":"exploit-loss-v3"}

NLP as an evidence extractor

Advisory NLP should resolve product/version spans, distinguish “could allow exploitation” from “exploitation observed,” capture who asserted the claim and when, link to exact text, and cluster documents by common origin. “No evidence of exploitation” is not evidence of no exploitation. A language model may summarize a report, but consequential decisions must retain the underlying span and deterministic entity resolution.

Safe Lab: Evidence-Weighted Expected Avoided Loss

This synthetic lab deduplicates correlated evidence, updates odds, and chooses emergency work only when expected avoided loss exceeds change cost.

from dataclasses import dataclass
from math import prod

@dataclass(frozen=True)
class Deployment:
    name: str; cve: str; epss: float; reach: float
    residual_after_patch: float; impact: float; change_cost: float

@dataclass(frozen=True)
class Evidence:
    cve: str; origin: str; lr: float

def posterior(prior: float, items: list[Evidence], cve: str) -> float:
    if not 0 < prior < 1:
        raise ValueError("prior outside (0,1)")
    groups: dict[str, float] = {}
    for e in items:
        if e.cve == cve:
            groups[e.origin] = max(e.lr, groups.get(e.origin, 0.0))
    odds = prior / (1 - prior) * prod(groups.values())
    return odds / (1 + odds)

evidence = [
    Evidence("CVE-A", "researcher-17", 3.0),
    Evidence("CVE-A", "researcher-17", 2.5), # copied report
    Evidence("CVE-A", "cisa-kev", 6.0),
    Evidence("CVE-B", "public-poc", 1.4),
]
assets = [
    Deployment("edge-idp", "CVE-A", .18, .95, .30, 900_000, 18_000),
    Deployment("isolated-build", "CVE-A", .18, .02, .30, 120_000, 8_000),
    Deployment("marketing-site", "CVE-B", .04, .80, .40, 70_000, 9_000),
]
out = []
for a in assets:
    p = posterior(a.epss, evidence, a.cve)
    benefit = p * a.reach * a.impact * (1 - a.residual_after_patch)
    action = "emergency_patch" if benefit > a.change_cost else "normal_queue"
    out.append((a.name, round(p, 3), round(benefit), action))

expected = [
 ('edge-idp', .798, 477621, 'emergency_patch'),
 ('isolated-build', .798, 1341, 'normal_queue'),
 ('marketing-site', .055, 1852, 'normal_queue')]
assert out == expected, out
print(out)

Expected output is exactly expected. The shared CVE-A forecast produces different actions because local exposure and consequence differ. Without origin deduplication, duplicated reporting would create false certainty.

Production Failure Analysis

Future leakage. Joining today’s KEV and latest EPSS to old snapshots creates a clairvoyant backtest. Snapshot feeds and use only data ingested before each historical decision.

Invisible assets. An inner join between scanner and CMDB erases unmanaged assets. Publish join coverage. Distinguish “not reachable with recent evidence” from “reachability unknown”; missing must never become false.

Catalog bias. KEV is curated for a mission, not a random sample. “Not in KEV” is not a clean negative label. Use confirmed positives, delayed outcomes, reviewed samples, and positive-unlabeled methods where justified.

Queue shock. A feed update can move thousands of deployments across a threshold. Group common remediations, enforce engineering capacity, reserve an incident lane, and rank marginal avoided loss per hour. If EPSS becomes stale, fall back to explicitly degraded logic rather than silently reusing it forever.

Adversarial manipulation. Attackers can publish false exploit claims or poison sensors. Authenticate feeds, hash source material, separate extraction confidence from exploit evidence, and support removing a source followed by deterministic replay.

Evaluate the forecast with horizon-specific Brier score, calibration, and precision–recall. Evaluate the policy with expected loss avoided, emergency changes, incidents tied to vulnerable deployments, and remediation capacity. A calibrated forecast can still drive a poor policy if impact or patch-cost estimates are wrong.

Designing the Production Prioritizer

The production service should expose two APIs rather than one. A forecast API answers, for a CVE and timestamp, what exploitation probability and evidence were available. A decision API accepts a deployment observation, candidate actions, and policy version, then returns the chosen action and loss decomposition. This separation lets the threat-research team improve evidence fusion without owning business impact estimates, and lets asset owners dispute inventory or consequence without rewriting threat history.

Forecast features must be monotone in time: a document received tomorrow cannot change what was knowable today. Maintain append-only feed snapshots and a canonical CVE alias table. Reject records whose CVE identifier cannot be resolved, but retain them in a quarantine stream because pre-CVE exploitation reports are often valuable. When a CVE is later assigned, create a sourced alias event rather than rewriting the old document.

Asset context needs its own freshness rules. Network reachability may expire after hours; ownership might remain valid for weeks; business-impact tiers may be reviewed quarterly. Each field should carry measured_at, source, and expiry. The decision engine should abstain or widen its loss range when a critical input is stale. One global “data fresh” flag conceals the fact that different evidence decays at different rates.

Remediation grouping deserves explicit modeling. A package upgrade may remove five CVEs across 4,000 hosts with one tested change, while separately ranking every pair makes the work look impossibly large. Build candidate actions such as “upgrade base image X from digest A to B” and calculate the union of affected deployment losses, avoiding double counting when several CVEs lead to the same compromise path. Subtract testing, rollout, and expected outage cost once per action, not once per CVE.

Capacity constraints turn ranking into scheduling. Emergency windows, platform-team skills, freeze periods, dependency order, and rollback readiness can be represented as constraints. A simple greedy queue based on avoided loss per engineering hour is transparent and often adequate; integer optimization becomes useful when actions share prerequisites or maintenance windows. The optimizer must never invent precision: if impact is a broad range, solve optimistic and pessimistic schedules and surface actions stable across both.

An example decision review

Suppose an endpoint-management CVE has EPSS 0.12, a public exploit from one independent origin, and no KEV entry. It affects 6,000 laptops, but the vulnerable service is disabled on 5,400. The remaining 600 include 40 privileged administrator devices. The correct response is not a fleetwide priority score. Produce at least three deployment segments, verify configuration evidence, and compare actions: disable the service remotely, upgrade the agent, or isolate the administrator devices. A reversible configuration mitigation may dominate a risky emergency upgrade even though it does not “close” the scanner finding.

Now suppose the scanner cannot distinguish disabled from enabled services on 15% of laptops. The denominator is 6,000, not the 5,100 with confident configuration. Report the unknown segment and sample it. If sampling shows configuration data fails disproportionately on older, high-risk devices, random extrapolation is invalid; stratify by operating system and management health.

Evaluation data construction

Define the forecast horizon before collecting labels. For a 30-day forecast made daily, adjacent observations for one CVE share outcomes and cannot be treated as independent rows in an ordinary random split. Split by time and, for robustness, by CVE disclosure cohort. A positive label should cite an exploitation observation whose timestamp falls inside the horizon and whose source was not itself used as an input unless the evaluation explicitly measures assimilation speed.

Unobserved exploitation is not a confirmed negative. Honeypots and telemetry cover only parts of the internet, and reporting is selective. In addition to conventional metrics, estimate performance on high-observability strata and report label coverage. Sensitivity analysis can ask how calibration changes if a plausible fraction of unlabeled cases were exploited. This is more honest than presenting six decimal places from incomplete surveillance.

Policy evaluation should replay action availability as well as forecasts. A patch not published at decision time was not a feasible action. Likewise, a mitigation requiring a control the organization had not deployed cannot be credited retrospectively. Historical simulation should reconstruct inventory, controls, maintenance constraints, and labor capacity. Otherwise the model is evaluated in a fictional organization with perfect options.

Governance and human authority

Threat researchers should be able to flag a source as compromised, but removing it must produce a new evidence-policy version and an impact report listing changed decisions. Asset owners may correct reachability or impact with evidence and expiry, not by editing the threat probability. Incident commanders may override scheduling during active exploitation; the override record should state duration, scope, and reason.

Metrics create incentives. If vulnerability teams are measured by the number of KEV items closed, they may prioritize easy low-impact deployments and suppress hard exceptions. Pair timeliness with remaining expected exposure, unknown coverage, emergency-change harm, and recurrence. Review a random sample of “not affected” dispositions because that status can become a hiding place for inventory defects.

Finally, publish uncertainty in language operators can use: what is known, what is inferred, what is missing, and which new measurement would change the action. That is more actionable than a falsely precise percentile.

The service should also preserve rejected alternatives. Recording why mitigation lost to patching, or why acceptance lost to measurement, makes later incident review possible and prevents operators from reconstructing rationale from a score whose inputs have since changed.

Sources and Further Reading

  • FIRST, Exploit Prediction Scoring System. A daily probability forecast for exploitation in the next 30 days, complementary to severity. https://www.first.org/epss/
  • CISA, Known Exploited Vulnerabilities Catalog. Strong curated exploitation evidence, but not an exhaustive negative-label boundary. https://www.cisa.gov/known-exploited-vulnerabilities-catalog
  • FIRST, CVSS v4.0. Technical severity characteristics, including threat and environmental metrics; not organization-specific exploit forecasting. https://www.first.org/cvss/v4.0/
  • NIST, National Vulnerability Database. Normalized enrichment whose publication and revision times matter to point-in-time analysis. https://nvd.nist.gov/
  • OASIS, STIX 2.1. Exchange semantics for intelligence objects, relationships, and provenance. https://docs.oasis-open.org/cti/stix/v2.1/stix-v2.1.html
  • MITRE ATT&CK and ATLAS. Behavioral knowledge bases for enterprise and AI-system threats. https://attack.mitre.org/ and https://atlas.mitre.org/

Together these sources imply a layered system: CVSS describes characteristics, EPSS forecasts population exploitation, KEV adds observed-exploitation evidence, STIX carries sourced claims, and ATT&CK/ATLAS connect claims to behaviors. The organization still owns exposure, consequence, and intervention cost.

Interview Practicum

Scenario: The Forecast Changes Mid-Meeting.

Prompt. You have 140,000 CVE–asset pairs and capacity to remediate 2,000 per week. Design the service.

A strong candidate asks whether capacity counts hosts, packages, or change tickets; requests reachability, asset-loss tiers, maintenance windows, compensating controls, point-in-time feeds, exploit labels, and shared patches.

Worked Answer

The initial design builds time-stamped deployment observations, uses EPSS as a prior, groups independent evidence, estimates exposure and residual control effectiveness, then schedules common remediation actions by expected avoided loss per engineering hour.

Follow-Up Questions and Answers

Constraint change one: reachability is only 60% complete and weekly. Introduce reachable, recently verified unreachable, and unknown states. Use loss bounds for unknowns. Cases whose action changes across the bounds enter a measurement queue. Publish coverage as an SLI; do not claim risk fell when visibility disappeared.

Constraint change two: an identity appliance enters KEV Friday afternoon, but its patch has a 4% outage rate and downtime is forbidden before Monday. Compare weekend compromise loss with outage loss. Apply reversible controls—management-plane restriction, targeted detection, stronger authentication, and active hunting—then patch in an approved window with rollback. Do not reduce the threat score to rationalize the operational decision.

Principal probe: leadership wants one number. Report estimated exploitable exposure above the approved loss threshold, with an uncertainty range, the fraction actively mitigated, and age. Operators retain the components.

Weak answers sort only by CVSS or EPSS, add incompatible scales, treat KEV absence as a negative label, or convert NLP confidence directly into exploit probability.

Key Takeaways

  • CVSS severity, EPSS probability, KEV evidence, and local risk are different variables.
  • Prioritize time-stamped CVE–asset–deployment observations, not CVEs alone.
  • Bayesian updates require calibrated likelihood ratios and source-lineage deduplication.
  • Schedule interventions by expected avoided loss under real remediation capacity.
  • Preserve feed history, unknown exposure states, evidence spans, and policy versions.
  • Evaluate forecast calibration and downstream policy outcomes separately.
