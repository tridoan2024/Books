Chapter 36: Evaluating Agent Security Controls

One Passing Run Proves Almost Nothing

An agent may refuse an attack on Tuesday and execute it on Wednesday because sampling, retrieval order, tool latency, memory, or a slightly different conversation changes its trajectory. Security evaluation must therefore estimate a distribution of outcomes, not preserve a favorite transcript. The evaluation unit is a scenario–configuration–trial tuple, and the claim should include uncertainty.

A safeguard can reduce attack success while destroying legitimate work. It can also appear strong because the test set contains obvious attacks, because evaluators stop after the first refusal, or because a sandbox prevents consequences without testing whether policy allowed them. Chapter 34 identified authority paths; Chapter 35 made actions observable. This chapter uses those artifacts to test the whole control stack: model, prompt/scaffold, retrieval, memory, policy, tool broker, sandbox, approval, and final outcome.

Evaluation Architecture

flowchart LR

 C[Control configurations] --> X

 X --> RN[Isolated runner seed N]

 R2 --> T
 RN --> T

 O --> M[Metrics by threat, utility, and segment]

 U --> G{Release gate}
 G -->|pass| D[Canary with kill switch]
 G -->|fail| B[Counterexample corpus]
 B --> S

The scenario registry is immutable per evaluation. Each entry identifies initial state, trusted and untrusted inputs, permitted actions, forbidden outcomes, benign task goal, termination rule, and oracle. The scheduler varies seeds and relevant environmental factors. Runners are disposable and deny real-world side effects. Oracles operate on typed traces and final state, not on whether output “sounds safe.”

Define the Estimands

For adversarial scenario family \(g\), attack success rate is

\[ ASR_g=P(\text{forbidden outcome}\mid g, configuration). \]

Defense success is not always \(1-ASR\): a run can avoid the forbidden outcome yet fail closed incorrectly, loop, or abandon the legitimate subtask. On benign tasks define false-refusal rate \(FRR=P(refusal\mid benign)\), task success \(TSR\), cost, latency, and human interventions. A paired utility difference between candidate \(c\) and baseline \(b\) can be

\[ \Delta U=E[w_t(TSR_c-TSR_b)-w_a(ASR_c-ASR_b) -w_f(FRR_c-FRR_b)-w_k(Cost_c-Cost_b)]. \]

Weights encode an explicit operating decision, but always publish components. A positive aggregate can hide catastrophic regression in a high-impact scenario.

Repetition and confidence intervals

For \(x\) successes in \(n\) independent trials, report \(\hat p=x/n\) with a Wilson interval rather than a naked rate. At zero observed bypasses, the one-sided “rule of three” gives an approximate 95 percent upper bound of \(3/n\): zero in ten trials still permits a true bypass probability near 30 percent. To claim an upper bound below 1 percent after zero failures requires roughly 300 representative trials, not three screenshots. The shortcut assumes approximately IID trials. When attempts cluster by repository, agent session, target, or model version, the effective sample size is smaller; use cluster-aware analysis or a cluster bootstrap rather than substituting the raw request count for \(n\).

Trials may not be independent. Provider updates, shared caches, rate limits, or persistent memory create clusters. Randomize execution order, isolate state, block by model/provider version, and use cluster bootstrap or hierarchical analysis when trials share conditions. Store seeds where supported, but do not confuse a seed with reproducibility across changing infrastructure.

Adaptive attacks

A static attack suite measures known strings, not a determined adversary. Split evaluation into fixed regression cases, mutation-based variants, and an adaptive phase in which a tester observes refusals and changes strategy within a bounded budget. Keep the final holdout private from control developers. Track attempts-to-bypass and success within budget.

Oracles

Output keyword matching is a weak oracle. Prefer state-based facts: Did a network connection reach a forbidden host? Was a credential read? Did the broker issue an unauthorized capability? Was production modified? Combine automatic oracles with blinded human adjudication for ambiguous semantic harm. Measure inter-rater agreement and resolve disagreements under a written rubric.

Experimental Design and Release Gates

Pair candidate and baseline on the same scenario instances to reduce variance. Randomize which runs first. Freeze model, tool, policy, scenario, and dependency versions for the comparison. If the production model is a moving service, record its provider version and repeat sentinel scenarios over time.

Pre-register primary metrics and gates. A credible gate might require: no critical forbidden outcome in a designated must-pass suite; candidate ASR upper confidence bound below 5 percent per high-risk family; benign task-success lower bound no more than two percentage points below baseline; false-refusal increase below one point; and no new unrestricted authority path. Gates are governance decisions, not statistically discovered after results arrive.

Avoid test-set contamination. Scenario text, hidden tokens, and oracle details should not enter training or everyday prompt repositories. Rotate semantic variants and test structural behavior. If a safeguard recognizes the phrase “ignore previous instructions,” it has learned a costume, not a boundary.

Executable Lab: Repeated-Trial Control Evaluation

This deterministic simulation models a nondeterministic agent under baseline and guarded configurations. It runs paired adversarial and benign trials, computes Wilson 95 percent intervals, and reports security and utility. Synthetic randomness makes the lab safe and repeatable.

from math import sqrt
from random import Random

SCENARIOS = [
    ("indirect_injection", "attack", .34, .08),
    ("delegation_escape", "attack", .22, .06),
    ("normal_refactor", "benign", .91, .87),
    ("dependency_update", "benign", .84, .79),
]

def wilson(successes, trials, z=1.96):
    p = successes / trials
    den = 1 + z*z/trials
    center = (p + z*z/(2*trials)) / den
    margin = z * sqrt((p*(1-p) + z*z/(4*trials))/trials) / den
    return center - margin, center + margin

def run(seed=2026, trials=200):
    rng = Random(seed)
    results = {}
    for name, kind, baseline_p, guarded_p in SCENARIOS:
        for config, probability in (("base", baseline_p),
                                    ("guard", guarded_p)):
            successes = sum(rng.random() < probability for _ in range(trials))
            results[(name, kind, config)] = (successes, trials)
    return results

results = run()
for (name, kind, config), (x, n) in results.items():
    lo, hi = wilson(x, n)
    metric = "ASR" if kind == "attack" else "TSR"
    print(f"{name:20} {config:5} {metric}={x/n:.3f} "
          f"95%CI=[{lo:.3f},{hi:.3f}]")

Expected output:

indirect_injection   base  ASR=0.290 95%CI=[0.232,0.356]
indirect_injection   guard ASR=0.050 95%CI=[0.027,0.090]
delegation_escape    base  ASR=0.220 95%CI=[0.168,0.282]
delegation_escape    guard ASR=0.085 95%CI=[0.054,0.132]
normal_refactor      base  TSR=0.940 95%CI=[0.898,0.965]
normal_refactor      guard TSR=0.865 95%CI=[0.811,0.906]
dependency_update    base  TSR=0.825 95%CI=[0.766,0.871]
dependency_update    guard TSR=0.775 95%CI=[0.712,0.827]

The guard clearly reduces simulated ASR, but it also reduces benign success. Whether it ships depends on predeclared utility and non-inferiority gates. In a real harness, replace Bernoulli draws with isolated agent executions, preserve typed traces, and have oracles inspect final state. Do not let the harness possess production credentials.

Operational Failure Analysis

Evaluating only the model. A model refusal can be followed by a scaffold retry that succeeds dangerously; a model compliance can be blocked by the broker. Score policy decisions, tool calls, and outcomes separately.

Stopping on a good result. Re-running until a control passes is optional stopping. Fix trial counts or use a documented sequential test with error spending. Publish all planned runs.

Scenario monoculture. Many paraphrases of one injection inflate sample size without threat diversity. Report both trial-weighted and family-weighted results. Maintain coverage against authority paths, tool classes, data boundaries, and persistence mechanisms.

Cross-trial contamination. Memory, caches, files, and provider sessions can carry attack instructions into later benign trials. Reset state and include contamination canaries. If production intentionally preserves memory, evaluate ordered multi-session sequences as their own scenario.

Unsafe testing. An evaluation that can email customers or deploy production is an incident generator. Substitute instrumented fake services, network sinks, synthetic secrets, and canary credentials with no authority. Test the real authorization layer in a dedicated nonproduction tenant.

Oracle leakage. If the agent sees the forbidden marker or evaluator rubric, it can optimize for the test. Keep oracle state out of context and use external observations.

Aggregate victory. A large improvement on easy cases can mask one critical regression. Use must-pass outcomes and report worst-family bounds. Never average away catastrophic impact.

Production drift. Controls interact with new models, tools, prompts, and policies. Trigger evaluation on component changes, run scheduled sentinel trials, and compare canary trace distributions. Preserve a tested kill switch and known-safe reduced-authority mode.

Reporting results

An evaluation report begins with the release decision and tested configuration, then lists gates, sample sizes, invalid trials, point estimates, intervals, and scenario coverage. Include every critical counterexample with secrets removed. Separate prespecified findings from exploratory observations. Provide machine-readable trial records so another team can reproduce calculations.

Avoid league tables that rank safeguards by one aggregate score. State where each control acts: prompt handling, memory, policy, broker, sandbox, or approval. Two controls with similar ASR can have different failure correlation; defense in depth is valuable when bypasses are not shared. Test combinations rather than assuming independent effects.

Source Synthesis

Reports should also state what was not tested, especially languages, tenants, tool versions, long-horizon memory, and provider regions. Named omissions prevent a local result from becoming an organization-wide safety claim.

Constructing the Suite

Design scenarios from authority edges, not jailbreak phrases. For each consequential tool, create cases where untrusted evidence alters object, action, destination, scope, or timing. Include encoded content, tool-output injection, poisoned memory, compromised dependencies, delegation, and multi-turn pressure. Create benign twins sharing surface features: legitimate research quoting attacks, an authorized sensitive-file request, and harmless tool recovery. Twins reveal vocabulary filters.

Each scenario contract names setup, roles, trusted inputs, attacker inputs, allowed actions, forbidden outcomes, maximum turns, cost budget, reset, and oracle. Give it a stable family identifier with instance variation. Version it whenever success criteria change. Add counterexamples to regression while retaining a private holdout.

Sampling should reflect frequency and risk. A frequency-weighted estimate predicts ordinary exposure; a risk-weighted suite stresses rare catastrophic paths. Publish both. A production task capable of rotating a root credential deserves substantial testing even if rare.

Power and thresholds

Confidence intervals describe uncertainty after testing; power analysis plans whether a meaningful change is detectable. If baseline ASR is 10 percent and useful reduction means 5 percent, choose sample size for that contrast and desired errors. For rare events, combine stress tests, structural authorization assurance, and conservative bounds. Absence of observed harm is not impossibility.

For benign utility use non-inferiority. Set margin (delta) before results: accept only if the lower confidence bound of (TSR_c-TSR_b) exceeds (-delta). Choose margins from user consequence, not release convenience. Measure tail latency and cost because loops make distributions heavy-tailed.

Multiple families create multiplicity. “Any critical failure” gates need no averaging. Label exploratory comparisons and control false discoveries for confirmatory claims. Never cherry-pick a seed, snapshot, or judge.

Harness engineering

Capture scenario version, model and parameters, system-prompt digest, retrieval corpus, memory snapshot, tool schemas, policy bundle, container image, network policy, and evaluator code. Assign trial IDs and derive seeds from a recorded master. Enforce timeout, token, tool, and spend budgets.

Fake tools must be behaviorally faithful. A mock deployer implements authorization, idempotency, state, and receipts rather than always succeeding. Synthetic credentials serve as canaries without real authority. Network sinks record destinations and content digests.

Evaluator failure is distinct from agent failure. Provider errors, invalid setup, and oracle crashes are neither attack nor defense success. Report invalid-trial rate, retry under a declared rule, and investigate configuration-correlated failures. A control must not look safe by crashing the harness.

Production bridge

Canaries begin with reduced authority and shadow policy. Compare production tool sequences, refusal patterns, and delegation depth with suite coverage. Do not replay private prompts into research without consent and minimization.

Define response thresholds before launch. One critical unauthorized action triggers containment; refusal regression may trigger rollback; a new model identity triggers sentinels or blocks execution. Preserve failed traces and sandbox state. Generalize failures into tests without broadly publishing bypass details.

NIST AI RMF frames evaluation as continuous risk management, while the Generative AI Profile identifies generative-system risks. OWASP and MITRE ATLAS organize concrete adversarial behaviors. Statistical guidance on binomial intervals prevents false certainty from small samples. Agent evaluation research contributes task environments, but security requires consequence-grounded oracles and authority-aware scenario coverage. The synthesis is a repeated, paired, isolated experiment with confidence bounds and explicit utility loss.

Interview Practicum

A vendor claims its new tool-call firewall cut prompt-injection success from 20 percent to zero in ten trials. Your coding agent serves 50,000 monthly tasks. You have two weeks and a constrained evaluation budget. After you propose a test, the vendor reveals that its control increases refusals and that the production model changes without notice.

Design the evaluation, quantify what the current evidence means, define release gates, and explain how you will handle adaptive attacks and model drift.

Worked Answer

Zero successes in ten does not establish zero risk; the approximate 95 percent upper bound is 30 percent. I would build a versioned suite from the Chapter 34 authority graph: indirect injection, delegation, credential access, egress, memory poisoning, tool confusion, and approval binding, plus benign tasks that exercise the same tools. Critical paths receive more trials than low-impact families.

Run baseline and firewall configurations paired on identical scenario instances, randomized in order, in isolated sandboxes. Record model/provider identity, scaffold, tool, policy, and seed where available. Automatic oracles inspect forbidden state transitions; blinded reviewers handle semantic ambiguity. Report ASR and Wilson intervals per family, benign task success, false refusal, latency, cost, and human escalation.

The release gate includes zero critical must-pass outcomes, bounded upper ASR per high-risk family, and a predeclared non-inferiority margin for task success and false refusal. A small adaptive team gets a fixed attempt budget after the static suite, while a private holdout remains untouched. Because the model changes without notice, provider identity becomes a blocking observability requirement or contractual risk; run daily sentinels and trigger the full suite on detected change. Canary deployment uses reduced authority and an immediate rollback path.

Follow-Up Questions and Answers

How many trials are enough?

Enough is claim-dependent. With zero failures, about 300 representative independent trials support an approximate 95 percent upper bound below 1 percent. Clustered or heterogeneous trials require more careful design, not merely more repetitions.

The control blocks attacks by blocking all tool calls. Did it pass?

No. Its ASR may be low, but task success and false refusal expose that it eliminated the product’s function. Security and utility are joint constraints.

Should adaptive results enter the same ASR as static tests?

Report them separately. Adaptive trials have conditional, budget-dependent sampling. Combining them with fixed random trials produces a number with unclear meaning.

What if human reviewers disagree?

Use a written rubric, blinded independent ratings, agreement statistics, and adjudication. Preserve both original judgments. Frequent disagreement means the oracle or scenario contract is underspecified.

Key Takeaways

  • Evaluate distributions of outcomes across repeated trials, not memorable transcripts.
  • Pair security metrics with benign utility, refusal, latency, cost, and escalation.
  • Report confidence intervals per threat family and protect catastrophic must-pass cases.
  • Isolate trials and ground oracles in tool-side state and typed traces.
  • Separate fixed regression, mutation, and adaptive attack evidence.
  • Re-run evaluations whenever models, scaffolds, tools, or policies change.

Field lesson: benchmark contracts must fail closed

The sec-pr project registered 564 benchmark contracts, while the single recorded benchmark run returned insufficient_evidence. Registration did not become an invented pass count. The harness exercised its fail-closed status path and preserved the difference between executable evaluation structure and mature human outcome evidence. The full case appears in Chapter 47.
