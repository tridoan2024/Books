Chapter 7: Machine Learning Methods and Selection

Benchmark Notebook: Three Models, One Review Queue

The product requirement is not “maximize AUC.” Each hour, a login service produces more suspicious sessions than investigators can review. The team can inspect the top 25 sessions in a batch. Missing a malicious login costs far more than reviewing a benign one, yet an uncalibrated probability cannot safely drive an automatic challenge.

We will build an imbalanced temporal fixture, compare logistic regression, a decision tree, and histogram gradient boosting, calibrate the selected model, and evaluate ranking, capacity, cost, stability, and interpretation. The fixture is synthetic so its mechanism is visible; the validation design is intended for real data.

Fixture: Make Time and Base Rate Visible

Each row represents a login. Features available at decision time are failed attempts in the preceding hour, device age, distance from the user's usual region, ASN rarity, and whether the session has strong authentication. Attack prevalence rises in the final period and the relationship between distance and attack changes slightly—a small regime shift.

import numpy as np
from sklearn.model_selection import TimeSeriesSplit, GridSearchCV
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import average_precision_score, roc_auc_score, brier_score_loss
from sklearn.calibration import CalibratedClassifierCV
from sklearn.frozen import FrozenEstimator

rng=np.random.default_rng(27); n=6000
day=np.repeat(np.arange(60),100)
failed=rng.poisson(0.7,n); device_age=rng.exponential(120,n)
distance=rng.gamma(1.5,350,n); asn_rare=rng.binomial(1,.08,n)
strong_auth=rng.binomial(1,.62,n)
logit=-4.7+0.72*failed-0.004*np.minimum(device_age,365)+0.0015*distance
logit += 1.45*asn_rare-1.2*strong_auth+0.8*((distance>900)&(device_age<7))
logit += .035*np.maximum(day-44,0)
prob=1/(1+np.exp(-logit)); y=rng.binomial(1,prob)
X=np.c_[failed,device_age,distance,asn_rare,strong_auth]
train=day<45; test=day>=45
print(X.shape, int(y.sum()), f"train={y[train].mean():.4f}", f"test={y[test].mean():.4f}")

With the specified seed, expected output in the companion environment is:

(6000, 5) 177 train=0.0284 test=0.0327

The positive class is rare, and prevalence differs across time. A random split would leak future regime composition into training and produce a deceptively stable estimate. The first 45 days are development data; the last 15 form a locked temporal test.

Metrics Before Models

Let the review capacity be \(k=25\) per 1,500-event test period. For scores \(s_i\), precision at \(k\) is positives among the largest \(k\) scores divided by \(k\); recall at \(k\) divides by all positives. A cost policy assigns 1 unit to a benign review and 40 units to a missed malicious login.

import numpy as np

def top_k(y, score, k=25):
    chosen=np.argsort(score)[-k:]
    tp=int(y[chosen].sum()); positives=int(y.sum())
    return tp/k, tp/positives, chosen

def queue_cost(y, score, k=25, review_cost=1, miss_cost=40):
    precision, recall, chosen=top_k(y,score,k)
    tp=int(y[chosen].sum()); fp=k-tp; fn=int(y.sum())-tp
    return fp*review_cost+fn*miss_cost, {"tp":tp,"fp":fp,"fn":fn}

Average precision summarizes the precision-recall ranking across thresholds and should be read against prevalence. ROC AUC remains informative about pairwise ranking but can look excellent while top-of-queue precision is unusable. Brier score evaluates squared probability error; calibration curves will reveal where errors occur.

The operational metric is not accuracy. Predicting every event benign already achieves about 96.7 percent accuracy on the test period and catches nothing.

Contenders and an Honest Search

Logistic regression is the low-variance, inspectable baseline. Scaling is inside its pipeline so each fold estimates scaling only on its training portion. The shallow tree captures thresholds and interactions but is prone to instability. Histogram boosting can learn nonlinearities and interactions with regularization.

import numpy as np
from sklearn.model_selection import TimeSeriesSplit, GridSearchCV
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import average_precision_score, roc_auc_score, brier_score_loss
from sklearn.calibration import CalibratedClassifierCV
from sklearn.frozen import FrozenEstimator

logit += 1.45*asn_rare-1.2*strong_auth+0.8*((distance>900)&(device_age<7))
logit += .035*np.maximum(day-44,0)

models={
 "logistic": Pipeline([("scale",StandardScaler()),
     ("model",LogisticRegression(max_iter=2000,class_weight="balanced",C=.2))]),
 "tree": DecisionTreeClassifier(max_depth=4,min_samples_leaf=30,
     class_weight="balanced",random_state=27),
 "boosting": HistGradientBoostingClassifier(max_iter=120,max_leaf_nodes=15,
     learning_rate=.06,l2_regularization=2.0,random_state=27)
}

for model in models.values(): model.fit(X[train],y[train])
for name,model in models.items():
    score=model.predict_proba(X[test])[:,1]
    p,r,_=top_k(y[test],score)
    cost,parts=queue_cost(y[test],score)
    print(name, f"AP={average_precision_score(y[test],score):.3f}",
          f"ROC={roc_auc_score(y[test],score):.3f}",
          f"P@25={p:.3f}",f"R@25={r:.3f}",f"cost={cost}",parts)

The higher-capacity models overfit a small positive class and unstable interactions. The relevant advantage is seven more discoveries than the tree in the first 25 and 369 lower cost units—not a vague claim that linear models are always safer.

Nested validation for tuning

The locked test cannot select hyperparameters. On the 45-day development interval, an outer temporal split estimates generalization and an inner temporal split selects settings. The inner folds must precede their validation windows.

import numpy as np
from sklearn.model_selection import TimeSeriesSplit, GridSearchCV
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import average_precision_score, roc_auc_score, brier_score_loss
from sklearn.calibration import CalibratedClassifierCV
from sklearn.frozen import FrozenEstimator

rng=np.random.default_rng(27); n=6000
day=np.repeat(np.arange(60),100)
failed=rng.poisson(0.7,n); device_age=rng.exponential(120,n)
distance=rng.gamma(1.5,350,n); asn_rare=rng.binomial(1,.08,n)
strong_auth=rng.binomial(1,.62,n)
logit=-4.7+0.72*failed-0.004*np.minimum(device_age,365)+0.0015*distance
logit += 1.45*asn_rare-1.2*strong_auth+0.8*((distance>900)&(device_age<7))
logit += .035*np.maximum(day-44,0)
prob=1/(1+np.exp(-logit)); y=rng.binomial(1,prob)
X=np.c_[failed,device_age,distance,asn_rare,strong_auth]
train=day<45; test=day>=45

outer=TimeSeriesSplit(n_splits=3)
grid={"max_leaf_nodes":[7,15],"learning_rate":[.04,.08],"l2_regularization":[1.,4.]}
outer_ap=[]
for outer_train,outer_valid in outer.split(X[train]):
    search=GridSearchCV(
        HistGradientBoostingClassifier(max_iter=100,random_state=27),grid,
        scoring="average_precision",cv=TimeSeriesSplit(n_splits=3),n_jobs=1)
    search.fit(X[train][outer_train],y[train][outer_train])
    score=search.best_estimator_.predict_proba(X[train][outer_valid])[:,1]
    outer_ap.append(average_precision_score(y[train][outer_valid],score))
print([round(x,3) for x in outer_ap], round(float(np.mean(outer_ap)),3))

Expected output:

[0.161, 0.222, 0.099] 0.161

Variation across outer folds is itself evidence. Report the fold distribution and dates, not only the mean. If multiple events belong to one identity or campaign, time splitting alone may still leak entity-specific patterns. Use grouped temporal blocks or purge an interval around fold boundaries when feature windows overlap.

Probability Repair Without Test Leakage

Class weighting changes the training objective and often distorts raw probabilities. Calibration requires data not used to fit the base model. Reserve the last portion of development data for calibration or use cross-validated calibration within development. Never fit the calibrator on the locked test.

import numpy as np
from sklearn.model_selection import TimeSeriesSplit, GridSearchCV
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import average_precision_score, roc_auc_score, brier_score_loss
from sklearn.calibration import CalibratedClassifierCV
from sklearn.frozen import FrozenEstimator

rng=np.random.default_rng(27); n=6000
day=np.repeat(np.arange(60),100)
failed=rng.poisson(0.7,n); device_age=rng.exponential(120,n)
distance=rng.gamma(1.5,350,n); asn_rare=rng.binomial(1,.08,n)
strong_auth=rng.binomial(1,.62,n)
logit=-4.7+0.72*failed-0.004*np.minimum(device_age,365)+0.0015*distance
logit += 1.45*asn_rare-1.2*strong_auth+0.8*((distance>900)&(device_age<7))
logit += .035*np.maximum(day-44,0)
prob=1/(1+np.exp(-logit)); y=rng.binomial(1,prob)
X=np.c_[failed,device_age,distance,asn_rare,strong_auth]
train=day<45; test=day>=45

fit_days=day<35; calibration_days=(day>=35)&(day<45)
base=Pipeline([("scale",StandardScaler()),
    ("model",LogisticRegression(max_iter=2000,class_weight="balanced",C=.2))])
base.fit(X[fit_days],y[fit_days])
calibrated=CalibratedClassifierCV(FrozenEstimator(base),method="isotonic")
calibrated.fit(X[calibration_days],y[calibration_days])
raw=base.predict_proba(X[test])[:,1]
fixed=calibrated.predict_proba(X[test])[:,1]
print(f"raw Brier={brier_score_loss(y[test],raw):.4f}")
print(f"calibrated Brier={brier_score_loss(y[test],fixed):.4f}")
print(f"mean predicted={fixed.mean():.4f} observed={y[test].mean():.4f}")

Expected output:

raw Brier=0.1569
calibrated Brier=0.0263
mean predicted=0.0280 observed=0.0327

Isotonic calibration can overfit when positives are scarce. Compare sigmoid calibration, inspect reliability bins with counts, and bootstrap by time block. Calibration does not improve ranking by design; it makes a score more interpretable as probability. A ranking queue may choose the uncalibrated model if ordering is best, while an automated step-up policy needs trustworthy probabilities and separate safety review.

Interpretation as Falsifiable Investigation

For logistic regression, standardized coefficients show direction and relative log-odds association, conditional on the feature set. They do not prove causes. Correlated variables can exchange coefficient magnitude.

For any model, permutation importance measures the performance decrease after shuffling one feature on a held-out set. It fails when correlated features substitute for one another and becomes misleading if shuffling creates impossible combinations. Partial dependence averages predictions over synthetic feature changes; accumulated local effects can behave better with correlated features but still describe the fitted model, not the world.

A security review should pair global and local analysis:

  • inspect performance by strong-auth status, device-age bands, region, customer, and time;
  • retrieve representative true positives, false positives, and false negatives;
  • perturb inputs within valid ranges and check monotonic expectations where policy requires them;
  • look for proxies such as geography standing in for customer or workforce population;
  • explain the final queue with observed feature values and comparison cases, not a causal story.

The fixture intentionally makes strong authentication protective. If local explanations repeatedly claim strong authentication increases risk, investigate correlation, encoding, and interaction before writing prose around the model.

Model Choice Beyond the Scoreboard

The benchmark does not automatically crown boosting. Logistic regression may be preferred when latency is extremely tight, the feature relationship is stable and close to linear, probability calibration is reliable, or reviewers require a compact reason code. The tree may be useful as an auditable policy prototype but loses here on ranking and stability. Boosting is justified when its measurable queue benefit survives temporal folds, subgroup review, latency tests, and operational complexity.

Nearest neighbors are often costly at inference and sensitive to scaling and irrelevant dimensions. Support-vector machines can work well on moderate sparse datasets but probability estimation and large-scale training require care. Random forests offer robust nonlinear baselines but their probability tails may need calibration. Neural networks are justified by enough data and representation needs—text, images, sequences—not by prestige. Unsupervised anomaly detection answers “unusual relative to its reference,” not “malicious”; validate it through a review queue and adversarially meaningful outcomes.

Active learning can spend analyst labels on uncertain or diverse events, but naive uncertainty sampling may neglect rare high-risk regions. Semi-supervised methods assume something about cluster or manifold structure that attackers may violate. Every learning paradigm imports assumptions; model selection is the work of exposing and testing them.

Robustness and Launch Record

Before launch, replay known telemetry failures: missing device age, new ASN categories, duplicated events, delayed feature updates, extreme distances, and changed strong-auth enrollment. Measure score and queue changes. Confirm feature computation is point-in-time correct and online/offline definitions match. Establish fallbacks when a feature is stale. Rate-limit actions so a malformed upstream field cannot challenge an entire customer.

The model card should record training and calibration intervals, label definition and delay, exclusions, prevalence, feature provenance, hyperparameters, fold results, locked-test metrics, capacity and cost assumptions, subgroup limitations, calibration method, latency, owner, rollback condition, and monitoring plan. Retraining is not the default response to every drift alarm; first determine whether data, population, attacker behavior, or labels changed.

Benchmark Hygiene: Ways to Win Dishonestly

Imbalanced benchmarks are unusually easy to manipulate without an explicit lie. One can tune hundreds of configurations and report only the best test score, resample before splitting so duplicates cross folds, choose the queue size after seeing results, or exclude periods with missing labels. Each choice transfers information from evaluation into model selection.

Freeze the evaluation protocol before viewing the locked test: unit of splitting, time boundaries, label-maturity cutoff, primary and secondary metrics, queue size, cost coefficients, subgroup slices, and tie-breaking rule. Record every attempted configuration or use a reproducible search object. If the test influences a design decision, it is no longer a pristine test; create a later holdout rather than continuing to cite it as untouched.

Class imbalance techniques belong inside training folds. Class weights alter the contribution of examples to the objective. Random under-sampling discards majority information but can reduce compute. Over-sampling repeats minority examples and can overfit. Synthetic methods interpolate assumptions about feature space and may generate impossible security events, particularly with categorical and temporal variables. None of these changes real deployment prevalence, so probability estimates require evaluation and often calibration on naturally distributed data.

Threshold selection is a policy operation. A fixed probability threshold produces variable queue size when prevalence or calibration moves. A fixed top-k policy respects staffing but can force review of weak candidates during quiet periods. A hybrid can review up to k items above a minimum calibrated probability. Backtest the exact policy, including tied scores, customer caps, and rate limits. Report coverage: what share of eligible events could be scored with fresh features?

Cost coefficients should not be magical constants. Estimate review minutes, challenge abandonment, analyst opportunity cost, incident severity distribution, and recovery expense. Conduct sensitivity analysis across plausible miss-to-review ratios. If model choice flips whenever the miss cost moves from 35 to 40, the evidence does not support a robust winner. Present the frontier of discoveries versus burden rather than hiding judgment in one scalar.

Confidence intervals need dependence-aware resampling. Bootstrapping individual logins assumes independence that campaigns and identities violate. Resample days, customers, or campaigns according to the deployment uncertainty. For model comparisons, use paired resamples so both models face the same blocks; examine the distribution of metric differences. A one-point AP gain with an interval spanning substantial loss should not justify a more fragile service.

Interpretation must also be benchmarked. Give analysts blinded explanations from true and false cases and ask whether explanations help identify data defects, understand ranking, or choose a response. Measure consistency and time, not whether a colorful attribution “looks right.” An explanation layer that varies wildly under tiny valid perturbations can erode rather than create trust.

The benchmark itself is a governed artifact: version its fixture, split manifest, metric implementation, and expected output together.

Interview Practicum

Defend a Malicious-Login Model

Prompt and constraint cards

“Choose a model for malicious-login detection.” After the candidate starts, the panel reveals: only 25 sessions per hour can be reviewed; labels mature after 30 days; one large customer accounts for half the attacks; the authentication team wants automatic challenges at probability 0.8; and legal asks whether country is acting as a workforce proxy.

Worked Answer

Model-selection defense

Frame two decisions separately: ranking a bounded review queue and automatically challenging a login. Establish a temporal, customer-aware split and a locked recent test. Benchmark a rules/current-policy baseline, regularized logistic regression, a shallow tree, and boosted trees. Select for precision and recall at 25, expected operational cost, temporal variability, latency, and subgroup behavior—not global accuracy.

Use nested temporal validation for tuning; group or report the dominant customer separately so it cannot determine the headline result. Calibrate on a later development slice with matured labels, then evaluate reliability on the locked test. An automatic threshold of 0.8 is acceptable only if calibration near that region has sufficient support, the action's error cost is approved, and safe fallbacks exist. Otherwise use the score for ranking or step-up experimentation rather than automatic blocking.

Audit country by comparing models with and without it, checking performance and error rates across affected populations, examining correlated features, and considering a coarser or policy-derived representation. Removing country does not remove geographic proxies. Document the lawful and operational purpose rather than treating a feature-importance plot as a fairness verdict.

Benchmark traps

“Use deep learning because attackers are complex” ignores sample size, latency, calibration, and tabular baselines. “Use AUC” ignores capacity. “Apply SMOTE before cross-validation” can leak synthetic information and distort time. “Set class weights and interpret output as probability” ignores calibration. “Drop country, therefore fair” ignores proxies and error distribution.

Follow-Up Questions and Answers

Adversarial panel follow-ups

The boosting gain is one extra true positive per hour. Is it worth it? Quantify prevented-loss value, review burden, latency, maintenance, and uncertainty across time. If the gain is unstable or operational cost dominates, ship logistic regression.

Labels are selectively observed because analysts review high scores. Preserve randomized exploration or audit samples, model selection propensity where defensible, and avoid treating unlabeled low-score events as benign.

The base rate doubles. Ranking may remain similar while calibration fails. Reassess reliability, capacity, thresholds, and whether the change reflects attacks, customer mix, or label policy.

Spoken model recommendation

Thirty seconds: “I would benchmark interpretable and nonlinear models on temporal, customer-aware splits; choose by discoveries and misses at the actual queue size; calibrate on separate matured labels before any automated action; and ship the simplest model whose advantage is stable and operationally material.”

Key Takeaways

  • Model selection begins with the deployed decision, capacity, temporal split, and error costs.
  • Precision-recall, top-k discovery, cost, calibration, and fold stability reveal failures hidden by accuracy or ROC AUC.
  • Tune inside development data; keep a recent locked test and prevent identity, campaign, or feature-window leakage.
  • Calibration needs independent matured labels and does not repair ranking.
  • Interpretation describes model behavior and supports investigation; it does not establish causality or fairness.
  • Prefer the simplest contender whose real operational advantage is stable, material, and supportable.
