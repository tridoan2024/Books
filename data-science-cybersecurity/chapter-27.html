Chapter 27: Network, Endpoint, Cloud, and Application Analytics

An Investigation Is a Join Across Partial Witnesses

No telemetry domain tells the whole story. A network flow sees endpoints and bytes but often not the process or authenticated user. Endpoint telemetry sees process ancestry but may lose traffic after a host sensor fails. Cloud audit records control-plane requests but not necessarily what happened inside a workload. Application logs know business objects and authorization outcomes but may not identify the originating container. Kubernetes audit records API decisions while runtime activity occurs elsewhere.

Cross-domain analytics therefore should not begin with an “entity risk score.” It begins with a claim that can be supported or contradicted by independent witnesses. Consider: “A stolen developer session was used to create a cloud credential, deploy a workload, and exfiltrate customer records.” The useful output is a time-ordered evidence bundle showing subject, process, workload, request, and network destination, with uncertainty at every join.

Correlation is not ordinary equality. Clocks differ, identifiers are reused, NAT collapses hosts, containers are ephemeral, and collectors duplicate or delay events. A reliable investigation timeline distinguishes observed facts from inferred links and records why each inference was made.

Domain-Specific Evidence

Network flow and encrypted metadata

A flow record should contain observation start/end, source and destination addresses and ports, transport, bytes and packets in each direction, sensor, sampling rate, network zone, and translated addresses when lawful and available. TLS metadata may include version, SNI or privacy-approved hostname category, certificate fingerprint, ALPN, and handshake outcome. JA3-like fingerprints can support hunting but are neither stable identities nor maliciousness labels; libraries and middleboxes create collisions.

Useful derived values include duration, byte ratio, packet-size statistics, fan-out, failed-connection rate, periodicity, and destination novelty. For event times \(t_1,\dots,t_n\), beacon regularity can be summarized by coefficient of variation

\[ CV=\frac{\operatorname{sd}(t_i-t_{i-1})}{\operatorname{mean}(t_i-t_{i-1})}. \]

Low \(CV\) is evidence of periodicity, not command-and-control: health checks and agents are periodic too. Destination reputation should retain observation date because domains and addresses change ownership.

Endpoint process trees

Process analytics require boot-scoped identity. A PID alone is unsafe because operating systems reuse it. A process key should combine device, boot identifier, PID, and start time. Record executable path and hash, signer, command-line representation subject to privacy controls, parent process key, user or workload identity, integrity level, and termination time.

Sequences often carry more meaning than individual names. winword -> powershell -> rundll32 is different from a management agent invoking PowerShell from an approved path, even if each binary is common. Represent ancestry as typed edges and preserve missing-parent status. If collection begins after process start, inventing a root creates false confidence.

Cloud control plane

Cloud events need provider, account/project/subscription, region, principal, credential/session, API operation, resource, source context, user agent, request parameters with secret redaction, response status, policy decision, and request ID. Separate control-plane creation from data-plane use. Creating an access key and using it are related but distinct evidence.

High-value patterns include disabling logs before privilege changes, creating credentials followed by new-region use, modifying trust policies, snapshot sharing, and unusual role assumption. Baseline by automation identity and deployment pipeline; infrastructure-as-code produces legitimate bursts that look extraordinary beside human administration.

Application and API activity

Application logs supply business semantics: tenant, authenticated principal, session, route template, object type, authorization decision, response class, records returned, and trace identifier. Never aggregate by raw URL when it embeds customer IDs. API abuse may appear as object enumeration, pagination manipulation, unusual error transitions, or a token exercising a permission it historically held but never used.

Kubernetes and workload identity

Kubernetes audit events identify user, groups, verb, object reference, namespace, request and response status, source IPs, stage, audit ID, and impersonation. Join pod UID—not merely pod name—to container runtime, image digest, node, service account, and cloud workload identity. Names are reusable; UIDs and validity intervals prevent yesterday's pod from being joined to today's traffic.

A Canonical Evidence Envelope

Do not flatten every source into a lowest-common-denominator table. Preserve source payloads and normalize only fields needed for correlation:

{
  "event_id":"cloud:01J5...",
  "event_type":"cloud.credential.create",
  "observed_at":"2026-08-20T15:04:12.882Z",
  "ingested_at":"2026-08-20T15:04:15.104Z",
  "producer":"aws-cloudtrail",
  "tenant_id":"acme",
  "actor":{"type":"human","id":"u-17","session_id":"s-91"},
  "object":{"type":"access_key","id":"key-tokenized-4"},
  "trace":{"request_id":"req-8","trace_id":null},
  "network":{"source_ip":"198.51.100.8","asn":64520},
  "source_schema":"cloudtrail-1.09",
  "normalizer_version":"3.4.1",
  "payload_ref":"object://immutable/evidence/01J5..."
}

This envelope resembles CloudEvents in separating event identity, source, type, subject, and time; OpenTelemetry supplies trace/span conventions for instrumented applications; ECS provides a broad field vocabulary. None removes the need for local semantics. user.id, for example, can mean an employee, customer, operating-system account, or workload. Record namespace and identity type.

Correlation as Bounded Inference

The strongest join uses a propagated trace or request ID. Next are cryptographically or platform-bound identifiers such as session ID, pod UID, or cloud request ID. Weaker joins use shared device, IP, user agent, and time. Every inferred link should carry a method and confidence.

If source \(A\) has clock-error bound \(\epsilon_A\) and source \(B\) has \(\epsilon_B\), events can be temporally compatible when

\[ [t_A-\epsilon_A,t_A+\epsilon_A]\cap[t_B-\epsilon_B,t_B+\epsilon_B]\ne\varnothing. \]

For an expected causal delay \([d_{min},d_{max}]\), shift the second interval accordingly. A fixed “within five minutes” join hides whether clocks are accurate to milliseconds or hours. Estimate skew from known paired events—load-balancer request IDs and application traces, for example—and monitor it per source.

Candidate-link confidence can be an auditable log-likelihood ratio:

\[ \ell(A,B)=\log\frac{P(M\mid same)}{P(M\mid different)}, \]

where \(M\) contains identifier match, temporal compatibility, topology, and expected sequence. Do not pretend independence among IP, subnet, and ASN. For investigations, expose the components rather than only the combined value.

SQL for a Point-in-Time Timeline

The following SQLite-compatible query constructs one evidence timeline using explicit keys. It avoids a many-to-many time-only join.

WITH scoped_sessions AS (
  SELECT session_id, subject_id, device_id, started_at, ended_at
  FROM identity_sessions
  WHERE subject_id = :subject_id
    AND started_at < :investigation_end
    AND COALESCE(ended_at, :investigation_end) >= :investigation_start
),
timeline AS (
  SELECT e.occurred_at, 'endpoint' AS domain, e.event_id,
         e.process_key AS object_id, s.session_id, 'device_session' AS link_method
  FROM endpoint_events e
  JOIN scoped_sessions s ON s.device_id = e.device_id
   AND e.occurred_at >= s.started_at
   AND e.occurred_at < COALESCE(s.ended_at, :investigation_end)
  UNION ALL
  SELECT c.occurred_at, 'cloud', c.event_id, c.resource_id,
         c.session_id, 'session_id'
  FROM cloud_events c JOIN scoped_sessions s ON s.session_id = c.session_id
  UNION ALL
  SELECT a.occurred_at, 'application', a.event_id, a.object_id,
         a.session_id, 'session_id'
  FROM application_events a JOIN scoped_sessions s ON s.session_id = a.session_id
)
SELECT occurred_at, domain, event_id, object_id, session_id, link_method
FROM timeline
ORDER BY occurred_at, domain, event_id;

Network flows need a separate mapping from device interface and validity interval; joining every flow by a shared public IP would be indefensible. All tables should retain ingested_at so investigators can tell whether an event was available to the original detector or only arrived later.

Safe Runnable Lab: Build an Evidence Timeline

This standard-library lab correlates synthetic records using explicit session and pod identifiers, then asserts the hypothesized sequence.

from datetime import datetime, timezone

def instant(value):
    return datetime.fromisoformat(value.replace("Z", "+00:00"))

events = [
 {"id":"e1","time":"2026-08-20T15:00:00Z","domain":"endpoint",
  "kind":"shell_start","session":"s91","pod":None},
 {"id":"c1","time":"2026-08-20T15:02:00Z","domain":"cloud",
  "kind":"credential_create","session":"s91","pod":None},
 {"id":"k1","time":"2026-08-20T15:05:00Z","domain":"kubernetes",
  "kind":"pod_create","session":"s91","pod":"pod-uid-7"},
 {"id":"a1","time":"2026-08-20T15:07:00Z","domain":"application",
  "kind":"bulk_export","session":None,"pod":"pod-uid-7"},
 {"id":"n1","time":"2026-08-20T15:08:00Z","domain":"network",
  "kind":"large_egress","session":None,"pod":"pod-uid-7"},
 {"id":"noise","time":"2026-08-20T15:06:00Z","domain":"network",
  "kind":"large_egress","session":None,"pod":"pod-uid-other"},
]

def correlated(seed_session, rows):
    selected = {r["id"] for r in rows if r["session"] == seed_session}
    pods = {r["pod"] for r in rows if r["id"] in selected and r["pod"]}
    changed = True
    while changed:
        changed = False
        for row in rows:
            if row["id"] not in selected and row["pod"] in pods:
                selected.add(row["id"]); changed = True
                if row["pod"]: pods.add(row["pod"])
    return sorted((r for r in rows if r["id"] in selected),
                  key=lambda r: (instant(r["time"]), r["id"]))

timeline = correlated("s91", events)
kinds = [row["kind"] for row in timeline]
print(" -> ".join(kinds))
assert kinds == ["shell_start", "credential_create", "pod_create",
                 "bulk_export", "large_egress"]
assert "noise" not in {row["id"] for row in timeline}
assert all(instant(timeline[i]["time"]) <= instant(timeline[i+1]["time"])
           for i in range(len(timeline)-1))

Expected output is shell_start -> credential_create -> pod_create -> bulk_export -> large_egress. The unrelated flow shares time and event type but not pod identity, so it is excluded. A production implementation should store each link as an edge with link_method, confidence, and evidence references; transitive expansion must have domain and time bounds to avoid swallowing an entire tenant.

From Timeline to Detection

Once evidence is linked, detection can operate on sequences rather than additive points. A finite-state rule for the constructed case might require credential creation by an interactive identity, workload creation using the credential within 15 minutes, sensitive export by that workload, and egress above a tenant-relative threshold. Each transition has a maximum delay and compatible identity relation.

Entity aggregation should preserve mechanisms. Summing “endpoint severity 40 + network severity 30 + cloud severity 50” creates a false numerical precision and lets ten weak correlated alerts outweigh one protocol violation. Prefer a small set of reasoned hypotheses with supporting/contradicting evidence. Deduplicate downstream alerts into an investigation keyed by incident hypothesis, not merely actor.

For streaming, event-time state must tolerate late arrivals. A watermark closes a window operationally, not epistemically; late evidence may revise a timeline. Emit revision numbers and avoid destructive overwrites. Analysts need to know that version 3 added a cloud event received 47 minutes late.

Production Failure Analysis

Identifier collision. PID, container name, username, and IP are reusable. Use boot IDs, UIDs, namespaces, and validity intervals.

Clock-skew fiction. A generous time window creates plausible but false stories. Measure per-source skew and show temporal uncertainty.

Cardinality explosion. Joining shared IPs or generic service accounts produces millions of links. Require stronger keys or cap fan-out and label ambiguity.

Normalization loss. Flattening source payloads discards request parameters needed later. Keep immutable raw evidence with access controls and retention.

Sensor-selective truth. Managed endpoints have rich evidence while unmanaged workloads appear quiet. Report coverage and never interpret missing telemetry as benign.

Duplicate cascades. Retries and multi-stage audit records multiply one action. Deduplicate with source IDs and documented stage semantics.

Collection-induced outage. Verbose application or Kubernetes auditing can overload systems or leak secrets. Redact at source, sample only where justified, and load-test policies.

Cross-tenant leakage. Correlation stores are powerful. Enforce tenant predicates in storage and service authorization, not only UI filters.

Operating a Correlation Pipeline

Each producer needs a measurable contract. Completeness can be approximated through sequence numbers, expected heartbeats, or comparison with an independent control-plane counter. Freshness should be measured as both source delay and pipeline delay: observed_at - occurred_at captures producer behavior, while available_at - observed_at captures transport and processing. Combining them into one latency hides where remediation belongs. Track p50, p95, and p99 by source, region, tenant class, and event type.

Schema changes should enter through versioned adapters and golden fixtures. A source field renamed from principalId to a nested object can silently null an identity join while event volume remains healthy. Contract tests should assert semantics: a known role-assumption fixture resolves the expected actor; a pod recreation generates a new UID; a denied API action remains denied after normalization. Preserve unknown enum values rather than mapping them to a familiar category.

Correlation rules need replayable versions. Store the normalized event IDs, rule version, state-machine transition, link methods, and window bounds for every emitted investigation. A rule edit should run against a fixed historical corpus and report changed cases, not only unit-test success. Because historical raw data may be sensitive or expensive, maintain small de-identified golden traces for common and adversarial sequences, plus access-controlled sampled replays for release review.

Queue behavior is part of validation. Measure how many source alerts consolidate into each investigation, how often separate incidents are incorrectly merged, and how often analysts split a case. Merge errors are asymmetric: over-merging creates an incoherent mega-incident; under-merging repeats work and hides a campaign. Provide reversible merge/split operations and feed those corrections into rule review without treating every analyst edit as ground truth.

Response automation should attach to verified transitions, not the mere existence of a cross-domain story. A known compromised token creating a credential may justify token revocation; a probabilistic IP/time link should not terminate a production workload. The investigation object should state which actions are permitted by which evidence class. If a required source becomes stale, keep the partial timeline, downgrade the hypothesis, and disable only dependent automation.

Retention tiers can reduce cost and exposure. Keep normalized envelopes and link edges for the investigation horizon; retain high-cardinality payloads for shorter, source-specific periods; preserve legal or incident evidence through explicit holds. Derived timelines must point to payload availability so an old explanation does not promise evidence already deleted. Hashes can verify integrity, but a hash of deleted evidence does not make the explanation independently reviewable.

Interview Practicum

Scenario: Correlation When a Sensor Disappears.

Prompt. A customer reports that a developer account created a credential, deployed a pod, and exported data. Design a real-time cross-domain detector and an investigation view.

Ask which identifiers propagate, source latency/skew, retention, workload identity mapping, sensitive application actions, expected automation, and response authority.

Worked Answer

Propose canonical envelopes plus immutable payloads; build explicit session, request, pod UID, and workload-identity links; represent the hypothesis as a bounded state machine; emit an evidence graph and ordered timeline. Backtest point-in-time and measure confirmed-hypothesis precision, stage coverage, time to coherent evidence, duplicate investigations, and analyst correction rate.

Follow-Up Questions and Answers

Midstream constraint. Endpoint telemetry is unavailable on developer laptops for 90 days.

Do not claim equivalent coverage. Start the sequence at identity/cloud evidence, require stronger session and phishing-resistant authentication context, and label endpoint stage unknown. Increase audit sampling and consider a narrow preventive control on credential creation. Report the exact attacks that are no longer observable, such as local process ancestry.

Second constraint. Network telemetry is sampled 1:100 and NAT mappings are retained only one hour.

Use network evidence as corroboration, not required identity proof. Correct volume estimates only where sampling design supports it; retain uncertainty. Capture approved workload-to-flow mapping within the hour, aggregate privacy-preserving destination categories, and allow the detector to conclude “export observed, egress unconfirmed.”

Third constraint. Platform engineering says full Kubernetes request bodies add unacceptable API-server load.

Select audit levels by high-risk verbs and resources, exclude secret bodies, and measure policy overhead in a canary. Rely on object references, actor, verb, response, audit ID, and deployment provenance. The answer is a coverage/cost decision, not “log everything.”

Weak answers join on IP and time, flatten all logs into one score, or treat absent sensors as negative evidence. Staff answers reason about identifiers, clocks, state, and revision. Principal answers negotiate minimum viable telemetry, quantify residual blind spots, and move controls to boundaries that remain observable.

Key Takeaways

  • Cross-domain analytics builds evidence for hypotheses; it does not merely sum alerts.
  • Preserve domain payloads while normalizing a small correlation envelope.
  • Prefer propagated and platform-bound identifiers; time/IP joins are weaker inferences.
  • Model clock error, late data, identifier validity, and timeline revisions explicitly.
  • Missing sensors reduce what can be claimed and may justify moving controls to observable boundaries.
