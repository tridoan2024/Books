Appendix A: Security Audit Checklist for AI Agents

This checklist is designed for security architects, penetration testers, and compliance auditors evaluating AI CLI agents, multi-agent systems, and RAG pipelines. It is organized by security domain, with each check referencing the relevant chapter for detailed analysis. Checks are prioritized by severity: [C] Critical, [H] High, [M] Medium, [L] Low.

Domain 1: Permission System & Access Control

1.1 Permission Model

  • [C] Verify that a permission system exists and gates every tool invocation
  • [C] Confirm deny rules are evaluated before allow rules (deny-first semantics)
  • [H] Verify that permission rules from lower-trust sources cannot override higher-trust deny rules
  • [H] Confirm that wildcard allow rules (Bash(*)) require explicit user configuration, not default
  • [M] Verify that unknown/new tools default to "ask" rather than "allow"
  • [M] Test that permission rules are evaluated on the canonicalized tool input, not the raw input
  • [L] Confirm that permission evaluation is logged with rule source and match details

1.2 Permission Modes

  • [H] Verify that "plan" mode logs all actions and requires human confirmation for every tool call
  • [H] Confirm that "auto" mode's AI classifier cannot be bypassed through prompt injection
  • [M] Test that mode restrictions are enforced server-side, not client-side
  • [M] Verify that mode changes are logged and auditable
  • [L] Confirm that the permission mode is visible to the user at all times

1.3 MCP Tool Permissions

  • [C] Verify that MCP tools pass through the same permission system as built-in tools
  • [H] Confirm that MCP tool names include server namespace prefix to prevent shadowing
  • [H] Verify that permission rules can target specific MCP servers and tools
  • [M] Test that MCP tool annotations (readOnlyHint, destructiveHint) influence permission decisions
  • [M] Verify that new MCP tools added via listChanged require approval

Domain 2: Command Execution Security

2.1 Shell Command Safety

  • [C] Verify that shell commands are validated before execution (not just logged after)
  • [C] Test for shell injection via: variable expansion, command substitution, process substitution, backticks, eval, base64 encoding
  • [H] Verify that the command validator handles multi-statement commands (;, &&, ||, pipes)
  • [H] Test that flag reordering (rm -r -f vs rm -rf) does not bypass pattern matching
  • [H] Verify that absolute path commands (/bin/rm) are checked, not just relative
  • [M] Test for regex denial-of-service (ReDoS) in command validation patterns
  • [M] Verify that command timeout applies and kills runaway processes
  • [L] Confirm that command output is size-limited before entering the LLM context

2.2 Sandbox Isolation

  • [H] Verify that sandbox/isolation mechanisms exist for tool execution
  • [H] Confirm that network access from sandboxed tools is restricted or monitored
  • [M] Test that filesystem access from sandboxed tools is limited to the project directory
  • [M] Verify that resource limits (CPU, memory, file descriptors) are enforced
  • [L] Confirm that sandbox violations are logged and alerted

Domain 3: File System Security

3.1 Path Traversal

  • [C] Test path traversal via ../, absolute paths, symlinks, and redundant separators
  • [H] Verify that paths are canonicalized before access (resolve symlinks, normalize separators)
  • [H] Test for TOCTOU between path validation and file access
  • [M] Verify that ZIP extraction validates all paths against traversal
  • [M] Confirm that symlink targets in ZIP archives are validated against extraction root

3.2 Sensitive File Protection

  • [C] Verify that .env, credentials.json, *.pem, *.key files are deny-listed
  • [H] Confirm that deny lists apply across all file-reading tools (Read, Grep, Bash cat)
  • [H] Test that deny-listed files cannot be accessed through alternative paths
  • [M] Verify that binary file detection prevents reading non-text files
  • [M] Confirm that file size limits prevent reading extremely large files
  • [L] Test that file classification rules correctly identify sensitive files by path pattern

Domain 4: Credential Management

4.1 Credential Storage

  • [C] Verify that credentials are stored in the OS secure storage (Keychain, libsecret, Credential Manager)
  • [C] Confirm that plaintext credential fallback logs a warning and is documented
  • [H] Test that credential files have restrictive permissions (0600 or equivalent)
  • [H] Verify that credentials are not written to log files, error messages, or telemetry
  • [M] Confirm that credential rotation/refresh works correctly
  • [M] Verify that expired/revoked credentials are cleaned up

4.2 Credential Exposure

  • [C] Verify that API keys are not passed to child processes (MCP servers, hooks, bash commands)
  • [H] Test that credentials are not included in git commits (secret-scan hook)
  • [H] Verify that credentials are not logged in debug output
  • [M] Confirm that credentials are not visible in process arguments (/proc/[pid]/cmdline)
  • [M] Test that credentials in environment variables are stripped before spawning subprocesses
  • [L] Verify that credential cache files are deleted on session end

4.3 JWT Security

  • [H] Verify that JWT tokens are validated with signature verification, not just decoded
  • [H] Confirm that JWT expiry is enforced and tokens are refreshed before expiry
  • [M] Test that JWT claims are validated against expected values
  • [M] Verify that JWKS endpoint is used for key rotation support
  • [L] Confirm that JWT token prefixes are not logged in debug output

Domain 5: Prompt Injection Defense

5.1 Content Trust Boundaries

  • [C] Verify that tool results are wrapped in content boundary markers
  • [H] Test that content boundary markers use unpredictable tokens (not static XML tags)
  • [H] Verify that MCP tool results are treated as untrusted content, not instructions
  • [M] Test injection via: embedded closing tags, system instruction impersonation, multi-step injection
  • [M] Verify that the system prompt instruction hierarchy is maintained across all content sources
  • [L] Confirm that content provenance is tracked through the processing pipeline

5.2 Input Validation

  • [H] Verify that user input is sanitized before processing
  • [H] Test that file content read by the agent does not execute as instructions
  • [M] Verify that MCP tool descriptions are scanned for instruction-like patterns
  • [M] Test that tool parameter descriptions do not inject behavioral instructions
  • [L] Confirm that error messages do not leak internal system information

Domain 6: MCP Protocol Security

6.1 Server Connection

  • [C] Verify that MCP servers from project configuration require user approval before connecting
  • [H] Confirm that npx -y invocations use version pinning, not @latest
  • [H] Test that server namespace prefixing prevents tool name collisions and shadowing
  • [M] Verify that server health checks detect unresponsive servers within 90 seconds
  • [M] Confirm that server reconnection re-negotiates capabilities and re-fetches tool lists
  • [L] Test that DNS rebinding does not redirect HTTP MCP connections

6.2 Server Tool Safety

  • [C] Verify that MCP tool descriptions are not blindly loaded into the system prompt
  • [H] Test that tool description injection (instructions embedded in descriptions) is detected or mitigated
  • [H] Verify that tool result size limits are enforced (truncation before context injection)
  • [M] Confirm that capability annotations are treated as hints, not authoritative declarations
  • [M] Test that listChanged notifications trigger re-approval for new tools
  • [L] Verify that progress notifications are rate-limited

6.3 Supply Chain

  • [C] Verify that an approved MCP server list exists and is enforced
  • [H] Confirm that .mcp.json changes are flagged during code review
  • [H] Test that managed settings can block unapproved MCP servers
  • [M] Verify that server packages are version-pinned in all configurations
  • [M] Confirm that server binary integrity is verified (hash or signature)
  • [L] Test for dependency confusion between internal and public package registries

Domain 7: Multi-Agent Security

7.1 Agent Isolation

  • [H] Verify that subagents have restricted tool access (not the full parent tool set)
  • [H] Confirm that subagent fork depth is limited to prevent recursive spawning
  • [M] Test that subagent context does not include the parent's full conversation history
  • [M] Verify that subagent resource budgets (tokens, time, tool calls) are enforced
  • [L] Confirm that subagent outputs are validated before incorporation into parent context

7.2 Inter-Agent Communication

  • [H] Verify that messages between agents are treated as untrusted content
  • [M] Test that a compromised agent cannot escalate privileges through the orchestrator
  • [M] Verify that result aggregation does not amplify poisoned content
  • [L] Confirm that agent-to-agent communication is logged for audit purposes

Domain 8: Configuration Security

8.1 Configuration Cascade

  • [C] Verify that managed/MDM settings cannot be overridden by lower-priority layers
  • [H] Confirm that project settings require trust dialog before loading
  • [H] Test that deny rules are additive-only (no layer can remove another's denies)
  • [M] Verify that configuration changes during a session trigger user notification
  • [M] Confirm that schema validation catches malformed configuration
  • [L] Test that unknown configuration keys are logged as warnings

8.2 Hook Security

  • [C] Verify that hook errors default to fail-open (and that security hooks implement fail-closed)
  • [H] Test that PreToolUse hooks can block dangerous operations effectively
  • [H] Confirm that allowManagedHooksOnly prevents project hook injection
  • [M] Verify that hook timeout kills prevent indefinite blocking
  • [M] Test that hook input modification (updatedInput) is re-validated against deny rules
  • [L] Confirm that hook execution priority follows the trust hierarchy

Domain 9: Enterprise & Compliance

9.1 MDM Enforcement

  • [C] Verify that MDM-locked fields cannot be overridden by any configuration layer
  • [H] Confirm that HMAC verification rejects tampered MDM profiles
  • [H] Test that disableAllHooks is locked to false in enterprise deployments
  • [M] Verify that managed settings are loaded before any user/project settings
  • [L] Confirm that MDM policy degradation is fail-closed (restrictive defaults)

9.2 Audit Logging

  • [H] Verify that all permission decisions are logged with timestamp, user, tool, decision, and rule
  • [H] Confirm that audit logs cannot be modified by the developer (append-only or forwarded)
  • [M] Test that session transcripts capture tool inputs and outputs at configurable detail levels
  • [M] Verify that data access logs record file reads with classification tags
  • [L] Confirm that audit log retention meets framework requirements

9.3 Data Protection

  • [H] Verify that privacy levels correctly restrict data flow to API, telemetry, and MCP endpoints
  • [H] Confirm that the sanitization pipeline detects API keys, tokens, and PII before transmission
  • [M] Test that "strict" privacy mode summarizes tool results rather than transmitting full content
  • [M] Verify that session data deletion works completely (all data stores cleared)
  • [L] Confirm that telemetry opt-out stops all non-essential data transmission

Domain 10: Network Security

10.1 API Communication

  • [H] Verify that all API calls use TLS 1.2 or higher
  • [M] Confirm that certificate validation is enabled and cannot be disabled by configuration
  • [M] Test that the enterprise proxy endpoint is enforced when configured via MDM
  • [L] Verify that WebSocket connections validate origin headers

10.2 External Access

  • [H] Test for SSRF via DNS rebinding or cross-origin redirects in web fetch tools
  • [M] Verify that URL allowlists/denylists are enforced for outbound connections
  • [M] Confirm that MCP remote server connections validate TLS certificates
  • [L] Test that localhost-bound services are not accessible from external MCP servers

Usage Guidelines

For Security Auditors

  1. Use this checklist as a structured starting point for AI agent security assessments
  2. Prioritize Critical and High checks for initial assessment
  3. Map findings to CWEs using Appendix B for standardized vulnerability reporting
  4. Use the threat model template from Appendix C to identify system-specific attack vectors not covered here

For Development Teams

  1. Integrate Critical checks into CI/CD pipelines as automated tests where possible
  2. Review High checks during code review for security-sensitive changes
  3. Perform Medium and Low checks quarterly as part of security maintenance
  4. Use this checklist to validate that new features do not regress existing security controls

For Compliance Teams

  1. Cross-reference checks with the compliance framework mapping in Chapter 23
  2. Each check that maps to a compliance requirement should have documented evidence
  3. Use the check IDs as references in compliance documentation
  4. Update the checklist when compliance framework requirements change
