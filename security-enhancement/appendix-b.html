Appendix B: Patch Application Guide

This appendix provides step-by-step instructions for applying all 35 direct patches identified in the security audit. The patches are organized by dependency order: patches in earlier phases must be applied before those in later phases, as later patches may depend on infrastructure established by earlier ones.

Each patch entry includes: the affected files, prerequisite patches, application steps, testing requirements, and rollback procedures.

Application Principles

Dependency Order

Patches must be applied in phase order. Within a phase, patches can be applied in any order unless a specific dependency is noted.

graph LR
    P1["Phase 1<br/>Plugin Supply Chain<br/>6 patches"] --> P2["Phase 2<br/>Credential Storage<br/>5 patches"]
    P2 --> P3["Phase 3<br/>Auth Token Lifecycle<br/>5 patches"]
    P3 --> P4["Phase 4<br/>Subagent Isolation<br/>3 patches"]
    P4 --> P5["Phase 5<br/>Bridge & Remote<br/>6 patches"]
    P5 --> P6["Phase 6<br/>Data Protection<br/>7 patches"]
    P6 --> P7["Phase 7<br/>Bash Security<br/>3 patches"]

Testing Requirements

Every patch must pass:

  1. Unit tests: Specific tests for the patched behavior
  2. Regression tests: Full test suite for the affected module
  3. Integration tests: Cross-module tests that exercise the patched code path
  4. Manual verification: The specific verification steps listed for each patch

Rollback Procedure

Each patch is designed to be independently reversible via git revert. The rollback section for each patch notes any special considerations.

Rollback Strategy

General Rollback Procedure

Every patch is designed to be independently revertable:

#!/usr/bin/env bash
set -euo pipefail

readonly PATCH_COMMIT="${1:?Usage: rollback-patch.sh <commit-sha>}"

echo "Rolling back patch commit: ${PATCH_COMMIT}"

# Step 1: Create revert commit
git revert --no-commit "${PATCH_COMMIT}"

# Step 2: Run tests to verify revert is safe
echo "Running tests..."
npm test

# Step 3: Complete the revert
git commit -m "revert: rollback patch ${PATCH_COMMIT} due to regression"

echo "Rollback complete. Run full test suite before deploying."

Phase-Level Rollback

If an entire phase needs to be reverted (e.g., Phase 4 Subagent Isolation causes a performance regression), revert in reverse order within the phase:

# Revert Phase 4 in reverse order:
git revert <patch-4.3-sha>  # MCP Sandboxing
git revert <patch-4.2-sha>  # Fork Depth
git revert <patch-4.1-sha>  # Process Isolation (foundational)

Patches That Cannot Be Independently Reverted

#!/usr/bin/env bash
