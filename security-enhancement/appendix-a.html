Appendix A: Complete Vulnerability Catalog

This appendix catalogs all 50 vulnerabilities discovered during the security audit of Claude Code's codebase, presented in a CVE-style format. Each entry includes the vulnerability identifier, severity rating, CVSS 3.1 score, CWE classification, affected source location, description, patch status, and verification steps.

The findings are organized by severity tier: CRITICAL (2), HIGH (8), MEDIUM (23), LOW (11), and INFO (6).

CRITICAL Severity

V-1: No Cryptographic Signature Verification for Plugins

Field Value
ID V-1
Severity CRITICAL
CVSS 3.1 9.1 (AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N)
CWE CWE-494: Download of Code Without Integrity Check
Location plugins/:0
Dependency Chain Plugin Supply Chain
Patch Type Architecture Solution
Chapter 4

Description: Plugins are downloaded from npm and executed without any cryptographic signature verification. An attacker who compromises an npm package or performs a registry substitution attack can deliver malicious code to all Claude Code users who install the affected plugin.

Verification Steps: 1. Verify ECDSA-P256 signature verification is called before plugin load 2. Verify unsigned plugins are rejected with clear error message 3. Verify tampered signature causes rejection 4. Verify valid signed plugin loads successfully

V-2: No Cryptographic Signature Verification for Downloaded Plugins

Field Value
ID V-2
Severity CRITICAL
CVSS 3.1 8.1 (AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:N)
CWE CWE-494: Download of Code Without Integrity Check
Location utils/plugins/pluginLoader.ts, marketplaceManager.ts:0
Dependency Chain Plugin Supply Chain
Patch Type Architecture Solution
Chapter 4

Description: The plugin download and marketplace integration paths lack signature verification. Both pluginLoader.ts and marketplaceManager.ts download and execute plugin code using only HTTPS transport security, without verifying the authenticity of the downloaded content.

Verification Steps: 1. Verify marketplace downloads include signature verification 2. Verify pluginLoader checks signatures before loading 3. Verify signature mismatch prevents plugin execution

HIGH Severity

V-3: Subagent Execution Without Process-Level Isolation

Field Value
ID V-3
Severity HIGH
CVSS 3.1 7.8 (AV:L/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:H)
CWE CWE-269: Improper Privilege Management
Location tools/AgentTool/runAgent.ts:248
Dependency Chain Subagent Isolation
Patch Type Architecture Solution
Chapter 13

Description: Subagents execute within the parent process, sharing memory space, file descriptors, and process-level permissions. A compromised or manipulated subagent has full access to the parent's credential material and can make API calls with the parent's authentication context.

Verification Steps: 1. Verify subagents launch via child_process.fork() with IPC 2. Verify memory isolation between parent and child 3. Verify capability-based tool filtering at process boundary 4. Verify parent crash does not expose child credentials

V-4: Symlink-Based Path Traversal Risk in ZIP Extraction

Field Value
ID V-4
Severity HIGH
CVSS 3.1 7.5 (AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:H/A:N)
CWE CWE-22: Improper Limitation of a Pathname to a Restricted Directory
Location utils/plugins/zipCache.ts, utils/dxt/zip.ts:0
Dependency Chain Plugin Supply Chain
Patch Type Direct Patch
Chapter 5

Description: ZIP extraction does not validate for symlink-based path traversal. A crafted ZIP file containing symlinks pointing outside the extraction directory could write files to arbitrary locations on the filesystem.

Verification Steps: 1. Verify symlinks in ZIP archives are rejected 2. Verify realpath() canonical path resolution after extraction 3. Verify TOCTOU check after all files written 4. Verify extraction directory cannot be escaped

V-5: JWT Decoded Without Signature Verification

Field Value
ID V-5
Severity HIGH
CVSS 3.1 7.5 (AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:H/A:N)
CWE CWE-347: Improper Verification of Cryptographic Signature
Location bridge/jwtUtils.ts:21
Dependency Chain Auth Token Lifecycle
Patch Type Direct Patch
Chapter 10

Description: JWT tokens from bridge sessions are decoded using simple base64url parsing without any signature verification. The decodeJwtPayload() function strips the sk-ant-si- prefix, splits on '.', and base64-decodes the payload without verifying the signature.

Verification Steps: 1. Verify JWKS-based signature verification implemented 2. Verify public key cache with automatic rotation 3. Verify exp claim cross-validated against server-provided expires_in 4. Verify clampTokenRefreshDelay defense implemented

V-7: Plaintext Credential Storage on Non-macOS Platforms

Field Value
ID V-7
Severity HIGH
CVSS 3.1 7.1 (AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:N)
CWE CWE-256: Plaintext Storage of a Password
Location utils/secureStorage/index.ts:9
Dependency Chain Credential Storage
Patch Type Architecture Solution
Chapter 7

Description: On non-macOS platforms (Linux, Windows), credentials are stored in plaintext JSON files without encryption. Any process running as the same user can read the credential file.

Verification Steps: 1. Verify libsecret integration on Linux 2. Verify Windows Credential Manager integration 3. Verify encrypted fallback with OS-derived key material 4. Verify plaintext storage no longer used on any platform

V-8: Plaintext Credential Fallback Storage

Field Value
ID V-8
Severity HIGH
CVSS 3.1 7.1 (AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:N)
CWE CWE-312: Cleartext Storage of Sensitive Information
Location utils/secureStorage/plainTextStorage.ts:57
Dependency Chain Credential Storage
Patch Type Direct Patch
Chapter 7

Description: The fallback credential storage writes credentials as plaintext JSON with writeFileSync followed by chmodSync(0o600), creating a race condition where the file is readable before permissions are applied.

Verification Steps: 1. Verify atomic write with O_CREAT|O_EXCL + fsync + rename 2. Verify fallback storage encrypts at rest 3. Verify no plaintext credential window between write and chmod

Location history.ts:115
Dependency Chain Data Exfiltration
Patch Type Architecture Solution

Verification Steps: 1. Verify automatic secret detection and redaction in history 2. Verify at-rest encryption for history files 3. Verify configurable TTL with automatic purging 4. Verify clear-history command implementation
